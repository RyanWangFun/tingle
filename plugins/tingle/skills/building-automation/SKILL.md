# building-automation

## 概述与核心原则

一句话职责：**把一件反复要做的活，声明成一条会在认领人机器上自己跑起来的自动化。**

**这算一个职责，不算两个。** 写声明与装到机器上看似两段，但装、跑、查、撤全是机械动作，已经由程序承担（`tingle auto` 那几条命令）；本 skill 只干那段需要判断的活——这件事该不该放手自己跑、放手到什么程度、出错了谁会知道。**边界就划在"要判断的"与"机械的"之间**，这与本插件"结果不依赖内容理解、两次运行必然同答案的进程序"是同一条线。

**适用环节**：换一个客户项目也会再次发生的固定环节——任何项目上都会有人手里攒着几件天天重复的活，想让它们自己发生。不是一次性事务。

**本 skill 是平台技能**：它管的是让项目怎么运转，不对应任何一个业务环节，因而不认领六组能力中的任何一组。

**三条核心原则（越一条即错）**：

- **触发和动作分开声明，永不合写。** 「什么时候」和「干什么」是两段各自独立的东西：同一个动作明天可能换个时点，同一个时点可能挂另一个动作。合在一起写，改任何一边都要重建整条。
- **"它不许干什么"由进程限死，不靠嘱咐。** 危害档决定无人值守跑起来时进程能拿到什么能力——高危动作是**根本拿不到工具**，不是"提示它别那么干"。凡是想靠在动作说明里写一句"注意不要……"来兜住风险的，一律判为定档定错了。
- **没人会发现的错，不许无人值守。** 每条自动化都要答一次「它跑错一次，谁会在什么时候发现」。答不出人和时点的，要么把产出摆到有人例行会看的地方，要么就不做成无人值守。

## 一条自动化住在哪（先看这个，它决定了整条流程的形状）

**执行的那一份住本机**，在项目工作文件夹的 `.tingle/` 里，与本地指针同一个交点：**随项目变**（一个项目一套）、**只属于这台机器**（用认领人的身份、在他的机器上跑）。

**这不是图省事，是要害**：定时任务是在没人看着的时候醒来的。真相源放在网上，就等于给"早上九点能不能干活"绑了一条网络与授权的依赖——授权过期、网抖一下、那份东西被挪走，活就没干成，而且没人在旁边。**本机那一份读不到的可能性，比云端小一个量级。**

**另有一份"公示"是可选的**：把这条自动化登记到项目云盘上一张共享表里，供三件事——别人不重复挂同样的活、休假离职时能接手、以及让管事的人看见系统在自己转。**它不参与任何一次运行**，读不到、没建过，都不影响照跑。

一句话记法：**执行看本机，公示给别人看。**

## 运行前检查与输入声明

**第一步跑 `tingle check building-automation`**，拿到开工单才开工；拿到卡点单本次不跑，转 REQUIRED SUB-SKILL: `tingle:project-readiness` 按卡点修，修完复验。

> **怎么调它**：`tingle-core` 不在 PATH 上，它的绝对路径由会话开头那段注入给出（「tingle 程序在这台机器上的绝对路径」那一行）；本页写 `tingle check …`，实际敲的是那个路径加上命令。找不到那一行就说明入口没到场，先补上入口再开工。
>
> **程序只判机械事实**——东西在不在、打不打得开、登记齐不齐。下面声明里的「就绪判据」程序一概不验，由本 skill 开跑时逐条对照判；判不准就停下问人，不许挑一个解释混过去。

本 skill 的 requirements 声明如下。格式的唯一真相源是 `tingle:project-readiness` 的参考件 `readiness-contract.md` 的「requirements 声明格式」一节，本页不复述。

```json
{
  "requirements": {
    "inputs": {
      "要自动化的那件事": {
        "每次输入不一样": true,
        "就绪判据": [
          "使用者说得出这件事在什么条件下该发生——一个具体时点，或一个说得出名字的事件",
          "使用者说得出这件事干完之后产出落在哪里",
          "使用者说得出这件事跑错了谁会在什么时候发现"
        ]
      }
    },
    "outputs": {}
  }
}
```

**为什么两段几乎是空的**：本 skill 写的东西落在**本机**（由程序写），本机不是飞书落点，不进 `outputs`；它读的东西是使用者当场口述的那件活，每次都不一样。**因此装了插件、在一个项目工作文件夹里，就能配第一条自动化——不必等这个项目在飞书上先建好什么。** 可选的公示登记不进声明，见「第六步」。

### 运行时要用到的每一样东西，从哪来（四类逐样点名）

- **要读的项目材料**：无。本 skill 不读任何认知件——它不产内容、不碰内容红线。
- **每次跑都是另一份的**：`要自动化的那件事`（使用者这一次口述的那件活）。
- **要写的落点**：本机 `.tingle/automations.json`（由程序写，非飞书落点）。选择登记公示时，另加项目云盘那张共享表——**地址由使用者在放行时给出，本 skill 不自行选址**。
- **要用的工具与授权**：`tingle-core`（跨项目同一份，随插件包）；本机至少装有一个可无头调用的 agent 命令行（跨项目同一份，由 `tingle doctor` 验）。登记公示时另需飞书读写工具（同样由 `doctor` 验）。
- **要调用的同族 skill**：REQUIRED SUB-SKILL: `tingle:project-readiness`（仅在拿到卡点单时）。

## 何时用 / 何时不用

**何时用**：有一件反复要做的活想让它自己发生；已建的自动化要改时点、改动作、换认领人或停掉。

**何时不用**：
- **把一段做法造成可复用的技能**——那是造技能。本页管的是让一件**已经会做**的活自己跑起来，不管这件活本身怎么做。**判别问句：这件活的"怎么干"在第二个项目也成立吗？成立 → 那部分该造成技能，自动化只负责按时调它。**
- **一次性的"帮我现在跑一下"**——直接跑，不必建自动化。判别问句：这件事下周还会再发生吗？不会 → 不建。
- **为别人的机器代建**——一条自动化只在认领人自己的机器上跑，用的是认领人自己的身份与凭证。要别人接管，由那个人在自己机器上认领。
- **跨项目的自动化**（"每周汇总我手上所有项目"）——**本版做不了**，它不属于任何一个项目工作文件夹，危害档也判不了（同一个动作在 A 项目是二档，在 B 项目可能是三档）。别硬塞，明说做不了。
- **飞书表格或文档变了就跑**——**官方目前没有这类事件**（1.0.88 上核过）。要做只能用时点触发轮询近似：每 N 分钟醒一次，前置条件写"有新记录才跑"。跟使用者说清楚这是轮询、有延迟，不是真的一变就响。

## 方法：五道闸

**闸未答完，不许写声明。** 五道闸的答案就是声明里那几格的内容本身——没答就没有东西可填，先填只能填进一个看不出真假的空壳。

### 闸一 · 触发是什么

**逼使用者把"什么时候"单独说清楚，不许和"干什么"混着说。**

**触发源是一份可增长的清单，不是固定的几格。** 当前六种，写声明时选一种：

| 触发类 | 什么时候响 | 触发表达式填什么 | 门槛 |
|---|---|---|---|
| **时点** | 到点了 | 5 段 cron（分 时 日 月 周） | 无 |
| **文件变化** | 盯的路径变了 | 要盯的路径，一行一个 | 只 macOS |
| **一开工就跑** | 人打开这个项目时 | 节流：每次／每天一次／每周一次 | 无 |
| **跑完接力** | 上游那条跑成之后 | 上游自动化的名字 | 无 |
| **飞书事件** | 妙记生成完、会议结束、审批状态变、收到消息…… | 事件名（跑 `lark-cli event list` 看有哪些） | 只 macOS；**部分事件要组织侧先在开发者后台订阅** |
| **邮件到达** | 收到新邮件 | 要盯的邮件文件夹，留空即收件箱 | 只 macOS；要组织侧配权限 |

**加一种触发源，动作层一个字不用改**——触发源与动作之间只有一句契约：**该跑的时候唤起这条自动化**。所以这张表会长，声明格式不会跟着变。

**两个要跟使用者讲清楚的**：

- **飞书事件分两种身份**。妙记生成、会议、审批、白板、任务这些是**本人身份**，他自己授权就能用；收 IM 消息、卡片按钮这些是**机器人身份**，要组织先在开发者后台配。装的时候程序会先试听一下，听不到会当场把确切的错和修法给他——**装上了却永远不响，比装不上更坏**。
- **文件变化不是存盘就响，实测约 45 秒**；而且短时间内改几次就触发几次，所以那条自动化的动作本身要经得起重复跑。

**禁止**：
- **禁止把触发写成"有需要的时候"「不定期」「随时」。** 那不是触发，是没有触发——六种里挑不出一种的，本次不建，回去把它想清楚。
- **禁止把动作里的条件混进触发段。** 「每天 9 点，如果昨天有投放才跑」——「每天 9 点」是触发，「如果昨天有投放」是前置条件，两处分开写。混在一起的后果是改条件要动触发、改时点要重读条件。

### 闸二 · 触发了干什么

**一段话说清这次要干的活，说不清就是不止一件事，先拆。**

动作段要交三样：**干什么**（一段交给 agent 的活儿说明，可点名要调哪个技能）、**输入从哪来**、**产出写到哪**。

**禁止**：
- **禁止把产出落点留空或写"看情况"。** 落点是运行前提，不是干完再找地方放——无人值守时没人能替它临时选址。
- **禁止一条自动化干两件不相干的活。** 拉数是一件、出报表是另一件，合成一条就无法单独停掉其中一件，也无法分别定档。判别问句：这两半能不能各自被独立命名、各自有人要？能 → 拆成两条。

### 闸三 · 这活跑错了，谁会在什么时候发现

**这一问必须逐条落成文字，无论你打算把它定成哪一档。**

| 答案 | 裁法 |
|---|---|
| 有人例行会看到它的产出，且看得出不对 | 可无人值守 |
| 产出会堆在没人看的地方 | 先改落点，把产出摆到有人例行会看的地方，再判；改不了就不做无人值守 |
| 错了要等到对外才暴露 | 不许无人值守——这条必然是三档，见闸四 |

**禁止拿"它做得挺准的"当答案。** 判的不是准不准，是错了有没有人知道。一件准确率很高但没人复看的自动化，错的那一次会一直错下去。

**禁止拿"我自己会看出来"当答案**，除非说得出他有哪一件例行动作必然会撞见那份产出——说不出例行动作的，等于没人看。

### 闸四 · 定危害档

**先分清这条触发有没有人在场**：「一开工就跑」是人在场的，它在会话里干、走平常的放行机制，危害档那道拒装闸对它不生效——**三档（对外或不可逆）正是只许挂在这类触发上**。其余五种都是没人看着的，下面这张表对它们生效。

**三档，含义固定，只许选档、不许改档的含义。**

| 危害档 | 这一档能干什么 | 判别问句 | 可否无人值守 |
|---|---|---|---|
| **一档 · 只看** | 读、算、比对、判断；结论只落在认领人本机的运行日志里 | 它写出来的东西，除了认领人自己还有第二个人会看到吗？没有 → 一档 | 可 |
| **二档 · 写自家地盘** | 一档全部，加上写本机项目工作文件夹、写项目云盘里已批准给这条自动化的落点 | 它写的地方，是不是只有本项目组的人会看？是 → 二档 | 可 |
| **三档 · 出门或抹改** | 发给项目组之外的任何人；改动或删除已经存在的记录；动被别处当作真相源的东西 | 它干的事，有没有**可能**让项目组之外的人看到，或让已有的东西回不去？有 → 三档 | **不可** |

**判档三条硬规矩**：

1. **两档之间拿不准，取高的那档。** 判低了的代价是无人时真的干出去，判高了的代价只是要人点一下。
2. **三档装不上。** 程序会直接拒绝——这不是劝告，是拦。三档的活只能挂"人在场"那类触发，在那类触发做出来之前，三档等于暂不可用。
3. **档位由人确认，不由本 skill 自行拍板。** 见下面的必停点。

**禁止把风险写进动作说明来降档。** 「发消息前先自己检查一遍」不改变它是三档；能不能干由进程给不给工具决定，不由动作说明里的自觉决定。

**注意第三档判别问句用的是"有没有可能"，不是"实际上有没有"。** 客户群里有客户，答案就是有——不因为"那个群平时都是我们自己人在说话"而改变。

### 闸五 · 认领与查重

- **认领人是谁**：这条自动化在谁的机器上跑。一条只有一个认领人——用的是他本人的身份与凭证，产出上留的也是他的名。
- **本机查重（必做）**：跑 `tingle auto list`，看这个项目在本机是不是已经有一条干同样的活。
- **公示查重（有则做）**：这个项目若有自动化公示表，一并查一遍别人挂了什么。**没有公示表时，必须明确告诉使用者一句：本机看不到同事挂了什么，重复的风险由你判断。** 不许沉默略过——沉默会让人以为查过了。

**禁止跳过查重。** 三个人各挂一条日报，每天出三份，而且谁都以为是自己那条在起作用。

## 六步做完（每步都有对应的命令）

1. **过五道闸**，答案落成文字。
2. **写声明文件**：按参考件 `automation-declaration.md` 的格式写一份 JSON，放在临时位置即可。
3. **收进本机**：`tingle auto add <声明文件.json>`。程序做机械校验——格齐不齐、名字合不合规、cron 写法对不对、危害档认不认得出。**不合规的当场点名是哪一格**，改好重收。
4. **试跑给人看**：`tingle auto run <名字> --dry-run`。它吐出到点会执行的命令与交给 agent 的完整提示词。**把这个摆给使用者看**——这是他唯一一次能在真跑之前看清"它到底会干什么"的机会。
5. **必停点一 · 危害档确认**：把「这条自动化将获得什么能力、拿不到什么能力」摆给使用者，他点头才装。定低了的错，要到无人值守真干出去那天才暴露。确认后 `tingle auto install <名字>`。
6. **可选 · 登记公示**：问使用者要不要把这条登记到项目云盘的共享表，让同事看得见。**要登记就是对外写入，必停等放行**——摆清楚写哪张表、加哪一条、这条今后会干什么，放行后再写。**不登记也完全能用**，只是别人看不见。

## 两个必停点

其余各步做错了使用者当场看得见，可自动；下面两步做错了没人会发现，**必停**：

1. **危害档确认**（第 5 步）——永远必停。
2. **登记公示前的放行**（第 6 步）——只在使用者选择登记时发生。

## 接口与边界（声明）

- **适用环节**：「把一件反复要做的活声明成一条自动化」——换个客户项目也会再次发生的固定环节，非一次性事务。
- **input schema**：`要自动化的那件事`（使用者口述，含何时发生、干什么、产出落哪、错了谁发现）。
- **output schema**：`自动化声明`（名字／触发段／动作段／危害档／定档理由／认领人／开关）；`定档理由`（为什么是这一档，含闸三那一问的答案）；`查重结果`（本机已有哪些、公示面查了没有、为什么这条不重）；`装机结果`（在认领人机器上装成没装成）。**可沉淀候选（reusable_candidates）**：`自动化声明` 的触发段与动作段——同一件活换个项目常常照搬得动；**同一段动作在第二个项目也要用时，那是"该造成技能"的信号**（见「何时不用」）。
- **写回位置**：本机 `.tingle/automations.json`（由程序写）。选择登记公示时，另写项目云盘那张共享表——地址由使用者在放行清单里给出。
- **规则层与项目事实**：不挂载通用／品类／品牌／类型任何一层（本 skill 不产内容、不碰内容红线）；所需项目事实字段：无。
- **工具**：`tingle-core` 的 `check` 与 `auto` 两族命令；登记公示时另用飞书读写工具。
- **决策档**：复核——产出是一条将来会自己跑的自动化，须经使用者确认危害档才算数。
- **复核包**：自动化声明全文 ＋ 定档理由（含「跑错了谁会在什么时候发现」的答案）＋ 查重结果 ＋ 试跑输出（`--dry-run` 那一段，含将执行的命令与完整提示词）。
- **升级条件（命中即停交人）**：①这件活涉及合规红线而判据不确定；②四层规则冲突；③缺关键项目事实；④输出需对外发送；⑤危害档在两档之间判不准，且使用者也拿不准；⑥使用者说不出「跑错了谁会在什么时候发现」；⑦要建的这条与已有的某条职责重叠，谁停谁留拿不准。

## 产出验收判据（DoD）

一次运行合格，当且仅当：

1. 五道闸各有落成文字的答案，且触发段与动作段**分开成文**——两者写在一处即判闸一未过；
2. 危害档已定，且定档理由里含「跑错了谁会在什么时候发现」的答案（人或角色 ＋ 时点，缺一即未答）；
3. `tingle auto add` 收下了这份声明（程序校验通过）；
4. 试跑输出摆给过使用者看，且危害档经他确认；
5. 查重做过且结果可复述——本机现有几条、公示面查了没有（没有公示表时，这句话是否说给使用者听过）；
6. `tingle auto install` 装成，`tingle auto status` 能查到它。

## Quick Reference

| 闸 | 一句判法 | 答不出就填不了的那一格 |
|---|---|---|
| 一 · 触发是什么 | 六种触发源里挑得出一种吗？挑不出就不是触发 | 触发段 |
| 二 · 干什么 | 一段话说得清吗？产出落在哪？ | 动作段 |
| 三 · 错了谁发现 | 谁、在什么时候？答不出就不许无人值守 | 定档理由 |
| 四 · 危害档 | 有没有**可能**让项目组之外的人看到、有没有可能让已有的东西回不去？ | 危害档 |
| 五 · 认领与查重 | 在谁机器上跑？本机与公示面各查过了吗？ | 认领人 |

| 想干的事 | 敲什么 |
|---|---|
| 把写好的声明收进本机（只收不装） | `tingle auto add <声明文件.json>` |
| 看本机这个项目下有哪些自动化 | `tingle auto list` |
| 试跑，看它到点会干什么 | `tingle auto run <名字> --dry-run` |
| 装上定时任务 | `tingle auto install <名字>` |
| 查各条上次跑成什么样 | `tingle auto status` |
| 撤掉定时任务（声明留着） | `tingle auto uninstall <名字>` |
| 撤掉并连声明一起删 | `tingle auto uninstall <名字> --forget` |
| 人在场时看现在有哪几条该干 | `tingle auto due` |
| 会话里干完一条，记一笔（节流靠它） | `tingle auto done <名字>` |
| 手动看某条监听听不听得到 | `tingle auto listen <名字>` |

## Common Mistakes

- **把触发和动作写成一句话**——最常见的一种。「每天 9 点出昨天的日报」读起来很顺，但要改成每周一次就得整条重写，要换成"表一更新就出"更是无从改起。
- **拿"我盯着呢"当闸三的答案**——盯着的是这一次，不是这条自动化此后的每一次。认领人本人不算"会发现的人"，除非他有一件例行动作必然会撞见那份产出。
- **为了能无人值守而把档往低了判**——判低了不会让它更安全，只会让它在没人的时候真的干出去。
- **一条自动化包了三件活**——停不掉其中一件，也没法分别定档；出了事查不出是哪一段错的。
- **建之前不查重，或查了本机就当查过了**——同事挂的那条在他机器上，本机 `auto list` 看不见。没有公示表时要把这句话说出来。
- **产出落在没人看的地方**——技术上跑得很好，实际上等于没跑；出错更是永远没人知道。
- **把同一段动作复制到第二个项目**——那说明"怎么干"这半是通用做法，该造成技能；复制出来的两份此后会各自漂移。
- **不试跑就装上**——`--dry-run` 是使用者唯一一次在真跑之前看清它会干什么的机会，跳过等于让他闭着眼签字。

## Red Flags（出现即停，回对应的闸）

- 「触发就写'需要的时候跑'吧」→ 那不是触发，回闸一。
- 「它顺手把结果发给客户也挺好」→ 那是三档，回闸四；三档装不上。
- 「先按低一档装上，出问题再收紧」→ 出问题的时候它已经干出去了。
- 「跑错了我自己会看出来」→ 你哪一件例行动作会撞见它？答不出就不是无人值守的活。
- 「动作说明里我写了让它小心点」→ 自觉不是约束，回闸四重新定档。
- 「那个客户群平时都是我们自己人在说话，不算对外」→ 判别问句是"有没有可能"，不是"实际上有没有"。
- 「先不查重了，重了大不了删一条」→ 重的那几天，三个人都以为是自己那条在跑。
- 「dry-run 我看过了，不用给他看」→ 要确认危害档的是他，不是你。
