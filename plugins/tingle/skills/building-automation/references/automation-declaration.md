# 自动化声明写法与危害档实现

> 本件随 `tingle:building-automation` 一起分发，是它的深读参考件：主手册管「下笔之前怎么判」，本件管「判完之后每一格具体填什么」。写声明那一步读它，别的步骤不必读。

---

## 一、声明长什么样

写一份 JSON，交给 `tingle auto add <文件>` 收进本机。程序会当场校验，不合规的点名是哪一格。

```json
{
  "名字": "daily-delivery-report",
  "触发类": "时点",
  "触发表达式": "3 9 * * 1-5",
  "前置条件": "昨天有新增投放记录才跑",
  "动作说明": "读投放数据表里昨天的记录，算出消耗、曝光、互动三项与前一日环比，写成一段日报，追加到日报文档末尾。数据缺失的项写「缺」，不要估算。",
  "输入从哪来": "项目云盘「投放数据」多维表格（链接：…）",
  "产出写到哪": "项目云盘「每日投放日报」文档（链接：…），追加到末尾",
  "危害档": "二档-写自家地盘",
  "定档理由": "只写项目组内部文档，不出门。跑错了张三次日 10 点晨会念日报时当场看得出。",
  "认领人": "张三",
  "开关": "启用",
  "建于": "2026-08-19"
}
```

**逐格说明**：

| 格 | 填什么 | 空得了吗 |
|---|---|---|
| **名字** | 小写字母、数字、连字符，不以连字符开头，**本项目内唯一**。它就是命令行里指名用的那个串 | 不 |
| **触发类** | 六种之一，见下节那张表 | 不 |
| **触发表达式** | **随触发类变**：时点填 cron／文件变化填路径／一开工就跑填节流档／跑完接力填上游名字／飞书事件填事件名／邮件到达填文件夹。见下节 | 不 |
| **筛选条件** | 只对「飞书事件」「邮件到达」有用：空格分隔的几个词，**每个词都出现在那条事件里**才算命中。写错的后果是不触发，不是乱触发 | 可 |
| **最小间隔秒** | 只对「听着」那两类有用：两次触发至少隔这么久，默认 60。防止刷屏把额度打光 | 可 |
| **前置条件** | 一句当场判得出成立不成立的话。不满足则本次不干活、只记一行日志 | **可** |
| **动作说明** | 交给 agent 的活儿说明。写法见第三节 | 不 |
| **输入从哪来** | 这次要读的东西在哪。地址写清楚，无人值守时没人能替它找 | 不 |
| **产出写到哪** | 落点地址。**不许写"看情况"** | 不 |
| **危害档** | `一档-只看` / `二档-写自家地盘` / `三档-出门或抹改`（写「一档」「二档」「三档」也认） | 不 |
| **定档理由** | 为什么是这一档，**必须含**「跑错了谁会在什么时候发现」的答案（人或角色 ＋ 时点） | 不 |
| **认领人** | 在谁的机器上跑。一条只有一个 | 不 |
| **开关** | `启用` / `停用`。停用的装不上、已装的不跑 | 不 |
| **建于** | 建这条的日期，纯备查 | 可 |

**三档能收下，但装不上**——`auto add` 收，`auto install` 拒。这样定成三档的声明仍留有记录，能看出"这件事被判为不许无人值守"，而不是凭空消失。

## 二、住在哪

| 东西 | 住哪 | 谁写 | 参不参与运行 |
|---|---|---|---|
| **声明本身** | 本机 `<项目工作文件夹>/.tingle/automations.json` | `tingle auto add` | **参与**——`auto run` 只读它 |
| **本机状态**（用哪个 agent、作业名、装于何时） | 同上，声明里 `_本机` 那一段 | `tingle auto install` | 参与 |
| **运行日志** | 本机 `<项目工作文件夹>/.tingle/runs/` | `tingle auto run` ／ `tingle auto done` | 不参与运行，但「一开工就跑」的节流靠它算 |
| **公示登记** | 项目云盘上一张共享表 | 本 skill 在放行后写 | **不参与**——读不到、没建过都不影响照跑 |

**为什么执行那一份放本机**：定时任务是在没人看着的时候醒来的。真相源放网上就等于给"早上九点能不能干活"绑了网络与授权的依赖，而那时没人在旁边补救。**这与本插件里「本机缓存纯加速、不参与任何判定」是同一手的反面：公示不参与执行。**

**`_本机` 那一段不要手写**，它由 `auto install` 填；手改了下次装会被覆盖。

## 二点五、六种触发源，触发表达式各填什么

| 触发类 | 触发表达式 | 装出来是什么 | 门槛 |
|---|---|---|---|
| **时点** | 5 段 cron，见下节 | launchd 日历作业 | 无 |
| **文件变化** | 要盯的路径，一行一个；相对路径按项目工作文件夹算 | launchd `WatchPaths` 作业 | **只 macOS**；实测约 **45 秒**才醒，不是存盘就响 |
| **一开工就跑** | 节流档：`每次` ／ `每天一次` ／ `每周一次` | 不装任何常驻物，由会话入口捎带 | 无 |
| **跑完接力** | 上游那条自动化的名字 | 不装任何常驻物，由上游跑成后唤起 | 无 |
| **飞书事件** | 事件名，跑 `lark-cli event list` 看有哪些 | launchd 常驻监听（`event consume`） | **只 macOS**；部分事件要组织在开发者后台先订阅 |
| **邮件到达** | 邮件文件夹名，留空即收件箱 | launchd 常驻监听（`mail +watch`） | **只 macOS**；要组织配 `mail:event` 权限 |

**装「听着」那两类之前程序会先试听一小会儿**：听不到就拒装，并把确切的错与修法（含订阅链接）给你。**装上了却永远不响、还没人知道，比装不上更坏。**

**飞书事件分两种身份**——妙记生成、会议、审批、白板、任务是**本人身份**（自己授权就能用）；收 IM 消息、卡片按钮是**机器人身份**（要组织先配）。跑 `lark-cli event list` 那一列 AUTH 就能看出来。

**没有"表格或文档变了"这类事件**（1.0.88 上核过）。要做只能用时点触发轮询近似：每 N 分钟醒一次、前置条件写"有新记录才跑"，并跟使用者说清楚这是轮询、有延迟。

## 三、时点怎么写（5 段 cron）

五段依次是：**分 时 日 月 周**，用认领人机器所在的时区。

| 想要 | 写成 |
|---|---|
| 每天早上 9 点 | `0 9 * * *` |
| 每个工作日早上 9 点 | `0 9 * * 1-5` |
| 每周五下午 5 点半 | `30 17 * * 5` |
| 每月 1 号早上 8 点 | `0 8 1 * *` |
| 每小时一次 | `0 * * * *` |
| 每 15 分钟一次 | `*/15 * * * *` |

**两条实务提醒**：

1. **避开整点整分**。所有人都写 `0 9`，于是同一秒一起醒来。时点不是硬要求时，往前后挪几分钟（`57 8` 或 `3 9`），谁都不会察觉。
2. **机器睡着时的那一次会补跑，不会跳过**。macOS 上错过的定时在唤醒后补一次，Windows 上由任务计划的「错过后尽快执行」承担。所以「每天 9 点」的准确含义是**「9 点，或当天开机的那一刻」**——把这句话说给使用者听，别让他以为是准点。

**Windows 上只支持四种写法**：每日（`m h * * *`）、每周（`m h * * <周几>`）、每月（`m h <几号> * *`）、每 N 分钟（`*/n * * * *`）。别的写法 `auto install` 会明说不支持，不硬凑。

## 四、动作说明怎么写

动作说明是无人值守时唯一交给 agent 的话，写它的时候要假设**现场没有人可以追问**。

**四条要求**：

1. **一段话说清一件事。** 两件事拆两条自动化。
2. **点名要调的技能**（如果有）。写「调 `<技能名>` 处理」，别写「按惯例处理」——惯例是人脑里的东西，无人值守时取不到。
3. **写清什么样算干完。** 「出一份日报」不够，「出一份含昨日消耗、曝光、互动三项与环比的日报，追加到产出落点」才够。
4. **不许写"注意不要……"式的自我约束。** 拦不住的东西不靠嘱咐拦——见下节，能不能干由进程给不给工具决定。

**程序会自动追加的几条硬规矩**（不必写进动作说明，写了也是重复）：前置条件不满足就什么都别做；只往声明里写明的落点写；不许执行任何需要 `--yes` 的命令；输入取不到就停、不要找替代；判不准就停、不要挑一个解释混过去；最后输出一段结论。

## 五、危害档怎么落到进程上

**这一节是给人查的说明，不是实现。** 实现只有一份，在 `tingle-core` 里；两处不一致时以程序为准。

| 危害档 | Claude Code 侧 | Codex 侧 | 装不装得上 |
|---|---|---|---|
| **一档 · 只看** | `--allowedTools` 只给 `Read` `Glob` `Grep` `Skill` 与飞书命令行的**只读子命令前缀**（`* list*`、`* get*`、`* search*`、`schema*`）；不给 `Write`／`Edit`／裸 `Bash` | `--sandbox read-only` | 装得上 |
| **二档 · 写自家地盘** | `--allowedTools` 加上 `Write` `Edit` 与飞书命令行全量；`--permission-mode acceptEdits` | `--sandbox workspace-write` | 装得上 |
| **三档 · 出门或抹改** | —— | —— | **装不上**：`tingle auto install` 直接拒绝 |

**一档的白名单是 fail-closed 的**：漏掉的命令跑不起来，使用者会来报；不会出现"漏了一条于是悄悄写出去了"。方向上宁可跑不动，不可跑过头。

**程序的一条不变量**：生成的命令里**永不出现 `--yes`**。飞书命令行把删记录、改权限这类不可逆动作标为 high-risk-write 并要求 `--yes`，不传即执行不了。

**装上没装上按事实复验**：`install` 不看命令的退出码，而是回头查系统里到底有没有这个作业（macOS 查 `launchctl print`，Windows 查 `schtasks /Query`）。只信退出码会两个方向都判错，其中"没装上却报成功"尤其坏——到点不跑，还没人知道。

### 一条残留风险，写在这里不藏

**二档在技术上仍能调到删改类命令。** Claude 侧的白名单管得了「哪个工具」，管不了「哪个参数」——`Bash(lark-cli *)` 放行之后，agent 自己在命令里补一个 `--yes` 是拦不住的；Codex 的沙箱管的是磁盘与网络，也不认飞书这一侧的风险分级。

**目前挡它的是三层软的**：① 不可逆动作按定义属三档、三档根本装不上，所以正常声明里不会出现；② 动作说明里没让它删，它没有理由去删；③ 每次运行留日志，事后查得出。

**要硬的保证，得等飞书工具链侧能传一个只读身份**——那之前，二档自动化的落点与动作说明要写得具体，别给它发挥空间。

## 六、常见的几种自动化（照着改比从头写快）

| 想要 | 触发 | 危害档 | 要留意的 |
|---|---|---|---|
| 每天出昨日数据日报 | `3 9 * * 1-5` | 二档 | 产出落点要选一个每天真的有人看的地方，否则闸三过不了 |
| 每周五汇总本周进展 | `30 17 * * 5` | 二档 | 前置条件写「本周有新增记录才出」，免得空周也出一份 |
| 每天扫一遍某项指标有没有越线 | `7 10 * * *` | 一档 | 一档不写任何地方，结论只在本机日志里——所以要配一句"越线了就在结论里写明"，人靠 `tingle auto status` 看 |
| 数据异动了通知客户 | —— | 三档 | **建不成**：对外动作装不上。拆成两条——一条二档的"发现并记下来"，一条人在场时才做的"发出去" |
| 开完会妙记一生成就整理成纪要 | 飞书事件 `minutes.minute.generated_v1` | 二档 | 本人身份，自己授权即可。装的时候程序会先试听，听不到会告诉你缺什么 |
| 审批一通过就跟着办后续 | 飞书事件 `approval.instance.status_changed_v4` | 二档 | 本人身份；筛选条件写审批单号或关键词，免得所有审批都触发 |
| 收到某类邮件就先归档摘要 | 邮件到达 `inbox` | 二档 | 筛选条件写发件人或主题里的词；最小间隔别设太小，邮件多时会连着触发 |
| 云盘同步下来新数据就跑一遍清洗 | 文件变化（那个目录） | 二档 | 只 macOS；短时间连改会连着触发，动作要经得起重复跑 |
| 每次开工先看一眼昨天有没有异常 | 一开工就跑 `每天一次` | 不限 | 人在场，在会话里干；这一类**可以**是三档 |
| 日报出完接着出周报汇总 | 跑完接力（上游那条的名字） | 二档 | 上游跑成才接；上游失败就不接 |
