# mapping-target-audiences

## 概述

一句话职责：**把一个产品转译成一张排好序、配好触达语言的人群表。**

- **卖给谁才是产品真正的开始**。一个物体在被赋予"用户是谁"之前还不算产品；卖给谁决定内容表达，内容表达决定投放策略，投放策略决定结果。
- **人群是从产品特性长出来的，不是拍出来的**。脑子里只有一个人群，团队写十条全针对同一个人，量上去了效率上不去。
- **人群是测出来的，不是一次定死的**。表里每个人群都带状态，未验证的不许当定论用。

## 何时用 / 何时不用

**何时用**：产品与打法已定，内容侧第一步；投放加了量但搜索不涨、要找新增量；任何"这个产品到底卖给谁"的问题。

**何时不用**：
- 要把某个人群的需求挖到能写选题的颗粒度、要配具体的用户原话——那是下游环节。**本环节到"这个人是谁、他大概为什么可能买、跟他说话要用哪一类词"为止。**
- 要做内容、配投放定向、做承接、做卖货、做复盘——各归各的环节。
- **特别注意**：投放定向人群包决定这条内容被推给谁**看**，本环节决定这条内容是**说给谁听**的。定向错了内容还是那条内容；"说给谁听"变了，内容就得重做。两者别混。

## 运行前

**第一步跑 `tingle check mapping-target-audiences`**，拿到开工单再开工；拿到卡点单本次不跑，按卡点单载入 REQUIRED SUB-SKILL: `tingle:project-readiness` 修完复验。开工单上附着的就绪判据由本 skill 开跑时逐条对照判，判不准停下问人。

## 业务方法

六道工序。**前两道是任何产品都要跑的主干，后四道按条件跑**（下表"何时跑"一列）。每道工序的细节在它自己的深读件里，走到那一道再读那一份。

| 工序 | 产出人群表的哪几列 | 何时跑 | 读哪份 |
|---|---|---|---|
| 一 · 从产品特性穷举人群 | 人群、来自哪条特性、需求方向、状态 | 必跑 | `references/audience-tree.md` |
| 二 · 排序：圈层与优先级 | 圈层、精准度、优先级 | 必跑 | `references/inverted-funnel.md` |
| 三 · 破圈：从功效原理长新场景 | 来源场景、切入口 | 要更多增量、或老品破圈时 | `references/breaking-into-new-scenarios.md` |
| 四 · 量化：流量口与渗透状态 | 主流量口、需求量（待验证）、渗透状态 | 成长期／成熟期，或要量化时 | `references/penetration-metrics.md` |
| 五 · 校准触达语言 | 自用非自用、触达语言、品类认知层、导向、精准度量级要求 | 对每个最终入表的人群逐个跑 | `references/audience-language.md` |
| 六 · 遍历法挖新细分人群 | 新增人群行 + 发现方式 | 抄不下去了、或要挖全新增量时 | `references/finding-new-segments.md` |

### 工序一 · 从产品特性穷举人群

**禁止**：

- **禁止跳过产品特性直接拍人群。** 人群必须从"哪一条产品特性"长出来，表里每一行都要标它来自哪条特性；标不出来的那一行是拍脑袋来的，删掉。
- **禁止只列一个人群就往下走。** 一个产品通常能长出数十个潜在人群，**先尽可能列全，不必立即都用**；穷举完再筛。
- **禁止硬凹用户。** 用户没需求，凹得再硬也不要——顺着人群和需求走。**大部分公司的问题出在内容上，不在投流。**

**母问句（每条特性都套一遍）**：**什么样的人，在什么场景，遇到哪些问题，需要这个特性？**

**穷举完按两个标准筛**：离用户决策更近（已明确要买这个品类）、离用户现状更近（内容场景和他的具体症状一致）。筛完通常优先做两三类人群。

**人群表每行必须带状态**：候选 / 测试中 / 已验证核心 / 已放弃。**不许把未验证的人群当成定论交给下游。**

### 工序二 · 排序：先抓核心，再向外发散

**禁止**：

- **禁止按"量大"排优先级。** 量大但泛、竞争激烈，往往不如"量中等、精准、竞争少"。第一个要打透的，永远是核心圈层里离痛点最近的那个。
- **禁止照搬以推荐分发为主的平台的人群顺序。** 这个平台有强搜索心智，是**从精到泛**；按"先大曝光囊括泛人群再层层洗"做，前面的钱基本浪费。
- **禁止只拿一拨人。** 任何内容的效率都会持续走低；只有找到新的人和新的需求，才会有新的流量。

**排序的三个字段**：圈层（核心／相邻／拓展／新领域）、精准度（品类认知 > 功效认知 > 泛认知）、优先级（由"需求量 × 竞争少 × 精准度"综合）。

### 工序三 · 破圈

**触达饱和的信号**：投放策略、内容、人群、合作方都没变，无论怎么加预算都没有新增量——说明这波人群饱和了。

**禁止**：

- **禁止为了流量把内容往人群外偏。** 破圈是往**功效相关**的方向长，不是往流量好看的方向跑。宁愿小曝光带来真转化，也好过大曝光零转化。
- **禁止拍脑袋换场景。** 每一个破圈出来的新人群，都必须能回溯到"产品的哪一条功效或作用原理"，回溯不到的删掉。
- **禁止未经验证就加量。** 衍生出的新方向先小量验证，有效才加量，无效就放弃。

### 工序四 · 量化渗透

**禁止**：

- **禁止臆造工具读数。** 搜索量、需求量、渗透率、声量占比这类数字**必须来自真实工具读数或平台月报**；拿不到就写"需用某工具验证某字段"的待办，**不填一个数**。
- **禁止把声量占比高当成渗透成功。** 只要肯花钱就能把细分词的占比做到很高，这不代表心智渗透真的发生了——要同时看内容端与流量端。
- **禁止把成熟期的量化指标用在起盘期。** 平台的人群资产分层数据对新品牌本就没有沉淀，起盘期以内容树 + 反漏斗为准。

### 工序五 · 校准触达语言

**这一道对每个最终入表的人群逐个跑，不许整批略过。**

**禁止**：

- **禁止给非自用人群配内在感受词。** 买的人和用的人不同的品类（照护类、宠物类），购买者只能感知**第三方可见的显性现象**，感知不到使用者的内在感受。
- **禁止用产品语言当触达语言。** 用户脑子里没有你的产品词，只有他自己的处境。同一个产品换个表达，拿到的人数完全不同。
- **禁止只围绕最专业的那个点做内容。** 对专业词有认知的人是最精准但也最小的一撮，拿完就没增量。
- **禁止先定表现形式再找关键词。** 顺序是**先关键词、后表现形式**——用户不会搜"自用分享""好物推荐"，他搜的是自己的处境词。

**终检（每个人群定完都要过）**：**把产品从这条内容里抠掉，这条内容还成不成立？** 成立 = 无效曝光 = 人群或语言没定对，回炉。

### 工序六 · 遍历法挖新细分人群

**何时跑**：已经抄不下去了（自己就是赛道前列）、或细分赛道里还有大量人群没被发现。

**禁止**：

- **禁止把工具输出的投放标签当内容人群用。** 通用工具的标签颗粒太粗、离执行太远，它不可能针对你的品类定制。内容人群是一种**判断**，要用本品类用户自己的语言写。
- **禁止由 AI 独自完成"从小标签到细分人群"那一跃。** 铺大标签、铺小标签是机械活，可以做完；**那一跃属于洞察，必停交人。**

**遍历法三步**：列大标签 → 把大标签细化成小标签 → 从小标签里找出细分人群。

## 接口与边界（声明）

- **适用环节**：「把产品转译成一张排好序、配好触达语言的人群表」——换一个客户项目也会再次发生的固定环节，非一次性事务。
- **input schema**：`产品特性`（数组，每条含特性描述与它的作用原理）；`产品事实`（品类、客单价、决策成本，对象）；`打法与阶段`（生命周期阶段、链路终点、人群预算结构，对象）；`已知核心人群`（可选，数组；老品有则作反漏斗核心层起点）；`工具读数`（可选，对象；搜索量、需求量、渗透率，缺则按待验证处理）。
- **output schema**：`人群表`（数组，每行含：人群、来自哪条特性、需求方向、状态、圈层、精准度、优先级、来源场景、切入口、主流量口、需求量与其验证状态、自用非自用、触达语言、品类认知层、导向、精准度量级要求、发现方式）；`待验证清单`（数组，写明每项需用什么工具验证哪个字段）；`已放弃人群及原因`（数组）。**可沉淀候选（reusable_candidates）**：`人群表`里状态为"已验证核心"的行（同品类下一单直接作为反漏斗起点）、破圈时那条"从功效原理到新场景"的推导路径、遍历法产出的细分人群维度框架。——**它们只是候选；够不够格真的留下、沉进哪一格、标什么成色，按 REQUIRED BACKGROUND: `tingle:banking-proven-assets` 判。**
- **写回位置**：`人群表落点`（见 requirements 的 outputs 段），地址由项目档案登记，不自行选址。
- **规则层与项目事实**：运行时挂 **合规类目层**（判触达语言里的症状描述、功效表述能不能用）与 **品类层**（品类认知分层的取值随品类变）；不挂类型层。所需项目事实字段：`合规类目`、`产品品类`、`品牌`、`阶段`。
- **工具**：读飞书文档与多维表格（经开工单地址取得）、写飞书多维表格（登记的落点）。平台侧的搜索量与渗透数据由人提供读数，本 skill 不直接调用平台接口。
- **决策档**：**复核**——人群表是下游全部内容工作的源头，定错了下游全是无源之水，产出须有人过目才算数。
- **复核包**：人群表本体 ＋ 每行"来自哪条特性"的回溯 ＋ 破圈人群到功效原理的回溯链 ＋ 所有工具读数的来源（截图或月报出处）与未取到的待验证清单 ＋ 已放弃人群及原因 ＋ 终检结果（把产品抠掉还成不成立）。
- **升级条件（命中即停交人）**：①触达语言里的症状或功效表述触及合规红线而判据不确定；②四层规则冲突；③缺关键项目事实（合规类目、产品品类任一取不到）；④输出需对外发送；⑤核心人群的优先级排序定稿；⑥破圈方向的取舍定稿；⑦遍历法里"从小标签到细分人群"那一跃；⑧拿不到任何工具读数、需求量全部无法验证。

## 产出验收判据（DoD）

一次运行合格，当且仅当：

1. 人群表每一行都能指认它**来自哪条产品特性**；破圈来的行还能回溯到该特性的作用原理；指认不出的行不在表内；
2. 每一行都带状态（候选／测试中／已验证核心／已放弃），**没有一行把未验证当已验证**；
3. 优先级不是按量大排的——每一行的优先级都写明它由"需求量、竞争度、精准度"哪几项推出来；
4. 表里出现的每一个量化数字都标了来源与采集时间；取不到的写在待验证清单里并写明"需用什么工具验证哪个字段"，**没有一个数是臆造的**；
5. 每一行都标了自用／非自用；标非自用的行，触达语言里**不含任何内在感受词**；
6. 每一行都过了终检——把产品从内容里抠掉这条内容就不成立；过不了的行已回炉或已标注原因；
7. 遍历法产出的细分人群行，"从小标签到细分人群"那一跃有人确认的记录，**没有一行是 AI 独自跃过去的**；
8. 人群表里每一个量化字段都挂得回一个定性意图——按 REQUIRED BACKGROUND: `tingle:keeping-metrics-anchored` 判，有孤儿指标即不合格。

## Quick Reference

| 情形 | 动作 |
|---|---|
| 拿到一个产品 | 先问卖给谁，不描述产品；从特性长人群 |
| 特性很抽象（说不清对应谁） | 先穷举症状，再由症状反推人群场景 |
| 穷举出几十个人群 | 按"离决策近／离现状近"筛到两三类 |
| 要定先打谁 | 核心圈层里离痛点最近的那个，不按量大排 |
| 加了投放搜索不涨 | 触达饱和，进破圈工序 |
| 想破圈 | 回到产品功效的作用原理，不从"现在用在哪"出发 |
| 拿不到搜索量数据 | 写待验证清单，不填数 |
| 买的人不是用的人 | 标非自用；触达语言只能用第三方可见的显性现象 |
| 团队最懂那个专业词 | 别只围绕它做内容——那撮人拿完就没增量 |
| 已经是赛道前列、抄不下去 | 进遍历法工序 |
| 遍历到"从小标签到细分人群" | 停，交人 |

## Common Mistakes

- **脑子里只有一个人群**——十条内容全针对同一个人，量上去了效率上不去。
- **直接拍人群，不标它来自哪条特性**——回溯不了，就是拍脑袋。
- **把量大的泛人群排在第一**——泛人群的有效曝光占比极低，除非池子量级足够大 cover 折损。
- **破圈往流量好看的方向跑**——人群偏了，曝光再大也零转化。
- **用产品语言写触达语言**——用户脑子里没有你的产品词，只有他自己的处境。
- **给非自用人群写内在感受词**——购买者根本感知不到，等于没说。
- **先定表现形式再找关键词**——用户搜的是自己的处境，不是内容体裁。
- **把通用工具的投放标签当内容人群**——颗粒太粗、离执行太远。
- **臆造工具读数**——一个编出来的搜索量会一路当真值用到投放。
- **把未验证的人群当定论交给下游**——下游据它做完整轮内容，错了才发现。

## Red Flags（出现即停，回到对应工序）

- 「这个产品显然就是卖给某某人的」→ 回工序一，从特性穷举。
- 「这个人群量最大，先打它」→ 回工序二，按精准度与竞争度排。
- 「换个场景试试，说不定能爆」→ 回工序三，回溯功效原理。
- 「搜索量大概是这个量级」→ 回工序四，写待验证。
- 「这么写更专业」→ 回工序五，换成用户自己的处境词。
- 「AI 把细分人群也一起想出来吧」→ 回工序六，那一跃交人。
