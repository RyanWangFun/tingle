# producing-content-pieces

## 概述

一句话职责：**把一条已定的内容方向做成一条可投的成片。**

- **把做内容填空题化**：左边输入产品素材，穿过模板，右边输出确定结果——减少每次做事时额外的思考和判断成本。
- **点击是下限，互动是上限**：没有点击，内容的下限就极低；决定上限的是用户点进来之后愿不愿意点赞、收藏、评论。
- **一条爆款不是灵感，是几个高分要素相乘出来的**。任何一个要素接近零，整条内容就接近零——**不能有明显短板。**

## 何时用 / 何时不用

**何时用**：内容方向表已定，要把方向写成成片；有曝光但没搜索、要查内容本身；要把一条已验证的内容裂变放大。

**何时不用**：
- 要定方向与形态——那是上游环节，本环节吃它的产出。
- 要配投放工具、定预算节奏、做搜索卡位、做承接与卖货、做复盘——各归各的环节。**本环节交出成片就结束，不决定它怎么被投出去。**

## 运行前

**第一步跑 `tingle check producing-content-pieces`**，拿到开工单再开工；拿到卡点单本次不跑，按卡点单载入 REQUIRED SUB-SKILL: `tingle:project-readiness` 修完复验。开工单上附着的就绪判据由本 skill 开跑时逐条对照判，判不准停下问人。

## 业务方法

四道工序。**一到三是任何一条成片都要走的主干；四在"要把一条已验证的内容放大成一批"时跑。**

| 工序 | 产出成片的哪几部分 | 读哪份 |
|---|---|---|
| 一 · 选内容类型、写正文结构 | 内容类型、正文结构 | `references/template-pipeline.md` |
| 二 · 写封面标题、配评论引导 | 封面、标题、评论引导 | `references/cover-and-title.md` |
| 三 · 过对象感质检关 | 质检结论、改写记录 | `references/objectness-and-pitfalls.md` |
| 四 · 要素化生产与裂变 | 外壳、内核、变体清单 | REQUIRED BACKGROUND: `tingle:elementizing-content`（拆／定位／体检）＋ `references/element-based-production.md`（找／排序／落地／裂变／组装） |

### 工序一 · 选内容类型、写正文结构

**内容类型按转化效率由高到低**：单品直推 > 多品横测／合集 > 痛点类 > 场景类 > 概括科普类 > 美好向往类。**越靠前离用户越近，转化效率越高；越靠后覆盖越广，但离用户越远。**

**禁止**：

- **禁止所有内容用同一套正文模板。** 不同封面标题吸引进来的人不同，正文必须有针对性的诉说语言；一套固定语言到底，转化率会极低。
- **禁止用产品语言写正文。** 用户脑子里没有你的产品词，只有他自己的处境。**同一个产品换个表达，拿到的人数完全不同。**
- **禁止只做一种内容类型。** 形态单一会把自己困死，而且没法测出哪种效率更高。多样化之后按数据把资源集中到高效的那一小部分上。

### 工序二 · 写封面标题、配评论引导

**点击率 = 封面 + 标题。** 封面标题里的关键词，**全部来自内容方向表**里的人、场景、痛点，不许现编。

**禁止**：

- **禁止在没有数据支撑时拆对标。** 没数据就拆，拆的可能是一条无效爆文——它自己都没带来结果。
- **禁止只抄封面标题的皮。** 抄要抄的是"别人怎么说服这波人、内容怎么表达、关键词怎么罗列"；只抄皮，点进来内容没触达用户，就不会有互动。
- **禁止让美好向往类只写向往。** 必须**中和**——既有向往提点击率，又嵌入具象关键词让人群精准。
- **禁止漏掉关键词植入。** 系统会把内容解读成关键词，再匹配给对应兴趣的人。关键词没做到位 → 推给不精准人群 → 不点击不互动 → 系统判定为差内容 → 后续没流量。
- **禁止把评论区当摆设。** 评论引导要写进成片交付物里，且只维护"还有互动增量"的内容。

### 工序三 · 过对象感质检关

**对象感的三个追问**：这个人是谁（不是人口学标签，是他的场景和需求）／他在哪些具象场景遇到具体问题／针对这个问题该怎么针对性地表达。

**这一道是放行闸，不过就回炉：**

| 质检项 | 不过的样子 |
|---|---|
| 产品不可取代 | 把产品从内容里去掉，完全不影响用户看下去 |
| 对象明确 | 同一张素材加个标签就发，正文什么都没变 |
| 内容与人群同步 | 用户在成长，还在用他早已无感的那套表达 |
| 关注点在产品上 | 用户的注意力落在别处（出镜者、场景、话题），跟产品无关 |
| 产品出现位置 | 产品出现在很靠后的位置，多数人根本看不到 |
| 客单价与人群匹配 | 抄来的爆文吸来的人买不起这个价位 |
| 表述方式 | 直接的东西直接说，撞审核；应当**用间接方式表达直接的东西** |

### 工序四 · 要素化生产与裂变

**这一道先加载 REQUIRED BACKGROUND: `tingle:elementizing-content`**，用它把这一坨拆成要素、定好层栏与外壳内核归属、做完乘法体检点出短板——**那套语言是内容侧几个环节共用的，本 skill 不重讲、也不许另起一套。** 拿到分解表之后，再按 `references/element-based-production.md` 做找、排序、落地、裂变、组装。

**禁止**：

- **禁止跳过要素分解直接开始改。** 没有分解表就不知道短板在哪，改的多半是长板——**把高分做得更高，不如把低分拉起来。**
- **禁止一次测多个变量。** 一条片里同时换五六样新东西，分不清是哪一样起的作用。**一次只测一个变量，且要把想测的东西怼到最前面。**
- **禁止刚验证就急着测下一个。** 一个要素刚被验证就丢下去测新的，是暴殄天物——**该先裂变放大**。反过来，永远只抄不创，就是没建专项。
- **禁止在组装时跳过铁律校验。** 外壳与内核不能同时都换新，**判据在要素化语法那件里，组装完回它校一次。**

## 接口与边界（声明）

- **适用环节**：「把内容方向做成可投成片」——换一个客户项目也会再次发生的固定环节，非一次性事务。
- **input schema**：`内容方向表`（数组，每行含人群、需求／痛点、内容方向、形态、认知阶段、决策链路段、为哪段意图作证）；`产品素材`（可选，数组；自有素材与对标素材）；`对标榜单`（可选，数组；每条含互动量、形态、采集时间）；`品牌调性与表述约束`（对象）。
- **output schema**：`成片`（数组，每条含：内容类型、标题、封面描述、正文结构、评论引导、关键词清单、挂回的定性意图、外壳、内核、质检结论）；`变体清单`（数组，同一验证过的要素裂变出的变体）；`质检不通过并回炉的记录`（数组）；`待验证项`（数组）。**可沉淀候选（reusable_candidates）**：跑出结果的正文结构骨架、被验证的封面与标题模板、被验证的句式（不是具体词汇）、被验证的外壳与内核组合。——**它们只是候选；够不够格真的留下、沉进哪一格、标什么成色，按 REQUIRED BACKGROUND: `tingle:banking-proven-assets` 判。**
- **写回位置**：`成片落点`（见 requirements 的 outputs 段），地址由项目档案登记，不自行选址。
- **规则层与项目事实**：运行时挂 **通用层**（平台通行的表述禁限）、**合规类目层**（本类目的功效与症状表述边界）、**品牌层**（调性与惯用表达）与 **类型层**（不同内容形态各自的成文规范）——**四层全挂，本环节直接产出对外内容**。所需项目事实字段：`合规类目`、`产品品类`、`品牌`、`阶段`。
- **工具**：读飞书文档与多维表格（经开工单地址取得）、写飞书文档或多维表格（登记的落点）。素材与榜单数据由人提供，本 skill 不直接调用平台接口。
- **决策档**：**复核**——成片是直接对外发布的内容，须有人过目才算数；涉及表述边界的部分不得自动放行。
- **复核包**：成片本体 ＋ 每条成片挂回的定性意图 ＋ 关键词清单及其在方向表里的出处 ＋ 对象感质检的逐项结论 ＋ 对标数据的来源与采集时间 ＋ 回炉记录 ＋ 待验证项清单。
- **升级条件（命中即停交人）**：①任何表述触及合规红线而判据不确定（功效、症状、绝对化、对比性表述）；②四层规则冲突；③缺关键项目事实（合规类目、产品品类任一取不到）；④**产出需对外发送——成片按定义就是对外内容，每次交付都命中本条**；⑤要抄一条对标而它的购买对象与本产品客单价不匹配；⑥质检关判为"产品可取代"却仍想发；⑦要动品牌调性边界（做过去没做过、但可能仍在调性内的表达）。

## 产出验收判据（DoD）

一次运行合格，当且仅当：

1. 每条成片的标题与封面里出现的关键词，**都能在内容方向表里指认到出处**；没有一个是现编的；
2. 每条成片的正文结构**承接它自己的封面标题**——不同标题进来的人用不同的正文骨架，没有两条不同选题共用一套固定语言；
3. 每条成片都配了评论引导，且写明它引导的是哪一类互动；
4. 每条成片都过了对象感质检的七项，逐项有结论；**任一项不过的已回炉并留下记录**；
5. 每条成片都挂回了一段先于本次内容就已记录在案的定性意图，能逐字指认；
6. 引用了对标的，标明对标的来源与采集时间，并写明"抄的是它的哪一层"（框架／素材／关键词）；
7. 做了裂变的，说明清楚**固定的是句式、替换的是词汇**，且每个变体都能追回它的母本；
8. 测新的部分说明了**这一次只测了哪一个变量**，以及它被放在什么位置；
9. 成片里出现的每一个量化承诺都挂得回一个定性意图——按 REQUIRED BACKGROUND: `tingle:keeping-metrics-anchored` 判，有裸承诺即不合格。

## Quick Reference

| 情形 | 动作 |
|---|---|
| 一条方向要落成片 | 先按转化效率选内容类型，再写对应的正文骨架 |
| 正文不知道怎么开头 | 看这条是从哪个封面标题进来的，顺着那个人写 |
| 要写美好向往类 | 向往 + 具象关键词中和，不然人群精准度极差 |
| 想抄一条爆文 | 先看它的购买对象是不是你的人、它带没带来转化 |
| 抄了以后 | 留框架、换素材、加关键词；信息密度不能比同行差 |
| 内容爆了但评论都在说别的 | 质检关不过——用户关注点不在产品上，回炉 |
| 产品出现在很靠后的位置 | 回炉——多数人根本看不到 |
| 直接的说法过不了审 | 用间接方式表达，让普遍认知的东西更客观一点 |
| 一个要素刚被验证 | 先裂变放大，不要急着测下一个 |
| 要测一个新要素 | 一次只测一个变量，放到最前面，条数要够 |
| 外壳和内核都想换新 | 停，回要素化语法那件过一次铁律 |

## Common Mistakes

- **一套正文模板走天下**——不同标题进来的人不同，转化率会极低。
- **用产品语言写正文**——用户脑子里没有那个词。
- **只抄封面标题的皮**——点进来内容没触达用户，不会有互动。
- **美好向往类只写向往**——人群精准度极差，点击高但转化没有。
- **漏掉关键词植入**——系统推给不精准的人，一路恶性循环。
- **拿爆文率做内部考核**——动作会变形，为拿曝光采用跟产品无关的角度。
- **抄一条客单价完全不同的爆文**——吸来的人买不起。
- **一次换五六个变量**——测完不知道是谁的功劳。
- **好句子配垃圾画面**——组装前没过乘法体检，短板把整条的乘积拉垮。
- **只发产品干货，不解决大流量选题**——先有选题，才有封面标题。

## Red Flags（出现即停，回到对应工序）

- 「用之前那套正文改改就行」→ 回工序一，看它从哪个标题进来。
- 「这个词更专业，写上去」→ 回工序一，换成用户的处境话。
- 「这条爆文点赞很高，照抄」→ 回工序二，先看对象和价值。
- 「封面好看就行了」→ 回工序二，关键词必须植入。
- 「产品放后面点，别太硬」→ 回工序三，产品可取代就是无效曝光。
- 「这次多改几个地方，一起测」→ 回工序四，一次一个变量。
- 「这条跑通了，赶紧测下一个新的」→ 回工序四，先裂变。
