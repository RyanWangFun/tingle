# 起盘、测品与算账放量

> 本件是 `converting-traffic-to-sales` 的深读件，**走到"起盘、测品、算账放量"那一道工序时读**。装的是人货场底层、新品从零到一怎么跑、测品怎么选、新老内容的销售贡献率怎么算、放量怎么算账止损。

---

## 一、人货场底层

### 两大流量池决定"货怎么摆"

| 流量池 | 用户心理 | 内容逻辑 |
|---|---|---|
| **搜索场域** | 带明确需求打开搜索框 | 与我"有用"——关键词逻辑 |
| **发现场域** | 随便刷，没有明确需求 | 与我"有关"——场景与痛点逻辑（唤醒） |

很多品牌做不好，是做内容时**只站在自己的角度表达**（全是专业语言，用户无法感知）。**只要切中用户的痛点需求、在两个池子里做到"与他有关、对他有用"，就能拿到流量。**

### 两类运营模式

- **定向选品 + 搜索场域拿精准品类流量**：不做品牌执念、只问怎么高效赚钱。打开关键词工具，找"品类词有搜索、但还没有出现具体品牌"的点 → 反向从供应链创造产品 → 在这个品类词下把靠前的位置做到相当占比 → 同样的产品换品牌名继续做 → 人力规模化。**挑战：持续拉新的流量成本越来越高、竞品会卡进来。**
- **洞察用户需求 + 发现场域拿大曝光流量**：围绕"产品背后的人有什么痛点场景"做内容，让内容在发现场域"与我有关"；**很多时候甚至不投放**（投放的效率还不如多发几条内容）。

### 运营 ≠ 商业模式

- **运营**（怎么做）：流量 × 转化率 × 客单价。流量从哪来——**哪里有用户需求，哪里就有流量。**
- **商业模式**（在哪赚钱）：知识壁垒型（把用户引入私域做后端）／复购型（品牌声量起来之后赚后端复购）。

### 货：选品可视化优先

这是内容平台，选品看**成图率**、看能不能拍出场景和想象力：

- 决策轻 + 场景化强、自带差异化的品，更容易出内容、出结果；决策重、展示上没有差异化的品，往后排。
- **选品两个标准**：① 东西好不好看（这里主打生活美学，好看就可能为一时好看买单）；② 是否自带流量、适配什么人群（客单价、人群泛不泛决定流量的获取方式）。
- **不同品类的选品逻辑不同**：外观取胜的品类看精致（产品本身就是展示）；靠信任成交的品类没有产品展示逻辑，靠场景唤醒、需求唤醒与信任；替他人购买的品类回归人群表达。

## 二、新品从零到一的冷启动

### 起盘前先做竞品分析

新品起盘的本质，是**把拍脑袋换成基于数据的竞品分析**。

- **选谁做竞品**：选近期才起盘、客单价与品类定位相似、已经拿到流量的品牌；**很久以前起盘的老品牌对起盘者没有参考意义**（入驻阶段、竞争激烈程度、成本完全不同）。
- **底层公式**：销售额 = 渠道 × 流量 × 转化率 × 客单价 × 复购率。既用于起盘（更关注"流量"那一环），也用于诊断卡点（逐环节排查）。
- **三条辩证纪律**：① 论证（对外讲的数据可能已经过时）；② 可复制性（至少对本方七成适用才值得抄，**团队基因极其重要**）；③ 信息维度多元，并留意对方那些看不见的资源。
- **水上与水下**：只看"水上动作"会死——把公开的合作费用当成全部成本、**忽略水下大量的投流**。

### 冷启动三步：测内容 → 数据回收搭模型 → 复制放量

1. **测内容（不是"做内容"）**："什么内容能高效拿到精准流量、带来转化"很难一次到位。**穷举足够多的适用人群，每个人群对应不同的场景与痛点方向**，围绕"人群 × 痛点"罗列内容方向去测。
   > **不存在战略性亏损**：既然做了就应该产生结果；没结果一定是当下的方向错了，**先调前端内容，别用"战略性亏损"自我安慰。**
2. **数据回收搭模型**：看什么内容的点击成本、互动成本、拉新能力更好 → 说明这个内容形态、这个卖点、这个人群是用户强烈想要的 → 搭出模型框架。
3. **复制放量**：围绕高效模板复制放大。

### 起盘的四个阶段：看现象信号，不看营收数字

**不要把阶段当成营收门槛**（某一家的体量换个品类完全不通用），**要当成"做对什么 → 看到什么信号 → 进下一阶段"的演进逻辑。**

| 阶段 | 这个阶段在做对什么 | 该进下一阶段的信号（看现象，不看营收） |
|---|---|---|
| **① 纯内容测试期** | 选一个已被市场验证、但痛点还没被解决的品 + 不停测"人群 × 场景 × 痛点"，纯内容、无投放无合作，快速决策方向。**选品本身就决定了相当大比例的成败** | **某个"人群 × 场景 × 痛点"组合的数据明显跑赢其余**（点击、互动、拉搜成本更优），方向被验证、能稳定出单 → 进 ② |
| **② 闭环完善期** | 围绕验证过的方向把闭环跑顺：创造新人群增量（如自用 → 送礼）、关键词植入迎合分发、回收用户反馈反哺定位、把第一款的经验复用到第二款 | **同一套模型在第二个品或第二个人群上复用也能成（经验可迁移），且单靠内容已经撞到天花板**（自然流明显下滑、感到不可控）→ 进 ③ |
| **③ 结构性增长期** | 不把鸡蛋放一个篮子，补可控的腿：**流量不会消失只会转移**——搭直播拿平台曝光、投流把概率事件变确定事件、内容铺量卡关键词、优化商品卡 | **多条腿（内容 + 直播 + 投流 + 商品卡）各自跑出稳定占比、整体不再依赖单一来源** → 进 ④ |
| **④ 利润放量期** | 在已跑通的模型上放大：多账号、多内容、多店铺；开始对外合作（**前提是先自己跑通内容、变成可交付的要求**）；建内容资源库（节点内容跨年复用） | （终态）持续测新维持稳定，不断找新人群、新话题、新场景补充爆款 |

> **关键判断锚**：每一跳的触发都是**现象级信号**——方向被数据验证、模型可复用、单一来源撞天花板、多腿稳定——**而不是"营收到了某个数"。营收数字是结果，不是切换条件。**

### 起盘前判市场容量与供给缺口

**通用规则**：起盘前先判两件事——**需求够不够大、供给挤不挤**：

- **搜索量 = 需求够不够大**：这个品类或词的背后，有没有足够的人在主动找。
- **搜索量 ÷ 内容量 = 供给缺不缺口**：有需求但内容供给还少，围绕这个点做能拿到更高的效果。
- 判完先用过去的经验做内容让市场给数据反馈：好就快速复制，不好就优化迭代。

> **护栏：及格线必须按本品类的客单价与体量自校准。**
> - **任何具体的阈值都只是某一家在某个品类下的示例基点，不是通用门槛。** 换品类要重建：同样是卡"产品词"，有的品类月搜索量只有几千（窄人群），有的能到上百万——**同一个绝对数，在不同品类里意义天差地别。**
> - **搜索量小的品类不等于不能做**：把产品嵌入更大的需求词反而能起（一个搜索量很小的高价品类，切进"送礼"场景之后把搜索与销量都拉了起来）。
> - **阈值更不是永真的**：某一套曾经赖以成立的打法，会因为平台规则调整而流量断崖——**任何"拿到流量的阈值"都绑定当下的平台规则与品类心智，必须定期用新账号重新校准。**

## 三、新老内容的销售贡献率

### 先把生意端口拆开

发现营收变化时，先把这几个端口的数据分门别类填进表，再看哪个端口出了问题：

| 端口 | 说明 |
|---|---|
| 内容 - 本月新增 | 本月新增多少条、带来多少销售 |
| 内容 - 历史沉淀 | 老内容持续出单（生命周期极久） |
| 投放 | 人为可控的部分 |
| 直播 | 合作直播、自播 |
| 商品卡 | 大促、品类流量、搜索决策 |
| 其他 | 挂链接的各种形态、评论区链接 |

### 为什么必须分新老

- **老内容的生命周期极久**：近期大量出单的，往往是很早之前发布的老内容（尤其是季节性的品）。
- **反常识：流量没变，只是流向了老内容**——每天来看内容的人是恒定的，流量被老内容占据，新内容的流量自然减少。**"最近新内容流量差"是正常现象。**
- **把平台当一个人看**：流量 = 每天固定数量的逛街的人（恒定），内容 = 店铺。逛街的人更愿意去验证过好吃的老店 → **平台一定把流量给"曾被验证过能卖货"的内容。** 由此推出三条：老内容挂链接的前提是它曾出过单；历史高销内容重新编辑 = 回到新内容状态、投不出去；新店比老店难做。

### 用它来谈目标

- **"加一个人就该多多少营收"是错的**：新增的人只能做**新发的内容**，而新发内容通常只占总生意的一小部分，**加一个人能加的量远小于按总营收比例算出来的数。**
- **"这批内容带来多少营收，除以条数再乘目标条数"也是错的**：把表按品、按新老拆开（不同品、新老内容的营收产出完全不同），这个逻辑自然站不住。

### 由过去倒推下个月的规划

| 板块 | 可预估性 |
|---|---|
| 新增内容 | 可预估（历史数据已知产量与曝光） |
| 老内容 | 可预估（看历史每月的稳定趋势） |
| 付费 | 可预估（预期投入产出下能放多少量） |
| 直播 | 合作稳定则可预估 |
| 商品卡 | **变量**：卡上好的搜索位则量大，卡不上就浮动——列在不可控之外 |

> **规划原则——先求稳**：稳是可控的，爆文不可控，围绕稳定的维度拆解预估。
>
> **人品配置**：**老品给新人**（老品稳定，只剩人的能力不稳定）、**新品给老人**（先围绕成功路径总结，再让新人复制）；**新人 + 新品 = 巨大的不可控，绝不组合。**

## 四、测品：差中择优，不是无限测

- **本质**：从一批品里选出下阶段要主推的那一个，是**筛选**，不是无限测。
- **操作**：多个品并上（每个品各发一批内容）→ 给每个品**灌流量**（只有灌了流量才能判断访客、转化、成交）→ 看链路流转（阅读 → 访客 → 转化 → 销售）→ 哪个品的数据出来了，就达到了筛选的目的。
- **心态**：当下的数据可能普遍不如历史最好的时候，但测品是"**差中择优**"。
- **数据归因常常推翻经验直觉**：以前认为一定能出单的内容没成交，反而不被看好的那条爆单。**内容和经验会说谎，数据不会。** 跑出模型之后，让团队围绕被验证的模板复制。

## 五、算账与放量止损

### 投入产出与放量临界点

- **投入产出 = 销售额 ÷ 投放成本**；**销售额 = 精准搜索 UV × 转化率 × 客单价。**
- 三个数据点之间有**折损**：前面阅读到搜索的效率就差，投入产出一定差。判断单条内容看"**多少阅读带来一个搜索**"——这个比值差一个数量级，结果就完全不同。
- 转化率在用户精准的前提下会趋近行业均值（有客观的判断标准），客单价是确定值，**所以可以侧重看搜索效率。**
- **算账给放量临界点**：毛利 = 产品成本（含仓储物流与赠品）+ 平台扣点 + 锁定利润。**很多人"前面投得很嗨"却忽略了产品成本，投入产出看着可以、算总账一直亏。到临界点就不能再投。**

### 数据要"转译"：后台原始数据 ≠ 可分析数据

后台直接拉的数据不符合分析标准，要清洗成运营链路：`展现 → 点击 → 商品访客 → 成交`。

> **转化率的正确口径 = 成交用户 ÷ 商品点击**（不是除以内容点击，因为锁定购买的是"商品点击"这一步）。

| 数据环节 | 决定要素 | 数据低时调什么 |
|---|---|---|
| 展现 → 点击 | 封面 + 标题 | 内容量、封面标题、前端投流拉曝光 |
| 点击 → 商品访客 | 正文 + 评论 + 价格 | 正文、评论、价格 |
| 访客 → 成交 | 评价 + 销量 + 价格 | 详情好评、销量、价格 |

### 判断标准：目标拆解 + 对比分析

1. **目标拆解**：先有清晰的目标，没达成就从"成交用户"端往前推到出问题的那一环。
2. **对比分析**：与行业相似品或行业大盘比；**跨渠道对比**——同一个产品在站外的转化率明显高于这里，说明这里的用户精准度有问题。

### 用数据基点高效止损

有历史复盘的数据基点，就大概知道"做到某个阅读量按道理该带来多少商品点击与转化"。**发到一定数量就发现阅读上来了但没有后端转化 → 立刻停下来诊断**：是产品难做？前端内容不行？承接不行？还是客单价不允许？

> **有数据基点才能高效止损，省下后面的试错成本和钱。**

### 站外溢出的诊断：内容问题还是产品问题

1. **先判断内容（流量端口）**：看曝光、阅读、点击率，与合作方的历史数据比对。曝光是平台主动给的（选题有需求就给曝光）；**曝光正常但阅读低 → 封面标题的点击率不够 → 是内容问题，不是选题问题。** 点击率没有绝对值——不同内容类型的合理区间差很多，**必须在同类型下和自己的历史、合作方的历史、竞品比对。**
2. **再判断流转（生意端口）**：进店访客（流转率）→ 成单（转化）。**注意时间周期**：数据回传有延迟，前几天可能什么都没有；太低时先看是不是时间太短（过一段时间再看），过了一段仍然差 → 回归"整体内容引流率"的问题。

### 测试工具

最快测内容效率的方式是挂上可追踪的组件。**不要一上来就要求投入产出达到多少，先判断"当下的动作对不对"，对就放量。**

> **注意**：测内容时把内容方向和追踪组件的**命名对应起来**（按前端设定的内容方向命名），否则拉下来的数据看不清哪个方向的流转效率更高。

## 六、把卖货从脑力活变成体力活

- 建产品推广的内容库 + 拆解市场上的好内容（读懂封面标题、正文、评论好在哪、写给谁）+ 做"我的人是谁、需求有哪些"这份作业 + 总结成"内容模板方向表"。
- **评论按类型沉淀到库**（购物反馈／引导购买／信息补充），团队替换产品词即可复用。
- 目标拆成可考核的数据链路（涨粉、留资、电商三类底层一致）：**搞清流转链路上的核心影响要素，每个要素就是每个环节要完成的关键点。**
- **遇外因必归内因**：问题不是"平台不给流量"这类外因；**归到内因才会逼自己找解法**（先把发布量放大、把池子撑开，再判断是不是内容本身有问题）。
