# converting-traffic-to-sales

## 概述

一句话职责：**把承接来的流量，变成一门算得清、能放量的生意。**

- **客单价是第一决策锚**：客单价的真正含义不是"多少钱"，是"用户掏这笔钱要思考多重"。决策越轻链路越短，决策越重越要蓄水、越要背书。
- **不存在战略性亏损**：既然做了就该产生结果；没结果一定是当下的方向错了，先调前端内容，别用"战略性亏损"自我安慰。
- **没有数据基点就不要硬放量**：先测、有基点，才谈得上止损与放大。

## 何时用 / 何时不用

**何时用**：流量已承接进来，要定这单用哪种卖法；新品要起盘、要测品；要规划下个月的营收；要判断什么时候放量、什么时候止损；有流量没销售，要把账重新算一遍。

**何时不用**：
- 要解决"流量怎么来"——内容、投放、搜索承接各是上游环节。
- 要做复盘归因与经验沉淀——那是下游环节。

## 运行前

**第一步跑 `tingle check converting-traffic-to-sales`**，拿到开工单再开工；拿到卡点单本次不跑，按卡点单载入 REQUIRED SUB-SKILL: `tingle:project-readiness` 修完复验。开工单上附着的就绪判据由本 skill 开跑时逐条对照判，判不准停下问人。

## 业务方法

三道工序。**顺序不能乱：先按客单价定骨架，再选卖法填充，最后用算账给放量临界点。**

| 工序 | 产出什么 | 读哪份 |
|---|---|---|
| 一 · 按客单价定转化骨架 | 决策档位、链路长短、身份类型、抬客单或降决策的技法 | `references/price-tier-logic.md` |
| 二 · 选闭环卖法（常组合） | 卖法组合、各自的门槛与执行要点、矩阵号配置 | `references/closed-loop-methods.md` |
| 三 · 起盘、测品、算账放量 | 冷启动路径、起盘阈值、新老贡献率、放量临界点与止损条件 | `references/launch-and-scaling.md` |

### 第 0 步 · 先选战场：站内闭环还是站外溢出

**先判断这个产品现在适不适合做站内闭环**：站内电商是否成熟、是不是低决策低客单、闭环有没有红利。

**高客单或需要认知的品类不走"看到就下单"的逻辑**——它成交的是已经有深度认知的那批人；前端没有大量种草、没有新的"草"长出来，再投也难转化。**这类要么走"站内种草 + 导站外闭环"，要么先把认知建起来再做闭环。**

### 工序一 · 按客单价定转化骨架

| 档位 | 决策特征 | 卖法 | 链路 | 载体与背书 |
|---|---|---|---|---|
| **极低 · 冲动** | 买了不痛不痒，刷到就买 | **快进快出**，流量最大化 | 极短，无需蓄水 | 素人 + 自制内容，产品好看即可 |
| **中 · 轻决策** | 会看一眼评价与销量，但不重 | 内容种草 + 挂链接与搜索承接 | 较短 | 自有账号硬广 + 素人增信 |
| **高 · 重决策** | 会全网检索、要品牌心智 | **先蓄水培养心智**，再转化 | 长（蓄水期 + 人群转化链路） | 专业背书，或培养"认人"的路径 |

**禁止**：

- **禁止对高决策成本产品只用素人。** 用户不信——这类必须有专业或垂类的背书身份。
- **禁止用一个统一的转化逻辑套所有价位。** 客单价不同，链路长短、内容载体、身份类型全都不同。
- **禁止在没判定人群层级时套用"降决策"那套组合。** 权威场景锚定 + 紧缺性这套**只对品牌认知弱、对参照系敏感的那一层有效**；对已经成熟、有品牌心智的人群不敏感，甚至反感。

### 工序二 · 选闭环卖法（常组合，不是单选）

四种卖法各有各的门槛：**挂链接**（拿临门一脚的人，量小；前提是这条内容曾经出过单）／**直播与内容联动**（拿进直播间的人；前提是合规、不挂链接、产出达标）／**爆文模板复制**（拿被模板触达的新用户；前提是有持续的素材抓手）／**搜索卡位卖货**（拿带明确消费场景的人；低预算也能起）。

**禁止**：

- **禁止把挂链接当唯一抓手猛投。** 可割的用户割完就没了，**放量越多、可割用户越少、转化效率越低**——这时必须往前推，用种草和教育内容让"草"长起来。
- **禁止用曝光量级定义"好爆文"。** **爆文好坏不由曝光和互动量级定，由"它带来的用户是否精准可成交"定。** 高曝光零成交是坏内容，低曝光高转化才是好内容。
- **禁止把硬广和软内容混在同一个账号里。** 自有账号就该硬——官方和用户都心知肚明；素人号就该软——"我是买过的真实使用者"。**混搭的结果是硬广不够硬、软广不够软。**
- **禁止把"极致复制"做成同质化。** 同质化是一模一样的素材；**正确的复制是同一逻辑、不同素材**——要挖的不是表象（怎么拍），而是"为什么这个人会认可这条内容、它戳中了什么心理"。

### 工序三 · 起盘、测品、算账放量

**冷启动的路径**：测内容（不是"做内容"）→ 数据回收搭模型 → 复制放量。**测内容的做法是穷举足够多的适用人群，每个人群对应不同的场景与痛点方向，围绕"人群 × 痛点"罗列内容方向去测。**

**禁止**：

- **禁止把别人的起盘阈值当通用真值。** 搜索量代表需求够不够大、搜索量除以内容量代表供给缺不缺口——**但及格线必须按本品类的客单价与体量重建**。同一个绝对数在不同品类里意义天差地别；搜索量小的品类也不等于不能做（可以把产品嵌入更大的需求词）。
- **禁止在没有历史数据基点时硬放量。** 有基点才知道"做到某个阅读量按道理该带来多少点击与转化"，才谈得上高效止损。
- **禁止把新人配新品。** 老品给新人（老品稳定，只剩人的能力不稳定）、新品给老人（先围绕成功路径总结，再让新人复制）；**新人加新品是巨大的不可控，绝不组合。**
- **禁止用笔记点击当转化率的分母。** 正确口径是**成交用户 ÷ 商品点击**——锁定购买的是商品点击这一步。
- **禁止把外因当结论。** 问题不是"平台不给流量"这类外因；**归到内因才会逼自己找解法。**

**算账给放量临界点**：`投入产出 = 销售额 ÷ 投放成本`；`销售额 = 精准搜索 UV × 转化率 × 客单价`。毛利要含产品成本（含仓储物流与赠品）、平台扣点、锁定利润。**很多人前面投得很嗨却忽略了产品成本，投入产出看着可以、算总账一直亏。到临界点就不能再投。**

## 接口与边界（声明）

- **input schema**：`产品事实`（品类、客单价、是否有复购、毛利、可视化强弱，对象）；`承接来的流量`（数组，每条含端口、用户认知阶段、精准度）；`团队基因`（内容强／投流强／能否直播／人力成本，对象）；`预算`（数值）；`历史复盘数据`（可选，对象；新老贡献率、各端口营收、合作方历史表现）。
- **output schema**：`闭环卖法`（数组，每条含方法、选用理由与对照的门槛、执行要点、矩阵号配置）；`客单价决策`（决策档位、链路长短、身份类型、抬客单或降决策的技法及其适用人群层）；`起盘与放量`（冷启动路径、起盘阈值判断及其数据来源、新老笔记规划、放量临界点与止损条件）；`待人确认项`（数组）。**可沉淀候选（reusable_candidates）**：跑通的闭环卖法组合、本品类的起盘阈值与折损基点、验证过的爆文模板、评论区话术库（按类型分）。——**它们只是候选；够不够格真的留下、沉进哪一格、标什么成色，按 REQUIRED BACKGROUND: `tingle:banking-proven-assets` 判。**
- **写回位置**：`卖货方案落点`（见 requirements 的 outputs 段），地址由项目档案登记，不自行选址。
- **规则层与项目事实**：运行时挂 **合规类目层**（判卖法本身能不能用——部分类目对直播带货、挂链接、导流有额外限制）与 **品牌层**（定价策略与调性）；不挂类型层。所需项目事实字段：`合规类目`、`产品品类`、`品牌`、`阶段`。
- **工具**：读飞书文档与多维表格（经开工单地址取得）、写飞书文档（登记的落点）。店铺与投放后台的数据由人提供读数，本 skill 不直接操作任何交易或投放后台。
- **决策档**：**决策**——本环节决定这门生意怎么做、放到多大、什么时候停，属于对项目走向本身的判断，须由人来定，本 skill 负责把账算清、把方案备齐。**不得标自动。**
- **复核包**：卖货方案本体 ＋ 客单价档位的判定依据 ＋ 每种卖法对照门槛的逐项判定 ＋ 起盘阈值的数据来源与采集时间 ＋ 放量临界点的完整算账过程（含产品成本、扣点、锁定利润）＋ 止损条件 ＋ 待人确认项。
- **升级条件（命中即停交人）**：①卖法或话术触及合规红线而判据不确定（直播带货、导流、功效表述）；②四层规则冲突；③缺关键项目事实（合规类目、产品品类、毛利任一取不到）；④输出需对外发送；⑤**任何一次实际的放量或止损决定**；⑥选品最终拍板；⑦抬客单的定位判断（改变产品在用户心里的位置）；⑧要走"品牌导向"还是"卖货导向"的路线取舍。

## 产出验收判据（DoD）

一次运行合格，当且仅当：

1. 先判定了战场（站内闭环还是站外溢出），并写明依据；
2. 客单价档位已判定，链路长短、载体与身份类型都与这个档位对得上；**高决策档位没有只配素人**；
3. 每一种选用的卖法都逐项对照了它自己的门槛，写明为什么它成立；未达门槛的卖法不在方案内；
4. 矩阵号配置写明了硬与软的分工，**没有把两类目的混进同一个账号**；
5. 起盘阈值的判断标了数据来源与采集时间，并写明**它是按本品类重建的、不是照搬来的**；
6. 放量临界点附完整算账过程（含产品成本、平台扣点、锁定利润），**没有算账就没有放量建议**；
7. 止损条件写成一条可当场判定的句子（含具体量级与观察窗口），不是"效果不好就停"；
8. 转化率的口径是"成交用户 ÷ 商品点击"，**没有用笔记点击当分母**；
9. 方案里每个量化指标都挂得回一个定性意图——按 REQUIRED BACKGROUND: `tingle:keeping-metrics-anchored` 判，有孤儿指标即不合格。

## Quick Reference

| 情形 | 动作 |
|---|---|
| 拿到一个产品要定卖法 | 先判客单价档位，再选卖法填充 |
| 高客单、白牌 | 先蓄水培养心智，别指望即时转化 |
| 挂链接转化效率在降 | 可割用户割完了——往前推，做种草与教育 |
| 想投一条老内容的挂链接 | 先确认它曾经出过单；编辑过就回到新内容状态 |
| 要开直播联动 | 时长要够（短时长没数据就下播会陷入恶性循环） |
| 找到一条低曝光高转化的内容 | 那就是好模板——围绕它复制，别去追下一条高曝光 |
| 复制模板 | 同一逻辑、不同素材；不是一模一样地发 |
| 低预算冷启动 | 走搜索卡位免费位，选竞争度低的长尾词 |
| 品类词卷不动 | 往下兼容——做痛点词、细分场景词 |
| 要抬客单价 | 场景升维 + 参照物锚定 |
| 高客单用户犹豫 | 权威场景锚定 + 紧缺性；**先确认目标是不是那一层人** |
| 要判断起盘阈值 | 用本品类的数据重建，别照搬任何示例值 |
| 发了一批没有后端转化 | 有基点就立刻停下诊断：产品、内容、承接、还是客单价 |
| 要放量或止损 | 停，交人 |

## Common Mistakes

- **用一套转化逻辑套所有价位**——客单价决定链路、载体、身份。
- **高决策产品只用素人**——用户不信，钱白花。
- **把挂链接当唯一抓手**——可割的人割完就没了。
- **用曝光量级定义好爆文**——高曝光零成交是坏内容。
- **硬广和软内容混在一个账号**——两边都不像。
- **把极致复制做成一模一样**——平台判同质化，流量会停。
- **照搬别人的起盘阈值**——同一个绝对数在不同品类里意义完全不同。
- **没有数据基点就放量**——出了问题也不知道停在哪。
- **新人配新品**——两个不可控叠在一起。
- **用笔记点击当转化率分母**——口径错了，后面全错。
- **算投入产出时忘了产品成本**——看着能跑，算总账一直亏。
- **把问题归到外因**——归内因才会逼出解法。

## Red Flags（出现即停，回到对应工序）

- 「这个价位也能看到就买吧」→ 回工序一，判决策成本。
- 「先都挂上链接跑跑看」→ 回工序二，看这条内容出过单没有。
- 「这条曝光很高，就它了」→ 回工序二，看它带来的人精不精准。
- 「素人号也发点硬广」→ 回工序二，硬软不混号。
- 「别人这个品类月搜多少就能做，我们照这个来」→ 回工序三，按本品类重建。
- 「数据还行，加大投入」→ 回工序三，先算总账、算到临界点。
- 「是平台不给流量」→ 回工序三，归内因。
