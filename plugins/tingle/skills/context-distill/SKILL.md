# context-distill

## 概述与核心原则

本 skill 只做一件事：**把一个项目散在各处的原始材料，经「引导询问 → 取料归集 → 蒸馏 → 查缺 → 索取 → 重蒸」的循环，蒸成每条都能溯回原材料的结构化产物，落进飞书供下游程序反复引用；材料更新就地重蒸。** 这道工序产两种形态的产物：**一套认知件 + 一份索引**——每件独立成飞书文档、各落各自的文件夹，外加一份索引串起整套、摊在项目云盘顶层，照入参的认知件清单产（**前三个意图**）；或**照调用方给的规格只产一份 skill 专用输入件**——落点随入参传入、不进索引（**第四意图**）。

> **"一件事"说的是这道工序（从该项目真实材料蒸出逐条溯源的产物），不是"只产认知件套"这一种产物形态。** 本 skill 有四个调用意图：前三个产的都是上面这套认知件 + 索引；**第四意图「按某 skill 的判据产它的专用输入件」走同一道工序、同一套手艺与纪律，但只产一份 skill 专用输入件，不产整套、不进索引**——它的完整规定见下方「第四意图」段。**全文凡以"认知件清单 / 认知件套 / 索引"为前提写死的句子，说的都是前三个意图**；本文各处已就地标出作用域，读到哪一处看哪一处。

**三条核心原则（记牢，越一条即错）：**

- **material-first —— 从真实材料起步，蓝图只事后核。** 循环第一步是引导人报出手上有什么料，产物**内容与块结构**从真实材料长出。任何"该有哪些块"的蓝图 / 下游契约，只在蒸馏之后的"查缺"步当**事后核对表**，绝不反过来当上游驱动去照单收料、先搭空框。数据只单向流：真实料 → 蒸馏 → 事后拿蓝图核缺。
  > **这一条与"照清单产"不冲突，两者管的是不同层**（**下面讲的清单机制是前三个意图的**；第四意图不传清单、规格来自目标输入的就绪判据，但 material-first 这一条对它**同样无条件适用**——内容照样只能从该项目真实 `raw/` 蒸，见「第四意图」段）：**产哪几件**由入参的认知件清单定死（不由本 skill 现场认定，也不由蓝图 / 下游契约认定）；**每件里装什么**只能从该项目真实 `raw/` 蒸。清单本身也不是上游驱动——它每一件都要先过"`raw/` 里有没有一处内容能落进它"这一问，没料的件不产、只在索引留一行「本项目无料·未产」。所以仍然没有"照单收料 / 先搭空框"这一步。
- **每条溯源 + 不发明。** 产物里每条实质内容都挂一个具名的一手来源，第三人拿源 + 这条产物能逐条比对。材料对不上的**标"材料不足待补"**，绝不凭品类常识 / 泛化硬编填空。
- **产出者不自宣完成。** 蒸馏产物是待复核件，由一个独立评审者**按序跑完三关**（逻辑·外推 → 质量·实用 → 忠实）全 PASS 后才升级；skill 自己不拍板"做完了"。**只验忠实不算验完**——可信不等于可用。**这一件不可降级**——自检顶不了独立评审；评审者派不出时停并报、等人拍（"派不出"的判法：先实际调一次子代理、以调用失败为准，见 `references/distill-craft.md` 工艺 4）。

**通则 · 降级须人批准**：**凡判断的结果是"这一道 / 这一件不用走、走不了"，不许自行推进——摆出来、停、等人拍。降级可以，但降级是人的决定，不是执行者的决定。** 粒度含道级 / 件级 / 格级。落到本 skill 身上，最常被自行降级的是三件：**认知件清单未传**（**前三个意图**：→ 停并报缺，不问人、不自拟。**第四意图不传清单，它对应的那一样是「该输入的就绪判据」**——判据未传、或粗到无从下手，**同样停并报缺**，见「第四意图」段）、**项目标签与阶段未传**（→ 停并报缺，不问人、不从材料认、不自取；**四个意图同规**）、**独立评审派不出**（→ 停并报，不自检顶替；**四个意图同规**）。三件的正确动作都是**停下来问人**，不是**换个简化版继续跑完**。

**通则 · 换掉被引用者**：**要换掉一个有人指向的东西时，新建的必须是没人指向的那一个——原件就地改，副本另存。** 一件东西的地址一旦被别处记下（认知件的链接记在索引里、项目档案的链接记在各成员的本地指针里），要用新版本替换它，就**就地改原件、把副本另存到别处**——绝不新建一份当正版、再把原件挪走。反着做，所有拿着旧地址的人打开的仍是被换掉的那一份，而没有任何工序负责去改他们手里的地址。本 skill 的重蒸就是这条通则的日常形态：受影响的认知件**就地更新**、索引里那一行的链接不变，落点与 `raw/` 结构不重建。

**适用环节**：本 skill 对应一条可复用环节——把一个项目的散乱 raw 材料整理成逐条溯源的产物，跨项目复现（每个项目可换、材料更新可重跑），不是一次性事务。

## 何时用 / 何时不用

**何时用**
- 新接一个项目，材料零散在在线文档 / 多维表格 / 电子表格 / 妙记 / 云盘 / 本地各处，要整理成一套可复用、每条溯源的认知件（含索引）。
- 已有这套产物，某处材料更新了 / 某环节定稿产物要纳入，要就地重蒸、受影响的件就地更新。
- 需要一个"一个项目 raw → 溯源认知件套"的通用蒸馏引擎，换个项目零改复用。
- 某个工作 skill 缺一份它专用的输入件，要照**那个输入自己的就绪判据**从该项目已收材料里把这一件产出来、交人审（**第四意图**，见「第四意图」段；它不产整套认知件、不进索引）。

**何时不用（When NOT）**
- **给项目建档 / 建库 / 配权限 / 通知团队** —— 这些是组织层的活，不在本环节。本 skill 的**标签与阶段**一律**由调用方随入参传入**（只读、不建不写、不改；未传即停并报缺，不问人、不从材料认，见入参契约）；客户 brief 一类**是材料不是标签**，按来料线索走第 2 步归集。本 skill 不建档。
- **做下游的选题 / 审稿 / 内容 / 投放 / 分析** —— 这些是蒸馏产物的独立消费者、各自独立环节。本 skill 只交"溯源产物"，越到任一件即错。
- **"任意材料 → 任意产物"的泛化引擎** —— 本 skill 锁定"一个项目 raw → 逐条溯源的产物"这一类，不做通用文本转换器。（**产物形态有两种、都在锁定范围内**：前三个意图产**一套溯源认知件**；第四意图产**一份 skill 专用输入件**——同样从该项目 `raw/` 蒸、同样逐条溯源、同样只产飞书文档形态，见「第四意图」段。除这两种之外不受理。）
- **判断"现在该不该蒸、该跑哪个环节 / 哪个 skill"（平台路由）** —— 本 skill 无平台判断脑，每次调用自带意图；环节编排归调用方（如 `project-readiness` 的初始化编排）。
- **材料完全无法读取时硬跑** —— 读不到就**停并报缺**（缺哪份、在哪），不猜路径、不凭常识硬编一份出来。

## 方法：material-first 六步循环

一次调用 = 一个反馈环：收料与蒸馏紧耦合（蒸出来发现缺 → 再收 → 再蒸），不拆成两段。

> **material-first 硬约束（贯穿全环，先记死）**：循环首步是"引导人报出手上有什么料"、从真实材料起步。查缺蓝图 / 下游契约**只在第 4 步"查缺"**作为事后 checklist 出现（这说的是**前三个意图**；**第四意图连第 4 步都不用这两样**，见「第四意图」段）。全流程**没有**"先照蓝图算出需要哪些字段 → 照单收料 / 先搭空产物骨架再填"的上游驱动步——那是本 skill 明令排除的反模式。

### 调用意图与入参契约

**本 skill 无平台判断脑**——不判断"现在该不该蒸、该跑哪个环节"；每次调用自带意图，四类：

- **(a) 初蒸**：由 `project-readiness` 在项目初始化"开云盘落点 → 收料 → 蒸馏"的编排处**一次性合并调用**，走完整六步循环（引导收料 + 上飞书 + 蒸馏一体）；调用方不参与过程、只验收结果（云盘有料 / 上下文产出 / 独立评审判定记录在）。**初蒸这一道不批量收取认知件地址**——认知件有哪几件归 `tingle-认知件索引` 管。**但某个 skill 在声明块里明确点名依赖的单件，其地址照常进档案**（2026-08-17 收窄，详见 `project-readiness` 道7）。
- **(b) 重产某件 / 某投影**：消费 skill 运行前检查发现某投影不达标 → 按 `produced_by: context-distill` 的修复路由回调本 skill；料够则重蒸该件，料不足则先查缺 / 索取再蒸。
- **(c) 收新料 / 定稿纳入 / 料更新重蒸**：项目成员直达本 skill——材料的事直达，不必绕编排；**环节定稿产物一旦产生，必纳回这一整套（定稿必纳入）**，随后重蒸受影响的件。
- **(d) 按某 skill 的判据产它的专用输入件**：某个工作 skill 缺一份它专用的输入件、或该输入的就绪判据不过时，由该输入声明的 `produced_by` 修复路由调入本 skill；**不传认知件清单——规格来自该输入自己的就绪判据**，只产那一件、只产飞书文档形态、不进认知件索引。**它的必传项、起跑点、产物级标准与落点都与前三个意图不同，完整规定见下方「第四意图」段，照那一段跑。**

**入参契约**（本节所列必传项是 (a)(b)(c) 三个意图的；**(d) 第四意图另有一套必传六样——项目云盘 `folder_token` 与项目标签阶段在那边同样必传，认知件清单则不传、改传就绪判据，见「第四意图」段**）：
- **必传（其一）= 项目云盘 `folder_token`**。初蒸时由调用方直传（**勿假设项目档案已有本 skill 的条目**）；重蒸 / 修复路由时由调用方从项目档案**顶层**解析后传入。
- **必传（其二）= 认知件清单**（**前三个意图**）：一份写定的清单，逐条给出该产哪几件、每件的形态与收录范围、产不产怎么判、落点长什么样。**这三个意图下，「该产哪几件」只有这一个来源。** 形态与取用方式见下方「输入 / 输出 schema」的栏位说明；**件名单不在本页**，其运行投影在调用方 `project-readiness` 主手册。**清单未传 = 本次不运行**：停并报 `缺认知件清单，请调用方传入`——**不问人该产哪几件、不从查缺蓝图或下游契约认定、不自拟件名、不设兜底件**。**这一条在这三个意图下无条件成立，不因任何理由放宽。**（**第四意图不传清单**——它的规格来源是「该输入的就绪判据」，那一样同样必传、未传即停，见「第四意图」段的必传六样。）
- **必传（其三）= 项目标签与阶段**：品类三级 `{业务线 / 合规类目 / 产品品类}` + 品牌 + 阶段（受控初始集：策略期 / 执行中 / 新周期，可扩）。**一律由调用方随入参传入，这是唯一来源**——打标与定阶段是**排在蒸馏之前**的独立环节，走到本 skill 时调用方手上已经有这几个值（初蒸由编排方直传；重蒸 / 修复路由由调用方从项目档案读出后传入）。**未传 = 本次不运行**：停并报 `缺项目标签 / 阶段，请调用方传入`——**不问人、不从材料认、不自己去项目档案取、不按品类名推断、不留"暂不填"一类兜底**。留任何一条兜底，都等于把"调用方漏传"变成一个可接受的状态。
- **必传（其四）= 项目定性**（**四个意图皆必传**）：一段写定的文字，讲**这个项目在做什么生意、为什么要做、受什么根本约束**——底下每一件产物的每一条内容，都能问一句「你为什么存在」并回到它。
  **它不是本 skill 的产出，是本 skill 的输入。** 理由：这段东西**不在 `raw/` 里**——「这一类生意在这个市场上能怎么讲」是法规与品类常识，不是这个项目的材料，而纪律 3「材料里没有的不写成定论」会让本 skill **正确地拒绝写它**。自下而上的工序产不出它。它由调用方（立项那一环）随入参传入，取值来自人。
  **未传 = 本次不运行**：停并报 `缺项目定性，请调用方传入`——**不问人、不从材料认、不自己按品类常识补一段**。
  **为什么必传**：没有它，各件之间没有共同的上位理由，产出的是**一堆互不相干的柴，不是一棵树**；而且本 skill 在「什么该收、什么该扔」上没有依据，只能全收——**穷尽是它唯一安全的选择，而穷尽就是机械**。
- **可选** = 已知来料线索（未传则第 1 步引导询问现场产出）。
- （可选，**前三个意图**）**查缺蓝图链接**（如组织维护的物料清单库）+ **下游契约链接集**（如某下游 skill 的 input 字段声明）——**仅第 4 步查缺当事后 checklist 用，运行时注入；只核块与字段漏没漏，不参与认定该产哪几件**。（**第四意图两样都不用**：它的第 4 步照该输入的就绪判据逐条核覆盖，见「第四意图」段。）

**本 skill 保留的判断只有材料域的**：这批料影响哪些件、缺哪块料该向谁要。环节编排、阶段路由归调用方。

**读不到料即停**：某份线索指向的材料读不到，停并报 `缺某材料，读不到，请确认位置 / 权限`，不猜路径、不硬编。

#### 第四意图 ·「按某 skill 的判据产它的专用输入件」

某个工作 skill 缺一份它专用的输入件（例如一个做文献引用校对的 skill 要一份「标记体例说明」），本意图照**那个输入自己的就绪判据**，从项目已收进 `raw/` 的材料里把这一件产出来，交人审。

**与前三个意图最根本的差别 —— 规格来自判据，不来自认知件清单。** 前三个意图都靠入参的认知件清单定"产哪几件"；本意图**不传清单、不问人该产什么、不自拟**，规格由目标输入的就绪判据逐条给出，产出成员定死为那一个输入。

**必传六样，缺任一即停并报 `缺<某样>，请调用方传入`**（不问人、不从材料认、不自己去项目档案取、不留兜底）：

1. **项目云盘 `folder_token`** —— 本意图要读 `raw/` 里已收的料，没有它找不到 `raw/`。**它不因"前三个意图必传"而自动继承过来，故在此单独写死：本意图同样必传。**
2. **目标 skill 名** —— 这份输入是给谁用的。
3. **输入名** —— 产的是它的哪一个输入。
4. **该输入的就绪判据，及其声明里的 `type`** —— 判据是逐条内容级可判的中文句，**它是本意图的规格来源**，位置等同于前三个意图里的认知件清单；`type` 与判据**同出一处**（同一份输入声明里的兄弟字段，形如 `"某输入": { "type": "lark-doc", "就绪判据": [...] }`），故一并取来一并传入，**不是拿不到、也不许自己认**。**`type` 非 `lark-doc` 即停并报**，见下方「产物形态」——没有它，那道闸永远触发不了，默认就写成一份文档，正是它要拦的那种静默失败。
5. **落点** —— 见下方「落点」，本 skill 不自行选址。
6. **项目标签与阶段** —— 品类三级 `{业务线 / 合规类目 / 产品品类}` + 品牌 + 阶段，与前三个意图同规，由调用方随入参传入。**它在本意图下有用途边界，见下一段。**

**第 6 样的用途边界**：**只作产物内容的语境参考**（同一份体例说明，处方类目与非处方类目未必同规），**不参与任何过滤、路由或模板取用判断**——本意图不做 `{阶段 × 项目类型}` 过滤，也不按合规类目去模板库取品类特有字段（那是清单意图的机制，不是本意图的）。

**产物形态：本轮只产 `lark-doc`（飞书文档）一种；形态一律看第 4 样随判据一并传入的 `type`**，不按落点、判据措辞或产物读着像什么去推断。

- ✅ `type: lark-doc` 的输入件 —— 本意图产。
- ⛔ `type: lark-base`（多维表格）／ `type: lark-drive` 的输入件 —— **不在本轮范围，另立车次**。遇到这两种形态：**停并报 `本意图本轮只产飞书文档形态的输入件，该件形态不在本轮范围`**，不在本 skill 里现造写表格的能力。
- **理由**（写出来是为了不让人顺手去造）：**本 skill 对多维表格是只读的**（见「依赖的工具 / 接口」：`lark-base` 只读项目料）。产一张多维表格 ＝ 建表 + 建字段 + 建记录，与写一份文档是两回事、是另一项能力，本意图没有设计它。

**与「重产某件 · 某投影」的分界 —— 判别线只有一条：规格来自哪儿。**

- **在入参认知件清单里（含清单列明的下游投影）** → 归**「重产某件 · 某投影」**。**下游投影归它、不归本意图**：投影的规格出自清单，哪怕它只服务一个下游消费者。
- **不在清单里、规格来自某个 skill 的就绪判据** → 归**本意图**。
- 判别时只问这一句。**不要问"这东西是不是多个 skill 共读"**——按共读与否判，会把只服务一个下游的投影误判进本意图。

**从哪一步起跑（六步循环的本意图分支）**：

- **Step 1 引导询问：不执行**——料已在 `raw/`，不重新问人手上有什么料。
- **Step 2 取料归集：不执行**——同上（**这说的是起跑时**；Step 5 索来的新料仍要先归集进 `raw/` 再回 Step 3，见 Step 5）。
- **Step 3 蒸馏：本意图的起点，从这里直接进。** 四步手艺照走（并行只读抽取 → 装配忠实台账 → 逐格溯源蒸馏 → 独立评审），六条贯穿纪律照守——**偏离只有三处，全部列在本段末的覆盖声明里（两处在工艺、一处在纪律），此外一律照手艺件办**。**本意图下"产哪几件"不需要清单来定**：就是第 3 样点名的那一个输入，不增不减、不合件。
- **Step 4 查缺：退化**为"照第 4 样判据逐条核覆盖"——判据的每一条，产物里要么有内容且有具名源，要么有一条显式缺口标注。**不用查缺蓝图、不用下游契约、不做 `{阶段 × 项目类型}` 过滤。**
- **Step 5 索取：仅在确实缺料时走**（缺什么、找谁要，照原样列清单去要）。
- **Step 6 重蒸：照旧，但不同步索引**——料补齐 / 更新回 Step 3 就地重跑，该件就地更新；本意图的产物不进认知件索引，没有索引行要同步（见本段末「覆盖二」）。

**产物长什么样**：一份飞书文档，**文档标题逐字取入参的「输入名」，不自拟主题名**；**开头一段结论段**——这件回答什么 ／ 声明它的那个 skill 什么时候必须来读它 ／ 一条「不知道就会翻车」的警告（没有就明写「本件无此项」）；**若本件与某认知件同源，逐条标明是哪一件的哪一节**——两处讲同一件事而互不指认，日后必各自漂移，且没人知道哪份是准的；内容按第 4 样判据逐条组织；每条实质内容**紧跟一个具名一手来源**；判据要求了而材料里没有的，显式标 `材料不足待补` ／ `待核` ／ `可确无·以某代理指标替代` 并写清去哪儿要；**材料内部对同一件事说法不一的，两种并列摆出、标注冲突，不替人挑一个**。

> **上面这两个动作都不算"命中升级条件"，照做即可、不停机。** 这类输入件多是从若干份既有材料逆向归纳出来的，头一处说法不一致几乎必然出现：**材料分歧的常规动作是并列 ＋ 标注冲突，材料缺的常规动作是标缺口 ＋ 走 Step 5 索取**。只有并列都摆不出（必须择一才能往下走）、或缺料到整份判据无一条可产时，才升级交人裁（见「决策档 · 复核包 · 升级条件」第 2、3 条）。

**产物必带一张三列对照表**：**「判据 → 产物内容 → 具名一手源」**，判据逐条各占一行。判据要了而材料里没有的，在表里就是**一个空的来源格**——一行显眼的空白，**而不是一段读着通顺的话**。

**⚠ 就绪判据是「写之前的规格」，不是验收判据。**

**理由这一段本来就写在这里**：只拿判据裁时，**判据是可以被倒模的**——把判据的措辞回填成产物正文的小标题，逐条判会全 PASS，而评审者看不出内容是编的。**「逐条核判据」这种清单式验收，凡是能被补一个格式项应付掉的，都会被应付掉。**

**拿什么验（本意图的产物级标准）** ＝ **与认知件同一套三关**（`references/distill-craft.md` 工艺 4）＋ **本页 DoD 第 2、3、4、5、6 条**（见本段末「覆盖三」）。三关落到本意图上：

- **第一关 · 逻辑（外推）**：拿一个该输入件**没有直接写过**的情况，看**声明它的那个 skill** 能不能从它推出该怎么办，**且说得出推的路径**。推不出来 → 那份输入件是判据的倒模，不是可用的规格。
- **第二关 · 质量（实用）**：**直接让声明它的那个 skill 拿这份输入件真跑一次**——本意图的消费者唯一确定，这比认知件那边另找真活更硬。
  **⚠ 现有这类输入件（各类规范说明、体例说明、红线类）几乎全是拦截型**——它们的价值在「拦得住坏稿／坏片／坏引用」。所以**必须用故意造坏的样例撞，每类约束各埋一处；拿一份好料跑顺一次不算数**（同一个道理见 `building-work-skill` 判废样例闸：跑顺了证明的是这一次没走岔，不是它拦得住什么）。
- **第三关 · 忠实**：三项专门抽查（溯源属实 ／ 素材警示遵守 ／ 缺口无静默填充）——**能抓住倒模的正是"溯源属实"与"缺口无静默填充"这两项**，一条都不可省；三项抽查是**抽**任意若干条，DoD 第 2 条是**每条**溯源可核，两者不可互相顶替。
- **本页「产出验收判据（DoD）」里的第 1 条「该有的件齐 + 件内该有的块齐」与第 7 条「索引与套一致」，不适用于本意图**——这两条都是件-套级条件（件的名单靠入参清单核、块的查缺靠 `{阶段 × 项目类型}` 过滤、索引每件一行），一份单独的专用输入件按构造必然 FAIL 它们；覆盖情况改由上面这套产物级标准判。**DoD 其余各条照判**，其中第 6 条「独立评审逐条 PASS，且判定记录在」照旧管着本意图：**产出者不自宣完成，这一件在本意图下同样不可降级**（判定记录仍落 `raw/_台账/`）。**这一条同时偏离了手艺件对评审标准范围的规定，具名覆盖声明见本段末「覆盖三」——派独立评审者时须把「覆盖三」一并交给他。**
- **"产出合格"与"输入就绪"是两件事，不得混判**：带 `待补` 的产物**产出合格**（缺口诚实标注了）、**输入不就绪**（那由运行前检查按它的契约另行判，走它既定的停并报卡点）。不拆开判，验收回路就会奖励编造——因为"填一个看起来合理的"会变成唯一能让流程走完的动作。

**落点**：

- **不进认知件索引。** 本意图产的不是认知件：不占索引的行、不改索引、不算进那一套。四步手艺第 3 步「出」那一行的"同步索引"在本意图下**不执行**，产物类型也不叫「认知件」（**具名覆盖声明见本段末「覆盖二」**）。
- **落到哪里由调用方随入参传入（第 5 样），本 skill 不自行选址**——不拿项目云盘顶层顶替、不自己在云盘挑个地方建。
- **该落点须由使用者在本次放行的待建内容清单里给出；未给出即停并报 `缺落点，请使用者在放行清单里给出`，等他定。** 建云盘目录 / 写飞书仍是对外不可逆动作，先放行再执行。
- **落点的停机报给谁，与另外五样不同**：另外五样缺了报调用方（`缺<某样>，请调用方传入`），**落点是六样里调用方也不能自己定的那一样**——它只能由使用者在放行清单里给出，故它的停机报使用者，用上一行那句话。

**谁调本意图**：与前三个意图一样，本意图**不自启**——**由运行前检查发现某个 skill 的该输入缺失、或其就绪判据不过时，经该输入声明的 `produced_by` 修复路由调入本 skill**。调用侧怎么发起、传参从哪儿取，是调用方的事，不在本 skill 的规定面内。

**判据不足以指导产出时，停，不发挥。** 判据是为"判"写的，未必足以指导"造"：当某条判据粗到无从下手（例如只写"格式正确"），**报 `判据不足以据此产出，请补明`，等人补**——不自由发挥补一个看起来合理的版本，也不把判据的措辞抄成小标题假装覆盖了。**这一条只堵"判据太粗"**；"判据清楚但材料里没有"是另一回事，走缺口标注（`材料不足待补`），不停机。

**对手艺件的本意图覆盖声明**——本意图偏离 `references/distill-craft.md` 的地方只有下列三条，逐条具名并写明优先级；**手艺件本身一个字不改**，其余各条工艺与纪律在本意图下照常适用：

> **覆盖一 · 单一来源可以成立。** 这类输入件常常是从一份或少数几份既有材料里逆向归纳出来的（例如从若干份已发稿归纳标记体例，而项目里可能只有一份已发稿可依）。**但产物里须写明"本件仅一份来源"**，不得默认当成多源合成。
> **本条覆盖 `references/distill-craft.md` 纪律 1「跨材料合成」的自查句**（原文：「每块只对应一份文件 = 还在按文件摘抄，回工艺 2 重排」）——**两处冲突时，以本段为准。** 纪律 1 的其余部分（按主题 / 类别组织、同源同事实合并列源、多源互证并列成条）在本意图下照常适用。
>
> **覆盖二 · 产物不是认知件，蒸完不同步索引。** 本意图产的是一份 skill 专用输入件，不进认知件索引、不占索引的行。
> **本条覆盖 `references/distill-craft.md` 工艺 3 的「出」那一行**（原文：「**出**：认知件（每件独立成飞书文档……）；受影响的件蒸完，同步索引（每件一行……）」）——该行的"产物类型 = 认知件"与"同步索引"两处在本意图下**不执行**，**两处冲突时，以本段为准。** 工艺 3 的六个步骤（逐格推进、每条紧跟具名来源、蒸到可直接引用的颗粒度、口径限定随条目、被禁话术挂标带出、对不上料不硬编）照常适用。
>
> **覆盖三 · 产物级标准不含件-套级的那两条。** 本意图的产物级标准 ＝ **与认知件同一套三关**（逻辑·外推 → 质量·实用 → 忠实，见 `references/distill-craft.md` 工艺 4）＋ **本页 DoD 第 2、3、4、5、6 条**；**不含**第 1 条「该有的件齐 + 件内该有的块齐」与第 7 条「索引与套一致」。
> **⚠ 就绪判据是写之前的规格（Step 4 照它逐条核覆盖），不是验收判据**——只拿判据裁，判据会被倒模。三关落到本意图上的具体做法见上方「拿什么验」那一段，**其中第二关须让声明它的那个 skill 真跑一次；这类输入件几乎全是拦截型，必须用故意造坏的样例撞**。
> **本条覆盖 `references/distill-craft.md` 工艺 4 第 2 步的「含 SKILL.md 的 DoD 全部条目」这一句**——本意图下改为「含本页 DoD **除第 1、7 条外**的各条」，**两处冲突时，以本段为准。** 工艺 4 的其余要求（独立评审不可降级、三项专门抽查、任一 FAIL 回工艺 3 修、回流不降标准、派不出即停并报）照常适用。**派给独立评审者的标准，须把这一条一并交给他**——不交，他会照手艺件按"全部条目"判，而一份单独的专用输入件按构造必然 FAIL 那两条。

**本段与全文别处的关系**：本段是第四意图的专属规定。全文别处凡以"认知件清单"为前提写死的句子，说的是需要清单的那三个意图；**与本段冲突时，以本段为准。** 反过来，本段不改前三个意图的任何规矩——它们的必传项、落点与行为照旧。

- **运行时注入项**（不内嵌进本 skill 正文）：调用意图与项目云盘 `folder_token`（见上）；**认知件清单（前三个意图必传——认知件套该产哪几件的唯一来源，这三个意图下未传即停；第四意图不注入它，改注入「该输入的就绪判据」，见「第四意图」段）**；来料线索清单（人报或引导产出）；可选的查缺蓝图链接、下游契约链接集（**前三个意图**的第 4 步用；**第四意图两样都不注入、也不用**——它的第 4 步照该输入的就绪判据逐条核覆盖，见「第四意图」段）；**项目标签与阶段（必传——由调用方随入参传入，是唯一来源，未传即停报缺；本 skill 不问人、不从材料认、不自己去项目档案取，见入参契约。「tingle-项目档案」他方建维，本 skill 不建不写、也不从它取标签 / 阶段）**。换个组织 / 无蓝图时（**前三个意图**），**查缺这一道照走**——只是 checklist 换成下游契约，两者都没有时退到仅靠纪律"缺则标待补"逐块自核（**第四意图不换 checklist**：它的第 4 步本就不用蓝图 / 下游契约，照就绪判据逐条核覆盖）。**"跳过查缺"不是本 skill 可以自己下的决定**：真要少走这一道，摆出来、停、等人拍（见通则 · 降级须人批准）。

**依赖的工具 / 接口**（读散在各处的项目料，飞书优先）：
- `lark-base`（多维表格）、`lark-sheets`（电子表格）、`lark-doc`（云文档 / Wiki 文档）、`lark-minutes`（妙记）——只读项目料；
- `lark-drive`（云盘文件夹 / 上传下载 / 快捷方式）——**材料只上传为文件，不用它的"导入为飞书格式"能力**；**建云盘文件夹 / 写飞书 = 对外不可逆动作，先放行再执行**；
- 本地 `Read`（识读与看图也用它）、PDF 走 `pdf2markdown` / `pdf`、docx / pptx 走对应 skill 转出、表格用 `xlsx` skill **直读不转**——用于转存与**转可读**：**本地料 = 转存过渡态**，先上传项目云盘 `raw/`（**一律以文件形态存放，不导入成飞书原生格式**），再逐件问「AI 现在能直接读它吗」——能则不动，不能、内容提得出来则转出文字落 `raw/_可读件/`，然后才处理；材料不滞留对话、不滞留本地。

四类飞书资源 → 四 lark skill 的具名映射、云盘操作、本地料转存与转可读规则，详见 `references/landing-and-read-contract.md` 「飞书读取契约」一节。

### 输入 / 输出 schema

- **input schema** = `{ 调用意图（初蒸 | 重产某件·某投影 | 收新料·定稿纳入·料更新重蒸 | 按某 skill 的判据产它的专用输入件）；项目云盘 folder_token（必传）；认知件清单（前三个意图必传、未传即停，形态见下方栏位说明（**件名单不在本页**）；第四意图不传，见下一行）；项目标签与阶段（四个意图皆必传，= 品类三级 {业务线 / 合规类目 / 产品品类} + 品牌 + 阶段，随入参传入、未传即停）；可选：来料线索清单[每条：材料名 / 类型（多维表格|电子表格|文档|妙记|云盘文件|本地文件）/ 位置 / 疑似一手 or 加工件]、查缺蓝图链接、下游契约链接集、重产目标（重产意图时必带） }`。
  **第四意图（按某 skill 的判据产它的专用输入件）的入参另计**：不传认知件清单，改传 `{ 目标 skill 名；输入名；该输入的就绪判据 + 其声明里的 type（两者同出一处、一并传入）；落点 }`，连同项目云盘 `folder_token` 与项目标签阶段共**必传六样，缺任一即停并报缺**；`type` 只受理 `lark-doc`，非它即停并报。详见「第四意图」段。
- **output schema**（**前三个意图的**；第四意图产什么见下一行）= `{ 认知件套：成员 = 入参清单逐条列明的那几件——照清单产，不增件、不减件、不合件、不自拟件名；每件独立成飞书文档、各落各自的文件夹，件内四段定序[① 结论段（回答什么 + 答案主干 + 一条会翻车的警告）→ ② 正文各节（每节开头一句判断；每条挂具名一手源；限定与被限定者同处；约束类另带「怎么改」）→ ③ 缺口（各写去处）→ ④ 文末溯源附表]；索引：一份、固定标题 tingle-认知件索引、落云盘顶层，清单每件各占一行（件名 + 链接 + 回答什么 + 什么时候读 + 状态 + 缺口），状态受控两值（已产 | 本项目无料·未产），本项目未产的件也留行、不从索引消失；下游投影：产不产同样只由清单定——清单列了才产，未列即不产，不在运行时现场决定要不要投影 }；落点：{ 各认知件（各自文件夹）；索引；raw/；raw/索引.md；raw/_可读件/ }`。
  **第四意图不产上面这一套**——它只产一份飞书文档形态的 skill 专用输入件（含「判据 → 产物内容 → 具名一手源」三列对照表），**不进认知件索引**，落点由调用方随入参传入。详见「第四意图」段。

**「产物 schema 不固定」现在只有一个意思**（**前三个意图**）：本 skill **正文**不写死件名，件名由入参清单给——换个组织传另一份清单，就是另一套件。它**不再**意味着"运行时可以现场决定产哪几件"：**任一次运行的产出成员，由该次传入的清单完全定死，运行中不得增减。** 故上面声明的是**结构契约**（每件长什么样、索引长什么样）而非件名单本身。**第四意图下"不许现场决定产什么"同样成立、只是定死它的东西换了一样**：产出成员就是入参点名的那一个输入，规格由它的就绪判据给，不增不减、不合件、不自拟（见「第四意图」段）。字段级判据（每字段类型 / 格式 / 判据 / 占位符正例）见 `references/landing-and-read-contract.md` 「input / output schema 字段级判据」一节。

**认知件清单（前三个意图入参必传）的形态**

**这一块由调用方原样传入，本 skill 只描述它长什么样、怎么用——正文里不留件名单。**

**为什么不留**：本页写死「清单未传即停，**不自拟件名、不设兜底件**」。若正文里躺着一份完整件名单，调用方一旦漏传，读本页的模型手上正好有一份现成的——**那条纪律就自带了一个后门**。件名单的运行投影只在调用方（`project-readiness` 主手册）那一份，其家在《tingle 插件统领设计方案》。

**传进来的块有哪几栏**：

| 栏 | 装什么 | 本 skill 怎么用 |
|---|---|---|
| `件名` | 该产哪几件，逐字写定 | **逐字照抄，不自拟主题名**；一件对一个物料，不合件 |
| `形态` | `字段模板` ｜ `归集件` ｜ `判据件` | 决定这一件怎么蒸（见块内「形态定义」） |
| `模板文档标题` | 走字段模板的件才有 | 按它去模板库精确匹配；零命中或多命中即停问人 |
| **`回答什么`** | **这一件产出来必须答上的那个问题** | **三处用它**：产之前定规格、产之中定取舍（**答不上这个问题的材料不该进这一件**）、产之后进验收第二关（实用测试的真活须落在它管辖范围内） |
| `收录范围` | 什么材料该进来 | 收料时的过滤器。**与「回答什么」并列、别混**——前者管进什么，后者管必须出什么，只有后者能拿来扔东西 |
| 件级附注 | 如 `过渡件`、`为什么不是归集件`、`分界判准` | 照它办；与本页正文冲突时以块内为准 |

**块内另附**（同样原样传入、照办不改）：`模板库`（位置 / 定位方式 / 品类特有字段的取用分支）、`形态定义`（三种形态各自怎么蒸）、`产不产`（逐件的判法）、`缺格标法`（三选一，只适用于走字段模板的件）、`件名规则`。

**取用纪律**：**照它产、不增不减**。产哪几件只由它定——不问人、不从查缺蓝图或下游契约认定、不自拟、不设兜底件。**第四意图不传这一块**，块内一切规定与它无关，它照「第四意图」段跑。

### 六步

> **意图分支（先读这一行再往下读）**：下面 Step 1–6 的正文写的是**前三个意图**的走法。**第四意图（按某 skill 的判据产它的专用输入件）不从 Step 1 起跑**——**起跑时** Step 1 引导询问与 Step 2 取料归集**不执行**（料已在 `raw/`；Step 5 索来的新料仍要先归集进 `raw/` 再回 Step 3，见 Step 5），**从 Step 3 直接进**；Step 3 里"产哪几件靠入参清单"那一套在本意图下不适用，产的就是入参点名的那一个输入；Step 4 查缺**退化**为"照该输入的就绪判据逐条核覆盖"，**不用查缺蓝图、不用下游契约、不做 `{阶段 × 项目类型}` 过滤**；Step 5 仅在确实缺料时走；Step 6 照旧，**但不同步索引**（该件就地更新即可——本意图的产物不进认知件索引）。**第四意图照「第四意图」段的规定走，与下面正文冲突时以那一段为准。**

**Step 1 · 引导询问**
- skill **主动引导**人报出：有没有材料？有哪些文件？在哪（在线文档 / 多维表格 / 电子表格 / 妙记 / 云盘 / 本地各处）？**不假设自己知道去哪读**，一项项问清。
- 出：一张"有哪些料、各在哪、疑似一手还是加工件"的**来料线索清单**（一次性工作件，归集后即弃，不入云盘明面）。

**Step 2 · 取料归集（含转可读）**
- 按线索用读取契约（见 reference）读取，归集进项目云盘 `raw/`：**先逐件过第 0 关**（筛掉不是材料的东西）→ 再三层去重 → 再按来源簇归类、一手 vs 加工件分层。**材料上云盘一律以文件形态存放，不导入成飞书原生格式**——导入即多出一个可编辑版本，同一份材料随即有两个真相源；原件只作溯源回查。
- **转可读**（本步之内、蒸馏之前；目的：把项目材料整理成 AI 干活时读得了的形态）：留下的每一件问一句「**AI 现在能直接读它吗？**」——能（表格、md、飞书在线文档）→ 不动；不能、内容提得出来（PDF、Word、PPT、图片）→ 转出文字落 `raw/_可读件/`（路径镜像原件），**能转就转，扫描件也一样**（AI 看着扫描页把内容誊出来）；试了转不出来的 → 如实记、原件留着（可再向来料人索取可编辑版）；壳（zip 等）→ 解压，内容物回到第一问；不是内容的 → 不管。**没列到的情形，照目的自己判；索引里如实记你做了什么。** 定死的只有两条：**表格不转、在线文档不搬副本**。处理模型全文、第 0 关、留哪一份、抽检，详见 reference 「本地料转可读」一节。
- 在线原生件（妙记 / 在线文档 / 多维表格）**不搬原件**——只在 `raw/索引.md` 登记一行，必要处加飞书快捷方式指过去；蒸馏时按索引用对应 lark skill 现读。
- `raw/索引.md` **每件材料一行、八段齐**：标题 / 类型 / 链接·token / 一句摘要 / 读它用哪个 lark skill / 一手 or 加工件 / 处理记录（**如实写做了什么，没有受控词表**）/ 读取位置（有转出件给转出件路径、原生直读给原件路径、其余如实说明去哪读）。
- 落点结构、去重三层、在线件登记法、索引行 schema，详见 `references/landing-and-read-contract.md` 「落点结构」与「input / output schema 字段级判据」两节。

**Step 3 · 蒸馏**
- 调 `references/distill-craft.md` 的**四步手艺**（并行只读抽取 → 装配忠实台账 → 逐格溯源蒸馏 → 独立评审），**（前三个意图）**把 `raw/` 蒸成**认知件套**——每件独立成飞书文档、各落各自的文件夹、摊在云盘顶层，并维护一份**索引**（固定标题 `tingle-认知件索引`，落顶层）串起整套，每件一行：件名 + 链接 + 回答什么 + 什么时候读 + 状态 + 缺口。**第四意图同样调这四步手艺**，但产的是入参点名的那一份 skill 专用输入件，**不产认知件套、不维护索引**（见「第四意图」段与其「覆盖二」）。
- **产哪几件，照入参清单办（前三个意图）。** 逐件按清单的「产不产」判法过一遍：打开该件的形态依据（有模板的对着模板逐格看，无模板的对着该件「收录范围」看），问一句"`raw/` 里有没有一处内容能落进它"——**有则产；全无则不产、不算缺、不催，并在索引里记一行「本项目无料·未产」（未产的件不从索引消失）；判不准则产。** 清单之外一件不产、清单之内一件不漏：不合件、不自拟件名、不设"其余材料"一类兜底件。下游投影同理——清单列了才产，未列即不产。**第四意图不用清单定成员**：产的就是入参点名的那一个输入，不增不减、不合件、不自拟（见「第四意图」段）。
- **清单未传即停（前三个意图，无条件）**：报 `缺认知件清单，请调用方传入`。**不在这一步问人该产哪几件，也不拿查缺蓝图 / 下游契约去认定成员**——那两张表只在第 4 步核块。（**第四意图不传清单，本条不适用于它**；它在这一步的对应停机是「就绪判据未传」与「判据粗到无从下手」——报 `判据不足以据此产出，请补明`，同样不发挥、不自拟，见「第四意图」段。）
- 对不上料的块标"材料不足待补"；受监管 / 有口径风险的领域，把口径承接 / 限定块随条目一并写上。
- 工序脚手架（extract 束 + 忠实台账）与**独立评审判定记录**（`评审判定-<YYYYMMDD>.md`）同落 `raw/_台账/`（非引用面）。

**Step 4 · 查缺**
- **（前三个意图）**拿运行时注入的查缺蓝图 + 下游契约当**事后 checklist**，核对"**该有的块 / 字段**漏没漏"。**件的名单不在这一步认定**——产哪几件由入参清单定死（见 Step 3），查缺不据蓝图 / 下游契约增件、减件或改件名。**第四意图的这一步是退化版**：不用蓝图、不用下游契约，改照该输入的就绪判据逐条核覆盖——判据的每一条，产物里要么有内容且有具名源，要么有一条显式缺口标注（见「第四意图」段）。
- **阶段感知过滤（前三个意图）**：checklist 按 `{阶段 × 项目类型}` 过滤——**本阶段不该有的缺项不算缺口、不去催**（如策略期缺执行数据属"本阶段不该有"）。**阶段值与标签一律取入参传入的那份**（阶段受控初始集：策略期 / 执行中 / 新周期，可扩；标签 = 品类三级 `{业务线 / 合规类目 / 产品品类}` + 品牌）——打标与定阶段排在蒸馏之前，走到本 skill 时调用方已持有这几个值。**未随入参传来即停并报缺、本次不运行**：不问人、不从材料认、不自己去项目档案取、不发明（见入参契约）——**这一条（标签与阶段必传、未传即停）四个意图同规**。**阶段值只用于材料域查缺，不做"哪个阶段跑哪些 skill"的平台路由。****第四意图不做这道 `{阶段 × 项目类型}` 过滤**：它的标签与阶段只作产物内容的语境参考，不参与过滤 / 路由 / 模板取用（见「第四意图」段）。
- **只事后校验，绝不照蓝图算需求再收料**（material-first 护栏见 reference）。蓝图是 type-level 通用清单，只回答"这类产物一般该有哪些种类的块"，绝不回答"某项目某块内容是什么"——内容只能从真实 raw 蒸。
- 出：一张缺口清单（一次性工作件，索取后即弃）。

**Step 5 · 索取**
- 把真缺的列成缺口清单去向人要；人给了新料，**回第 2 步**归集进 `raw/`（+ 索引）。**第四意图同此**——它的 Step 2「不执行」说的是**起跑时**料已在 `raw/`；这一步索来的新料同样要先归集进 `raw/`，再回 Step 3。

**Step 6 · 重蒸**
- 料补齐 / 更新 → **回第 3 步就地重跑**；受影响的认知件就地更新、索引同步，落点 / raw 结构不重建。（**第四意图**：那一份 skill 专用输入件就地更新，**不同步索引**——它不进认知件索引，见「第四意图」段「覆盖二」。）

## 决策档 · 复核包 · 升级条件

- **决策档 = 复核**。本 skill 产出的是**待复核蒸馏产物**，由人验收后才升级；skill 不自宣完成、不替人拍板。
- **复核包（交人复核时随附）**：① 本次产出 / 更新的认知件（含索引）；② 溯源可核（每条挂具名一手源、可逐条回核）；③ 缺口清单（哪些块料不足 / 待核 / 可确无）；④ 台账素材警示（蒸馏前钉死的雷区，供核是否被绕开）；⑤ **独立评审判定记录**（**三关各自的判定与证据**：外推题与推的路径 ／ 真活或坏样例与做出来的结果 ／ 三项专门抽查）——它是**复核过程件、非引用面产物**，**落 `raw/_台账/评审判定-<YYYYMMDD>.md`**（与 extract 束、忠实台账同性质）；交人复核时指这一份，不另存副本。**第四意图的复核包只换第 ① 件**：换成本次产出的那一份 skill 专用输入件 + 它必带的「判据 → 产物内容 → 具名一手源」三列对照表（**不含索引**——它不进认知件索引）；②③④⑤ 照旧、一件不减。
- **升级条件（命中任一即停、交人裁决，不自行推进）**：
  1. **合规 / 口径红线不确定** —— 某条内容是否越线、口径怎么承接判不准；
  2. **一手源内部冲突** —— 多份一手材料对同一事实互相打架、无法自洽取舍（**常规动作不是停**：材料分歧一律两种并列摆出 ＋ 标注冲突、不替人挑一个，**那不算命中本条**；只有并列都摆不出、必须择一才能往下走时才命中）；
  3. **缺关键材料** —— 缺某份料导致某必备块蒸不出，非补料不能推进（**常规动作不是停**：缺料一律标缺口「材料不足待补」＋ 走 Step 5 去要，**那不算命中本条**；只有缺到整块 / 整份判据无一条可产时才命中）；
  4. **对外不可逆动作** —— 建云盘落点文件夹 / 写飞书 / 发送到项目外部等，**先放行再执行**。**一次放行覆盖本次运行在该项目云盘内的建目录与写入**（含 `raw/_台账/`、各认知件与索引的建立及就地更新），不逐次重复请示；跨项目动作、删除类动作另行请示。
  5. **独立评审派不出** —— **实际调过一次子代理、以调用失败为准**（判法见 `references/distill-craft.md` 工艺 4）后仍派不出，则停下把产物摆给人、报 `独立评审派不出（附实际发起的调用与它的失败信息），请指定评审者或明确改判`，**等人拍**。**不许自检顶替、不许"这儿大概不让派"就跳过**——这一件的降级是人的决定。

## 写回位置 · 可沉淀候选

- **写回位置** = 项目云盘：**（前三个意图）**顶层摊认知件套 + 索引 `tingle-认知件索引`（下游引用面；成员 = 入参清单列明的那几件）、`raw/` 收原料与 `raw/_可读件/` 收转出件（溯源回查面，一律文件形态、不导入飞书格式）、`raw/_台账/` 收工序脚手架与独立评审判定记录（非引用面）。落点结构详见 `references/landing-and-read-contract.md` 「落点结构」一节。**第四意图的产物落点另计**：落到调用方随入参传入的那个落点（该落点须由使用者在放行清单里给出），**不进认知件索引、本 skill 不自行选址、不拿云盘顶层顶替**；`raw/`、`raw/_可读件/`、`raw/_台账/` 三处照旧（见「第四意图」段「落点」）。
- **可沉淀候选**（output schema 中标"是"）：认知件中经复核确认、**跨材料合成且稳定**的件 / 块（如项目身份 / 人群卡点 / 认知主线类）可标为回流资产、供复用；纯溯源脚手架（extract / 台账 / raw 索引）标"否"、不回流。

## 产出验收判据（DoD）

> **⚠ 先读这一条：验收的主体是三关，不是下面这张清单。**
> **验收 ＝ 第一关逻辑（外推测试）→ 第二关质量（实用测试）→ 第三关忠实**，按序跑、不许调换、不许只跑一关，完整判法见 `references/distill-craft.md` 工艺 4。
> **下面第 1、7 条是件-套级的交代要求，第 2–5 条是第三关（忠实）的具体化，第 6 条管评审本身。** 它们**都不是「可用」的判据**——一份七条全绿的产物照样可以没人能用（**实测**：某项目九件跑了 11 轮全 PASS，最后整体重写）。
> **凡「能不能被补个格式项应付掉」的条款，一律不进验收**，它们是写的时候的要求，归工艺 3 与六条纪律。

一套蒸馏产物（认知件套）**合格**，当且仅当**三关全过**，且以下全部成立（可判句、非裸形容词）——**下列七条是前三个意图的**；**第四意图不含第 1、7 条**，见「第四意图」段「覆盖三」：
1. **该有的件齐 + 件内该有的块齐**（**第四意图不适用本条**，见「第四意图」段「覆盖三」）—— **件**：入参清单逐条都有交代（产了，或索引里记着「本项目无料·未产」），且无清单外新增件；**块**：按 `{阶段 × 项目类型}` 过滤后的查缺无遗漏，或遗漏已显式标"材料不足待补"；
2. **每条溯源可核** —— 每条实质内容挂具名一手源，第三人可逐条回核到原材料段落；
3. **溯源抽查无发明** —— 抽查任意若干条，均能落回具名源，无凭常识 / 泛化硬编的定论；
4. **缺口显式标注** —— 料没覆盖的地方标"待补 / 待核 / 可确无·以某代理指标"，不静默填充；
5. **素材雷区被绕开** —— 台账素材警示列出的判断陷阱，逐一被产物绕开（无被禁话术、无归属存疑卖点当定论、无截断数据当全量）；
6. **独立评审三关全 PASS，且判定记录在** —— 独立评审者按序跑完三关、全 PASS（产出者不自宣），且判定记录已落 `raw/_台账/评审判定-<YYYYMMDD>.md`，内含**三关各自的判定与证据**：第一关的三道外推题原文＋答案＋**推的路径**；第二关那件真活（或坏样例）原文＋只用本件做出来的结果＋为什么算过关（**拦截型须写明每类约束各埋在哪、各被哪条拦下**）；第三关三项抽查的结果。**自检不算独立评审**；"派不出评审者"是停并报的理由，**不是本条可以免判的理由**——**没有这份记录，本条即 FAIL**；
7. **索引与套一致**（**第四意图不适用本条**，见「第四意图」段「覆盖三」）—— 索引标题为 `tingle-认知件索引`、落云盘顶层；入参清单每件各有一行（件名 + 链接 + 回答什么 + 什么时候读 + 状态 + 缺口，状态取 `已产` ｜ `本项目无料·未产` 之一），**本项目未产的件也留行**；无孤儿件（有件而索引无行）、无悬空行（有行而件不存在或链接失效）。
> 内容层面的具体对错（哪些口径越线）交由运行时项目材料 + 可选下游契约承载；本判据本身可据以判定某份产物合格与否。

## 常见错误（Common Mistakes）

- **清单没传就自己定该产哪几件**（**前三个意图**）—— 问人"这次要产哪些件"、或照查缺蓝图 / 下游契约列一份名单、或自拟几个主题名先蒸起来。违照清单产：**清单未传即停报缺**，蓝图 / 下游契约只在第 4 步核块。同一批材料两个人跑出不同的件数与件名，根子就在这里。**第四意图下的同款错误是"判据太粗，我先按理解补一个版本"**——同样停并报 `判据不足以据此产出，请补明`，不发挥、不把判据措辞抄成小标题假装覆盖。**两边根子是同一个：产什么、按什么规格产，都不许运行时自己定。**
- **把蓝图当上游驱动照单收料** —— 先照 checklist 算出应有字段、再去找料 / 先搭空框。违 material-first。蓝图只在蒸馏之后当事后核对表。
- **对不上料硬编泛化填空** —— "这块没料，凭品类常识补一句吧"。违不发明。没源就标"材料不足待补"。
- **溯源指向脚手架而非一手** —— 来源标注指向 extract / 台账等中间件。违每条溯源。来源须指真实一手材料段落。
- **把前人加工件当一手 / 当"已满足"** —— 别的目的裁剪组织过的加工件，直接采信为承重。违回一手。加工件只作参考待核，要用回它对应的一手原件重做。
- **产物留内部裸码 / 流程标签** —— 正文留"品-1"类裸码、"承重"类流程标签、指向脚手架的来源。违产物自解释。内部代号 / 映射一律隔离进文末溯源附表。
- **建云盘 / 写飞书不先请示** —— 直接建文件夹、直接写飞书表。违对外动作先放行。命中升级条件，先摆出要执行、等放行。
- **产出者自宣完成** —— 蒸完自己说"合格"。违产出者不自宣。须独立评审**按序跑完三关**全 PASS，判定记录落 `raw/_台账/评审判定-<YYYYMMDD>.md`。
- **只跑忠实那一关就说验完了** —— 每条都能溯源、每条都真，**不等于这份东西有人能用**。三关缺一即未验完。
- **没试过就宣告"派不出评审者"，改自检顶上** —— 读到一条"默认不主动使用子代理"就判定环境不允许，于是"我自己再通读一遍"代替独立评审。违独立评审不可降级。**"派不出"只能由一次实际调用的失败来证明**：先真的去调，调不动才算数；真调不动就停下报给人、等人拍，不自己把这一件降级成自检。
- **标签 / 阶段没传就自己想办法凑** —— 问使用者一句、从材料里认一个、或去项目档案里取。违标签随入参传入。打标与定阶段排在蒸馏之前，值该由调用方带来；**未传即停并报缺**，凑出来的值会让同一个项目在两次运行里取到不同的合规类目。
- **初蒸时去项目档案找本 skill 的条目** —— 初蒸时项目档案尚无本 skill 条目，`folder_token` 由调用方直传；去解析等于对不存在的登记硬跑。
- **把"本阶段不该有"的缺项当缺口去催料**（**前三个意图**）—— 查缺先按 `{阶段 × 项目类型}` 过滤；策略期不催执行数据。**第四意图不做这道过滤**：就绪判据的每一条都要核到，没覆盖的一律显式标缺口——**不许拿"本阶段不该有"把一条判据过滤掉**（见「第四意图」段）。
- **对话里贴来的材料直接蒸** —— 本地料 = 转存过渡态：先上传项目云盘 `raw/`（存成文件、过转可读一道），再按云盘件处理；材料不滞留对话 / 本地。

## Red Flags

看到自己出现以下念头或动作，停下重判：
- 「调用方没给清单，我先问问这次该产哪几件吧」/「照蓝图列一份名单也一样吧」/「这两件内容挺像，合成一件吧」→ 成员不许现场认定、不许合件，停下报 `缺认知件清单`（**前三个意图**）。**第四意图下的同款念头是「判据没写清，我先按理解产一版吧」** → 停下报 `判据不足以据此产出，请补明`；成员同样不许现场认定。
- 「这份料落进哪一件说不清，那就新起一件吧」→ 清单外不新增件；记进最沾边那一件并标「归属待核」。（**第四意图下同理**：产出成员就是入参点名的那一个输入，不另起件。）
- 「先照 checklist 把该有的框搭全，再去找料填」→ 上游驱动，违 material-first，收回。
- 「这块没料，凭品类常识补一句吧」→ 发明，标"材料不足待补"，别硬编。
- 「这份前人加工过的，直接当一手用吧」→ 违回一手，回它的一手原件重做。
- 「来源就写指向那份 extract 吧」→ 溯源指脚手架，改指真实一手材料。
- 「直接建云盘文件夹 / 改飞书吧」→ 对外不可逆动作，先请示放行。
- 「我蒸完了，应该没问题，交付吧」→ 没独立评审，别自宣，先派独立评审逐条判。
- 「这个环境大概不让派子代理 / 有规矩说别主动派，那我自己核一遍算了」→ **没试过就宣告不可用 = 自行降级**。先实际调一次子代理，以调用失败为准；真调不动，停下把产物摆给人、等人拍，别拿自检顶替。
- 「调用方没给标签，我先问使用者一句 / 从材料里认一个 / 去项目档案取吧」→ 标签与阶段只有入参一个来源，停并报 `缺项目标签 / 阶段`。
- 「这一件走不了，那就跳过 / 换个简化版接着跑吧」→ 降级是人的决定，不是你的决定：摆出来、停、等人拍。
- 「用户贴在对话里的料，顺手直接蒸吧」→ 先上云盘 `raw/`（存成文件、过转可读一道）再处理，不滞留对话。
- 「这个缺口先催了再说」→ 先核阶段：本阶段不该有的缺项不算缺口、不去催（**前三个意图**）。**第四意图反过来**：不按阶段过滤，判据没覆盖的一律显式标缺口，别拿阶段替它消掉。
