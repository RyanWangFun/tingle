# context-distill

## 概述与核心原则

本 skill 只做一件事：**把一个项目散在各处的原始材料，经「引导询问 → 取料归集 → 蒸馏 → 查缺 → 索取 → 重蒸」的循环，蒸成一套每条都能溯回原材料的结构化认知件——每件独立成飞书文档、各落各自的文件夹，外加一份索引串起整套，摊在项目云盘顶层，供下游程序反复引用；材料更新就地重蒸。**

**三条核心原则（记牢，越一条即错）：**

- **material-first —— 从真实材料起步，蓝图只事后核。** 循环第一步是引导人报出手上有什么料，产物**内容与块结构**从真实材料长出。任何"该有哪些块"的蓝图 / 下游契约，只在蒸馏之后的"查缺"步当**事后核对表**，绝不反过来当上游驱动去照单收料、先搭空框。数据只单向流：真实料 → 蒸馏 → 事后拿蓝图核缺。
  > **这一条与"照清单产"不冲突，两者管的是不同层**：**产哪几件**由入参的认知件清单定死（不由本 skill 现场认定，也不由蓝图 / 下游契约认定）；**每件里装什么**只能从该项目真实 `raw/` 蒸。清单本身也不是上游驱动——它每一件都要先过"`raw/` 里有没有一处内容能落进它"这一问，没料的件不产、只在索引留一行「本项目无料·未产」。所以仍然没有"照单收料 / 先搭空框"这一步。
- **每条溯源 + 不发明。** 产物里每条实质内容都挂一个具名的一手来源，第三人拿源 + 这条产物能逐条比对。材料对不上的**标"材料不足待补"**，绝不凭品类常识 / 泛化硬编填空。
- **产出者不自宣完成。** 蒸馏产物是待复核件，由一个独立评审者拿产物级标准逐条判 PASS/FAIL 后才升级；skill 自己不拍板"做完了"。

**适用环节**：本 skill 对应一条可复用环节——把一个项目的散乱 raw 材料整理成一套溯源认知件，跨项目复现（每个项目可换、材料更新可重跑），不是一次性事务。

## 何时用 / 何时不用

**何时用**
- 新接一个项目，材料零散在在线文档 / 多维表格 / 电子表格 / 妙记 / 云盘 / 本地各处，要整理成一套可复用、每条溯源的认知件（含索引）。
- 已有这套产物，某处材料更新了 / 某环节定稿产物要纳入，要就地重蒸、受影响的件就地更新。
- 需要一个"一个项目 raw → 溯源认知件套"的通用蒸馏引擎，换个项目零改复用。

**何时不用（When NOT）**
- **给项目建档 / 建库 / 配权限 / 通知团队** —— 这些是组织层的活，不在本环节。本 skill 只读别人给的标签 / brief（有则读，无则从材料认），不建档。
- **做下游的选题 / 审稿 / 内容 / 投放 / 分析** —— 这些是蒸馏产物的独立消费者、各自独立环节。本 skill 只交"溯源产物"，越到任一件即错。
- **"任意材料 → 任意产物"的泛化引擎** —— 本 skill 锁定"一个项目 raw → 一套溯源认知件"这一类，不做通用文本转换器。
- **判断"现在该不该蒸、该跑哪个环节 / 哪个 skill"（平台路由）** —— 本 skill 无平台判断脑，每次调用自带意图；环节编排归调用方（如 `project-readiness` 的初始化编排）。
- **材料完全无法读取时硬跑** —— 读不到就**停并报缺**（缺哪份、在哪），不猜路径、不凭常识硬编一份出来。

## 方法：material-first 六步循环

一次调用 = 一个反馈环：收料与蒸馏紧耦合（蒸出来发现缺 → 再收 → 再蒸），不拆成两段。

> **material-first 硬约束（贯穿全环，先记死）**：循环首步是"引导人报出手上有什么料"、从真实材料起步。查缺蓝图 / 下游契约**只在第 4 步"查缺"**作为事后 checklist 出现。全流程**没有**"先照蓝图算出需要哪些字段 → 照单收料 / 先搭空产物骨架再填"的上游驱动步——那是本 skill 明令排除的反模式。

### 调用意图与入参契约

**本 skill 无平台判断脑**——不判断"现在该不该蒸、该跑哪个环节"；每次调用自带意图，三类：

- **(a) 初蒸**：由 `project-readiness` 在项目初始化"开云盘落点 → 收料 → 蒸馏"的编排处**一次性合并调用**，走完整六步循环（引导收料 + 上飞书 + 蒸馏一体）；调用方不参与过程、只验收结果（云盘有料 / 上下文产出 / 取地址登记）。
- **(b) 重产某件 / 某投影**：消费 skill 运行前检查发现某投影不达标 → 按 `produced_by: context-distill` 的修复路由回调本 skill；料够则重蒸该件，料不足则先查缺 / 索取再蒸。
- **(c) 收新料 / 定稿纳入 / 料更新重蒸**：项目成员直达本 skill——材料的事直达，不必绕编排；**环节定稿产物一旦产生，必纳回这一整套（定稿必纳入）**，随后重蒸受影响的件。

**入参契约**：
- **必传（其一）= 项目云盘 `folder_token`**。初蒸时由调用方直传（**勿假设项目档案已有本 skill 的条目**）；重蒸 / 修复路由时由调用方从项目档案解析后传入。
- **必传（其二）= 认知件清单**：一份写定的清单，逐条给出该产哪几件、每件的形态与收录范围、产不产怎么判、落点长什么样。**「该产哪几件」只有这一个来源。** 形态与取用方式见下方「输入 / 输出 schema」的清单块。**清单未传 = 本次不运行**：停并报 `缺认知件清单，请调用方传入`——**不问人该产哪几件、不从查缺蓝图或下游契约认定、不自拟件名、不设兜底件**。
- **可选** = 已知来料线索（未传则第 1 步引导询问现场产出）。
- （可选）**查缺蓝图链接**（如组织维护的物料清单库）+ **下游契约链接集**（如某下游 skill 的 input 字段声明）——**仅第 4 步查缺当事后 checklist 用，运行时注入；只核块与字段漏没漏，不参与认定该产哪几件**。

**本 skill 保留的判断只有材料域的**：这批料影响哪些件、缺哪块料该向谁要。环节编排、阶段路由归调用方。

**读不到料即停**：某份线索指向的材料读不到，停并报 `缺某材料，读不到，请确认位置 / 权限`，不猜路径、不硬编。

### 依赖

**依赖的规则层与项目事实**：
- **不装配品类 / 品牌等创作规则层**——蒸馏是"忠实搬运 + 溯源"，不套创作 / 合规规则去改写内容；材料里带的口径 / 限定块随条目沿用（从材料来，不从规则层来）。
- **运行时注入项**（不内嵌进本 skill 正文）：调用意图与项目云盘 `folder_token`（见上）；**认知件清单（必传——认知件套该产哪几件的唯一来源，未传即停）**；来料线索清单（人报或引导产出）；可选的查缺蓝图链接、下游契约链接集（第 4 步用）；项目档案的标签 / 阶段值（「tingle-项目档案」他方建维，本 skill **不建不写、只读**）。换个组织 / 无蓝图时，skill 仍可只用下游契约、或跳过查缺、仅靠纪律"缺则标待补"兜底。

**依赖的工具 / 接口**（读散在各处的项目料，飞书优先）：
- `lark-base`（多维表格）、`lark-sheets`（电子表格）、`lark-doc`（云文档 / Wiki 文档）、`lark-minutes`（妙记）——只读项目料；
- `lark-drive`（云盘文件夹 / 上传下载 / 快捷方式）——**材料只上传为文件，不用它的"导入为飞书格式"能力**；**建云盘文件夹 / 写飞书 = 对外不可逆动作，先放行再执行**；
- 本地 `Read`（识读与看图也用它）、PDF 走 `pdf2markdown` / `pdf`、docx / pptx 走对应 skill 转出、表格用 `xlsx` skill **直读不转**——用于转存与**转可读**：**本地料 = 转存过渡态**，先上传项目云盘 `raw/`（**一律以文件形态存放，不导入成飞书原生格式**），再逐件问「AI 现在能直接读它吗」——能则不动，不能、内容提得出来则转出文字落 `raw/_可读件/`，然后才处理；材料不滞留对话、不滞留本地。

四类飞书资源 → 四 lark skill 的具名映射、云盘操作、本地料转存与转可读规则，详见 `references/landing-and-read-contract.md` 「飞书读取契约」一节。

### 输入 / 输出 schema

- **input schema** = `{ 调用意图（初蒸 | 重产某件·某投影 | 收新料·定稿纳入·料更新重蒸）；项目云盘 folder_token（必传）；认知件清单（必传，形态见下方清单块）；可选：来料线索清单[每条：材料名 / 类型（多维表格|电子表格|文档|妙记|云盘文件|本地文件）/ 位置 / 疑似一手 or 加工件]、查缺蓝图链接、下游契约链接集、重产目标（重产意图时必带） }`。
- **output schema** = `{ 认知件套：成员 = 入参清单逐条列明的那几件——照清单产，不增件、不减件、不合件、不自拟件名；每件独立成飞书文档、各落各自的文件夹，件内[按主题分块 + 每条溯源标注（具名一手源）+ 可选口径承接 / 限定块 + 缺口标注 + 文末溯源附表]；索引：一份、固定标题 tingle-认知件索引、落云盘顶层，清单每件各占一行（件名 + 链接 + 一句用途 + 状态 + 缺口），状态受控两值（已产 | 本项目无料·未产），本项目未产的件也留行、不从索引消失；下游投影：产不产同样只由清单定——清单列了才产，未列即不产，不在运行时现场决定要不要投影 }；落点：{ 各认知件（各自文件夹）；索引；raw/；raw/索引.md；raw/_可读件/ }`。

**「产物 schema 不固定」现在只有一个意思**：本 skill **正文**不写死件名，件名由入参清单给——换个组织传另一份清单，就是另一套件。它**不再**意味着"运行时可以现场决定产哪几件"：**任一次运行的产出成员，由该次传入的清单完全定死，运行中不得增减。** 故上面声明的是**结构契约**（每件长什么样、索引长什么样）而非件名单本身。字段级判据（每字段类型 / 格式 / 判据 / 占位符正例）见 `references/landing-and-read-contract.md` 「input / output schema 字段级判据」一节。

**认知件清单（入参必传）的形态** —— 下面这一块由调用方原样传入：该产哪几件、每件形态与收录范围、模板怎么定位、品类特有字段怎么取、产不产怎么判、缺格怎么标、落点与索引长什么样，全在其中。本 skill **照它产、不增不减**；块内两行 HTML 注释是校验锚点，渲染不可见。

    先问: 初蒸时项目档案尚未建成（建档案是初始化最后一道），不要去档案里取。先向使用者问一句——本项目的业务线 / 合规类目 / 产品品类 / 品牌各是什么
    问得到: 按合规类目对号取用该组品类特有字段
    问不到但材料里写着: 按材料认，并把该格标「待核」——须指得出是哪份材料哪一句；仅凭品类名推断的不算
    问不到且材料里也没有: 只填通用层，品类特有一节整节标「本项目合规类目待定，暂不填」，并把这一条记进缺口清单交还调用方
    不猜: 不从品类名一眼判"这看着像医药的"，也不发明
    重蒸时: 项目档案已建成，改从档案的「合规类目」字段取，不必再问

归集件形态: 忠实誊录相关原文 + 逐条标出处，不划格子

产不产:
  逐件问: 项目云盘 raw/ 里有没有一处内容能落进它——有模板的对着模板逐格看，无模板的对着本件的「收录范围」看
  有: 产
  全无: 不产、不算缺、不催；在索引里记一行「本项目无料·未产」
  判不准: 产
  不设门槛: 满一处即产，不要求上游齐；一份材料可同时充当多件的上游；部分覆盖照产；不设空件下限
  跨件材料: 一份材料同时沾多件时，各件都收它相关的那部分；若某段内容归哪一件说不清，记进最沾边的那一件并标「归属待核」，不为它新起一件

缺格标法:
  适用: 只用于走字段模板的四件（归集件不划格子，本无格可缺）
  不许留白: 缺的格必须落到下列三种之一
  材料不足待补: 这一格应该有内容，但手上材料里没有——并写明去哪儿要
  待核: 材料里有线索，但不足以定论，需要人确认——并写明核什么
  可确无·并写明代理指标: 这一格在本项目确实不存在——并给出可替代观察的指标

件名规则: 件名逐字照抄上列，不自拟主题名；一件对应且只对应一个物料，不合件

落点:

    位置: 项目云盘顶层

### 六步

**Step 1 · 引导询问**
- skill **主动引导**人报出：有没有材料？有哪些文件？在哪（在线文档 / 多维表格 / 电子表格 / 妙记 / 云盘 / 本地各处）？**不假设自己知道去哪读**，一项项问清。
- 出：一张"有哪些料、各在哪、疑似一手还是加工件"的**来料线索清单**（一次性工作件，归集后即弃，不入云盘明面）。

**Step 2 · 取料归集（含转可读）**
- 按线索用读取契约（见 reference）读取，归集进项目云盘 `raw/`：**先逐件过第 0 关**（筛掉不是材料的东西）→ 再三层去重 → 再按来源簇归类、一手 vs 加工件分层。**材料上云盘一律以文件形态存放，不导入成飞书原生格式**——导入即多出一个可编辑版本，同一份材料随即有两个真相源；原件只作溯源回查。
- **转可读**（本步之内、蒸馏之前；目的：把项目材料整理成 AI 干活时读得了的形态）：留下的每一件问一句「**AI 现在能直接读它吗？**」——能（表格、md、飞书在线文档）→ 不动；不能、内容提得出来（PDF、Word、PPT、图片）→ 转出文字落 `raw/_可读件/`（路径镜像原件），**能转就转，扫描件也一样**（AI 看着扫描页把内容誊出来）；试了转不出来的 → 如实记、原件留着（可再向来料人索取可编辑版）；壳（zip 等）→ 解压，内容物回到第一问；不是内容的 → 不管。**没列到的情形，照目的自己判；索引里如实记你做了什么。** 定死的只有两条：**表格不转、在线文档不搬副本**。处理模型全文、第 0 关、留哪一份、抽检，详见 reference 「本地料转可读」一节。
- 在线原生件（妙记 / 在线文档 / 多维表格）**不搬原件**——只在 `raw/索引.md` 登记一行，必要处加飞书快捷方式指过去；蒸馏时按索引用对应 lark skill 现读。
- `raw/索引.md` **每件材料一行、八段齐**：标题 / 类型 / 链接·token / 一句摘要 / 读它用哪个 lark skill / 一手 or 加工件 / 处理记录（**如实写做了什么，没有受控词表**）/ 读取位置（有转出件给转出件路径、原生直读给原件路径、其余如实说明去哪读）。
- 落点结构、去重三层、在线件登记法、索引行 schema，详见 `references/landing-and-read-contract.md` 「落点结构」与「input / output schema 字段级判据」两节。

**Step 3 · 蒸馏**
- 调 `references/distill-craft.md` 的**四步手艺**（并行只读抽取 → 装配忠实台账 → 逐格溯源蒸馏 → 独立评审），把 `raw/` 蒸成**认知件套**——每件独立成飞书文档、各落各自的文件夹、摊在云盘顶层，并维护一份**索引**（固定标题 `tingle-认知件索引`，落顶层）串起整套，每件一行：件名 + 链接 + 一句用途 + 状态 + 缺口。
- **产哪几件，照入参清单办。** 逐件按清单的「产不产」判法过一遍：打开该件的形态依据（有模板的对着模板逐格看，无模板的对着该件「收录范围」看），问一句"`raw/` 里有没有一处内容能落进它"——**有则产；全无则不产、不算缺、不催，并在索引里记一行「本项目无料·未产」（未产的件不从索引消失）；判不准则产。** 清单之外一件不产、清单之内一件不漏：不合件、不自拟件名、不设"其余材料"一类兜底件。下游投影同理——清单列了才产，未列即不产。
- **清单未传即停**：报 `缺认知件清单，请调用方传入`。**不在这一步问人该产哪几件，也不拿查缺蓝图 / 下游契约去认定成员**——那两张表只在第 4 步核块。
- 对不上料的块标"材料不足待补"；受监管 / 有口径风险的领域，把口径承接 / 限定块随条目一并写上。
- 工序脚手架（extract 束 + 忠实台账）落 `raw/_台账/`（非引用面）。

**Step 4 · 查缺**
- 拿运行时注入的查缺蓝图 + 下游契约当**事后 checklist**，核对"**该有的块 / 字段**漏没漏"。**件的名单不在这一步认定**——产哪几件由入参清单定死（见 Step 3），查缺不据蓝图 / 下游契约增件、减件或改件名。
- **阶段感知过滤**：checklist 按 `{阶段 × 项目类型}` 过滤——**本阶段不该有的缺项不算缺口、不去催**（如策略期缺执行数据属"本阶段不该有"）。阶段值读项目档案「阶段」字段（受控初始集：策略期 / 执行中 / 新周期，可扩）；初蒸时标签（品类三级 `{业务线 / 合规类目 / 产品品类}` + 品牌）/ 阶段尚未落定 → 询问用户或从材料认，不发明。**阶段值只用于材料域查缺，不做"哪个阶段跑哪些 skill"的平台路由。**
- **只事后校验，绝不照蓝图算需求再收料**（material-first 护栏见 reference）。蓝图是 type-level 通用清单，只回答"这类产物一般该有哪些种类的块"，绝不回答"某项目某块内容是什么"——内容只能从真实 raw 蒸。
- 出：一张缺口清单（一次性工作件，索取后即弃）。

**Step 5 · 索取**
- 把真缺的列成缺口清单去向人要；人给了新料，**回第 2 步**归集进 `raw/`（+ 索引）。

**Step 6 · 重蒸**
- 料补齐 / 更新 → **回第 3 步就地重跑**；受影响的认知件就地更新、索引同步，落点 / raw 结构不重建。

## 决策档 · 复核包 · 升级条件

- **决策档 = 复核**。本 skill 产出的是**待复核蒸馏产物**，由人验收后才升级；skill 不自宣完成、不替人拍板。
- **复核包（交人复核时随附）**：① 本次产出 / 更新的认知件（含索引）；② 溯源可核（每条挂具名一手源、可逐条回核）；③ 缺口清单（哪些块料不足 / 待核 / 可确无）；④ 台账素材警示（蒸馏前钉死的雷区，供核是否被绕开）；⑤ **独立评审判定记录**（拿产物级标准逐条 PASS/FAIL 的结果——这是复核过程件，不是产物、不入 `raw/`）。
- **升级条件（命中任一即停、交人裁决，不自行推进）**：
  1. **合规 / 口径红线不确定** —— 某条内容是否越线、口径怎么承接判不准；
  2. **一手源内部冲突** —— 多份一手材料对同一事实互相打架、无法自洽取舍；
  3. **缺关键材料** —— 缺某份料导致某必备块蒸不出，非补料不能推进；
  4. **对外不可逆动作** —— 建云盘落点文件夹 / 写飞书 / 发送到项目外部等，**先放行再执行**。**一次放行覆盖本次运行在该项目云盘内的建目录与写入**（含 `raw/_台账/`、各认知件与索引的建立及就地更新），不逐次重复请示；跨项目动作、删除类动作另行请示。

## 写回位置 · 可沉淀候选

- **写回位置** = 项目云盘：顶层摊认知件套 + 索引 `tingle-认知件索引`（下游引用面；成员 = 入参清单列明的那几件）、`raw/` 收原料与 `raw/_可读件/` 收转出件（溯源回查面，一律文件形态、不导入飞书格式）。落点结构详见 `references/landing-and-read-contract.md` 「落点结构」一节。
- **可沉淀候选**（output schema 中标"是"）：认知件中经复核确认、**跨材料合成且稳定**的件 / 块（如项目身份 / 人群卡点 / 认知主线类）可标为回流资产、供复用；纯溯源脚手架（extract / 台账 / raw 索引）标"否"、不回流。

## 产出验收判据（DoD）

一套蒸馏产物（认知件套）**合格**，当且仅当以下全部成立（可判句、非裸形容词）：
1. **该有的件齐 + 件内该有的块齐** —— **件**：入参清单逐条都有交代（产了，或索引里记着「本项目无料·未产」），且无清单外新增件；**块**：按 `{阶段 × 项目类型}` 过滤后的查缺无遗漏，或遗漏已显式标"材料不足待补"；
2. **每条溯源可核** —— 每条实质内容挂具名一手源，第三人可逐条回核到原材料段落；
3. **溯源抽查无发明** —— 抽查任意若干条，均能落回具名源，无凭常识 / 泛化硬编的定论；
4. **缺口显式标注** —— 料没覆盖的地方标"待补 / 待核 / 可确无·以某代理指标"，不静默填充；
5. **素材雷区被绕开** —— 台账素材警示列出的判断陷阱，逐一被产物绕开（无被禁话术、无归属存疑卖点当定论、无截断数据当全量）；
6. **独立评审逐条 PASS** —— 独立评审者拿产物级标准逐条判，全 PASS（产出者不自宣）；
7. **索引与套一致** —— 索引标题为 `tingle-认知件索引`、落云盘顶层；入参清单每件各有一行（件名 + 链接 + 一句用途 + 状态 + 缺口，状态取 `已产` ｜ `本项目无料·未产` 之一），**本项目未产的件也留行**；无孤儿件（有件而索引无行）、无悬空行（有行而件不存在或链接失效）。
> 内容层面的具体对错（哪些口径越线）交由运行时项目材料 + 可选下游契约承载；本判据本身可据以判定某份产物合格与否。

## 常见错误（Common Mistakes）

- **清单没传就自己定该产哪几件** —— 问人"这次要产哪些件"、或照查缺蓝图 / 下游契约列一份名单、或自拟几个主题名先蒸起来。违照清单产：**清单未传即停报缺**，蓝图 / 下游契约只在第 4 步核块。同一批材料两个人跑出不同的件数与件名，根子就在这里。
- **把蓝图当上游驱动照单收料** —— 先照 checklist 算出应有字段、再去找料 / 先搭空框。违 material-first。蓝图只在蒸馏之后当事后核对表。
- **对不上料硬编泛化填空** —— "这块没料，凭品类常识补一句吧"。违不发明。没源就标"材料不足待补"。
- **溯源指向脚手架而非一手** —— 来源标注指向 extract / 台账等中间件。违每条溯源。来源须指真实一手材料段落。
- **把前人加工件当一手 / 当"已满足"** —— 别的目的裁剪组织过的加工件，直接采信为承重。违回一手。加工件只作参考待核，要用回它对应的一手原件重做。
- **产物留内部裸码 / 流程标签** —— 正文留"品-1"类裸码、"承重"类流程标签、指向脚手架的来源。违产物自解释。内部代号 / 映射一律隔离进文末溯源附表。
- **建云盘 / 写飞书不先请示** —— 直接建文件夹、直接写飞书表。违对外动作先放行。命中升级条件，先摆出要执行、等放行。
- **产出者自宣完成** —— 蒸完自己说"合格"。违产出者不自宣。须独立评审逐条判 PASS。
- **初蒸时去项目档案找本 skill 的条目** —— 初蒸时项目档案尚无本 skill 条目，`folder_token` 由调用方直传；去解析等于对不存在的登记硬跑。
- **把"本阶段不该有"的缺项当缺口去催料** —— 查缺先按 `{阶段 × 项目类型}` 过滤；策略期不催执行数据。
- **对话里贴来的材料直接蒸** —— 本地料 = 转存过渡态：先上传项目云盘 `raw/`（存成文件、过转可读一道），再按云盘件处理；材料不滞留对话 / 本地。

## Red Flags

看到自己出现以下念头或动作，停下重判：
- 「调用方没给清单，我先问问这次该产哪几件吧」/「照蓝图列一份名单也一样吧」/「这两件内容挺像，合成一件吧」→ 成员不许现场认定、不许合件，停下报 `缺认知件清单`。
- 「这份料落进哪一件说不清，那就新起一件吧」→ 清单外不新增件；记进最沾边那一件并标「归属待核」。
- 「先照 checklist 把该有的框搭全，再去找料填」→ 上游驱动，违 material-first，收回。
- 「这块没料，凭品类常识补一句吧」→ 发明，标"材料不足待补"，别硬编。
- 「这份前人加工过的，直接当一手用吧」→ 违回一手，回它的一手原件重做。
- 「来源就写指向那份 extract 吧」→ 溯源指脚手架，改指真实一手材料。
- 「直接建云盘文件夹 / 改飞书吧」→ 对外不可逆动作，先请示放行。
- 「我蒸完了，应该没问题，交付吧」→ 没独立评审，别自宣，先派独立评审逐条判。
- 「用户贴在对话里的料，顺手直接蒸吧」→ 先上云盘 `raw/`（存成文件、过转可读一道）再处理，不滞留对话。
- 「这个缺口先催了再说」→ 先核阶段：本阶段不该有的缺项不算缺口、不去催。
