# context-distill —— 落点与读取契约

本 reference 钉四样东西：**落点结构**（产物与原料摊在哪、产哪几件由什么定）、**飞书读取契约**（哪类资源用哪个工具读、材料怎么存、怎么处理到 AI 读得了）、**查缺 checklist 用法**（蓝图 / 下游契约怎么用而不越位）、**input / output schema 字段级判据**。

正例一律用占位符（`[项目名]` `[材料X]` `[来源簇A]` 等）——只示"形"，不写死任何真实客户 / 品牌 / 项目实例。

---

## 1. 落点结构（两主面：顶层认知件套 + raw/）

一个项目一个云盘。落点两个主面——顶层引用面（认知件套 + 索引）与 `raw/` 回查面，不另造第三面：

```
[项目云盘]
├── tingle-项目档案               ← 他方建维；本 skill **不建不写、只读**（查缺读「阶段」、重蒸取标签）
├── tingle-项目索引               ← 他方建维（`project-readiness` 道10）；本 skill **不建不写**。
│                                   项目总索引：记这个项目有哪几类东西、每类从哪儿进（认知件 /
│                                   原料 / 内务件三行起）。本 skill 产的两份索引各被它指一行——
│                                   `tingle-认知件索引` 归「认知件」行、`raw/索引.md` 归「原料」行
├── <认知件A>/                    ← 每件独立成飞书文档、各落各自的文件夹；件内：
│                                   按主题分块 + 每条挂具名一手源 + 必要处口径承接 / 限定块 +
│                                   缺口显式标"材料不足待补" + 内部代号隔离进文末溯源附表
├── <认知件B>/ …                  ← 套成员 = 入参「认知件清单」逐条列明的那几件：照清单产，
│                                   不增件 / 不减件 / 不合件 / 不自拟件名；下游投影产不产同样
│                                   只由清单定（清单未列即不产）
├── tingle-认知件索引             ← 一份、固定标题、落顶层，串起整套：清单每件各占一行
│                                   （件名 + 链接 + 一句用途 + 状态 + 缺口），状态受控两值
│                                   「已产」｜「本项目无料·未产」，本项目未产的件也留行；
│                                   下游从索引进入整套、按件引用
├── _tingle/                      ← 他方建维（`project-readiness` 迁移档案时存旧版档案）；本 skill
│                                   **不建不写**。顶层的内务目录，与 `raw/_可读件/`、`raw/_台账/`
│                                   同归总索引「内务件」那一行覆盖——三个目录，一行管全
└── raw/                          ← 原始材料收这里：**一律以文件形态存放，不导入成飞书原生格式**；
                                    仅供溯源回查，非日常引用面
    ├── <按来源簇归类的一手原件>    ← 如 [产品/事实源] [合规/红线源] [人群/场景源] [立项/执行源]…（按项目实际材料分）
    ├── <标明"加工件"的前人加工件>  ← 与一手分层存放，只作交叉印证（见 distill-craft 纪律 5）
    ├── 索引.md                    ← `raw/` 下每件材料各一行（行 schema 八段，见第 4 节）；
    │                               在线原生件不搬原件、只在此登记
    ├── _可读件/                   ← 转可读的转出件（markdown）：路径镜像原件、转写件（工具转或
    │                               AI 誊写）——非一手、非引用面；下划线前缀标明「非引用面」（见第 2 节「本地料转可读」）
    └── _台账/                     ← 蒸馏工序脚手架（extract 束 + 忠实台账）**＋ 独立评审判定记录
                                     `评审判定-<YYYYMMDD>.md`**：我方加工件、非一手、非引用面；
                                     下划线前缀标明「非引用面」，下游一眼跳过
```

### 三件机制（逐一定死）

**(a) 收料去重（三层，取料归集时做）**
1. 同一在线件被多处指到 → `raw/索引.md` 只登记一条；
2. 字节相同的重复文件 → 留一份、备注来处；
3. 同源同事实的多份材料 → **不删**，蒸馏时"合并列源"（多源互证的并列成条）。
**去重只针对冗余副本，绝不因"看着重复"丢掉可能互证的独立源。**

**(b) 在线原生件不搬原件**
妙记、在线文档、多维表格等在线原生件**不下载、不搬副本**进 `raw/`——在 `raw/索引.md` 登记一行（八段：标题 / 类型 / 链接·token / 一句摘要 / 读它用哪个 lark skill / 一手 or 加工件 / 处理记录——如实写「在线件，现读不搬副本」/ 读取位置——写明按第③段链接现读），并在 `raw/` 下加一个飞书快捷方式指过去（平台支持时；快捷方式是增强，**索引登记是主机制**）。蒸馏时按索引用对应 lark skill 现读内容，读完不留副本。
**为什么**：在线件是活的、会被团队改；搬副本会与真相源分叉。

**(c) 认知件成套摊顶层**
认知件**逐件摊在云盘顶层**（每件各自的文件夹），由一份**索引**串起整套——**各认知件不合并为单一文档**。下游打开云盘顶层，从索引进入整套、按件引用。

**套成员 = 入参「认知件清单」逐条列明的那几件。** 照清单产：不增件、不减件、不合件、不自拟件名，清单外不设"其余材料"一类兜底件；下游投影产不产同样只由清单定，清单未列即不产。**清单未传 = 本次不运行**（停并报缺）——不问人该产哪几件、不从查缺蓝图或下游契约认定。**每一件仍要过料**：清单逐件问"`raw/` 里有没有一处内容能落进它"，有则产、全无则不产（索引留一行「本项目无料·未产」）、判不准则产。

**索引**：固定标题 `tingle-认知件索引`、落项目云盘**顶层**（靠固定标题定位，不靠人记链接，与项目档案同法）；清单**每件各占一行**，一行五段 = **件名 + 链接 + 一句用途 + 状态 + 缺口**；**状态受控两值** = `已产` ｜ `本项目无料·未产`；**本项目未产的件也留行、不从索引消失**——否则下游分不清"这个项目没有这块"与"忘了产"，而这两件事的处置完全不同（前者不算缺、不催；后者是漏）。

### 脚手架落点（定死：`raw/_台账/`）

`raw/_台账/` 住三样：**extract 束**、**忠实台账**、**独立评审判定记录 `评审判定-<YYYYMMDD>.md`**。三样同性质——既非一手原始材料、也非下游引用面，但**都须持久化**：独立评审要拿台账核溯源、重蒸要增量重用台账，而判定记录是**上游验收要查的那份文件**（编排方按「`raw/_台账/评审判定-<YYYYMMDD>.md` 在不在」验收蒸馏这一道，查不到即不通过）。落 `raw/_台账/`：在 raw/ 之内（不另造顶层第三面）、下划线前缀标明"非引用面工序件"。

### 无孤儿文件不变量（tingle 落进云盘的每个文件都被某份索引覆盖）

**不变量：tingle 落进这个项目云盘的每一个文件，都要被某一份索引覆盖到——最近的那份祖先索引即可。** 一份文件谁都不管，就等于没人知道它是什么、还算不算数、该不该读。

**范围＝本体系写进去的东西，判法是"谁按契约写的"**：一个文件在不在本不变量范围内，看的是**它是否由某一道次或某个 skill 按契约落进这个云盘**——**不看它像不像产物，也不凭执行者临场感觉**。**范围外的典型**：落点复用既有文件夹时，使用者明示「照原样留着」的那批既有内容——**它不是 tingle 的产物，tingle 不为它的可发现性负责**：不必覆盖，**也不去归置**（人明确说过别动的东西，动了就是往没人批准的地方伸手）。**复用场景下哪些属既有内容，不靠回忆认**：以 `project-readiness` 道4 第 2 步①（摆待建内容清单时，复用的落点须注明它原本装着什么）记下并经使用者放行的那份记载为准；那份清单本身见该处，此处不复述。

**"范围外"不是免责口，两头一起堵**：

- ① 那批既有内容**既不必被任何索引覆盖，也不得就地登记进任何索引**——就地登进去就是拿别人的东西冒充本体系产物，索引从此说不清哪些是自己产的（要用它见 ②：先按材料归进 `raw/`，再按材料登记）；
- ② **要引用它，先把它按材料归进 `raw/`**（作为一件来料收进来、由 `raw/索引.md` 覆盖），**不得就地引用一个未登记的文件**——就地引用等于给产物挂一个没人管、随时会变的出处；
- ③ **"这个文件不是我产的"只对使用者既有内容成立**：凡经本体系任一道次或任一 skill 落进云盘的，**一律在范围内**，不得因为"是别的 skill 写的""是他方建维的"就不管——`tingle-项目档案`、`tingle-项目索引`、`_tingle/` 都是他方所产，照样各有归属（前两件走下面的例外，`_tingle/` 走「内务件」那一行）。

**范围之内，例外恰有两件，是穷举**——**穷举的对象是"本体系产物里的例外"，不是云盘里的一切**（云盘里还可能有使用者原有的东西，那属上面的范围外，本不变量根本不管）：云盘顶层的 **`tingle-项目档案`** 与 **`tingle-项目索引`** 自身。这两件是索引体系的根与配置面，**不靠索引找、靠固定寻址找**——档案靠每名成员本地指针（`.tingle/state.json`）里存的链接直接打开，找不着时回退到"云盘顶层 ＋ 固定标题「tingle-项目档案」"搜；总索引同样靠"云盘顶层 ＋ 固定标题「tingle-项目索引」"。**所以它们不是孤儿**：每一件都有一条不依赖任何索引、且写死在契约里的寻址路径。**并且档案明令不进总索引**（同一个地址两处记，改一处另一处就悄悄过期）。**除这两件外无例外**——不得援引它们给别的东西免责：其余一切照上面的不变量判。

三条推论，照此判：

1. **一个文件夹只有在其内容未被祖先索引覆盖时，才需要自己的索引。** `raw/` 下的材料由 `raw/索引.md` 逐件覆盖，所以 `raw/` 自带一份索引；`raw/_可读件/`、`raw/_台账/`（以及顶层的 `_tingle/`——他方所产，同归这一行）不自带索引——**三个目录**都由顶层 `tingle-项目索引`「内务件」那一行**一行覆盖整个目录**，覆盖已成立，不必再建。**不要为了"看起来齐整"给每个目录都补一份索引**，多一份就多一个要维护的地方。
2. **下划线前缀的内务件一行覆盖整目录，不逐件登记。** 它们本就是非引用面的工序件，逐件登记既无人读也无人维护。（0.3.0 实跑查出 `raw/_台账/` 无任何索引覆盖的洞，就是这一行补上的。）
3. **索引记语义与状态，不记纯文件名清单。** 一列文件名不回答任何问题——每一行要说清"这是什么、现在什么状态"：`raw/索引.md` 记八段（含处理记录与读取位置）、`tingle-认知件索引` 记五段（含状态与缺口）、`tingle-项目索引` 记五段（类别 / 入口链接 / 一句这是什么 / 谁产的 / 最近更新——**末段指那一行本身的变动日，不是那一类内容的变动日**）。`ls` 一下就能得到的东西，不值得单独存一份。

**分层：总索引管有哪几类，每一类自己管有哪几条。** 顶层的 `tingle-项目索引` 只列类别与入口（他方建维，本 skill 不建不写），本 skill 产的两份索引各被它指一行——`tingle-认知件索引` 归「认知件」行、`raw/索引.md` 归「原料」行；**这两份索引里有哪几条，仍由它们各自管，不上报总索引**。所以本 skill 新增 / 更新一件认知件、新收一件材料，改的都只是自己那份索引，不去动总索引。

**往云盘顶层新落一类东西之前，先问一句**：它归哪份索引管？答不上来 —— 要么把它归进 `raw/`（由 `raw/索引.md` 覆盖），要么它得成为总索引里的新一类并自带索引。**没有第三种落法**——上面穷举的那两件顶层寻址件是全部例外，**那份名单不再扩大**，不得拿它们当先例给新落的东西免责。

### 什么不落盘（明确排除，免得误存）

| 件 | 性质 | 为何不落盘 |
|---|---|---|
| 来料线索清单 | 第 1 步引导询问的一次性工作件 | 归集完成即弃，不入云盘明面 |
| 缺口清单 | 第 4 步查缺的一次性工作件 | 索取完成即弃 |
| **查缺蓝图 / 下游契约** | **可选的外部运行时注入输入**（别人维护的活库 / 契约） | **不是本项目的材料、不是落点文件——不存进 `raw/`、不复制进云盘**；只在第 4 步按链接现读，**只核块与字段，不认定该产哪几件** |
| **认知件清单** | **必传入参**（该产哪几件的唯一来源） | 是参数、不是本项目的材料——**不存进 `raw/`、不复制进云盘**；未传即停报缺，不问人、不从蓝图 / 下游契约认 |

**独立评审判定记录不在本表——它落盘。** 落 `raw/_台账/评审判定-<YYYYMMDD>.md`，与 extract 束、忠实台账同性质（见上方「脚手架落点」）。0.3.0 曾把它列进本表、写作"随复核包交人，不进 `raw/`"，**那条已废**：判定记录不持久化，上游按「这份文件在不在」验收蒸馏这一道就永远查不到东西，而口头回报顶不了这一条；不落盘的它也不被任何索引覆盖，直接撞上方的无孤儿文件不变量。

## 2. 飞书读取契约（读项目料，飞书优先）

### 四类资源 → 四个 lark skill（具名映射）

| 资源类型 | 识别特征 | 用哪个 skill | 动作 |
|---|---|---|---|
| 多维表格（Base / bitable） | `/base/` 链接、bitable token | `lark-base` | 只读表记录 / 字段 / 视图 |
| 电子表格（Sheets） | `/sheets/` 链接、sheet token | `lark-sheets` | 只读工作表数据 / 单元格 |
| 云文档（Docx / Wiki 文档） | `/docx/`、`/wiki/` 链接、doc token | `lark-doc` | 只读文档正文；文档内嵌表格 / 多维表格先用 lark-doc 提 token 再切 lark-sheets / lark-base |
| 妙记（会议录音 / 录屏纪要） | minute_token、本地音视频 | `lark-minutes` | 读妙记逐字稿 / 纪要产物（本地音视频转纪要也走它，不用 ffmpeg / whisper） |

### 补充（非上表四类，但落点 / 收料要用）

- **云盘文件与文件夹操作** → `lark-drive`：建项目云盘文件夹与 `raw/`、上传 / 下载本地原件、加飞书快捷方式指入 `raw/`。**不用它的"导入为飞书格式"能力**——见下条。**建云盘文件夹 / 写飞书 = 对外不可逆动作，运行时先请示、放行后再做**（SKILL.md 升级条件之一）。
- **写认知件 / 索引 doc** → `lark-doc`（写产物属对外动作，与本次运行的放行同次覆盖）。**认知件与索引是产物、仍是飞书文档**；下面"材料一律文件形态"只管材料与转出件，两者别改混。
- **本地料 = 转存过渡态**（本地各处的 md / docx / xlsx / pptx / pdf / 图片，含用户直接交给 AI / 贴进对话的材料）：**先上传项目云盘 `raw/`，一律以文件形态存放、不导入成飞书原生格式**（`lark-drive` 上传，随本次运行放行覆盖）；**再逐件过「转可读」一道**（见下节；并非每件都产转出件——表格、md 原生直读），然后才处理——材料不滞留对话、不滞留本地。
  **为什么不导入**：导入即变成可在线编辑的飞书件，同一份材料随即有两个版本，日后无从判定哪份算数；而 `raw/` 里的材料只用于回头查证出处，不是工作面。转存前的识读用原生 `Read`（PDF 走 `pdf2markdown` / `pdf`），转存后一律按云盘件处理。

### 本地料转可读（在 Step 2 之内、Step 3 蒸馏之前）

材料搬上云盘之后走这一道，做完的样子是：**材料都处理到 AI 读得了或原件在场、索引如实记录、无静默跳过**——PDF / pptx 这类 AI 直接读效果差、读不全的原件转出文字，表格这类原生读得了的不动，"哪件怎么处理了、去读哪"索引可查。它发生在本 skill 内部（编排方不参与、只验收结果）。

#### 整批三段顺序（定死，不可对调）

```
① 全批逐件过第 0 关（筛掉不是材料的东西）
   └─ 判出局的件到此为止：不上传、不转、不入索引，【也不进入去重池】
② 过了第 0 关的件才进去重池（本文 §1(a) 三层去重）
   └─ 第 2 层被舍弃的副本到此为止
③ 去重后留下的件逐件按下方「处理模型」判并执行
```

**第 0 关必须先于去重**：乱码名与正常名之间的字节序没有固定方向，若先去重，可能选中乱码那一份、把它的正常名副本舍弃，等第 0 关再跑到它时已找不到同 MD5 的正常名副本，于是把一件本该跳过的重复件"还名留了下来"，而正常名那一份反倒没了。**这是静默出错**——哪几组翻车取决于文件名细节，不看不知道。

#### 第 0 关 · 四条（按序判）

| # | 判据 | 处置 |
|---|---|---|
| 1 | 文件名以 `.~` 或 `~$` 开头 | Office 临时锁文件。**不上传、不转、不入索引** |
| 2 | 路径里含隐藏工具目录（`.git/`、其他工具的自用目录） | 不是客户材料。**不上传、不转、不入索引** |
| 3 | 文件名乱码（连续替换字符 / 八进制转义串） | **逐件判，不整棵判**——见下 |
| 4 | 扩展名本文没列到 / 格式认不出 | **不在这关出局——没列到的情形，照目的自己判**（进入后续处理，按下方「处理模型」问那一句）；判了什么、做了什么，索引里如实记。看了内容仍判不出这是什么东西 → 问来料人 |

**第 3 条不许整棵目录跳过**：乱码只说明名字坏了，不说明这件东西多余——乱码树里可能藏着全库唯一的一份材料，而它对应的正常名目录是空的。逐件三步：① 算 MD5，在全部材料里找有没有字节相同的另一份；② **有**同 MD5 的正常名副本 → 确属重复解压产物，跳过；③ **没有** → 这是唯一一份，**必须留**：先还名，再当普通材料处理。

> **还名方法**（乱码名在文件系统里常是**字面的八进制转义文本**，不是原始 GBK 字节）：从左到右扫一遍，在每个 `\` 处按两条还原成字节，整串再按 GBK 解码——① `\` 后紧跟又一个 `\`（字面 `\\`）→ **收成一个字节 `0x5C`**，吃掉这两个字符；② `\` 后跟三位八进制数字（`\NNN`）→ 还原成那一个字节，吃掉这四个字符。
> **第 ① 条不能省**：有些汉字的 GBK 第二字节本身就是 `0x5C`（反斜杠），解压器会把它一并转义；只做第 ② 条会解出比正确名字多一个反斜杠的名字——**而它是一串可读中文，"解不出中文就停"的兜底拦不住它**，错名字会一路传进 `raw/` 文件名、索引标题、转出件路径，事后毫无信号。
> **还名失败**（解不出可读中文，或解出来仍是乱码）→ **停下向来料人要原压缩包**：不猜名、不硬转，**更不许因为名字读不出来就跳过**。
> **还名之后一律用还原名**（口径收口）：以还原名入 `raw/`、索引标题用还原名、转出件用 `<还原名>.md`；本节说的"原文件名"，对这类件就指还原名。乱码的父目录名不用管（`raw/` 按来源簇重组，父目录不跟进来）。

#### 去重第 2 层：留哪一份（必须定死）

第 2 层（字节相同的重复文件"留一份"）**必须有留哪份的规则**，否则这一道不可复现——转出件路径镜像原件路径，两个执行者留下不同副本就会产出不同的 `_可读件/` 路径。

> **留同一 MD5 的多份里、文件名按字节序（`LC_ALL=C` 排序）最靠前的那一份**；文件名也完全相同时，再比这几份此刻在来料目录下的相对路径、同样取最靠前的。其余不搬进 `raw/`。**被舍弃副本的路径与文件名写进留下那一份的索引摘要**（`另有同字节副本：<路径>`）——被舍弃的那个名字往往才是带信息的那个（带品牌、投放形式、版本号），不能连名字一起丢掉。

**排序键为什么是文件名、不能是 `raw/` 下的相对路径**：这一层的判定发生在搬进 `raw/` **之前**，那一刻 `raw/` 下的路径还不存在，拿尚未产生的东西当判据等于没定。文件名还是材料自身的属性，不受"这批料当初怎么打包"影响（`_extracted/`、`_work/` 这类目录层是打包与解压的偶然产物）。**第 3 层（同源同事实的多份）规则不变：不删，两件都留、各转各的、索引各一行。**

#### 每一件材料的八步（任一关判定成立即停在该关，不再往下走）

1. **第 0 关**（四条）——不是材料的在这里出局，**且不进入下一步的去重池**。
2. **去重关**（只作用于过了第 0 关的件）：命中第 2 层而又不是选中留下的那一份 → 到此为止，不搬进 `raw/`。
3. **问模型那一句**：AI 现在能直接读它吗？——按下方「处理模型」定动作（不动 / 转出文字 / 解压 / 不管）。
4. **不产转出件的**：不动的（表格、md 等原生读得了的件）、不管的（非内容件）、壳（解压后内容物逐件回到第 1 步）——写索引行（八段齐，⑦⑧ 如实记），**这一件结束**。
5. **要转的**：转出文字成 markdown——工具挑趁手的（PDF 走 `pdf2markdown` / `pdf`，docx / pptx 走对应 skill，图片与扫描页由 AI 看着原件把内容誊写出来），加下方固定头部；试了转不出来的 → 如实记、原件留着（见下方「工具转不动」）。
6. **落位**：写到 `raw/_可读件/<镜像路径>/<原名含扩展名>.md`，上传云盘。
7. **写索引行**：八段齐，⑦ 如实写做了什么、⑧ 填刚写的转出件完整路径。
8. **抽检**：打开转出件看头尾——明显丢内容则在缺失处补 `> [转出缺失] …`；**整份基本为空**（转出正文不足 50 字符而原件明显有内容）→ **换 AI 对着原件把内容誊写进转出件**（工具跑通了不等于内容提出来了），誊也誊不出的才删掉空转出件、原件留着、索引⑦⑧改为如实记（如「誊不出，留原件」/「原件在 `raw/` 原位」）。

#### 转出件落哪（在现有 `raw/` 结构之上只加一个平级目录 `_可读件/`）

1. **目录名 `_可读件/`**，下划线前缀——与 `_台账/` 同一约定：非引用面的工序中间件，下游读认知件时一眼跳过。
2. **路径镜像**：转出件在 `_可读件/` 下的相对路径，与原件在 `raw/` 下的相对路径**逐段相同**。
3. **文件名 = 原文件名（含原扩展名）+ `.md`**，**不是换扩展名**（`X.pdf` → `X.pdf.md`，不是 `X.md`）。两个理由：一眼看出源头格式；同名不同格式的两件（`X.pdf` 与 `X.docx`）不会撞名互相覆盖。

**转出件同样以 `.md` 文件上传云盘、不导入为飞书文档**——它与 `raw/索引.md`、`raw/_台账/` 同性质：机器转写的工序中间件、非引用面。**大文件不切分**：一件原件恰好一个 `.md`，不论多大（切分会让"一件原件 ↔ 一个转出件 ↔ 索引一行"的对应关系断掉）。

**转出件正文固定头部**（一行，转出件之间零差异）：

```markdown
<!-- 源件：raw/<原件相对路径> ｜ 原格式：<扩展名> ｜ 转出工具：<工具名，或「AI 誊写」> ｜ 转出日期：YYYY-MM-DD -->
```

**转不全时不静默**：转出件明显丢内容（整页只有图、某页是纯图表、扫描页读不清一角），在转出件里该位置写 `> [转出缺失] <一句说明缺的是什么>`，**不留空、不假装完整**——蒸馏读到这一行就知道该回原件看。

#### 处理模型（正文即全部——没列到的照它判，不查表）

> **目的：把项目材料整理成 AI 干活时读得了的形态。**
>
> 遇到每个文件问一句：**AI 现在能直接读它吗？**
> - 能（表格、md、飞书在线文档）→ 不动；
> - 不能、内容提得出来（PDF、Word、PPT、图片）→ 转出文字——**能转就转，扫描件也一样**（AI 看着扫描页把内容誊出来）；
> - 试了转不出来的 → 如实记、原件留着；
> - 壳（zip 等）→ 解压，内容物回到第一问；
> - 不是内容的（logo、系统文件）→ 不管。
>
> **没列到的情形，照目的自己判；索引里如实记你做了什么。**

**定死的只有两条：**

1. **表格不转**——表格的原生表现形式就是表格，AI 用表格工具直接读（xlsx 用 `xlsx` skill、csv 用原生 `Read`，在线表格按读取契约现读）。原件照常留 `raw/`，索引⑦如实记（如「表格，原生直读不转」）、⑧填原件在 `raw/` 的相对路径。
2. **在线文档不搬副本**——现读，防真相源分叉（§1(b) 逐字保持）。

**转出件长什么样（对要转的件）**：markdown、内容忠实于原件——文档保留标题层级与表格；PPT 每页一节（`## 第 N 页 · <页标题>`）、演讲者备注全带上；图与图表内容誊得出的誊成文字，实在提不出的原位留 `[图片]` 占位并按"转不全时不静默"标注。用什么转由执行 AI 挑趁手的（PDF 走 `pdf2markdown` / `pdf`，docx / pptx 走对应 skill，扫描页与图片由 AI 看着原件誊写），转出来对就行。

#### 几类情形的工艺细则（真实材料教出来的坑；动作仍按上方处理模型判）

**扫描 / 盖章 PDF（整份零文本）**。判法：`pdftotext <file> - | tr -d '[:space:]' | wc -c` 结果为 `0`——这只说明工具提不出文字层，**不改变动作：能转就转**。由 AI 逐页看扫描页把内容誊写成转出件（落位、头部、抽检同一般转出件；读不清的处标 `> [转出缺失]`）。页面糊到读不出、整份誊不出来的 → 如实记、原件留着：索引⑦写「扫描件，誊不出，留原件」，**摘要必须写明它是哪类件**（合同 / 报价 / 资质 / 结算），让蒸馏不打开也知道里面大概是什么；此时可再向来料人索取该件的可编辑版（docx / xlsx）——在认知件里标 `材料不足待补——去处：向来料人索取可编辑版`，由 Step 5 索取后回 Step 2 重走本道。

**图片**。**内容型**（图里有"读了会改变结论"的信息：排期、数据、流程、口径）：AI 直接看图（原生 `Read` 能看图）把内容誊写成转出件——表誊成表、数誊成数；看不清的处标 `> [转出缺失]`，整张誊不出的如实记、原图留 `raw/`。**非内容型**（标识 / 装饰）：不是内容 → 不管——原图照常留 `raw/`、不产转出件，索引⑦如实记（如「非内容件（标识），不管」），蒸馏跳过。**判不准就按内容型处理**——多誊一张图的代价远小于漏掉一张排期表。

**壳（zip / rar 等）**。容器本身**不上传、不转**，索引⑦如实记「壳，已解压」、摘要写 `已解压，内容见 <目录名>/`；真正的材料是解压出来的那些文件，**逐件回到整批流程开头**（第 0 关 → 去重 → 处理模型）。**没有同名解压目录的**：先用 `unar` 解到同级同名目录再逐件处理（能被 `unar` 解开的少见归档格式同此）。**解压失败**（加密、报错）→ **停下问来料人要解压后的目录或另一个版本，不猜内容、不跳过**。

**系统替身 / 快捷方式**（指针文件，指向的原件不在材料包里）。**不上传、不转**（上传一个 1KB 的指针毫无意义）；索引⑦如实记「指针文件，原件不在材料包里」，摘要写出它本该指向的文件名；**并列入缺口清单**，由 Step 5 向来料人要原件——不在这一道自己解决，也不去本机四处找。

**工具转不动**（报错 / 超时 / 内存不够）。**单件墙钟上限 10 分钟**：一件从开始转起算，10 分钟仍未返回即判工具失败，中止，**同一工具不试第二次**。（选墙钟而不设体积阈值：体积阈值要预先猜"多大算转不动"，那取决于当时的机器与工具版本，猜死了会把本来转得动的件挡在外面；墙钟不猜能力、机器无关，只是耐心预算。这个数要改属换版，不在运行时临场改。）
工具失败后**先换 AI 直接看原件誊写**（能读多少誊多少，缺处标 `> [转出缺失]`）；连原件都读不了、誊也誊不出的 → 如实记：原件留 `raw/` 原位、不产转出件，索引⑦写「转不出（<原因>），留原件」；**摘要必须写清两件事——失败原因（报错 / 超时 / 损坏）＋这件东西的规模**（几页 / 多大），让蒸馏知道自己漏掉的是多大一块，而不是以为它无关紧要。规模这样拿（都不解析文件内容，几百 MB 也秒回）：

| 形态 | 命令 | 读出什么 |
|---|---|---|
| pptx | `unzip -l '<file>' \| grep -cE 'ppt/slides/slide[0-9]+\.xml$'` | 页数 |
| PDF | `pdfinfo '<file>'` | `Pages:` = 页数，`File size:` = 体积 |
| docx | 无同样便宜的页数口径（页数由渲染决定） | 写字节体积即可，不必强报页数 |

**这些命令本身也失败**（文件损坏、加密）→ 摘要写 `规模未知（<用过的命令> 亦失败）`，**不留空、不猜**。**并列入缺口清单**，与誊不出的扫描件同路：由 Step 5 向来料人要一个能用的版本。

> **"转不出"与"转不全"不同**：转不全是内容有缺、转出件照产，缺处标 `> [转出缺失]`；转不出是连誊都誊不出、压根没有转出件——索引如实记、原件在场，绝不静默跳过。

### 读取契约硬约束

- 全程只**读**项目料，不改源材料；
- 路由依据是**资源类型 / 链接路径模式**（`/base/` `/sheets/` `/docx/` `/wiki/` `minute_token`），**不是域名**；
- 读不到（无权限 / 链接失效）→ 停并报缺，不猜路径、不跳过硬蒸。

## 3. 查缺 checklist 用法（蓝图只事后核，绝不上游驱动）

### 两张 checklist，都是运行时注入的外部输入

| checklist | 是什么 | 核什么 |
|---|---|---|
| **查缺蓝图** | 组织维护的"该有哪类物料 / 块"的通用清单库（常见形态：多维表格，用 `lark-base` 只读） | 按其维度（如环节 × 角色 × 类型）过滤出与本产物下游相关的物料**类别**，逐类核对"我的产物里有没有对应的块"，缺的记入缺口清单 |
| **下游契约** | 已知下游 skill 声明的 input 字段表（其 reference / 契约文档） | 核"我的产物是否覆盖已知消费者要的字段" |

**两张都是外部运行时注入的输入**：链接 / token 作为调用入参传进来（见第 4 节 input schema），**不硬编进本 skill 正文，也不存进 `raw/`**——它们不是本项目的材料，是别人维护的活库，按链接现读。没有蓝图 / 契约的场景，跳过对应核对、仅靠纪律"缺则标待补"兜底，skill 照常可用。

**两张都只核块与字段，都不认定该产哪几件。** 产哪几件由入参「认知件清单」定死（第 1 节），**查缺不据蓝图或下游契约增件、减件、改件名，也不据此判定某件"下游用不上所以不产"**——照下游契约倒推该产什么，是已被推翻的做法：那等于让一个消费者决定所有人看到的形态。蓝图里若出现清单没有的物料类别，记进缺口清单交还调用方（由调用方决定要不要改清单），**不在运行时自行加件**。

### 用法四规（越一条即错）

1. **时机 = 第 4 步、蒸馏之后**：查缺在蒸馏产物已从真实材料蒸出**之后**跑，不在之前。
2. **用途 = 事后核"该有哪类块"**：蓝图是 type-level 通用清单，**只回答"这类产物一般该有哪些种类的块"**。
3. **绝不拿它取项目内容**：蓝图**不回答"某项目某块内容是什么"**——项目内容只能从该项目真实 `raw/` 蒸，不能从蓝图取、不能按蓝图编。
4. **绝不上游驱动**：**排除**任何"先照蓝图算出应有字段 / 物料 → 据此列应收料清单 → 照单去收料 / 先搭空产物骨架再填"的步骤。

### 阶段感知过滤（查缺的第一道筛）

checklist 逐类核对之前，先按 `{阶段 × 项目类型}` 过滤——**本阶段不该有的缺项不算缺口、不去催**（如策略期缺执行数据属"本阶段不该有"，不进缺口清单、不去向人要）。

- **阶段值**：读项目档案（「tingle-项目档案」，他方建维、本 skill 不建不写只读）的「阶段」字段；受控初始集 = `策略期 / 执行中 / 新周期`（可扩）。
- **标签结构**：品类为三级 `{业务线 / 合规类目 / 产品品类}`（**合规类目是规则加载的承重键**；业务线为"美妆 / 大健康"一类的通用划分）+ 品牌——**非单字符串**。
- **初蒸时**标签 / 阶段尚未落定 → 询问用户或从材料认，**不发明**。
- **边界**：阶段值只用于材料域查缺的过滤，**不做"哪个阶段跑哪些 skill"的平台路由**（环节编排归调用方）。

### material-first 护栏（数据流单向）

```
真实材料 ──归集──▶ raw/ ──蒸馏──▶ 认知件套 + 索引 ──(事后)──▶ 拿蓝图/契约核缺 ──▶ 缺口清单 ──▶ 向人索取
                                                        │
                                            无反向：蓝图不驱动收料、不生成内容、不预搭骨架
```

产物结构从真实材料长出；蓝图只在产物已存在之后做交叉核对。任何时刻发现自己在"照 checklist 搭框 / 收料"，即命中 SKILL.md Red Flag，停下收回。

## 4. input / output schema 字段级判据

**「产物 schema 不固定」只有一个意思**：本 skill 正文不写死件名，件名由入参「认知件清单」给——换个组织传另一份清单就是另一套件。它**不再**意味着"运行时可以现场决定产哪几件"：**任一次运行的产出成员由该次传入的清单完全定死，运行中不得增减。** 以下钉的是**结构契约**（每件长什么样、索引长什么样）：每字段的类型 / 判据 / 格式 / 占位符正例。
