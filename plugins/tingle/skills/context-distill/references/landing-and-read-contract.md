# context-distill —— 落点与读取契约

本 reference 钉四样东西：**落点结构**（产物与原料摊在哪）、**飞书读取契约**（哪类资源用哪个工具读）、**查缺 checklist 用法**（蓝图 / 下游契约怎么用而不越位）、**input / output schema 字段级判据**。

正例一律用占位符（`[项目名]` `[材料X]` `[来源簇A]` 等）——只示"形"，不写死任何真实客户 / 品牌 / 项目实例。

---

## 1. 落点结构（两主面：顶层认知件套 + raw/）

一个项目一个云盘。落点两个主面——顶层引用面（认知件套 + 索引）与 `raw/` 回查面，不另造第三面：

```
[项目云盘]
├── tingle-项目档案               ← 他方建维；本 skill **不建不写、只读**（查缺读「阶段」、重蒸取标签）
├── <认知件A>/                    ← 每件独立成飞书文档、各落各自的文件夹；件内：
│                                   按主题分块 + 每条挂具名一手源 + 必要处口径承接 / 限定块 +
│                                   缺口显式标"材料不足待补" + 内部代号隔离进文末溯源附表
├── <认知件B>/ …                  ← 套成员由运行时注入的清单（成员名单 / 蓝图 / 下游需求）定义，
│                                   本 skill 不硬编成员；下游投影同为独立文档、同为套内成员
├── <索引>                        ← 一份、串起整套：每件一条（件名 + 链接 + 状态 / 缺口）；
│                                   下游从索引进入整套、按件引用
└── raw/                          ← 原始材料收这里（内部结构不变）：仅供溯源回查，非日常引用面
    ├── <按来源簇归类的一手原件>    ← 如 [产品/事实源] [合规/红线源] [人群/场景源] [立项/执行源]…（按项目实际材料分）
    ├── <标明"加工件"的前人加工件>  ← 与一手分层存放，只作交叉印证（见 distill-craft 纪律 5）
    ├── 索引.md                    ← 在线原生件不搬原件，在此登记（行 schema 见第 4 节）
    └── _台账/                     ← 蒸馏工序脚手架（extract 束 + 忠实台账）：我方加工件、非一手、
                                     非引用面；下划线前缀标明「非引用面」，下游一眼跳过
```

### 三件机制（逐一定死）

**(a) 收料去重（三层，取料归集时做）**
1. 同一在线件被多处指到 → `raw/索引.md` 只登记一条；
2. 字节相同的重复文件 → 留一份、备注来处；
3. 同源同事实的多份材料 → **不删**，蒸馏时"合并列源"（多源互证的并列成条）。
**去重只针对冗余副本，绝不因"看着重复"丢掉可能互证的独立源。**

**(b) 在线原生件不搬原件**
妙记、在线文档、多维表格等在线原生件**不下载、不搬副本**进 `raw/`——在 `raw/索引.md` 登记一行（标题 + 类型 + 链接 / token + 一句摘要 + 读它用哪个 lark skill + 一手 or 加工件），并在 `raw/` 下加一个飞书快捷方式指过去（平台支持时；快捷方式是增强，**索引登记是主机制**）。蒸馏时按索引用对应 lark skill 现读内容，读完不留副本。
**为什么**：在线件是活的、会被团队改；搬副本会与真相源分叉。

**(c) 认知件成套摊顶层**
认知件**逐件摊在云盘顶层**（每件各自的文件夹），由一份**索引**串起整套——**各认知件不合并为单一文档**。套成员由运行时注入的清单（成员名单 / 蓝图 / 下游需求）定义，本 skill 不硬编成员；下游投影同为独立文档、同为套内成员。下游打开云盘顶层，从索引进入整套、按件引用。

### 脚手架落点（定死：`raw/_台账/`）

extract 束与忠实台账是蒸馏工序中间件——既非一手原始材料、也非下游引用面，但**须持久化**：独立评审要拿台账核溯源、重蒸要增量重用台账。落 `raw/_台账/`：在 raw/ 之内（不另造顶层第三面）、下划线前缀标明"非引用面工序件"。

### 什么不落盘（明确排除，免得误存）

| 件 | 性质 | 为何不落盘 |
|---|---|---|
| 来料线索清单 | 第 1 步引导询问的一次性工作件 | 归集完成即弃，不入云盘明面 |
| 缺口清单 | 第 4 步查缺的一次性工作件 | 索取完成即弃 |
| **查缺蓝图 / 下游契约 / 成员名单** | **外部运行时注入的输入**（别人维护的库 / 契约 / 清单） | **不是本项目的材料、不是落点文件——不存进 `raw/`、不复制进云盘**；蓝图 / 契约只在第 4 步按链接现读 |
| **独立评审判定记录** | 复核包的**过程件**（交人复核的闸门材料） | 随复核包交人，不是产物、不入 `raw/` |

### 落点件与循环读写对照（每个持久件都有写者与读者）

| 落点件 | 谁写它（循环步） | 谁读它 |
|---|---|---|
| `tingle-项目档案`（顶层） | **他方建维（本 skill 不建不写）** | 步 4 查缺（读「阶段」）、重蒸（读标签 / 阶段） |
| `<各认知件>` + `<索引>`（顶层） | 步 3 蒸馏（首建）、步 6 重蒸（就地更新 + 索引同步） | 步 4 查缺；下游程序（出本 skill 范围） |
| `raw/<原件>` | 步 2 取料归集、步 5 索取（补料回归） | 步 3 蒸馏（抽取 / 溯源）、独立评审 |
| `raw/索引.md` | 步 2 取料归集、步 5 索取 | 步 3 蒸馏（按索引现读在线件）、溯源回核 |
| `raw/_台账/` | 步 3 蒸馏内部（工艺 1 写 extract、工艺 2 写台账） | 步 3 工艺 3 逐格蒸馏、工艺 4 独立评审、步 6 重蒸增量重用 |

## 2. 飞书读取契约（读项目料，飞书优先）

### 四类资源 → 四个 lark skill（具名映射）

| 资源类型 | 识别特征 | 用哪个 skill | 动作 |
|---|---|---|---|
| 多维表格（Base / bitable） | `/base/` 链接、bitable token | `lark-base` | 只读表记录 / 字段 / 视图 |
| 电子表格（Sheets） | `/sheets/` 链接、sheet token | `lark-sheets` | 只读工作表数据 / 单元格 |
| 云文档（Docx / Wiki 文档） | `/docx/`、`/wiki/` 链接、doc token | `lark-doc` | 只读文档正文；文档内嵌表格 / 多维表格先用 lark-doc 提 token 再切 lark-sheets / lark-base |
| 妙记（会议录音 / 录屏纪要） | minute_token、本地音视频 | `lark-minutes` | 读妙记逐字稿 / 纪要产物（本地音视频转纪要也走它，不用 ffmpeg / whisper） |

### 补充（非上表四类，但落点 / 收料要用）

- **云盘文件与文件夹操作** → `lark-drive`：建项目云盘文件夹与 `raw/`、上传 / 下载本地原件、加飞书快捷方式指入 `raw/`、导入本地 Word / Excel / PDF 为飞书格式。**建云盘文件夹 / 写飞书 = 对外不可逆动作，运行时先请示、放行后再做**（SKILL.md 升级条件之一）。
- **写认知件 / 索引 doc** → `lark-doc`（写产物属对外动作，与本次运行的放行同次覆盖）。
- **本地料 = 转存过渡态**（本地各处的 md / docx / xlsx / pdf，含用户直接交给 AI / 贴进对话的材料）：**先上传项目云盘 `raw/` 并转成相应格式（`lark-drive` 导入，随本次运行放行覆盖），然后才处理**——材料不滞留对话、不滞留本地。转存前的识读用原生 `Read`（PDF 走 `pdf2markdown` / `pdf`），转存后一律按云盘件处理。

### 读取契约硬约束

- 全程只**读**项目料，不改源材料；
- 路由依据是**资源类型 / 链接路径模式**（`/base/` `/sheets/` `/docx/` `/wiki/` `minute_token`），**不是域名**；
- 读不到（无权限 / 链接失效）→ 停并报缺，不猜路径、不跳过硬蒸。

## 3. 查缺 checklist 用法（蓝图只事后核，绝不上游驱动）

### 两张 checklist，都是运行时注入的外部输入

| checklist | 是什么 | 核什么 |
|---|---|---|
| **查缺蓝图** | 组织维护的"该有哪类物料 / 块"的通用清单库（常见形态：多维表格，用 `lark-base` 只读） | 按其维度（如环节 × 角色 × 类型）过滤出与本产物下游相关的物料**类别**，逐类核对"我的产物里有没有对应的块"，缺的记入缺口清单 |
| **下游契约** | 已知下游 skill 声明的 input 字段表（其 reference / 契约文档） | 核"我的产物是否覆盖已知消费者要的字段" |

**两张都是外部运行时注入的输入**：链接 / token 作为调用入参传进来（见第 4 节 input schema），**不硬编进本 skill 正文，也不存进 `raw/`**——它们不是本项目的材料，是别人维护的活库，按链接现读。没有蓝图 / 契约的场景，跳过对应核对、仅靠纪律"缺则标待补"兜底，skill 照常可用。

### 用法四规（越一条即错）

1. **时机 = 第 4 步、蒸馏之后**：查缺在蒸馏产物已从真实材料蒸出**之后**跑，不在之前。
2. **用途 = 事后核"该有哪类块"**：蓝图是 type-level 通用清单，**只回答"这类产物一般该有哪些种类的块"**。
3. **绝不拿它取项目内容**：蓝图**不回答"某项目某块内容是什么"**——项目内容只能从该项目真实 `raw/` 蒸，不能从蓝图取、不能按蓝图编。
4. **绝不上游驱动**：**排除**任何"先照蓝图算出应有字段 / 物料 → 据此列应收料清单 → 照单去收料 / 先搭空产物骨架再填"的步骤。

### 阶段感知过滤（查缺的第一道筛）

checklist 逐类核对之前，先按 `{阶段 × 项目类型}` 过滤——**本阶段不该有的缺项不算缺口、不去催**（如策略期缺执行数据属"本阶段不该有"，不进缺口清单、不去向人要）。

- **阶段值**：读项目档案（「tingle-项目档案」，他方建维、本 skill 不建不写只读）的「阶段」字段；受控初始集 = `策略期 / 执行中 / 新周期`（可扩）。
- **标签结构**：品类为三级 `{业务线 / 合规类目 / 产品品类}`（**合规类目是规则加载的承重键**；业务线为"美妆 / 大健康"一类的通用划分）+ 品牌——**非单字符串**。
- **初蒸时**标签 / 阶段尚未落定 → 询问用户或从材料认，**不发明**。
- **边界**：阶段值只用于材料域查缺的过滤，**不做"哪个阶段跑哪些 skill"的平台路由**（环节编排归调用方）。

### material-first 护栏（数据流单向）

```
真实材料 ──归集──▶ raw/ ──蒸馏──▶ 认知件套 + 索引 ──(事后)──▶ 拿蓝图/契约核缺 ──▶ 缺口清单 ──▶ 向人索取
                                                        │
                                            无反向：蓝图不驱动收料、不生成内容、不预搭骨架
```

产物结构从真实材料长出；蓝图只在产物已存在之后做交叉核对。任何时刻发现自己在"照 checklist 搭框 / 收料"，即命中 SKILL.md Red Flag，停下收回。

## 4. input / output schema 字段级判据

产物 schema 不固定（因项目 / 下游而变），以下钉的是**结构契约**：每字段的类型 / 判据 / 格式 / 占位符正例。

### 4.1 input schema

| # | 字段名 | 类型 | 填什么（判据） | 格式 | 必填 | 正例（占位符） |
|---|---|---|---|---|---|---|
| 入① | 调用意图 | 枚举 | 三类之一：`初蒸`（`project-readiness` 初始化编排处一次性合并调用）/ `重产某件·某投影`（修复路由回调）/ `收新料·定稿纳入·料更新重蒸`（项目成员直达）。每次调用自带、本 skill 不自判。 | 单值 | 必填 | `初蒸` |
| 入② | 项目云盘 folder_token | token | 该项目云盘落点入口。初蒸 = 调用方直传（**勿假设项目档案已有本 skill 的条目**）；重蒸 / 修复路由 = 调用方从项目档案解析后传入。 | token 字符串 | 必填 | `[folder_token]` |
| 入③ | 来料线索清单 | 条目化列表 | 每条一份材料线索，四个子字段齐：**材料名**（人叫得出的名字）/ **类型**（枚举：多维表格 \| 电子表格 \| 文档 \| 妙记 \| 云盘文件 \| 本地文件）/ **位置**（飞书链接或 token，或本地绝对路径）/ **疑似一手 or 加工件**（人初判，归集时复核）。 | 每条一行四段 | 可选（未传则第 1 步引导询问现场产出） | `[材料X：某次沟通妙记] / 妙记 / [minute_token] / 一手` |
| 入④ | 成员名单 | 条目化列表 | 认知件套的成员定义（运行时注入；与查缺蓝图 / 下游需求同源）；缺省则从蓝图 / 下游契约 / 引导询问认定，**本 skill 不硬编成员**。 | 每条一件名 | 可选 | `[认知件A：人群与卡点]、[认知件B：产品事实]` |
| 入⑤ | 查缺蓝图链接 | URL / token | 组织维护的"该有哪类块"清单库入口，第 4 步只读；**运行时注入，不硬编**。 | 链接或 token | 可选（缺省则跳过蓝图核对） | `[某物料清单库链接]` |
| 入⑥ | 下游契约链接集 | URL 列表 | 已知下游 skill 的 input 字段声明文档，第 4 步只读；**运行时注入，不硬编**。 | 每条一链接 | 可选（缺省则跳过契约核对） | `[某下游 skill 的 io 契约文档链接]` |
| 入⑦ | 重产目标 | 文本 | 意图 = `重产某件·某投影` 时必带：哪件 / 哪个投影 + 不达标点。 | `件名：不达标点` | 条件必填（仅重产意图） | `[认知件B]：[缺某字段 / 某块已过期]` |

### 4.2 output schema —— 认知件套（顶层）

结构契约 = **套 + 索引 + 每件一个 link**：套成员由运行时注入的清单定义（本 skill 不硬编）、每件独立成飞书文档，索引每件一条挂链接。

| # | 字段名 | 类型 | 填什么（判据） | 格式 | 可沉淀候选 | 正例（占位符） |
|---|---|---|---|---|---|---|
| 出⓪ | 套成员 | 件清单（成员随项目 / 下游定） | 成员由运行时注入的清单（成员名单 / 蓝图 / 下游需求）定义，**不硬编**；每件独立成飞书文档、各落各自的文件夹；下游投影同为独立文档、同为套内成员。 | 每件一 doc（各自文件夹） | **是**（经复核确认、跨材料合成且稳定的件可回流复用） | `[认知件A：人群与卡点]、[认知件B：产品事实]、[投影C：某下游裁剪面]` |
| 出① | 件内主题块 | 分块结构（块数 / 块名随件定） | 件内按主题 / 类别组织成块，**块名自解释**（无内部裸码）；每块内容结构化（列表 / 表 / 分层小节），蒸到下游能直接用的颗粒度，非抽象名词标签。 | 每块一节，块名 = 自解释主题名 | —（随件） | `## [主题块A：目标人群与卡点]`、`## [主题块B：产品事实]` |
| 出② | 条目溯源标注 | 每条实质内容尾缀 | 每条实质内容紧跟具名来源，指向**真实一手材料的具名段落 / 字段**（非 extract / 台账脚手架）；第三人可按名定位、逐条比对。 | `（来源：[材料X]·[位置]）` | 否（随条目走，不单独沉淀） | `[某条结论]（来源：[材料X]·[字段③]）` |
| 出③ | 口径承接 / 限定块 | 条目附注（按需） | 受监管 / 有口径风险的条目，限定（适用范围 / 禁用场景 / 表述口径）随条目写上，**下游引用不可剥离**。 | 条目下的限定小注 | 否 | `[某主张]——限定：[仅适用某场景，不得表述为某承诺]` |
| 出④ | 缺口标注 | 显式标记（三种取值） | 料没覆盖处显式标注：`材料不足待补`（+补料去处）/ `待核`（+核什么）/ `可确无·以 [代理指标] 替代`（须真查全所有源才可下）。**不静默填充。** | 块内显式标记行 | 否 | `[字段①]：材料不足待补——去处：[问某角色 / 找某类文件]` |
| 出⑤ | 文末溯源附表 | 每件末尾附表 | 内部代号 ↔ 自解释字段映射、脚手架文件清单、源材料链接 / token，一律隔离在此，正文零出现；附表开头注明"仅供内部对齐，读产物内容不需要它"。 | 每件文末一表 | 否 | `[码-1] ↔ [主题块A·字段①]（仅内部对齐用）` |
| 出⑥ | 索引 | 一份 doc（串起整套） | 每件一条 = **件名 + 链接（可达）+ 一句用途 + 状态 / 缺口**；与套一致——无孤儿件（有件无条目）、无悬空条目（有条目无件或链接失效）。 | 一行一件 | 否 | `[认知件A] / [链接] / [一句用途] / 完整`、`[认知件B] / [链接] / [一句用途] / 缺 [某块] 待补` |

### 4.3 output —— 落点件（与产物一并产出）
