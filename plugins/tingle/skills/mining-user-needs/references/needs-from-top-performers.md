# 从已跑出结果的素材反向抽需求

> 本件是 `mining-user-needs` 的深读件，**走到"从素材反向抽需求"那一道工序时读**。装的是：需求专项怎么做（位置 + 频率统计法）、记原话的铁律、以及在哪些位置能挖到痛点。
> 与上游两道工序的关系：前面是**从产品端推出需求**（保证不漏自家卖点），本件是**从素材端反向抽需求**（保证抓到市场已验证的真需求）。**两条路互补，都要走。**

---

## 一、需求是什么：用户语言下的下单理由

一句话定义：

> **需求是用户下单的核心理由，本质是用户语言**——不是产品语言，不是被抽象过的行业黑话。

一个贯穿性判断：

> **有消耗就一定有需求，但有需求不一定能出来消耗。**

为什么有需求却跑不出结果？因为一条内容是多个因素连乘出来的，需求只是其中一个因子——画面、结构没到位，需求再准也乘不出结果。**所以挖需求不是终点，是给后面所有决定定方向的第一个因子。**

需求可以做两个二分：① 视觉需求 / 表达需求；② **问题型需求 / 效果型需求**（用户是因为"有个问题"还是"想要个效果"而买）。同一个品类里，不同需求可能指向完全不同的开头方式、内容类型和人群方向。

---

## 二、需求专项：只看需求，统计"位置 + 频率"

需求专项的操作核心是**收窄注意力**——承认注意力有限，就只把注意力集中在一个地方：**只看需求，别的都不看。**

### 操作五步

1. 准备**一批对标素材**（最关注的那个竞争对手，或对标品牌），通常取榜单前二十条。
2. 逐条**只看开头几秒、只看需求**——文案里的需求或画面里的需求都记，不看视觉花活、不看别的东西。
3. 输出一份**需求词单**——"这批词就是你关注到的用户需求"。
4. **记录一律用原话，不抽象**（铁律，见下节）。
5. 给每条需求标两个统计维度：

| 维度 | 含义 | 怎么用 |
|---|---|---|
| **位置** | 该需求所在素材在榜单里排第几（**是消耗排名，不是第几秒**） | **位置越靠前 = 对应消耗量越大 = 越值得重视** |
| **频率** | 该需求在这批素材里出现了几次 | **出现两次以上就重视**；同一个点在不同位置高频复现 = 该品类的核心需求被反复验证 |

> 工具：能看到对标内容与消耗排名的第三方内容数据工具。

### 一个现场范本

逐条看开头几秒打的是什么需求，抽出一串需求词：

| 抽出的需求 | 关键洞察 |
|---|---|
| 服帖 / 蹭不掉 / 不脱 | 这一条正是这个品类要解决的核心卖点——它是这个品类最突出的第一信息位 |
| 不脱妆、不浮粉 | 同一需求的不同措辞——**记录时不要替换成一个抽象词** |
| 运动出汗一整天都不脱 | 这条指向一个**新人群、新场景**——不同人群的需求增长点 |
| 会显得有光泽 | 既有"重点"也有"欲望"的表达 |

### 三条配套纪律

- **"知道" ≠ "做过专项"**（最反直觉）：做这个品类当然早就知道那个痛点是核心——但把二十条对标拆完、看到它在榜单里的位置和出现次数，**感受完全不一样**。看到数据之后再"知道"，是另一种认知质量。**别凭记忆，要做专项。**
- **不带人群看需求会误判**："运动出汗一整天不脱"你不会买，不是它没需求，是**你不是它的人群**。判断需求必须带人群视角。
- **最好的对标是"过去的自己"**：去找外部对标之前，先对标过去的自己——控制变量最干净、可比性最强；外部竞品会因体量、阶段、人群差异而失真。**需求底层相通时可以跨品类对标**（同一个困扰的两种解决方案之间）。

---

## 三、铁律：记原话，不要抽象

> **记录需求时，回到用户或素材的原本措辞，而不是把它抽象掉。**

一个常见的反例：把平台上的原话"往上抽象"成一个行业概念。"运动出汗"就记"运动出汗"，不要抽象成"户外场景需求"。

**理由**：抽象会丢掉用户语言的颗粒度，而需求恰恰**就是**用户语言。被抽象掉的不只是颗粒度，还是**下一次能直接拿来用的那句话**——抽象成上位概念之后，下一单想调出来填进内容里就没法用了。

> **这条直接决定沉淀质量**：留下来的每一条，存的必须是用户原话（带位置和频率），不是抽象功效词。**抽象过的需求是脏数据，回头喂不出能用的内容。**

## 四、在哪些位置挖痛点

核心问句是"本品类的痛点，可以在哪些位置找？"汇总的渠道：

| 渠道类 | 具体位置 |
|---|---|
| **评论区类** | 内容评论区／站外电商的问答区／直播弹幕 |
| **搜索词类** | 平台搜索词、上下游词、**避雷词**；通用搜索引擎的关键词热度占比 |
| **访谈类** | 用户访谈／问研发／问产品负责人当初的"研发初心" |
| **同行类** | 同行爆款打的痛点（看开头几秒） |
| **海外类** | 做海外市场的看海外内容平台评论 + 海外电商评论；国内还没上市的产品可以先看海外评论 |
| **自身体验类** | 自己就在这个处境里的一手体验 |

> **"避雷词"特别值钱**：用户写避雷，等于直接告诉你他被哪个痛点坑过、最怕什么——是隐性痛点的高纯度来源。

### 最优解：广撒网找候选，用专项法验真

如果只做一件事去找痛点，最优先做哪件？答案不是上面任何一个渠道：

> **最快的是专项法。** 痛点早就在同行素材的开头几秒里——同品类同行的前二十条素材，**如果有八条都在打同一个痛点，它已经帮你指了一条明路。**

**两者配合**：广撒网的渠道负责挖出候选痛点池，专项法负责用榜单频率快速验证哪几个已经跑出过结果。

## 五、痛点挖掘的意义高于表达

**痛点的定义**：**用户本身就具有的、不解决就会持续觉得不舒服的那个点。**

分两层：

- **显性痛点**：用户自己就认识它，接近搜索逻辑——他搜的时候就把答案告诉你了。
- **隐性痛点**：用户平常不认识它，被内容激发之后才认同——更接近内容激发的逻辑。

痛点可以拆成两个**不同的子专项**：① **痛点挖掘专项**（知道用户痛在哪几个地方）；② **痛点表达专项**（用哪种画面、哪种话术把隐性需求激发出来）。

**本环节只负责挖掘，不负责表达**——表达属于下游。这里要守住的判断是：

> 挖掘是表达的前置——挖准了痛在哪，才谈得上怎么表达；挖错了，表达再花也是戳空气。"打痛点谁都会，难的是表达"这句讲的是**表达**的稀缺；但挖掘这一步如果跳过去（直接抄别人的痛点画面），就会抄到**表面痛点**，而不是真正驱动购买的那个点。

### 公共痛点：确定性极高的流量饼

每个行业都有共同痛点。有些品类的深层确定需求跨品类成立（比如"显年轻""显高级""显瘦"这类，不挑具体品类）。**这类公共痛点是确定存在的流量饼，问题只是你能不能吃到**——挖掘阶段要优先把它们盘出来。

> **与"品类对比"的边界**：用户痛点侧重**用户自身的问题**；品类对比侧重**这个品类的解决方案本身有什么问题**。两者有交集但侧重不同，挖掘时分开记。

---

## 六、为什么值得单独做一遍

需求和痛点一旦按"原话 + 位置 + 频率"挖成条目，就不再是一单的一次性填空，而是可以跨单复用的东西：

- 每做一次需求专项都是**做一次、多次收益**：发现的被忽略的老需求、指向新人群的需求，下一单直接调出来用。
- 前提是记录质量过关——**原话、位置、频率三样齐全**，缺一样，下一单就调不动它。
