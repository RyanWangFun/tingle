# keeping-metrics-anchored

## 概述

一句话职责：**判每个数字挂不挂得回一段定性意图、每段意图有没有定量投影。**

**这是一份方法技能**：它不对应任何一个工作环节，不读项目材料，不产出独立交付物。它被各环节以 `REQUIRED BACKGROUND:` 引为共同前提，**用来在那个环节自己的产出交出去之前过一遍。**

**核心命题：定量是定性的可测投影。** 客户的目标和客户的指标不是两套东西，是同一个结果的两面。**你呈现的每一个数字，唯一的存在理由就是回答"它兑现了哪一段意图"。**

## 何时用 / 何时不用

**何时用**：任何一份含数字的产出交出去之前；有人拿一堆达标的数字来汇报成果时；"各项指标都绿了、结果却没来"时。

**何时不用**：
- 要产出那些数字本身——那是各环节自己的活。
- 要判数字算得对不对、口径准不准——**本件只判数字与意图之间有没有断开，不判算术。**
- 要判内容合不合规、表述过不过——那是红线的事。

---

## 两条铁律

| 铁律 | 含义 | 违反的症状 |
|---|---|---|
| **每一个定量数字，必须挂得回一段定性意图** | 报一个指标，就要说清它在证明哪一段策略 | **孤儿指标**——好看但没有意义（某个率变绿了，不等于心智被激活） |
| **每一段定性意图，必须有定量投影** | 策略里写了"要做成某件事"，就必须有一个数在量它 | **裸承诺**——说做了，但没有任何数据能验证 |

---

## 检查程序（三步，按序）

**第一步 · 遍历产出里的每一个定量数字**，问：它能不能挂回意图集里某一条具体的意图？
- 挂得上 → 记录它挂在哪一条（**要能逐字指认，不能只说"挂在提升认知上"**）。
- 挂不上 → 标记 **孤儿指标**。

**第二步 · 遍历意图集里的每一段意图**，问：这一次的产出里有没有一个定量投影在量它？
- 有 → 记录是哪一个。
- 没有 → 标记 **裸承诺**。

**第三步 · 输出 flag 清单**，每条标明是"缺意图"还是"缺投影"，并给修补建议。**有 flag 就拦住，不流向下游。**

---

## 判据：什么样算真的挂上了

**一个数字算挂上了，必须同时满足三条**：

1. **指得出具体是哪一条意图**——能逐字引用意图集里的那句话，不是指向一个大类。
2. **这条意图先于这次产出就已经被记录**——**不许为这个数字现写一条意图**。照着数字反写意图（数字是"某个率提升"，就把意图写成"提升某个率"），这道闸必然通过，等于没判。
3. **这个数字变好，那条意图就真的前进了一步**——问一句：**假设这个数字百分之百达成，那条意图是不是仍然原地不动？** 是，就没挂上。

**同理，一段意图算有投影了，要满足**：这个投影是**可采集、可复算**的（说得出它从哪来、多久采一次），不是"到时候看情况"。

---

## 四种最常见的伪挂回

| 伪挂回 | 长什么样 | 为什么不算 |
|---|---|---|
| **反写意图** | 先有数字，再照着数字造一条意图挂上 | 尺子是照着结果刻的，必然通过 |
| **挂到大类上** | "这个数字服务于提升品牌认知" | 指不出具体哪一条，等于没挂 |
| **过程当结果** | 用一个中间环节的数字去兑现一段终点意图 | 中间环节达标不等于终点达成 |
| **一对多兜底** | 一个数字同时挂在好几条意图上 | 它到底在证明哪一条？说不清就是没挂 |

## 由此定义的失败态

> **达标的失败 = 定量达标 × 与定性脱锚。**

所有的灯都绿了、项目其实是失败的（某个渗透类目标远未达成，而所有效率类指标全绿）——**本质就是脱锚。**

**这条方法存在的全部理由，就是让这种脱锚一眼可见，而不是让一排绿灯把它盖住。**

---

## 落到呈现上的两条结构含义

- **意图与指标的一一对应表，是任何一份数据呈现的脊椎**。它应当在项目开始时就建立；**产出时只能挂回它，不能新造。**
- **呈现层按"意图"组织，不按"数据来源"组织**——打开任何一个数字，都知道它在为哪一段意图作证。
- 呈现层必须能标出两种脱锚：**有数字没意图（孤儿）、有意图没数字（裸承诺）。**

---

## 接口与边界（声明）

- **适用范围**：被任一含数字产出的环节引为共同前提的判准——**它不是一个独立环节**，换一个客户项目、换一个环节都同样适用。
- **input schema**：`待检产出`（含定量数字的任意产出，结构不限）；`意图集`（数组，本项目先于本次产出就已记录在案的定性意图条目，每条可逐字指认）。
- **output schema**：`挂回记录`（数组，每条含数字、它挂回的那条意图原文、三条判据的逐条判定）；`flag清单`（数组，每条含类型枚举「孤儿指标」／「裸承诺」、涉及的数字或意图、修补建议）；`是否放行`（布尔——有 flag 即为否）。**可沉淀候选（reusable_candidates）**：`挂回记录`（同一项目下一次产出可直接复用同一套对应关系）。
- **写回位置**：**无独立落点**——判词随调用它的那个环节的产出一起走，进那个环节的复核包。
- **规则层与项目事实**：**不挂任何规则层**（本件不产内容、不碰红线）。所需项目事实字段：无——它读的意图集由调用方传入。
- **工具**：无外部接口调用。
- **决策档**：**复核**——它给的是一份 flag 清单与放行结论，须随所在产出一起由人过目；**判为不放行时不得由调用方自行放行。**
- **复核包**：挂回记录 ＋ flag 清单 ＋ 意图集的出处（它是在什么时候、由谁记录下来的）。
- **升级条件（命中即停交人）**：①待检产出涉及合规红线而判据不确定；②同一个数字在不同层的规则下要挂回不同的意图（四层规则冲突）；③**拿不到先于本次产出就已记录的意图集**——此时本件跑不了，不许现造一份；④产出需对外发送；⑤判出脱锚（所有过程指标达标而终点意图没有投影或没有前进）。

---

## 产出验收判据（DoD）

一次检查合格，当且仅当：

1. 产出里的**每一个**定量数字都被遍历过，各自有"挂上了/孤儿"的结论，无一遗漏；
2. 判为挂上的，**逐字引用了它挂回的那条意图原文**，不是指向一个大类；
3. 意图集里的**每一段**意图都被遍历过，各自有"有投影/裸承诺"的结论；
4. 每条挂回都过了三条判据（指得出具体哪条／意图先于产出已记录／数字达成则意图真的前进），逐条有结论；
5. flag 清单里每条都标明了类型与修补建议；
6. 有 flag 时结论是"不放行"，**没有出现"先放行、回头再补"**。

## Quick Reference

| 情形 | 判法 |
|---|---|
| 一个数字很好看 | 问它挂回哪条意图，要能逐字指认 |
| 挂不上 | 孤儿指标，拦住 |
| 意图里写了要做成某件事 | 问哪个数在量它；没有就是裸承诺 |
| 意图是刚为这个数字写的 | 不算——反写意图，尺子照着结果刻 |
| "服务于提升品牌认知" | 不算——挂到大类等于没挂 |
| 用中间环节的数兑现终点意图 | 不算——过程不是结果 |
| 一个数字挂在好几条意图上 | 不算——说不清在证明哪一条 |
| 所有指标都绿、结果没来 | 脱锚，停下交人 |
| 拿不到已记录的意图集 | 跑不了本件，交人——不许现造 |

## Common Mistakes

- **照着数字反写意图**——这道闸就永远通过，等于没有。
- **挂到一个大类上**——"服务于增长""服务于认知"指不出任何具体的东西。
- **只查数字不查意图**——只做了第一步，漏掉的全是裸承诺。
- **用过程指标兑现终点意图**——最常见的脱锚形态。
- **发现 flag 还是放行**——"先交出去，回头再补"，回头就没有了。
- **把它当成算术检查**——本件不判数字算得对不对，判的是它和意图断没断开。

## Red Flags（出现即停）

- 「这个数挺重要的，先放上去」→ 挂不回意图就是孤儿指标。
- 「意图我现在补一条」→ 反写，不算。
- 「大方向上是对的」→ 指不出具体哪一条就是没挂上。
- 「过程指标都达标了」→ 那不是结果，去查终点意图有没有投影。
- 「有 flag 但不影响交付」→ 有 flag 就是不放行。
