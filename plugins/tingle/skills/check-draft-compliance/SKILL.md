# check-draft-compliance

## 概述与核心原则

一句话职责：**逐处核一份未发布的内容稿对不对得上本项目的既定规矩，交出逐处判定、每处的改法与一个送审判断**——拿本项目的表述禁令、产品事实与稿件规范当尺子，把稿子拆成可逐处定位的单元，逐处判它越没越线、说得实不实、该带的带没带齐、放没放对位置，每一处判有问题的都给出可直接替换的改法，最后汇总成一个「能不能送出去」的判断。

**这算一个职责，不算两个。** 给改法在这里没有独立的消费者——它读的是本环节自己刚产出的判断（这一处越了哪一条、越在哪个字上、该带的限定语是哪一句），脱离这份判断它无事可做。**一个动作是另一个动作的最后一步，不构成两个能力。** 反过来，只交一张问题清单、让写稿的人自己想改法，必然失真：做判断的知道"越在哪一条上"，想改法的只知道"这句有问题"，于是把一个绝对化词换成另一个绝对化词，或者索性整段删掉。

**但给改法不等于改稿。** 改法是"这一处应改成这样"，**落不落进稿子是写稿人的决定，不是本环节的动作**——本环节不产新稿，见「何时不用」。

**适用环节**：换一个客户项目也会再次发生的固定环节——凡产出要送客户或送内部审核的内容，成稿之后、送出去之前都要过这一道，不是一次性事务。

**属于哪组能力**：项目自动化（供上位方案对账用——本环节是项目执行链上的一道，不属诊断、洞察、盯盘、策略建议或复盘沉淀）。

**三条核心原则（越一条即错）**：

- **逐处留痕，包括判「没问题」的那些。** 只列有问题的处，等于让"漏判"与"这处没问题"在产物里长得一模一样，而漏判的代价是一句该改的话原样发了出去。
- **判据来自装载进来的规则与项目件，不来自你觉得。** "这话挺常见的""这个词大家都在用"不是判据。**装载进来的规则没写到的那一类，判归判，另标出来问**——不自己往里补一条。自己补的那一条与项目约定的那一条在产物里长得一模一样，而复核的人不会知道有一条是当场定的。
- **只判有外部标准可核的东西。** 稿子写得好不好、够不够抓人、像不像某个人说的话，没有可对照的既定标准，**不是本环节的判据**——把它写进判定，等于用一个说不清的意见挤掉了真正该被看见的那几处。

## 何时用 / 何时不用

**何时用**

- 一份稿写完了，要送客户、送内部审核或直接发出去，需要先过一轮"哪一处越线、哪一处失实、该带的带没带齐"的自查，**并要拿回每一处的改法**。
- 稿子改过之后要重判一遍——改动可能带进新的问题，也可能把上一轮补上的限定语又删掉了。
- 想知道某几句话在本项目的规矩下能不能说，以及卡的是"红线明写了不许说"还是"规矩里根本没写到这一类"。

**何时不用（When NOT）**

- **改写或重写稿件**——本环节只判并给改法，**不产新稿**。要把改法落进稿子、要重新组织段落、要按某个账号的语气重写，那是内容生产，交回写稿的人。
- **判稿子写得好不好**——够不够抓人、开头留不留得住人、像不像某个达人说的话，这些没有可对照的既定标准，不是本环节的判据。把它们写进判定，等于用说不清的意见挤掉真正该被看见的那几处。
- **引用与角标校对**——本环节不判"这话有没有出处、角标标对没有、文末条目对不对得上"。那是另一道环节，稿件定下来之后过。
- **核一条已拍成的成片**——成片对不对得上脚本、品牌元素露出得够不够早、字幕有没有错字，那是成片交付前那一环，不在这里。
- **稿件读不全时硬跑**——只读版式文件的文本层残缺、表格里的正文取不到、分不清哪一段属于哪一栏，一律停并报，索要可编辑原件或补一份栏位说明。
- **拿装载进来的规则当"参考意见"**——本环节不是在提建议，是在核一份稿对不对得上既定的规矩。规矩没写到的，标出来问，不是自由裁量的空间。

## 方法

### 一 · 把稿子拆成可逐处定位的单元

- **取文时连表格一起取。** 分镜类、脚本类的稿件正文常整段躺在表格里，只读普通段落会漏掉整栏而不留任何痕迹。取完先自查：取到的文本能不能对应回它属于哪一栏。
- **按「稿件规范说明」给的栏位切分**——哪一栏是要念出来的、哪一栏是屏幕上的字、哪一栏是画面说明、哪一栏是发布时才用的。**不同栏位适用的判据不同**（同一句话在这一栏合规、在那一栏不合规），所以不切分就没法逐处判。
- **切到"能被指着说"的颗粒度**：一处 = 一个可定位的判定单元（第几栏第几句、或第几镜第几行）。指不到具体位置的判定，写稿的人无从下手。
- **交出覆盖清单**（抽到几栏、每栏几处、按本项目口径算出的字数），请人确认没有漏抽（**必停**，见下）。

### 二 · 逐处判（四维，按序扫，不跳维度）

对每一处，按下列次序各问一遍。**次序是方法**——先判越没越线，再判说得实不实，再判该带的带没带齐，最后判放没放对位置；倒过来会让一处已经越线的内容因为"位置对的"而被放过。

| 维 | 判什么 | 判据从哪来 |
|---|---|---|
| 一 · **越线** | 这一处说了本项目不许说的话吗 | 装载进来的规则（当下承载＝输入「品牌项目红线」） |
| 二 · **失实** | 这一处说的，与产品事实对不上吗——名称、宣称、适用人群、适用条件 | 输入「产品资料」 |
| 三 · **缺件** | 该带的带齐了吗——必须出现的要素、必须随附的限定语、同类要素的数量下限 | 输入「稿件规范说明」＋装载进来的规则 |
| 四 · **错位** | 内容放对栏位与位置了吗——该在屏幕小字里的进了口播、该在前段出现的拖到了后段、超了数量上限 | 输入「稿件规范说明」 |

**每一处四维各留一个结果，不只留一个总结果。** 判定表里一处占一行，行内四维各有一格。**只给总结果的表，判过四维与跳过三维长得一模一样**——而跳维度恰恰是压力下最先发生的事。

**每一维的判定取值**（固定五值，不自拟）：`无问题` · `有问题` · `不适用` · `待确认` · `待确认·规矩未写到`。判 `有问题` 的那一格，另按该维填其问题类型：越线 / 失实 / 缺件 / 错位。

**判 `无问题` 时，若这一处的内容命中了装载进来的规则里某一条的近似说法，须写明为什么判它没越线。** 其余判 `无问题` 的不必写理由。

**禁止**：

- **禁止只列有问题的那几处。** 逐处都要在判定表里有一行，含判「无问题」的。**已观测的原样**：时间紧时只挑明显的几句列出来，交出去的表和一份完整判过的表长得一模一样，而漏掉的那几处不留任何痕迹。
- **禁止拿"这话挺常见的""这个词大家都在用"当判据。** 判的是它对不对得上装载进来的规则，不是它常不常见。
- **禁止在规则没写到某一类时，自己补一条进去。** 照本维的判问句判出结论，**并把"这一类本项目没写"标成 `待确认·规矩未写到` 交人**——不把自己的判断当成项目约定。
- **禁止把一处判定的理由写成规则的转述。** 每一处判有问题的，须写明它撞的是**哪一条**（指得到装载进来的那一条），不写"违反了相关规定"。
- **禁止把创作质量意见塞进判定表。** "开头不够抓人""这句太干"没有可对照的标准，不属本环节。
- **禁止在一处里裹着两个问题时只判一个。** 一句话可以同时越线又缺限定语，逐个列出，各给各的改法。
- **禁止把判有问题的那一处降格。** 降不降由装载进来的那一条是不是硬性要求决定，**不由客户催了几轮、制作方返了几次工、稿子改起来有多麻烦决定**。要让步是人的决定，摆出来交人，不在判定表里悄悄改档。
- **禁止给引用下结论。** "这句缺文献""角标标错了"是隔壁环节的判定；本环节遇到时只在待确认里记一行"建议过引用校对那一环"，不判合格与否。

**合理化对照表**

| 心里的那句话 | 实际是什么 | 怎么裁 |
|---|---|---|
| 「时间紧，先把明显的几处列出来交了」 | 漏判与"这处没问题"在产物里分不开，而拿到表的人默认它是判完的 | 逐处留痕，含判无问题的 |
| 「这稿是资深的人写的，大面上应该没问题」 | 判的是这一份稿对不对得上规矩，不是写它的人靠不靠谱 | 照样逐处判 |
| 「客户已经催三轮了，这处小问题放过去算了」 | 催的是进度，判的是这处越没越线——两件事 | 照判，严重度由三档判断承载，不由"放不放过"承载 |
| 「红线里没写这一类，那就是可以说」 | 没写到与允许是两回事 | 判 `待确认·规矩未写到`，交人 |
| 「这个词红线里没有，但看着挺像那一类的，算它越线吧」 | 自己补的那一条与项目约定的那一条在产物里分不开 | 同上——标出来问，不自己补规则 |
| 「这句既踩了红线又漏了限定语，写一条省事」 | 两个问题各有各的改法，合成一条会让其中一个被漏改 | 逐个列 |
| 「这稿改起来太麻烦了，这处算可选优化吧」 | 降格的依据是规则的硬性程度，不是改起来费不费劲 | 照判，让步摆出来交人 |
| 「上一稿这么写也过了，这次也行」 | 上一稿过了可能是上一稿漏判了；判的是这一份对不对得上规矩 | 照样逐处判 |
| 「这句读着别扭，一并写进去吧」 | 创作意见挤掉真正该被看见的那几处 | 不写进判定表 |
| 「这句好像没出处，标个缺文献」 | 引用是隔壁环节，本环节给不出合格判定 | 只记一行建议过那一环 |

**Red Flags（出现即停，回方法二）**

- 「先扫一遍看有没有明显的」（扫一遍不是逐处判）
- 「这几处应该没问题，跳过」
- 「规矩里没写，我按常理来」
- 「这条我记得客户说过」（记得不是核过）
- 「反正后面还有客户那一道，漏一点没关系」（后面那一道正是本环节要替它拦下的）

### 三 · 给改法

每一处判有问题的，**给出可直接替换的文本**，不写"建议优化表述"。

**改法的四条契约（缺一条即改法不合格）**：

1. **给的是替换文本，不是方向。** 写"这一处改成：<具体的字>"，不写"建议弱化表述""建议加限定"。
2. **只动出问题的那一处。** 不顺手重写整段、不调整语序、不改与本次判定无关的字——重写是生产，不是本环节。
3. **改法本身要过一遍同样的四维。** 常见的失手是把一个越线词换成另一个越线词、或者补上限定语的同时把必含要素挤掉了。
4. **写明它依据的是哪一条。** 改法后面跟一句"依据：<装载进来的哪一条／产品资料的哪一句／稿件规范说明的哪一项>"。

**改不动的，不硬凑。** 出现下面任一种，判 `须回作者重写`，写明卡在哪，不给一个看似能用的替换文本：

- 要改这一处就得推翻它所在的整段逻辑；
- 这一处失实的根子在事实本身（稿子说的那件事产品资料里没有），换个说法仍然失实；
- 装载进来的规则对这一类只给了禁止、没给可用的替代说法。

### 四 · 下送审判断

汇总成三档之一，**不用第四种说法、不用"各有优劣"一类模糊结论收尾**：

| 档 | 什么时候用 |
|---|---|
| **可送审** | 无越线、无失实、无缺件；仅有可选优化 |
| **改后可送审** | 存在明确问题，但每一处都给得出改法，改完即可送 |
| **不建议送审** | 出现下列任一：改法给不出（`须回作者重写`）、必含要素成组缺失、失实的根子在事实本身 |

**下「可送审」这一档必停交人**（见下方必停名单）。另两档是"要改"，人本来就要动手，不必停。

**本环节无权宣称任何外部审核已通过。** 交出的判断只说"已按本项目现有材料与既定规矩逐处核过"，**不得写成"已通过医学审核／法务审核／平台审核"**——本环节不是那几道审核，也不代表它们。

### 五 · 步骤

1. **取文并拆单元**（方法一）——连表格一起取，按栏位切分，切到可定位的颗粒度。**交出覆盖清单，请人确认没有漏抽**（必停，见下）。
2. **逐处按四维判**（方法二），逐处留痕，含判无问题的。
3. **给改法**（方法三）——每一处判有问题的都给，给不出的判 `须回作者重写`。
4. **汇总送审判断**（方法四）。
5. **出审核产出**——逐处判定表、改法、覆盖清单、送审判断、待确认项。
6. **判断为「可送审」时，交人点头**（必停，见下）；另两档直接交出。
7. **收尾自查并交付**——照 DoD 逐条核，核过之后交出产出与复核包。

## 依赖的规则层与项目事实

- **挂三层**：**通用层**——不分行业都适用的表述禁令（绝对化用语、不把相关性写成因果、不把机制推导写成效果结论）；**品类层**——按合规类目取值的那一套（哪些话此类产品不得直接说、须随附什么提示、什么须报备），换一个合规类目整套换；**品牌层**——本项目已约定的术语正名、可说的宣称边界、必带限定语的具体文案、以及"这类表述默认不必判"的豁免条款。

- **这三层当下的承载，就是输入「品牌项目红线」那一份项目件——组织级的规则库还不存在。** 所以本环节运行时**不去任何组织级的地方取规则**：上述三层要用的内容，全部写在本项目那一份里（它的就绪判据已把这几样逐条列出）。**这不是权宜**——规则库建出来之前，项目件就是唯一真相源；建出来之后，改的是那份文件从哪儿继承内容，本 skill 的读法一个字不变。

- **不挂类型层**：现有材料里没有出现"换一种产出类型，同一句该不该判就变了"的情形——不同栏位的差异由输入「稿件规范说明」承载，那是同一种产出类型内部的分栏，不是类型层。**这一条是按现有材料判的，不是验过的**——若日后出现产出类型改变判定门槛的项目，此处须重判。

- **它没写到的，一律标出来问，不自己补一条。** 取不到规则与"这一类不必判"是两回事：前者要停下来问人，后者要有人写明才算。

- **所需项目事实字段**：`合规类目`、`品牌`（决定装载哪一套上述规则），由运行前检查从项目档案取得。

## 输入 / 输出 schema

**input schema**

- `待审稿件`（本次要判的那一份成稿。**由调用时当场给出**，三种来源一律接：本地文件 / 云文档链接 / 云盘文件）
- `稿件形态`（枚举：可编辑文稿 / 只读版式文件 / 纯文本。只读版式文件的文本层残缺、或栏位分不出来时，停并报，索要可编辑原件）
- `品牌项目红线`（本项目不许说什么、必须随附什么）
- `产品资料`（产品正式名称、官方宣称原文及其限定语、适用人群与条件）
- `稿件规范说明`（本项目一份稿分哪几栏、必须出现什么、放在哪、数量几何、字数怎么算）
- 上述后三样的实际地址以 Step 0 运行前检查返回的已解析地址为准。

**output schema**

**最终交付物（一件）**

- `审核产出`（一份文件，含下列五项）：
  - `逐处判定表`（每行：位置 / 原文摘录 / 所属栏位 / **越线** / **失实** / **缺件** / **错位** 四维各一格 / 撞的是哪一条 / 改法或卡在哪。每维取值：无问题 · 有问题 · 不适用 · 待确认 · 待确认·规矩未写到；给不出改法的另标 `须回作者重写`）
  - `覆盖清单`（抽到几栏、每栏几处、按本项目口径算出的字数）
  - `送审判断`（三档之一：可送审 · 改后可送审 · 不建议送审，附一句理由）
  - `待确认项`（每条：卡在哪一样、缺什么、要谁补）
  - `本次装载的规则来源`（这一次判定依据的是哪一份项目件的哪一版，供复核的人回核）

**可沉淀候选（reusable_candidates）**

- `本次判为「待确认·规矩未写到」的那几类`（它们是规则的缺口，补进「品牌项目红线」之后全项目受益）
- `本次高频复现的越线类型与其可用替代说法`（下一稿再遇到同类表述可直接复用，宜回写「品牌项目红线」的豁免与替代说法一节）

## 决策档 · 必停名单 · 复核包 · 升级条件

**决策档**：**复核**。产出连着对外——稿子改完要送客户或送内部审核，不标自动。**能自动出判定不改变这一档。**

**哪几步必停（不是统一档位，是这一份名单）**：

| 步 | 判 | 这一步做错了，谁会在什么时候发现 |
|---|---|---|
| 1 取文并拆单元 | **必停**——交出覆盖清单请人确认 | **没有人。** 漏抽一整栏与"这一栏没问题"在产物里长得一模一样：判定表只呈现它看见的东西，漏掉的部分不留任何痕迹；而那一栏照样原样出现在稿子里发出去 |
| 2 逐处按四维判 | 可自动（**条件是逐处留痕**） | 若只列有问题的处，漏判无痕、无人发现；改为逐处都出现在判定表里之后，漏掉的处变成看得见的缺口，人核得动 |
| 3 给改法 | 可自动 | 下游必然看到：写稿的人采用改法时当场判断它可不可用，不可用会顶回来 |
| 4 汇总判断 · 下「改后可送审」「不建议送审」 | 可自动 | 这两档都是"要改"，人本来就要动手，动手时判断错没错当场暴露 |
| 4 汇总判断 · 下「**可送审**」 | **必停**——交人点头 | **发现时已经对外。** 拿到"可送审"的人就把稿子送客户或送内部审核了，那边审出问题时已经消耗掉一轮对外机会，而稿面上"可送审"与真的没问题长得一模一样 |
| 5 出审核产出 | 可自动 | 它本身就是交给人看的东西 |
| — 把审核意见发给写稿人之外的人 | **必停** | 意见一旦发给达人、制作方或客户即不可撤回 |

**复核包**（随产出附上，使复核的人不必回头翻上下文）：待审稿件本身、逐处判定表、覆盖清单、送审判断及其理由、待确认项清单、**本次装载的规则来源**（复核要核的正是这一处——每一处判定撞的那一条，没有它复核的人只能信、不能核）。

**升级条件（命中即停交人）**：①合规红线不确定——某一处越没越线判不准；②四层规则冲突（两层各有一套说法）；③缺关键项目事实（合规类目或品牌未取到，不知道该装哪套规则）；④产出需对外发送；⑤稿件读不全（只读版式文件文本层残缺、表格里正文取不到、栏位分不出来）；⑥装载进来的规则对某一类表述完全没写到——判归判，另标 `待确认·规矩未写到`，不自己补规则；⑦一处的改法给不出（要改就得推翻整段、或失实的根子在事实本身）；⑧判断为「可送审」；⑨「产品资料」与稿件说法冲突，且分不清是稿子写错了还是产品资料没更新。

## 写回位置 · 可沉淀候选

- **写回位置**：requirements 落点「审核产出落点」，地址由项目档案填、运行前检查解析。每次审核各自成一件落在这里、不覆盖上一次——上一轮的判定是这一轮改动的对照物。**原稿不覆盖、不改动**：本环节不产新稿。
- **可沉淀候选**：见 output schema 中标出的两项。

## 产出验收判据（DoD）

一次运行合格，当且仅当：

1. 稿件中每一个判定单元都在逐处判定表里有一行，含判「无问题」的；**行内四维各有一格结果，无空格**；覆盖清单已交出且经人确认。
2. 每一条判为 `越线` / `失实` / `缺件` / `错位` 的，都写明了它撞的是哪一条（指得到装载进来的具体那一条、或产品资料／稿件规范说明的具体哪一项），无"违反相关规定"一类不可回核的表述。
3. 每一条判有问题的都给出了可直接替换的改法，且改法满足四条契约（是替换文本、只动出问题那一处、自身过得了四维、写明依据）；给不出的落在 `须回作者重写` 并写明卡在哪。
4. 装载进来的规则没写到的那几类，已逐条标为 `待确认·规矩未写到` 交人，未自己补规则。
5. 送审判断落在三档之一并附理由；判为「可送审」的，已取得人的点头。
6. 判定表里没有创作质量意见（写得好不好、抓不抓人、像不像谁），也没有对引用是否合格的结论。
7. 原稿未被改动，本次运行没有产出新稿。
8. 复核包齐全，复核的人据它可以逐处核到判定所依据的那一条，不必回头问作者。

## Quick Reference

| 问题 | 一句判法 |
|---|---|
| 这一处要不要判？ | 每一处都判，逐处留痕，含判"没问题"的 |
| 按什么次序判？ | 越线 → 失实 → 缺件 → 错位，不跳维度 |
| 逐处的判定怎么留？ | 四维各留一格，不只留一个总结果——只给总结果的表，判过四维与跳过三维分不开 |
| 判据从哪来？ | 装载进来的规则（当下＝「品牌项目红线」）＋「产品资料」＋「稿件规范说明」；不是"我觉得" |
| 规矩里没写这一类怎么办？ | 照判问句判出结论，另标 `待确认·规矩未写到` 交人；不自己补一条规则 |
| 改法怎么写才算数？ | 可直接替换的文本 ＋ 只动出问题那一处 ＋ 自身过得了四维 ＋ 写明依据 |
| 改法给不出怎么办？ | 判 `须回作者重写`，写明卡在哪，不硬凑一个看似能用的 |
| 稿子写得好不好要不要判？ | 不判——没有可对照的既定标准，不是本环节的判据 |
| 这句缺不缺文献要不要判？ | 不判——引用是隔壁环节，只记一行建议过那一环 |
| 交什么？ | 判定表 ＋ 覆盖清单 ＋ 送审判断 ＋ 待确认项 ＋ 本次装载的规则来源；**不交新稿** |
| 哪一步不许自动？ | 拆单元后的覆盖确认、下「可送审」这一档、把意见发给写稿人之外的人；另有九条升级条件命中即停 |

## 常见错误（Common Mistakes）

- **只列有问题的那几处**——漏判与"没问题"在产物里分不开，逐处留痕才把漏判变成看得见的缺口。
- **顺手把稿子改了交出去**——本环节不产新稿；改不改是写稿人的决定，替他改会让原稿与改稿再也无法并排对照。
- **改法写成"建议弱化表述"**——写稿的人照样不知道改成什么，最后要么不改要么乱改。
- **把一个越线词换成另一个越线词**——改法自身没过四维。
- **规矩没写到就自己补一条**——自己补的那一条与项目约定的那一条在产物里长得一模一样，而复核的人不会知道有一条是当场定的。
- **只给一个总判定、不分四维留痕**——跳维度是压力下最先发生的事，而总结果表看不出跳没跳。
- **把硬性问题悄悄降成建议**——让步是人的决定，不该在判定表里发生。
- **把创作意见混进判定表**——用说不清的意见挤掉真正该被看见的那几处。
- **只读普通段落、漏掉表格里的正文**——分镜类稿件的整栏口播常在表格里，漏掉不留痕。
- **判定理由写成"违反相关规定"**——复核的人回核不到具体哪一条，只能信、不能核。
- **把某个客户的禁用词表抄进本页**——词表随项目变，抄进正文的那一份不会跟着项目件改，而判的人读的是正文这一份。
- **宣称"已通过医学／法务审核"**——本环节不是那几道审核，也不代表它们。
