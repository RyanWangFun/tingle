# validating-the-real-problem

## 概述

一句话职责：**把一个模糊或表象的命题，验成一句可衡量的真问题，并追到根因。**

**这是一份方法技能**：它不对应任何一个工作环节，不读项目材料，不产出独立交付物。它被各环节以 `REQUIRED BACKGROUND:` 引为共同前提——读 brief 时用它、复盘时也用它，**是同一套方法，不是两套。**

**核心命题：提问的人问的，往往不是最根本的那个问题。** 他基于日常经验给问题下了一个定义，**而这个定义可能是错的**。照着那个定义去做，会解出一个伪问题——而且整个过程会自洽地服务于它、一路无人察觉，直到最后才暴露。

## 何时用 / 何时不用

**何时用**：诉求是"问题型"的（"转化率低""数据不好""做了没结果""加了预算营收不变"）；对方拿一个表象或一个别人的结果让你照做；任何"为什么没做到"的追问；复盘中要定位根因时。

**何时不用**：
- 要产出解决方案本身——那是各环节自己的活，**本件只负责把问题验真、把根因追出来。**
- 要判某个数字算得对不对、口径准不准——不在本件范围。

## 第一心法：拒绝"我觉得"，先找参照物

> 面对"这个目标你只做到了一部分，问题出在哪"，绝大多数人只会甩一句"我觉得是转化率不高／人群不精准"。**"我觉得"永远找不到真问题，也说服不了任何人。**

**第一步不是回答问题，是给问题找参照物**：

- 不要张口就说"我这里差"。先问自己——**我用什么标准界定这个"差"？**
- 参照物只有四个来源：**往期数据 / 原定预期 / 行业数据 / 竞品数据**。
- **四个都拿不到，就先去建监控，而不是先下结论。**

**用参照物定位维度的样本**：把自己与同行在同一条链路上逐段对比——同样数量的内容带来的阅读量、阅读到搜索的折损、搜索到转化的转化率。**每个指标都建参照物、逐一判断好坏，再聚焦到差的那一段深挖。**

> **第一件要解决的不是那个结果本身，而是定位到具体哪个维度出了问题。**

## 四步法

| 步 | 动作 | 纪律 |
|---|---|---|
| **1 · 明确并理解问题** | 先问"为什么有这个问题"，界定它是真问题还是伪问题 | **别用日常经验给它下定义**，定义本身可能就是错的 |
| **2 · 拆解并定位** | 把问题做**公式化拆解**，拆成三四个子问题或独立数据链 | 多数人只看表象，看不到它由哪些模块构成 |
| **3 · 找解决方向** | 针对子问题不停**追问 why**，渗透到最重要的那一点 | **问到根因，不停在中间层** |
| **4 · 总结沉淀** | 把判断逻辑沉淀成共识清单与数据基点 | 形成可复制的资产，**不靠个人** |

**两条贯穿始终的铁律**：

1. **界定问题要可衡量、可具象**——是从三百降到二百五，还是从一千降到三十？是这两天，还是连续两周？
2. **数据是客观的，不会说谎**——**经验会说谎，客观数据不会。**

## 验真伪的标准动作：先数据化，再判断

凡拿到问题型的诉求，第一步永远是把它换算成可衡量的数字，看它是否真的存在、是不是根本问题。

**一个完整的验真样本**：某个耐用品牌说"转化率比竞品低"——

1. **真的低吗？** 搜核心品牌词与竞品对比，转化率差异极小 → **不是重点。**
2. **不是搜索转化低，那是店铺链接转化低吗？** 看下来直接转化的效率差异也不大 → **排除。**
3. **那为什么会觉得转化低是问题？** 因为决策层觉得整个生意的排名上不去。**而生意排名除了转化，还有一个因素是流量。**
4. **回归前端**：其实是流量问题——拉新与老客的比例都不如竞品。

> **结论**：他提出的"转化率低"不是根本问题，回溯之后真问题是**流量端口**。

**另一个样本**：某品牌说"有爆文、有访客但没转化"。先问"有多少爆文、多少访客"——这类相对高决策的行业，成熟品牌的精准转化率就在某个量级；**若访客量本身很小，乘上这个转化率本就没多少单。先把问题数据化，再判断它是不是真问题**，等访客量到了临界值之后再看。

---

## 公式化拆解：把开放问题拆成可定位的要素

把开放式问题先回归到可衡量的需求，再用公式拆成几条独立的数据链，**定位哪一环可增长且最快达成。**

**一个样本**："如何放大投放效率" → 先回归为"我想提升成交体量"：

> 成交额 = 各个成交端口之和。**每个端口是一条独立的数据链**：内容量 → 阅读量 → 商品点击 → 转化 → 成交。

再判断哪个端口可增长、且操作起来更快：自制内容（可控性最高，先优化它）→ 投放带来的成交（在保证投入产出的前提下增加量）→ 外部合作（拓展更多合作方）。

**因果链**：先优化人力可控、最快达成的自制内容 → 出现大量能出单的内容 → 投放顺势起来 → 店铺数据好看 → 外部合作方更愿意合作。

> **优先做人力可控、能快速达成的那一部分。**

---

## 追问 why：设变量逐一排除

定位根因时，设**"花钱"和"结果"两个变量**，逐一排查。

**一个样本**：某个功能性保健食品"几个月花了一笔预算却没结果"——

1. **钱花到位了吗？效率太低吗？** 把花费除以拿到的阅读量，得到单位阅读成本，与行业平均比——差不多，**效率不是问题，排除。**
2. **那就是内容问题。** 看内容发现：品牌的历史经验来自专业渠道，因此沟通时切的都是"很重的问题"——**而那不是这个产品能解决的。**

> **结论**：根因是**人群适配**——内容沟通的人群不对，几十万人看完没人来买。
>
> **两个变量的含义**：第一个是"花钱"（看效率：同样的钱别人带来多少阅读、你带来多少）；第二个是"结果"（收钱的端口为什么没人来）。

---

## 切断"我以为"：起点本身可能就是错的

拆完数据、追问"为什么没带来预期增量"时，核心动作是**切断"我以为"**：

> 最忌讳"我觉得／我认为／我感觉"。**只允许围绕客观事实不停追溯**：当时是怎么决策的、判断依据是什么。否则知其然不知其所以然，**以后一定还会再犯。**

**一个"起点错误"的样本**：某品牌看到自己的品牌词有一定月搜索量，决定来"收割已有认知的用户"，花了很多钱、合作了多家服务商、铺了大量品牌内容，却没有带来站外搜索增量。层层追溯发现——**问题出在起点本身**：那个搜索量**太小，不足以撬动流量杠杆**；这是对平台的定位和理解出了问题。

> **认知不纠正，后续所有动作都会变形——这才是"原点"。**
>
> 开头把问题抛给一屋子人时，每个人都会凭"我觉得"点评（内容不行、评论不精准、人群不精准），**都是片面的。只有层层追溯，才能找到背后真正的原因。**

---

## 穷举再判断，逐一排除

> **不要"我觉得"，要先做穷举再做判断。**

一个直接的例子：有人说"某个内容形态没优势"，但这个品牌压根就没做过那个形态——**那就不是这个点。** 逐一验证、逐一排除，最终锁定真问题集中攻克。

**层层追溯的样本**（"为什么阅读量不够"）：

- **预算不够**——拨预算的机制按上一期的销售定下一期的费用，形成**恶性循环**；
- **对外合作量不够**——档期被竞品截留、资源库不足、合作效率差（可能是话术、寄样周期、审核周期的问题）；
- **投流消耗不出去**——预算没到位、没有新素材、引以为傲的老内容进入了衰退期。

> **关键认知**：影响一个指标的从来不是单一维度，而是每一层级都要层层渗透。**只有到这个程度，才能真正解决问题、防止复发。**

---

## 一个问题往往不是一个问题

必须拆开、追深到"我到底要解决什么"。

- 影响"进店"（看完内容没来找你）的要素：内容种草力不够 / 市场竞争截留 / 有负面。
- 影响"转化"（进店没买）的要素：价格机制 / 详情页不打动 / 评价区有负面 / 详情页与营销内容不匹配 / **前端引来的人群不精准（最隐蔽）**。
- 一个团队同时抱怨"产能不够、招不到人、新品没人做"，**这是三件独立的事**，要分开追深。

## 五种典型的表象命题，各自的真问题

| 表象 | 真问题 | 处置 |
|---|---|---|
| **"某某玩法在我们这儿失效了"** | 学到的是对方早已不用的旧玩法，或者有效的那部分**动作没做到位**（比如做出了爆文却没做承接） | 把玩法拆成要素，逐条对照本方是否具备；不具备就**变形成本方可行的样子** |
| **"抄了竞品的爆款却没结果"** | 抄了壳子，没抄**王牌点与人群** | 抄它面向的人群、这个人群的核心关注点、内容写给谁看。**模板背后的人群和你的产品人群不是一类，就是念错了人** |
| **"我们做的都对，怎么数据和别人不一样"** | 对方带着一个未说出口的**绝对假设**（"大家都只投这一个渠道"） | 把假设拎出来，**把数据拉平了再判断**——先列出影响这个结果的所有渠道 |
| **"已经做到品类前列，还有什么玩法"** | 拿流量能力不够——内容全是收割型，前端的认知与兴趣口子没打开 | 往前走，做打开流量口的内容，而不是继续在收割层里转 |
| **"花大钱做大型合作，怕没效果"** | 营销本身有博弈风险，不可能百分之百确定 | 按合作类型**建筛选清单**（对方过往同类合作的最终数据、用户重合度、素材复用价值），逐条筛到风险足够低 |

## 问题要溯源，提问要给前因后果

**一个溯源的样本**：某品牌过去没有数据链路的意识，只知道"销售额下跌了"。按链路重新梳理之后不到一周就发现——**每月的内容量没变，但阅读量断崖式下跌，而问题其实几个月前就出现了**，因为当时没有这个意识，一直延续到现在。

> **本可以在问题出现的那个月就意识到并快速解决，但没有这个意识，就不知道问题出在哪。**

**提问也要有前因后果**：过去只会问一个点（"投入产出下降了""感觉销售没之前高"）；现在能讲清——**用了什么数据 → 拿到什么结果 → 发现的问题是什么 → 我觉得可能在哪几处 → 再沟通探讨。**

> 类比：问一个模型都得给足设定，问人却只扔一句话，当然不行。

## 两条组织纪律

- **成功不能转嫁**：如果你想把一个项目的成功交给别人，那这个项目离失败就不远了。**外部团队没有那个责任和义务必须帮你拿到结果。**
- **全员探讨，杜绝甩锅**：很多复盘开成了"甩锅会"——"这问题不是我造成的"。**甩完锅，问题还在。** 追根因这一步要把相关的人聚在一起，每个人围绕找到的问题点发言。

---

## 一个常被忽略的根因来源：对平台的理解

对平台理解不到位会直接导致决策失误：

1. **流量分发机制**：不同来源的内容生命周期差别很大——**搜索场域里一条内容的生命周期可以是曝光场域的数倍。** 不知道流量在哪，决策就会出问题。
2. **不同场景的内容需求不同**：搜索场域要信息密度高，发现场域偏人和场景。**很多公司用同一套内容投所有池子。**
3. **市场是动态平衡的**：平台不允许一种玩法长期高效，某个玩法过一段时间会失效、再过一段又可能复活。
4. **平台的新规则与新功能**：了解才能吃到红利、提高账号安全性。

> 底层逻辑：**要讨好两类人——平台和用户。**

## 本方法的输出：三条结论

用这套方法处理完，必须产出：

1. **提出的问题是真问题还是伪问题**；若是伪，**真问题是什么**——写成**一句可衡量的话，含起点数与目标数**。
2. **真问题的根因落在哪一环**：流量 / 内容 / 人群 / 渠道 / 动作没做到位 / 玩法不适配。
3. **对应的解决方向**，以及它能回归到哪一个具体的执行动作。

## 接口与边界（声明）

- **适用范围**：被任一要判断"问题是不是真问题"的环节引为共同前提的判准——**它不是一个独立环节**，换一个客户项目、换一个环节都同样适用。
- **input schema**：`原始命题`（对方原话，字符串）；`可用数据`（对象，与该命题相关的链路数据）；`参照物`（数组，来自往期／预期／行业／竞品，缺则标"缺参照物"）；`执行动作记录`（可选，数组，供过程回溯用）。
- **output schema**：`真伪判定`（枚举：真／伪）；`真问题`（一句含起点数与目标数的可衡量的话）；`根因落点`（枚举：流量／内容／人群／渠道／动作没做到位／玩法不适配）；`解决方向`（能回归到哪个具体执行动作）；`验真过程`（数组，每条含"问了什么、看了什么数、排除了什么"）；`缺参照物清单`（数组）。**可沉淀候选（reusable_candidates）**：`验真过程`里那条"问题 → 根因"的判断路径（同类命题下一次直接复用）。
- **写回位置**：**无独立落点**——判定结果随调用它的那个环节的产出一起走，进那个环节的复核包。
- **规则层与项目事实**：**不挂任何规则层**（本件不产内容、不碰红线）。所需项目事实字段：无——所需数据由调用方传入。
- **工具**：无外部接口调用。
- **决策档**：**决策**——"客户或上级提的不是真问题、真问题是另一个"这件事本身要由人来定，本件负责把数据化过程与排除路径备齐。**不得标自动。**
- **复核包**：真伪判定与真问题 ＋ 完整的验真过程（问了什么、看了哪些数、逐条排除了什么）＋ 每个参照物的出处 ＋ 缺参照物清单 ＋ 根因的追溯链（从表象一路追到根因的每一层）。
- **升级条件（命中即停交人）**：①命题涉及合规红线而判据不确定；②同一个命题在不同层的规则下指向不同的根因（四层规则冲突）；③**四个来源的参照物一个都拿不到**——此时本件跑不了，不许凭印象判；④判定结果需对外发送（要跟客户或上级说"你提的不是真问题"）；⑤判定为伪问题、真问题另有其一。

---

## 产出验收判据（DoD）

一次运行合格，当且仅当：

1. 原始命题里的每一个模糊词都被**换算成了可衡量的形态**（从多少变成多少、持续多久），没有一个模糊词被直接当作判断依据；
2. 每一个"差"都对上了一个具名参照物，并写明它来自往期、预期、行业还是竞品；**四个都没有的，已写入缺参照物清单并停下交人**；
3. 判为伪问题的，真问题写成**一句含起点数与目标数的可衡量的话**；
4. 根因落到了六个落点之一，且**追溯链完整**——从表象到根因每一层都写明"问了什么、看了什么数、排除了什么"；
5. 排除过程是**穷举之后逐一排除**的，不是直接跳到某一个结论；
6. 全程没有出现"我觉得""我以为"作为判断依据；
7. 解决方向能回归到一个具体的执行动作，不是一句方向性的话。

## Quick Reference

| 情形 | 动作 |
|---|---|
| 对方说"数据不好" | 先数据化：从多少变成多少、持续多久 |
| 不知道跟什么比 | 四个参照物来源；都没有就停下交人 |
| 想直接回答"问题是什么" | 先给问题找参照物，别先回答 |
| 拆不动一个开放问题 | 公式化拆成几条独立数据链，看哪条最快达成 |
| 要找根因 | 设"花钱"和"结果"两个变量逐一排除 |
| 一屋子人各有各的看法 | 全是"我觉得"——回到客观事实层层追溯 |
| 怀疑某个环节 | 先穷举所有可能，再逐一排除，别直接跳结论 |
| "某某玩法失效了" | 拆成要素对照本方；不具备就变形 |
| "抄了却没结果" | 看它面向的人群是不是你的人 |
| 对方带着一个未说出口的前提 | 把假设拎出来，把数据拉平了再判 |
| 追到一半好像有答案了 | 再问一层——多数人停在中间层 |

## Common Mistakes

- **用"我觉得"开场**——找不到真问题，也说服不了人。
- **没有参照物就说"差"**——"差"这个字本身没有意义。
- **照着表象的定义往下做**——解出一个伪问题，而且全程自洽、无人察觉。
- **停在中间层**——中间层的原因看着成立，但改完问题还会再犯。
- **不穷举就下结论**——排除掉的那些，很可能压根不存在于本方。
- **忽略起点本身可能就是错的**——认知不纠正，后面所有动作都会变形。
- **把多个问题当成一个**——三件独立的事混在一起，一件也解决不了。
- **只问结论不给前因后果**——扔一句话过去，得到的也只能是一句话。

## Red Flags（出现即停）

- 「我觉得是人群不精准」→ 找参照物，说出具体差距。
- 「问题很明显，不用验了」→ 先数据化再判真伪。
- 「大概就是内容的问题」→ 穷举完再逐一排除。
- 「找到原因了」→ 再问一层，看它是不是中间层。
- 「当时就是这么决定的」→ 追问判断依据，切断"我以为"。
- 「没有对比数据，先按经验判」→ 停，交人。
