# capturing-search-demand

## 概述

一句话职责：**把被种草的人在他回搜的那一刻接住并转化。**

- **搜索是链路的中轴**：搜索 UV 就是种草有没有真的发生的那道验证关。**种草做的所有教育，都会在用户回搜这一步被验证或被浪费。**
- **种草不配收割，等于把人推给竞品**：用户找的是"当下这个问题的解决方案"，不一定非你不可；他搜你的时候看到的是竞品或负面，前面投的钱就全浪费了。
- **接住比曝光更近目的**：鱼塘再大，鱼捞不进桶里就没有价值。**先把第一条鱼弄到手，再扩鱼塘。**

## 何时用 / 何时不用

**何时用**：投放跑起来、有了精准曝光，要做收口；曝光很大但搜索或销售上不去，要查承接漏在哪；发现搜索结果里被竞品、负面或仿品占位。

**何时不用**：
- 要做内容本身、配投放工具——各是上游环节。
- 要定卖货方法、算放量与止损、做复盘归因——各归各的环节。**本环节只管"他来找你的那一刻，你在不在、接不接得住"。**

## 运行前

**第一步跑 `tingle check capturing-search-demand`**，拿到开工单再开工；拿到卡点单本次不跑，按卡点单载入 REQUIRED SUB-SKILL: `tingle:project-readiness` 修完复验。开工单上附着的就绪判据由本 skill 开跑时逐条对照判，判不准停下问人。

## 业务方法

三道工序。**一、三是任何承接都要走的主干；二在要定考核口径、判断内容值不值得放量、或做异常诊断时跑。**

| 工序 | 产出什么 | 读哪份 |
|---|---|---|
| 一 · 卡位 | 关键词矩阵、坑位策略、防拦截安排 | `references/search-positioning.md` |
| 二 · 度量 | 考核口径、效率基点、卡点定位 | `references/search-metrics.md` |
| 三 · 收口 | 承接落点、内容软硬度、自然流安排、客单价收口 | `references/reception-and-organic.md` |

### 工序一 · 卡位

**禁止**：

- **禁止按热度选词。** 顺序是**先穷举、再筛选**：先想清"我的产品卖给谁""这个用户打开搜索框会搜什么"，把需求词、场景词、痛点词、品类词、品牌词全部穷举出来，**再**判断哪个竞争度低、卡位更容易、大概要做多少量。
- **禁止只做品类词。** 很多公司的关键词只有一个品类词，而围绕产品的词其实非常多元。**每多一个词，就多一个精准流量、一个新增量。**
- **禁止用带浏览历史的账号看搜索结果。** 千人千面会干扰判断，**必须用一个当天新注册、没有任何浏览行为的账号**去看真实盘面。
- **禁止套用任何固定的坑位数字。** 不同搜索词、不同类目的盘面不同，**以那个词裸号实搜到的真实盘面为准**。
- **禁止在没算账之前买搜索广告。** 搜索场域的转化率明显高于曝光场域，但**点击成本也高一个量级**。

**每个候选词逐步实测的七步**：切"最新"看更新频次 → 用"品类 + 功效 + 人群"组长尾换更松的竞争 → 切回综合、用裸号看真实盘面 → 拆核心展示形态与标题埋词规律 → 看前排的基础互动量定卡位门槛 →（可选）用投流把数据补到超过前排 → 对齐前排正在吃的内容偏向。

**判品类适不适合做卡位**：看用户在这个品类下**是不是在找"推荐、怎么选"**，以及**这个需求的月搜索量级有多大**。搜索量极低的品类做卡位没有价值——**应该往前一步，先用内容让用户从无到有产生需求。**

### 工序二 · 度量

**禁止**：

- **禁止用互动量考核搜索流量。** 用户把这里当资料库用，搜到答案就走，不会刻意互动。**搜索流量用阅读拉搜考核**——每一个能打开搜索框进来的阅读都是有效阅读，只需看"看过之后多少人愿意来找我"。
- **禁止拿发现场景的尺子量搜索场景。** 发现场景看互动与内容评分，搜索场景看阅读拉搜。**两个池子两套尺，不能混用。**
- **禁止拿前几天的数据下结论。** 这里的数据有回流周期，一条内容的价值往往要跑完一到两个月才完整。
- **禁止在基数没跨过阈值时判"内容不行"。** 有些品要几百个阅读才带来一个搜索；只有几十个阅读、阈值都没跨过，看不到结果**不是内容不行，是基数不够**。

**诊断的顺序**：销售额低要先**定位卡在哪个端口**（有效阅读量太低？阅读上来了但拉搜效率差？搜来了但转化没有？），**卡点不同，解决的侧重完全不同**。优先解决的第一件事永远是提高有效阅读量。

### 工序三 · 收口

**先想清楚承接的目的，最忌"既要又要"**：自留地（培养自制爆文能力）／品宣（传递价值、提升信任）／互动粘性／沉淀商业流量（把付费买来的人变成自有用户）。**目的不同，运营策略、内容形态、用人特质完全不同。**

**禁止**：

- **禁止用自然流表现去判承接内容的好坏。** 承接型内容大概率是硬广，**自然流不好才是正常的**；它的使命是作为抓手去做付费投放与转化。**阅读量少不等于流量差——它触达的人足够直接、足够精准。**
- **禁止为了自然流好看就把承接内容做软。** 逐层变软（纯硬广 → 加场景与痛点 → 叠干货 → 结合更大的话题）确实能放大流量口子，**但只在"有效"已经无法满足需求时才这么做**。
- **禁止不做收割就一直种草。** 要算种草与收割的比例，并持续找效率更高的组合。
- **禁止让高客单产品直接挂链接就算完。** 高客单用户会等大促、当下不下单；更该引到站外电商，让那边二次触达唤醒。**并且一定要建立承接渠道**——相当高比例的用户仍习惯到站外完成购买。
- **禁止对负面置之不理。** 高客单品类下，一条排在靠前位置的负面就足以让前面所有动作作废——**要用真实的素人内容把好内容顶上去、把负面压下去。**

## 接口与边界（声明）

- **input schema**：`投放情况`（内容源、投放词与定向、已跑出的拉搜效率高的内容，对象）；`成片清单`（数组，含封面标题里的关键词、有无挂链接）；`产品事实`（品类、客单价、决策成本、链路终点，对象）；`品牌资产`（自有账号是否认证及其定位、品牌词、已知负面，对象）。
- **output schema**：`搜索卡位方案`（关键词矩阵——每条含词、类型、搜索量级与来源、竞争度实测结论、卡位难度、目标量、是否买广告及算账；坑位策略；防拦截安排）；`承接方案`（承接落点、承接目的、内容软硬度、自然流提升点、客单价收口方式、私域动作若走留资、考核口径）；`效率基点`（阅读拉搜比、各端口折损率及其来源）；`诊断记录`（数组）。**可沉淀候选（reusable_candidates）**：本品类的阅读拉搜基点与各端口折损率、验证过的关键词矩阵、能卡上位的内容形态与埋词规律。——**它们只是候选；够不够格真的留下、沉进哪一格、标什么成色，按 REQUIRED BACKGROUND: `tingle:banking-proven-assets` 判。**
- **写回位置**：`搜索承接方案落点`（见 requirements 的 outputs 段），地址由项目档案登记，不自行选址。
- **规则层与项目事实**：运行时挂 **合规类目层**（判承接内容与评论区话术的表述边界——部分类目对引导、留资、功效表述有额外限制）与 **品牌层**（自有账号的定位与调性）；不挂类型层。所需项目事实字段：`合规类目`、`产品品类`、`品牌`、`阶段`。
- **工具**：读飞书文档与多维表格（经开工单地址取得）、写飞书文档（登记的落点）。搜索盘面的实测与关键词数据由人提供读数与截图，本 skill 不直接操作平台。
- **决策档**：**复核**——本环节决定钱和内容往哪些词上压、用户落到哪里，产出须有人过目才算数。
- **复核包**：卡位方案与承接方案本体 ＋ 每个词的竞争度实测记录（用什么账号、什么时间、看到什么）＋ 搜索量数据的来源与采集时间 ＋ 买不买搜索广告的算账过程 ＋ 效率基点的来源 ＋ 诊断记录 ＋ 待验证清单。
- **升级条件（命中即停交人）**：①承接内容或评论区话术触及合规红线而判据不确定（引导、留资、功效表述）；②四层规则冲突；③缺关键项目事实（合规类目、产品品类任一取不到）；④输出需对外发送；⑤要买搜索广告；⑥要处置负面（压制方案涉及第三方内容）；⑦判定这个品类不适合做搜索卡位、要改走别的路径；⑧拿不到任何搜索量与竞争度实测数据。

## 产出验收判据（DoD）

一次运行合格，当且仅当：

1. 关键词矩阵里每个词都能指认它**来自哪个人群或哪条需求**，且标了类型；**没有一个词是按热度选进来的**；
2. 每个进入矩阵的词都有**竞争度实测记录**（用什么账号、什么时间、看到的更新频次与前排形态），**没有一个是查热度拍脑袋定的**；
3. 每个词的搜索量级都标了来源与采集时间；取不到的标"待验证"并写明用什么工具查；
4. 买搜索广告的决定附了算账过程（这个词的搜索场域转化率与点击成本的对比），**没有算账就没有购买建议**；
5. 承接方案写明了**唯一的承接目的**，不出现"既要又要"；
6. 承接内容标了软硬度档位，并写明为什么停在这一档（"有效已经够用"还是"需要更大流量口子"）；
7. 考核口径写明搜索侧用阅读拉搜、发现侧用互动，**两套尺没有混用**；
8. 效率基点（阅读拉搜比、折损率）标了来源；本项目还没有基点的写"需先建监控"，**不借用别的品类的值**；
9. 方案里每个量化指标都挂得回一个定性意图——按 REQUIRED BACKGROUND: `tingle:keeping-metrics-anchored` 判，有孤儿指标即不合格。

## Quick Reference

| 情形 | 动作 |
|---|---|
| 要选卡位词 | 先穷举（需求／场景／痛点／品类／品牌），再筛竞争度 |
| 想知道一个词好不好卡 | 切"最新"看几屏到一天前；再用裸号看综合页真实盘面 |
| 竞争太激烈 | 用"品类 + 功效 + 人群"组长尾，拿量级换概率 |
| 不知道要做到多少量 | 看前排的基础互动量，那就是卡位门槛 |
| 品类搜索量极低 | 不做卡位，往前一步用内容唤醒需求 |
| 想买搜索广告 | 先算账；日常更划算的是用信息流去抢免费位 |
| 新内容卡不上、被自己老内容占着 | 做新形式去抢别的位置，不要指望新内容顶掉自己的老内容 |
| 搜索页全是仿品 | 补品牌词与产品词直接出现在标题封面的内容，把量铺上来 |
| 承接内容只有十几个阅读 | 正常——硬广自然流天生差，看它有没有效 |
| 曝光很大但没搜索 | 查阅读拉搜效率；先确认基数跨没跨过阈值 |
| 高客单要收口 | 不直接挂链接，引到站外电商 + 前期建立信任 |
| 品牌词下有负面 | 用真实素人内容把好内容顶上去 |

## Common Mistakes

- **按热度选词**——热的不等于精准的，转化效率上不来。
- **只做品类词**——丢掉了所有场景词、痛点词带来的增量。
- **用自己的常用账号看搜索结果**——千人千面把盘面看歪了。
- **套用固定坑位数字**——不同词、不同类目盘面完全不同。
- **用互动量考核搜索流量**——搜到答案的人本来就不互动。
- **拿前几天的数据下结论**——这里的数据有回流周期。
- **基数没到就判内容不行**——阈值都没跨过，看不到结果是正常的。
- **承接目的"既要又要"**——运营策略、内容形态、用人全都拧巴。
- **为了自然流好看把承接内容做软**——它本来就不是拿自然流的。
- **只种草不收割**——把教育好的用户推给了竞品。
- **高客单直接挂链接**——用户会等大促，当下不下单。

## Red Flags（出现即停，回到对应工序）

- 「这个词搜索量最大，先卡它」→ 回工序一，先穷举再筛竞争度。
- 「我搜了一下，前面都是我们的」→ 回工序一，换裸号再看一遍。
- 「这条内容互动太低，别投了」→ 回工序二，搜索侧看拉搜不看互动。
- 「发了一周没动静，撤了」→ 回工序二，数据有回流周期。
- 「承接号阅读太少，做软一点」→ 回工序三，先问"有效"够不够用。
- 「先把量做起来，收割以后再说」→ 回工序三，种草不配收割等于送人。
