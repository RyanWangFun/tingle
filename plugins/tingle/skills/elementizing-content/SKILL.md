# elementizing-content

## 概述

一句话职责：**把一坨内容侧的产出拆成要素、定位、找出短板。**

**这是一份方法技能**：它不对应任何一个工作环节，不读项目材料，不产出独立交付物。它被各环节以 `REQUIRED BACKGROUND:` 引为共同前提，**用来在那个环节自己要拆内容的那一步过一遍。**

- **别整条看。** 整条看只能看出"好像不错"或"好像不行"；拆成要素才知道该动哪一处。**模糊的感受和清晰的方法之间，桥梁是要素。**
- **要素之间是连乘，不是加法。** 任何一个要素接近零，整条就接近零——**所以下一步永远是补最低的那一项，不是把已经很高的做得更高。**
- **这套语言只盖内容。** 判据是那句口诀：**要问的是"这条内容好在哪、缺哪个要素"——用本件；要问的是"这单生意怎么打、钱怎么投、词怎么卡、货怎么卖"——出本件。** 把这套装置硬套到预算分配、搜索卡位、成交漏斗上，凑出来的对应关系是假的。

## 何时用 / 何时不用

**何时用**：

- **要拆已经跑赢的内容，把它凭什么赢的那几样攒下来**——复盘时最常用的一种；拆出来的要素接着交给沉淀判准判够不够格留下。
- **要诊断一条或一系列内容差在哪**——它没跑起来，得说清是哪一处拖的。
- **要拿要素装一条新的**——从已有的要素里挑、组合、换位。
- **要把散落的要素归位成一张统一的表**，让不同的人对着同一张图说话。

**注意"拆赢的"和"拆输的"是两个方向**：拆输的问"哪一项是短板"，拆赢的问"哪几项凑出了这个结果、其中哪几项换条内容还能再用"。两个方向走的是同一套语法，但结论不同——**别把拆爆款做成挑毛病。**

**何时不用**：

- **要去找要素**——去哪找、找几家、看多少条，是各环节自己的对标工序，本件不管。本件只管"拿到之后怎么拆"。
- **要判一个要素够不够格留给下一单复用**——那是另一套判准（证据够不够、验过几次），本件的三属性闸只判"它算不算一个要素"，不判"它值不值得留下"。
- **要判内容之外的事**——投多少钱、卡哪个词、怎么成交、怎么归因，全部出本件。

**本件不独立运行**，没有运行前检查，由引它的技能在自己的工序里加载。

## 方法

三道工序按序走。**工序二、三的细节在各自的深读件里，走到那一道再读那一份。**

| 工序 | 交出要素分解表的哪几列 | 读哪份 |
|---|---|---|
| 一 · 拆成要素（过三属性闸） | 要素、粒度、三属性判定 | 本页 |
| 二 · 定位（层栏归属、外壳还是内核） | 层栏、外壳／内核归属 | `references/pyramid-and-shell.md` |
| 三 · 乘法体检（四维打分、点出短板） | 四维分、短板标记 | `references/multiplication-check.md` |

### 工序一 · 拆成要素（三属性闸）

**逐层剥到最小单元**——一个镜头、一句话、一个词、一个动作、一张脸、一个需求、一个人群标签都可能是一个要素。**判断不看它长什么样，只过下面三条闸。**

| 属性 | 判据 | 不过的样子 |
|---|---|---|
| **重要** | 它离结果近吗、容易爆吗 | 有它没它结果一样——那是装饰，不是要素 |
| **重复** | 换一条内容还能再用吗 | 只在这一条里成立，换一条就不成立 |
| **独立** | 能被单独拆出来打磨、能和别的要素组合吗 | 抠出来就散了，离开原文什么都不是 |

**三条缺一，它就只是一个点，不是一个要素**——不进分解表。

**禁止**：

- **禁止把整条内容当成一个要素。** 分解表只有一两行，说明根本没拆——回去继续剥，剥到"能被单独换掉"为止。
- **禁止把感受写进要素名。** "有质感""高级""一看就想买"不是要素，是没拆完的感受。**把感受拆成可下任务的维度**（是肥瘦、顺泽、纹理、透明度、清晰度，还是别的），拆不动就说明这一处还没看懂。
- **禁止抽象改写。** 要素名一律用原话——素材里怎么说就怎么记，用户怎么说就怎么记。**往上抽象一层，可复用的那个颗粒度就丢了。**
- **禁止漏掉重复出现的东西。** **任何东西出现两次，很可能就是一个要素——立刻双击它。** 出现两次以上还没进表，是漏拆不是不重要。

### 工序二 · 定位（详见 `references/pyramid-and-shell.md`）

每个要素做两件定位，都要落进分解表：

1. **挂层栏**——它落在四层（需求／人群／类型／特征）的哪一层，还是底部三栏（脚本主要素／最小内核／视觉主要素）的哪一栏。**塔里没有的一律归到"特征"层**，不要因为列表里没有就当它不存在。
2. **判外壳还是内核**——它是管引流与停留的那一段，还是管转化与成交的那一段，抑或两者都能用。

**禁止**：

- **禁止把"外壳"当成头三秒。** 外壳是一系列内容的开头策略，不是某一条的前三秒。混掉这一条，"找一堆验证过的开头跳着装到不同内核前面"这个动作就无从谈起。
- **禁止把四层当成加法。** 四层是相乘的——**一层接近零，整条就接近零**，不是"其他三层好就能补回来"。

### 工序三 · 乘法体检（详见 `references/multiplication-check.md`）

**沿四维给每个要素打分：数量（乘进去了几个）／权重（这个要素本身的天花板）／分数（这一个做到几分）／时间（还能有效多久）。** 打分两个方向共用一套，**但交出的结论不同——按拆解目的分**：

| 拆的是 | 结论交什么 |
|---|---|
| **没跑起来的**（诊断找短板） | **点出乘积最小的那一项**，并说清下一步补它到什么程度算补上了 |
| **已经跑赢的**（拆爆款攒要素） | **点出哪几项凑出了这个结果**，并逐项标出**它换条内容还能不能再用**——能再用的那几项才是要攒的，只在这一条里成立的（时机、热点、一次性资源）单独标出来、不要攒 |

**禁止**：

- **禁止把长板做得更高**（诊断向）。它是连乘——把 9 分做到 9.5 分，不如把 2 分做到 5 分。**诊断时分解表交出去必须点名短板是哪一个**，点不出来这一次体检就没做。
- **禁止把拆爆款做成挑毛病。** 一条已经跑赢的内容当然也有短板，但拆它的目的不是修它，是**取走它身上还能再用的那几样**。交一份"这条爆款有哪些不足"回去，等于这一趟白拆。
- **禁止拆完爆款不区分"能再用的"和"只这一次成立的"。** 分不出来，攒进去的就是一堆下次调不出来的东西——**这一格分不清的，宁可标不确定，别当成能再用的攒。**
- **禁止拿数量凑分数。** 一百个各拿一次的低分要素，乘不过两个高分要素相插。
- **禁止无视时效。** 一个要素今年有效不代表明年有效；**去年的满分是今年的起点**，过期的要标出来重新打磨，不能当现成的用。

## 接口与边界（声明）

- **适用范围**：「把一坨内容侧产出拆成要素、定位、找短板」——**它不对应链上任何一站**，是横切多个环节的方法与判准，被别的技能引为共同前提。这件事**换一个客户项目、每一次内容工作都会再次发生**，非一次性事务；且它同时被内容侧多个环节共用（这两条正是它立为方法而非某一个环节正文的理由）。
- **input schema**：`待拆产出`（一坨内容侧的原始产出：一批对标素材、一组人群草稿、一串需求词、一条或一系列内容，形态不限，由调用方在会话里递入）；`拆解目的`（枚举：拆爆款攒要素／诊断找短板／装一条新的／盘点家底——决定三道工序各走多深，也决定工序三交出的是"哪一项拖了后腿"还是"哪几项凑出了结果"）。**每次输入不一样，不登记进项目档案。**
- **output schema**：`要素分解表`（数组，每行含：要素、粒度、三属性判定、层栏、外壳或内核归属、四维分、是否短板、原话出处）；`体检结论`（对象，按拆解目的二选一：**诊断向**＝短板要素、它落在哪一层栏、下一步补它到什么程度算补上了；**拆爆款向**＝凑出这个结果的那几项、各自"换条内容还能不能再用"的判定、以及被判为只在这一次成立的那些项）；`未过闸的条目`（数组，每条含它被三属性里的哪一条拦下）。**可沉淀候选（reusable_candidates）**：`要素分解表` 里过了三属性闸的那些行——**它们只是候选，够不够格留给下一单复用由 REQUIRED BACKGROUND: `tingle:banking-proven-assets` 判，本件不判。**
- **写回位置**：**无**。本件不写任何落点——分解表交回调用方，由调用方写它自己声明的落点。
- **规则层与项目事实**：**四层规则一层不挂**（本件不产对外内容、不碰红线，只做拆解与定位）。所需项目事实字段：**无**。
- **工具**：**无**。不读写任何文档与表格、不调任何平台接口、不读文件系统——本件只吃调用方递进来的那一坨东西。
- **决策档**：**自动**。三道工序的每一步做错了，调用方在紧接着的下一步就会撞上（分解表只有一行则挑不出短板；层栏与内容对不上一眼看得出；外壳内核归属判错则铁律校验自相矛盾），故不必逐次交人。本件不对项目走向本身做判断。
- **复核包**：交人复核时随附——要素分解表本体 ＋ 每个要素的原话出处 ＋ 未过三属性闸的条目及其被哪一条拦下 ＋ 短板结论及其打分依据。
- **升级条件（命中即停交人）**：①合规红线不确定；②四层规则冲突；③缺关键项目事实；④输出需对外发送；⑤同一个要素在层栏归属上两可，且两种归法会导出不同的短板结论。（①–④在本件极少出现，出现即停、不自行推进。）

## 产出验收判据（DoD）

一次运行合格，当且仅当：

1. 分解表里**每一行都过了三属性三条闸**，且未过闸的条目单独列出、各自写明被哪一条拦下；
2. **每个要素名都是原话**——素材或用户的原本措辞，不是往上抽象一层的概括词；
3. **每一行都有层栏归属**，塔里没有的归在"特征"层，无一行留空；
4. **每一行都标了外壳／内核归属**（或标明两者都能用）；
5. **工序三交出了与拆解目的相符的那一种结论**——拆没跑起来的，**点名短板是哪一个要素**并写清它落在哪一层栏；拆已经跑赢的，**点名哪几项凑出了结果**并逐项标了"换条内容还能不能再用"。**只列分数、不给这两种结论中的任何一种，判不合格；给错方向（拆爆款交回一份毛病清单）同样判不合格；**
6. 分解表的行数**多于一行**——只有一行等于没拆；
7. 出现两次以上的东西**没有一个漏在表外**。

## Quick Reference

| 情形 | 动作 |
|---|---|
| 拿到一坨东西不知从哪下手 | 先剥到最小单元，再过三属性闸 |
| 有一条跑赢了，想知道凭什么 | 拆爆款向——点出哪几项凑出了结果，逐项判还能不能再用 |
| 拆完爆款要把要素攒起来 | 交给沉淀判准判够不够格留下，本件不判 |
| 拆爆款时发现它也有短板 | 记一笔就行，别把这趟做成挑毛病 |
| 某一项是靠当时的热点／一次性资源 | 标成只这一次成立，不要攒 |
| 某一处到底算不算要素 | 问三条：离结果近吗／换一条还能用吗／抠出来还成立吗 |
| 某个东西在列表里找不到位置 | 归"特征"层——它是开放接口，不是漏了 |
| 说不清这条为什么爆 | 沿四层逐层问：需求清不清、人群对不对、类型选得好不好、特征够不够明显 |
| 想拔高但不知道动哪 | 打四维分，动乘积最小的那一项 |
| 四个要素三个满分一个近零 | 整条接近零，先补那个近零的 |
| 要换开头 | 那是外壳——一系列的开头策略，不是这一条的前三秒 |
| 开头和转化段都想换新 | 只动一头，另一头用已验证的 |
| 某个要素去年很好使 | 标时效，重新打磨过再用 |
| 同一个东西出现了两次 | 双击它，八成是个要素 |
| 要问钱怎么投、词怎么卡 | 出本件，这套语言不盖那些 |

## Common Mistakes

- **整条看，然后说"感觉差点意思"**——没拆就没有下一步动作。
- **要素名写成感受**——"有质感"不是要素，是还没拆完。
- **把原话往上抽象**——抽象一层，可复用的颗粒度就没了。
- **只列了一两行就说拆完了**——那是把整条当成了一个要素。
- **层栏留空，或因为列表里没有就丢掉**——塔外的归特征层。
- **把四层当加法**——以为三层好能补一层垮，实际是相乘。
- **把外壳理解成头三秒**——外壳是一系列的开头策略。
- **打完分不给结论**——分数只是过程；诊断向的结论是短板，拆爆款向的结论是"哪几项在起作用、哪几项还能再用"。
- **拆爆款拆成了挑毛病**——交回一份不足清单，该取走的东西一样没取。
- **拆完爆款不分"能再用"和"只这一次成立"**——攒进去的是一堆下次调不出来的东西。
- **专挑长板加码**——连乘里这是最不划算的一种努力。
- **拿要素数量凑结果**——一百个低分乘不过两个高分。
- **把这套装置套到内容之外**——预算、卡词、成交、归因都不适用，凑出来的对应关系是假的。

## Red Flags（出现即停，回到对应工序）

- 「这条整体感觉不错」→ 回工序一，拆了再说。
- 「这一处不好描述，先写'高级感'吧」→ 回工序一，把感受拆成可下任务的维度。
- 「原话太土了，我提炼一下」→ 回工序一，记原话。
- 「这个塔里没有，跳过」→ 回工序二，归特征层。
- 「外壳嘛，就是开头三秒」→ 回工序二，外壳是一系列的开头策略。
- 「开头和转化段一起换新，一次测完更快」→ 回工序二，只动一头。
- 「这几项都挺高的，再往上顶一顶」→ 回工序三，找最低那一项。
- 「短板不太好说，先把分列上」→ 回工序三，点不出结论等于没体检。
- 「这条爆款其实也有不少毛病，我列一列」→ 回工序三，拆赢的是来取东西的，不是来挑毛病的。
- 「这几项都算能再用吧」→ 回工序三，分不清的标不确定，别当成能再用的攒。
- 「这条要素以前特别好使，直接用」→ 回工序三，先看时效。
