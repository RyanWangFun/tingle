# reviewing-campaign-results

## 概述

一句话职责：**把跑出来的数据归因到根因，并把它沉淀成下一单能直接用的东西。**

- **复盘不是过一遍数据、填一张表**：没有建立客观的链路和流程、没有回到底层逻辑，填完了问题还会再犯。
- **能看结果就优先看结果**：只有在结果指标反馈太慢时才往前推、看过程指标；**过程指标永远只是参考，绝不能当结果本身。**
- **经验会说谎，数据不会**：坚持数据导向不是因为数据更准，是因为**数据可复制**——降低对个人手感的依赖，运营才可控。

## 何时用 / 何时不用

**何时用**：一单或一个周期跑完；上级抛来一句模糊命题（"销售没之前高""投入产出下降了"）；周期性与节点性复盘；异常事件复盘；要由过去数据倒推下期规划；跑出一个被验证的模型要把它沉淀下来。

**何时不用**：
- 数据还没跑出来、还在做方案——那是上游各环节。
- 要把复盘结论直接改成新的投放动作、新的内容——**本环节交出归因与回流条目，不代下游做决策。**

## 运行前

**第一步跑 `tingle check reviewing-campaign-results`**，拿到开工单再开工；拿到卡点单本次不跑，按卡点单载入 REQUIRED SUB-SKILL: `tingle:project-readiness` 修完复验。开工单上附着的就绪判据由本 skill 开跑时逐条对照判，判不准停下问人。

## 业务方法

**总骨架是四步，不可缺一**：① 系统扫描、明确并量化目标 → ② 预期与实际逐维比对、定位维度 → ③ 层层追溯根因 → ④ 沉淀为可复制资产。下面五道工序挂在这四步之下。

| 工序 | 对应四步的哪一步 | 读哪份 |
|---|---|---|
| 一 · 套四步骨架、定参照物 | ①② | `references/review-four-steps.md` |
| 二 · 拆销售额与生意端口 | ② | `references/sales-decomposition.md` |
| 三 · 分层归因，定位卡点 | ③ | `references/layered-attribution.md`；**拆爆款攒要素那一半**按 REQUIRED BACKGROUND: `tingle:elementizing-content` |
| 四 · 判过程指标该不该看 | ③ | `references/process-vs-result-metrics.md` |
| 五 · 建数据基点、沉淀回流 | ④ | `references/benchmarks-and-feedback.md`；**够不够格沉、沉哪一格、什么成色**按 REQUIRED BACKGROUND: `tingle:banking-proven-assets` |

**验真问题贯穿工序一与工序三**：凡上级或客户给的是一句模糊命题、或拿一个表象让你照做，先按 REQUIRED BACKGROUND: `tingle:validating-the-real-problem` 把它验真、追到根因，再往下走。

### 工序一 · 套四步骨架、定参照物

**禁止**：

- **禁止用"我觉得"开场。** 面对"为什么没做到"，绝大多数人只会甩"我觉得转化率不高""我觉得人群不精准"——**这既找不到真问题，也说服不了任何人。** 要把"差"界定成"比谁低多少"的具体差距。
- **禁止在没有参照物时下结论。** 参照物只有四个来源：往期数据、原定预期、行业数据、竞品数据。**四个都没有，就先去建监控，而不是先下结论。**
- **禁止把目标定得太大太泛。** 目标太泛就无法往下找原因。
- **禁止把多个问题当成一个问题处理。** 一个问题往往不是一个问题，要拆开、追深到"我到底要解决什么"。

### 工序二 · 拆销售额与生意端口

**两条公式各有各的用途**：`销售额 = 流量 × 客单价 × 转化率 ×（1 + 复购率）` 用于定位大方向（**先解决流量**，客单价相对固定、转化率大致固定）；`内容 → 曝光 → 阅读 → 回搜 → 转化` 用于定位是哪一环、由什么要素决定。

**禁止**：

- **禁止只看一个总数。** 先把生意按端口拆开（新增内容／历史内容／投放／直播／商品卡／其它），再看是哪个端口出了问题。
- **禁止不分新老内容。** 新发内容通常只占总生意的一小部分；**"最近新内容流量差"往往是正常现象**——流量没变，只是流向了被验证过的老内容。不分新老，所有关于产能与目标的推算都会错。
- **禁止忽略折损率。** 链路每一段都在漏，**前端阅读量太低时，再乘折损几乎就没有搜索，自然没有销售额**——这时候的问题不在转化端。

### 工序三 · 分层归因，定位卡点

**分层归因的总表**：曝光低 = **选题**问题；曝光正常但阅读低 = **封面标题**问题（不是选题问题）；阅读正常但回搜低 = **正文**问题；回搜正常但转化低 = **人群精准度**（以及价格、详情、口碑）。

**禁止**：

- **禁止一上来就猜"是内容问题还是投放问题"。** 所有排查都是**由粗到细**：先站在生意逻辑上整理整条链路的数据 → 判断卡点在哪个维度 → 判断影响这个维度的要素 → 围绕要素解决。
- **禁止把点击率当成有绝对值的指标。** 不同内容类型的合理区间差很多，**必须在同一类型下，和自己的历史、合作方的历史、竞品比对。**
- **禁止把大爆文当成果。** **有互动但没带来搜索的爆文是无效爆文。** 前面环节都"绿了"而结果没来，往往就是把过程指标错当了结果指标。
- **禁止一棒子打死。** 复盘是**分层 → 找共性 → 放大**：曝光高说明选题对，阅读高说明封面标题对，转化高说明正文对——**把它们组合起来，而不是整体否定。**

**这一道有两半，别只做诊断那一半。** 拆没跑起来的是**诊断**（找短板），拆已经跑赢的是**取东西**（把它凭什么赢拆出来、攒成下一单能调用的要素）。**后一半按 REQUIRED BACKGROUND: `tingle:elementizing-content` 执行**——拆成要素、定层栏与外壳内核归属、逐项判"换条内容还能不能再用"。

**禁止把拆爆款做成挑毛病**：拆赢的那条是来取东西的，不是来修它的。**也禁止拆完不区分"能再用的"与"只这一次成立的"**——靠热点、靠一次性资源、靠特定档期赢的那些，攒进去下次也调不出来。

### 工序四 · 判过程指标该不该看

**唯一的判断主轴是决策周期长短、结果反馈快慢**：超长决策、反馈慢的品该看过程指标；快决策的品不该看；**结果已经看得清的，优先看结果，别往前推。**

**禁止**：

- **禁止把过程当结果。** "团队搭在哪""做了多少条爆文""人群层涨了多少"都是过程；**招到人不等于项目能起，人群层涨了不等于生意成了。**
- **禁止把别人的过程指标基准当通用真值。** 每个行业有自己的特征和标准。
- **禁止把跨端口重复计算的转化当成真实增量。** 同一个用户会被多个端口各记一次，**要用控制变量法核算比例，最终衡量整体总账。**

### 工序五 · 建数据基点、沉淀回流

**基点必须从历史或竞品归因得来**：从结果往前推 → 从成功者（自己跑得好的、或成功的竞品）身上找归因 → 得到参考标准 → 套用到实际再验证。

**回流条目是候选，不是资产。** 哪些够格真的留下、沉进哪一格、标什么成色，**按 REQUIRED BACKGROUND: `tingle:banking-proven-assets` 判**——本 skill 只负责把候选连同它的证据与来源交出来，不自行放宽标准。

> **与工序三的接力关系**：工序三用要素化语法把跑赢的那条拆成要素、判出哪几项"换条内容还能再用"；这一道再判它们"证据上够不够格沉"。**前者判形态上能不能复用，后者判证据上够不够格——两道闸不重叠，都要过。**

**禁止**：

- **禁止把某个示例阈值当通用基准线。** 基点随品类、内容形态、自身历史而变，**必须自己建一条。**
- **禁止等整个周期结束才回收数据。** 要以周或月为单位回收、及时补缺口。
- **禁止把沉淀留在个人身上。** 天赋型选手的经验也要建成团队基点——**把人的手感外化成客观基点**，否则人一走经验就没了。

## 接口与边界（声明）

- **input schema**：`目标与原定指标`（对象，含主指标与过程指标链）；`本期数据`（对象，含链路各环数据、各端口营收、花费）；`产品事实`（决策成本、是否有复购、客单价、毛利，对象）；`参照物`（数组，往期／预期／行业／竞品，缺则标"缺参照物"）；`本期执行动作记录`（数组，供过程回溯用）。
- **output schema**：`归因结论`（卡点环节、病灶落点、是内容还是产品还是人群、是否存在脱锚）；`真问题界定`（真伪、真问题一句话、根因、可复用经验与不可复制的时机因素之分）；`各端口完成率`（数组）；`回流条目`（数据基点数组，每条含环节、阈值、来源；值得放量的内容与人群；要建的流程与文档；下次怎么用）；`下期规划倒推`（可选，含新老贡献率、可预估端口与变量端口、先求稳的预估值、人品配置）；`缺参照物清单`（数组）。**可沉淀候选（reusable_candidates）**：`回流条目`全部（这是本环节存在的理由）、`归因结论`里那条"问题 → 根因"的判断路径、验证过的内容模板与人群、识别不合格合作方的数据画像。——**它们只是候选；够不够格真的留下、沉进哪一格、标什么成色，按 REQUIRED BACKGROUND: `tingle:banking-proven-assets` 判。**
- **写回位置**：`复盘报告落点`（见 requirements 的 outputs 段），地址由项目档案登记，不自行选址。
- **规则层与项目事实**：运行时挂 **品类层**（各环节的基准区间随品类变）与 **品牌层**（历史基点）；不挂通用层与类型层——本环节不产对外内容。所需项目事实字段：`产品品类`、`品牌`、`阶段`、`合规类目`。
- **工具**：读飞书文档与多维表格（经开工单地址取得）、写飞书文档（登记的落点）。各平台后台数据由人提供读数，本 skill 不直接调用任何数据后台。
- **决策档**：**复核**——归因结论会直接改变下一单的资源投向，须有人过目才算数。
- **复核包**：复盘报告本体 ＋ 每条归因的排查路径（由粗到细的定位过程）＋ 每个数字的来源与统计周期 ＋ 参照物的出处 ＋ 缺参照物清单 ＋ 回流条目及其阈值来源 ＋ 被判为"不可复制的时机因素"的那部分及其理由。
- **升级条件（命中即停交人）**：①归因涉及合规问题（违规、下架、处罚）而判据不确定；②四层规则冲突；③缺关键项目事实（产品品类、阶段任一取不到）；④输出需对外发送（交给客户、进季度评审）；⑤判定上级或客户提的是伪问题、真问题另有其一；⑥判定某个方向、某个合作对象要停；⑦四个来源的参照物一个都没有；⑧要把某条结论定为团队基准线。

## 产出验收判据（DoD）

一次运行合格，当且仅当：

1. 目标已量化，且每个"差多少"都对上了一个具名参照物（往期／预期／行业／竞品）；**四个都没有的，已写入缺参照物清单并停下交人**；
2. 生意已按端口拆开，**内容端口已分新增与历史两类**；分不开的已写明原因；
3. 卡点定位到了具体环节，并写明**由粗到细的排查路径**（先看了什么、排除了什么、才落到这一环）；
4. 每个引用的比率、阈值都标了来源与统计周期；**引用示例值的地方明确标注"示例、非本项目基准"**；
5. 点击率类指标的比对是在**同一内容类型下**做的，并写明比的是自己历史、合作方历史还是竞品；
6. 判为伪问题的，真问题写成一句含起点数与目标数的可衡量的话，并写明根因；
7. **区分了"不可复制的时机因素"与"可复用的经验"**，两者各自列出；
8. 回流条目里每条数据基点都写明它由什么归因得来，**没有一条是照搬的**；
9. 拆跑赢的那条时，每个抽出来的要素都标了**它挂在哪一层哪一栏**，以及**换条内容还能不能再用**（能再用／只这一次成立／不确定）；靠热点、一次性资源、特定档期赢的已被单独标出；
10. 每条回流条目都标了**它沉进哪一格、成色是哪一档**，以及被哪一条资格闸拦下（若未过闸）；**成色没标或格没定的，不算完成沉淀**；
11. 如果做了下期倒推，可预估端口与变量端口已分开，且遵循"先求稳"；人品配置没有出现"新人配新品"；
12. 报告里每个数字都挂得回一个定性意图——按 REQUIRED BACKGROUND: `tingle:keeping-metrics-anchored` 判，**前面全绿而结果没来的情况已被显式标为脱锚**。

## Quick Reference

| 情形 | 动作 |
|---|---|
| 上级说"销售没之前高" | 先数据化：从多少变成多少、连续多久，再验真伪 |
| 不知道该跟什么比 | 四个参照物来源：往期／预期／行业／竞品；都没有就停 |
| 销售低 | 先拆端口，再拆链路环节，别一上来猜原因 |
| 新内容流量很差 | 正常现象——流量流向了被验证过的老内容 |
| 曝光正常但阅读低 | 封面标题问题，不是选题问题 |
| 阅读正常但没回搜 | 正文问题、内容引导不到位 |
| 回搜正常但没转化 | 先查前端引来的人群精不精准 |
| 有大爆文却没结果 | 无效爆文；查它的关注点是不是落在产品上 |
| 前面全绿、结果没来 | 脱锚——把过程指标当成了结果指标 |
| 想看人群资产类过程指标 | 先判决策周期：快决策的品不该看 |
| 跨端口的转化对不上 | 重复计算，用控制变量法核算比例 |
| 要定一条基准线 | 从自己历史或成功竞品归因得来，不照搬 |
| 复盘完了 | 沉淀成基点与流程，否则这一单白跑 |

## Common Mistakes

- **用"我觉得"做归因**——找不到真问题，也说服不了人。
- **没有参照物就下结论**——"差"这个字本身没有意义。
- **只看总数不拆端口**——问题是"总的"，就没有抓手。
- **不分新老内容**——所有关于产能和目标的推算都会错。
- **一上来就猜是内容还是投放**——排查必须由粗到细。
- **把点击率当有绝对值的指标**——不同类型差很多。
- **把大爆文当成果**——没带来搜索的爆文是无效的。
- **把过程指标当结果指标**——招到人不等于项目能起。
- **照搬别人的基准线**——每个行业有自己的特征。
- **等周期结束才回收数据**——错过了所有可纠正的节点。
- **一棒子打死**——曝光高的选题、阅读高的封面、转化高的正文，本该被组合起来复用。
- **复盘完不沉淀**——下一单从零开始，这一单等于白跑。

## Red Flags（出现即停，回到对应工序）
