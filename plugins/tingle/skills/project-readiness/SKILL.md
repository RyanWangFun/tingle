# project-readiness

## 概述

全家族「项目就绪」的唯一承担者，一句话职责：**判定「这个项目对这名成员、这一次运行就绪没有」；不就绪，就编排补齐到就绪。** 诊断只是第一步，补齐才是目的。

三条基座（记牢）：

- **判定引擎只此一份**：三步就绪判定在本 skill 内唯一实现。各 work-skill 的运行前检查只是一行调用本 skill，不自带任何判定逻辑；入口 skill（using-tingle）只锚定与路由，不判定。要改判定规则，只改本 skill 与其参考件这一处。
- **就绪按人各自判、每次现算**：装备、授权、锚都是个人的——同一项目对甲成员就绪、对乙成员可能不就绪；就绪结论不落盘、不复用、不互相代表。两层状态只存事实（地址、日期），不存结论（就绪勾）。
- **对外动作先放行**：凡写飞书（建文件夹 / 建表 / 建档案 / 改档案），先产出待建内容清单、停、等使用者放行——这是本 skill 的永久行为，不是可省略的礼节。

两层状态模板（项目档案 JSON 模板 / 本地锚模板）、requirements 声明格式与多人运行原则的完整规定，见随身参考件 `references/readiness-contract.md`；本文保留可执行主干——单凭本文即可跑完三步判定与补齐编排。

## 何时用 / 何时不用

**何时用**：使用者要把某个项目弄就绪（初始化新项目、加入已初始化的项目）；入口路由过来（本地锚缺失 / 不可解析）；任一 work-skill 运行前的检查触发（一行调用）；怀疑某项运行前提失效要复核。

**何时不用**：
- **会话开始的项目锚定与路由**（当前在哪个项目工作、帮建工作文件夹）——归 using-tingle；本 skill 从已锚定的项目工作文件夹起步。
- **材料工序本体**（引导收料、材料上云盘、蒸馏、重蒸）——归 context-distill；本 skill 只当黑盒调用并验收结果。
- **任何具体业务环节**（选题 / 审稿 / 内容 / 投放 / 分析）——归各 work-skill；本 skill 只回答「能不能跑」，不干业务的活。
- **共享数据底座等项目外设施的建设**——本 skill 只验通可用，不建、不修其内部。

## 两层状态模型（速览）

- **项目级＝飞书「项目档案」**：一项目一份，落在项目云盘**顶层**的一份 lark-doc，标题固定为「tingle-项目档案」，正文为约定结构的 JSON 代码块（档案 schema 版本当前为 **1**）。记项目身份（id / name）、标签（品类三级＋品牌）、阶段、各 skill 的输入地址、项目级初始化完成日。项目内全体成员共读共用同一份。
- **个人级＝本地薄锚 `.tingle/state.json`**：每名成员一份，落在自己机器上该项目工作文件夹根下的 `.tingle/` 内。仅三字段：`tingle_state_version`（当前为 **2**）、`profile_link`（项目档案链接）、`initialized_at`（个人级初始化完成日）——没有第四个字段，不存任何输入地址。
- 一个项目 N 名成员＝ **N 份锚＋1 份档案**；一切输入地址只记在档案一处，地址变更只改档案，各成员下次运行自动获得新地址。两份模板的字段全文见参考件。

## 三种入径与返回契约

| 入径 | 触发 | 行为 |
|---|---|---|
| ① 用户直呼 | 使用者说「把这个项目弄就绪」等 | 对该项目启用的全部 work-skill 跑三步判定 → 不就绪则进补齐编排 → 复验 |
| ② 被入口路由 | using-tingle 扫锚发现缺失 / 不可解析，路由过来 | 同直呼径。判定会自行揭示是「项目未初始化」还是「项目已初始化、仅这名成员个人未就绪」（后者走加入路径，见下） |
| ③ 被 work-skill 运行前一行调用 | 该 skill 每次运行前 | 只以该 skill 为目标跑三步判定，按下述返回契约返回 |

**一行调用的返回契约**：
- **就绪** → 返回「放行」＋该 skill 全部声明输入的**已解析地址**（从档案 `skills.<skill_name>` 段取出，逐输入给 `type` 与对应值字段：`lark-doc`→`link`；`lark-base`→`base_token`＋`table_id`；`lark-drive`→`folder_token`）。调用方直接照地址取用，不再自行读档案。
- **不就绪** → 返回「不就绪」＋卡点清单（卡在三步哪一条）＋补齐去向；**该 skill 本次不运行**。

**work-skill 侧的标准一行写法**（各 work-skill 的运行前检查一节照此照抄，此外不得自带任何判定步骤）：

```markdown
**Step 0 · 运行前检查（仅此一行，不自带判定）**：REQUIRED SUB-SKILL: `tingle:project-readiness`
——传入本 skill 名；返回「放行」才继续运行，并以其返回的已解析地址为各输入的取用地址；
返回「不就绪」则本次不运行，待其补齐并复验通过后重来。
```

## 引擎 procedure：三步就绪判定（唯一实现）

三步顺序不可颠倒——环境是最基础依赖，环境不全，档案与资源也读不了。**三步全过＝本次就绪；任一步不过＝不就绪，转入补齐编排，不运行这一次。** 判定全程只读（读文件、读飞书、跑只读命令），不写任何东西。

**目标 skill 的取法**：一行调用入径＝发起调用的那个 skill；直呼 / 被路由入径＝该项目启用的全部 work-skill（与使用者确认本项目实际用哪些；缺省＝插件内全部带 requirements 声明的 work-skill），逐个过第二步第 6 查与第三步。

### 第一步 · 环境（现场查，永不落盘）

按**官方装备清单**（当前 v1；清单按需可扩展——新 skill 入驻带新依赖时，随其 requirements 声明进清单）逐项核查，全部成立才过：

1. **lark-cli 二进制已装**：`command -v lark-cli` 有输出；
2. **lark-* skill 目录全套在场**：`~/.claude/skills/lark-*` 或 `~/.agents/skills/lark-*` 路径下存在完整一套 lark 相关 skill 目录；
3. **lark-cli 授权有效**：`lark-cli auth status` 返回已授权状态；
4. **tingle 插件自身已装**：核对插件处于已安装、已启用状态。

任一项不成立→环境未就绪，**不必再看第二、三步**，先转补齐编排的装备 / 权限道次。环境状态永远现场查、永不写进锚或档案。

### 第二步 · 锚与档案（六查，按顺序）

1. **锚在**：当前项目工作文件夹下 `.tingle/state.json` 存在，且 `tingle_state_version`、`profile_link`、`initialized_at` 三字段齐全非空；
2. **锚版本匹配**：`tingle_state_version` 值等于 **2**（当前锚 schema 版本）；
3. **档案打得开**：以 lark-doc 打开 `profile_link` 指向的文档，能读取正文中的 JSON 代码块并成功解析；
4. **档案版本匹配**：档案 `tingle_profile_version` 值等于 **1**（当前档案 schema 版本）；
5. **档案项目字段齐**：`project.id`、`project.name` 存在且非空；`project.tags.品类` 下三级（`业务线` / `合规类目` / `产品品类`）均存在且非空；`project.tags.品牌` 存在且非空；`project.阶段` 存在且非空；项目级 `initialized_at` 字段存在；
6. **目标 skill 输入齐**：目标 skill（按其名字）在档案 `skills` 段下有对应键，且该键下每一个输入字段齐全——`type` 有值，且按 `type` 对应的值字段有值（`lark-doc`→`link`；`lark-base`→`base_token`＋`table_id`；`lark-drive`→`folder_token`）。

任一查不成立→不就绪：第 2、4 查（版本不匹配）→**路由重建**——锚版本不匹配按当前模板重建锚；档案版本不匹配重建 / 升级档案（写飞书，先放行）；其余各查→路由补齐（对应道次见编排节的卡点映射表）。

### 第三步 · 验（地址可达＋就绪判据）

对目标 skill 在档案 `skills` 段下记录的**每一个输入**，逐个执行两项：

1. **地址当场打得开**：按 `type` 对该地址轻量访问一次——`lark-doc` 读取文档标题、`lark-base` 读取表的基本信息、`lark-drive` 列出文件夹内容——访问成功即通过。链接失效、资源被删、**当前成员权限不足**都在此项暴露；
2. **就绪判据逐条过**：该输入在其 skill 的 requirements 里声明的每一条「就绪判据」，当场验证成立；未声明判据的输入，只做第 1 项。

任一输入任一项不过→不就绪，转入修复：地址失效→更新档案中对应配置（写飞书，先放行）；判据不过且该输入标有 `produced_by`→调该生产者 skill 重产此输入（如蒸馏产物→回调 context-distill 重蒸，此时项目云盘 `folder_token` 由本 skill 从档案解析后传入）；无 `produced_by` 的输入→转补齐编排或人工修复。

**同一个输入，调过生产者之后仍不过 → 停，不再重试。** 生产者跑完后复验该输入，**仍缺或判据仍不过**时立刻停下，**不做第二次回调**——同样的调用第二遍不会有不同结果，只会一圈圈转，而且转得无声无息。停时报出四样：①**这个输入的名字**；②**调了哪个生产者**；③**该生产者报的完成状态**；④**一句诊断**——「生产者跑完了但这件仍缺，很可能它不在该生产者的产出清单里：名字不符 / 尚未接入 / 模板未就位」。**这不是本 skill 能修的**：真正的修法是把那件东西接进生产者的产出清单与物料 IO 表，或改正声明里的输入名——交人处理，本 skill 只负责把卡点报清楚，不替人猜、不反复重试。

## 编排 procedure：完备集补齐（十一道）

判定不就绪后进入本节：把卡点映射到道次，逐道补齐，补完**复验**（重跑三步），全过才宣告就绪。补齐由各 work-skill 的 requirements 声明驱动——家族里的 skill 声明需要什么，就补什么；新 skill 入驻，本节零改。

**两级划分**：**项目级七道，一个项目只做一次**（开云盘落点、收料上飞书、蒸馏、打标、定阶段、建承接、接线）；**个人级四道，每名成员各做一次**（锚项目 / 建工作文件夹、装备预装、权限、写本地锚）。第 11 道「登记」两级各占一半。新成员加入已初始化的项目只走个人级四道（见下节）。

**写飞书道次的放行闸（永久行为）**：道4、道5＋6（整体）、道9、道11 项目级半含对外写入。执行到任一道前：先产出**待建内容清单**（要建什么 / 写什么 / 落在哪），**停**，摆出待使用者放行状态；放行后才执行，未经放行绝不写飞书。

| 道次 | 级别 | 归属与做法 |
|---|---|---|
| 1 锚项目 / 建工作文件夹 | 个人级 | **归入口引导（using-tingle），本 skill 不重复**——走到本 skill 时项目工作文件夹应已锚定；未锚定则回入口 |
| 2 装备预装 | 个人级 | 本 skill 执行：按装备清单逐项补——缺 lark-cli / lark-* skills → `npx skills add larksuite/cli -g`；缺授权 → `lark-cli auth login`（授权走成员本人的用户身份）；缺插件自身 → 指引经插件市场安装；装后复查第一步 |
| 3 权限 | 个人级 | 本 skill 执行：核对成员飞书账号对项目资源（云盘 / 档案 / 各表）的访问权；无权限时引导找项目资源管理者开通——本 skill 不能替人授权，开通后复验 |
| 4 开云盘落点 | 项目级 | 本 skill 执行（写飞书，先放行）：项目已有云盘文件夹则取其 `folder_token`；没有则放行后建；所得 `folder_token` 供道5＋6 直传、道11 登记 |
| 5 收料上飞书 ＋ 6 蒸馏 | 项目级 | **一次性合并调用 context-distill 黑盒**（REQUIRED SUB-SKILL: `tingle:context-distill`；含写飞书，先放行）：由它完成引导收料、材料上云盘并转成 AI 读得了的形式、按本 skill 所传清单蒸馏产出项目共享上下文的全过程；本 skill 不参与过程、**只验收结果三样**——①**云盘有料且已转可读**：`raw/索引.md` 每行都带「加工状态」，该转的都有转出件在 `raw/` 下（本项目确无可转件时转出件可以为零，**验收以索引逐行的加工状态为准**）；②**共享上下文已按所传清单产出**：清单所列各件都有着落（已产，或在索引里记「本项目无料·未产」），并有那一份索引把整套串起来；③取得各产物地址供道11 登记。**转可读与蒸馏的做法一概归被调方**——本 skill 只验收上述结果，**不执行转换、不复述做法**。**被调方的运行前检查不重复触发**：其运行前提已由本次编排承担（档案与锚此刻尚未建成，再判必然不就绪），入参由本 skill 直传。**入参含必传的蒸馏清单，契约见下** |
| 7 打标 | 项目级 | 本 skill 执行：确定品类三级（`业务线` / `合规类目` / `产品品类`）＋`品牌` 标签——取值向使用者确认或从项目材料认定，**缺料不发明**；值进道11 的待建档案内容 |
| 8 定阶段 | 项目级 | 本 skill 执行：确定 `阶段`（受控初始集：策略期 / 执行中 / 新周期，可扩）——同样问人或从材料认，不发明 |
| 9 建承接 | 项目级 | 本 skill 执行（写飞书，先放行）：按各启用 skill 的 requirements，为其输出建承接表 / 文档（表结构照该 skill 自己的接口契约）；建成地址供道11 登记 |
| 10 接线 | 项目级 | 本 skill 执行：共享数据底座（项目无关设施，如某跨项目共享的底座表）**只验通、不建**——按声明输入轻量访问验证可达；不可达或无地址时向底座维护方索取地址 / 申请权限 |
| 11 登记 | 两级各半 | **项目级半**（写飞书档案，先放行）：把项目身份、标签、阶段、各 skill 输入地址、项目级 `initialized_at` 写入云盘顶层「tingle-项目档案」（照参考件档案模板，版本 1）——各项目级道次完成即累积待写内容，放行后落笔；**个人级半**（本地动作，直接执行）：写 `.tingle/state.json`（照参考件锚模板，恰三字段，版本 2） |

**未启用任何 work-skill 时怎么记（照实记，判定逻辑不因此改动）**：目标 skill 集为空（与使用者确认后本项目这一次不启用任何 work-skill）时，**第二步第 6 查与第三步没有判定对象**——补齐台账与复核包里记「本轮无对象」，**不记「过了」**：那是「这一次没有可判的东西」，不是「判过并通过」。同理，道9 建承接与道10 接线都由各启用 skill 的 requirements 驱动，**无启用 skill 即本轮无事可做**，同样记「无对象」——**不得为了把十一道凑齐，去建一张没人要的承接表或验一个没人要的底座**。其余各条照常判、照常补：第一步环境与第二步 1–5 查仍须逐条过，项目级的道4、道5＋6、道7、道8、道11 仍照常做。

**合并调用入参契约（道5＋6 调 context-distill 时必守）**：
- **必传一＝项目云盘 `folder_token`**，恒成立；
  - **初蒸**（初始化中的合并调用）：`folder_token` 由**道4 的产出直传**——此时档案尚无 context-distill 条目，**不得假设档案已有、不得去档案解析**；
  - **重蒸 / 修复路由**（第三步判据不过、按 `produced_by` 回调）：由本 skill **从档案解析**后传入——地址只记在档案一处；
- **必传二＝蒸馏清单**：该产哪几件、每件什么形态、缺格怎么标、落哪儿、索引怎么写，全由清单定死。**清单是本 skill 传给被调方的入参，不是被调方现场问人产出的东西**——没有「无清单则现场询问」这条路，两次调用产出的件数与件名不因谁执行、现场怎么问而变。清单原文见下块，**连起止标记一起整块字节照传，不改写、不重排、不摘录**；
- **可选**＝已知来料线索（有则传；无则由被调方在引导收料时现场获取）。

## 新成员加入已初始化的项目（两路）

项目档案已在飞书（项目级七道已完成）时，新成员只走**个人级四道**（锚项目 / 建工作文件夹→归入口；装备；权限；写锚），项目级全部跳过——读到档案即知该项目已初始化。定位档案有两路：

- **路一 · 有档案链接**：使用者直接粘贴「tingle-项目档案」文档链接→验通（打得开、JSON 解析得出、`tingle_profile_version`＝1）→写本地锚指向它；
- **路二 · 只知项目名、有项目云盘访问权**：在项目云盘**顶层**按固定标题「tingle-项目档案」搜索定位→唯一命中则同路一验通写锚；零命中→项目可能未初始化，转全套编排；多命中→停，交使用者确认哪份为准。

写锚后重跑三步复验，全过即该成员就绪。

## 多人共用一个项目

- **N 锚 1 档案**：档案是项目共享真相，锚是个人的；地址变更只改档案一处，各成员下次运行自动获得新地址。
- **就绪按人各自判**：每名成员在自己的机器与自己的飞书账号下各自判，互不代表、互不复用结论。
- **承接表并发**：只追加（append-only），不修改、不删除已有行；写入前按去重键查重，表中已有同键行则跳过（去重键由各 skill 自己的接口契约定义）。
- **经手人承载**：承接表记录「谁产出的」**不需要专门字段、不需要询问使用者**——各成员写入走本人的飞书授权身份（用户身份授权），记录的**创建人元数据即为本人**；需要读取经手人时，从该记录创建历史的「创建」事件操作者读出。前提是写入始终以用户身份授权进行（若以应用身份写入，创建人会显示为应用）——道2 / 道3 的授权环节即以用户身份为准。

多人运行原则全文见参考件。

## 材料纪律（项目全程）

过程中使用者直接交给 AI 的材料（对话里粘贴的、本地文件），**必须先上传该项目的飞书项目云盘并转成相应格式，然后才处理**——飞书＝材料真相源，材料不滞留对话、不滞留本地。此纪律覆盖项目全程，不限于初始化；收料环节由 context-distill 执行时同样遵守，两处一致。

## 接口与边界（声明）

- **适用环节**：「项目就绪的判定与补齐」——每个项目、每名成员、每次 work-skill 运行前都会发生的可复用环节，非一次性事务。
- **input schema**：`entry`（入径，枚举：`direct` 直呼 / `routed` 入口路由 / `step0` 运行前一行调用）；`project_folder`（项目工作文件夹路径，字符串）；`target_skill`（目标 skill 名，字符串；`step0` 入径必带，其余入径缺省＝项目启用的全部 work-skill）。
- **output schema**：`verdict`（枚举：`ready` / `not-ready`）；`blockers`（卡点清单，逐条指向三步的具体条目）；`resolved_inputs`（已解析地址集，仅 `ready` 且 `step0` 入径返回：逐输入 `type`＋对应值字段）；`remediation_log`（补齐台账：每道＝已满足跳过 / 已补齐 / 待放行 三态之一）。可沉淀候选：无——判定结论即用即弃、永不落盘，状态与地址不是内容资产。
- **写回位置**：本地锚 `.tingle/state.json`（个人级）；飞书「项目档案」（项目级，写经放行）。
- **规则层与项目事实**：不挂载品类 / 品牌 / 类型任何规则层（本 skill 不产内容、不碰红线）；项目事实（标签 / 阶段）是本 skill 的**登记对象**而非注入输入，取值只来自使用者确认或项目材料。
- **工具**：文件系统读写（锚、工作文件夹）；`lark-cli`（环境核查与授权状态）；`lark-doc`（读写项目档案——写经放行）；`lark-drive`（云盘落点、按标题搜档案、列文件夹验地址——建经放行）；`lark-base`（读表基本信息验地址、建承接表——建经放行）；Skill 工具（调 context-distill）。
- **决策档**：判定＝自动（三步机械执行）；补齐中的对外写入＝复核（待建内容清单经使用者放行后执行）。
- **复核包（交人复核 / 放行时随附）**：三步判定逐条记录；卡点清单；补齐台账；待建内容清单（写飞书前）；复验结果。

## 产出验收判据（DoD）

一次运行合格，当且仅当以下全部成立：

1. **判定结论明确且有据**：三步逐条有过 / 不过记录；结论为「就绪」或「不就绪＋卡点清单」，卡点逐条对应到三步的具体条目；
2. **一行调用返回件齐全**：`step0` 入径就绪时，返回件含放行结论＋该 skill 全部声明输入的已解析地址（逐输入 `type`＋对应值字段，取自档案）；
3. **不就绪不跑这一次**：判不就绪时，未放行任何 work-skill 的本次运行；
4. **写飞书零未经放行执行**：每次飞书写入前都有「待建内容清单＋使用者放行」记录；
5. **缺料不发明**：打标 / 定阶段的取值均来自使用者确认或项目材料；取不到的标待补，不凭常识填；
6. **补齐后复验通过**：宣告「已就绪」前重跑三步且全过；复验不过则继续补**尚未补过的卡点**，**同一卡点补过一次仍不过→停交人，不再补第二遍**（按卡点各自计次：这一轮该补几道就补几道，禁的只是回头重补同一个卡点）；
7. **落盘合模板**：写出的锚恰三字段且版本＝2；写出 / 更新的档案版本＝1 且字段齐（照参考件模板）；
8. **判定零外泄**：本次工作未在任何其他 skill 文件中添加判定逻辑——引擎只此一份。

## Common Mistakes

- **替入口做锚定 / 建工作文件夹**——道1 归入口引导，本 skill 不重复；未锚定回入口。
- **把判定逻辑抄进别的 skill**——引擎只此一份；其他 skill 的运行前检查只允许一行调用。
- **代替 context-distill 收料 / 蒸馏**——它是黑盒，本 skill 只发起合并调用、只验收三样结果。
- **初蒸时去档案解析 `folder_token`**——初蒸时档案尚无该条目，由道4 产出直传。
- **把就绪结论写进锚或档案**——两层只存事实（地址、日期），就绪每次现算。
- **环境状态落盘或沿用上次结果**——环境永远现场查。
- **复用他人 / 上次的判定结论**——就绪按人、按次各自判。
- **补完不复验就宣告就绪**——补齐后必须重跑三步且全过。
- **给承接表加经手人字段或询问使用者身份**——创建人元数据已承载，不加字段、不询问。
- **改写 / 删除承接表已有行**——只追加；写入前按去重键查重。

## Red Flags（出现即停，回到该守的闸）

- 「环境上次查过了，跳过第一步吧」→ 环境现场查，永不沿用。
- 「就差一点点，先放行这一次」→ **不就绪不跑这一次**。
- 「标签 / 阶段看着像这个，先填上吧」→ **缺料不发明**——问人或从材料认，取不到标待补。
- 「文件夹 / 表 / 档案顺手就建了吧」→ **对外动作先放行**——先摆待建内容清单，等放行。
- 「我这边就绪，他那边肯定也行」→ 就绪按人各自判。
- 「把三步抄一份进那个 skill，省得调用」→ 判定引擎只此一份，抄即坏架构。
- 「材料先在对话里用起来，回头再传云盘」→ 先上飞书项目云盘转格式，再处理。
- 「锚里顺便多存几个地址，省得每次读档案」→ 锚仅三字段，地址只在档案。
