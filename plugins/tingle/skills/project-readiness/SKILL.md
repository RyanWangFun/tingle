# project-readiness

## 概述

全家族「项目就绪」的唯一承担者，一句话职责：**判定「这个项目对这名成员、这一次运行就绪没有」；不就绪，就编排补齐到就绪。** 诊断只是第一步，补齐才是目的。

三条基座（记牢）：

- **判定引擎只此一份**：三步就绪判定在本 skill 内唯一实现。各 work-skill 的运行前检查只是一行调用本 skill，不自带任何判定逻辑；入口 skill（using-tingle）只锚定与路由，不判定。要改判定规则，只改本 skill 与其参考件这一处。
- **就绪按人各自判、每次现算**：装备、授权、锚都是个人的——同一项目对甲成员就绪、对乙成员可能不就绪；就绪结论不落盘、不复用、不互相代表。两层状态只存事实（地址、日期），不存结论（就绪勾）。
- **对外动作先放行**：凡写飞书（建文件夹 / 建表 / 建档案 / 改档案），先产出待建内容清单、停、等使用者放行——这是本 skill 的永久行为，不是可省略的礼节。

**通则 · 要换掉一个有人指向的东西时，新建的必须是没人指向的那一个**：一件东西的地址一旦被别处记下（项目档案的链接记在每名成员的本地锚里、认知件的链接记在索引里），要用新版本替换它，就**就地改原件、把副本另存到别处**——绝不新建一份当正版、再把原件挪走。反着做，所有拿着旧地址的人打开的仍是被换掉的那一份，而没有任何工序负责去改他们手里的地址。档案版本升级即照此办（见「档案版本不匹配：迁移入径」）。

**通则 · 降级是人的决定，不是执行者的决定**：凡判断的结果是"这一道 / 这一件 / 这一格**不用走、走不了**"，**一律不许自行推进**——把这个判断连同理由**摆出来、停、等人拍**。降级可以，但**降级是人的决定，不是执行者的决定**。粒度含**道级**（这一道不必走）、**件级**（这一件不必产）、**格级**（这一格不必填），也含"改用简化做法先跑完"这种半降级——同样是降级，同样要人拍。**与"按判法判出来的合法结果"分清**：判法走完了、照判法得出「无」（如逐件对着收录范围看过、确认无料，于是照规矩记「本项目无料·未产」），那是判定结论，不是降级；**判法没走完、或走不通就换个说法接着跑**，才是这条禁的东西。

两层状态模板（项目档案 JSON 模板 / 本地锚模板）、requirements 声明格式与多人运行原则的完整规定，见随身参考件 `references/readiness-contract.md`；本文保留可执行主干——单凭本文即可跑完三步判定与补齐编排。

## 何时用 / 何时不用

**何时用**：使用者要把某个项目弄就绪（初始化新项目、加入已初始化的项目）；入口路由过来（本地锚缺失 / 不可解析）；任一 work-skill 运行前的检查触发（一行调用）；怀疑某项运行前提失效要复核。

**何时不用**：
- **会话开始的项目锚定与路由**（当前在哪个项目工作、帮建工作文件夹）——归 using-tingle；本 skill 从已锚定的项目工作文件夹起步。
- **材料工序本体**（引导收料、材料上云盘、蒸馏、重蒸）——归 context-distill；本 skill 只当黑盒调用并验收结果。
- **任何具体业务环节**（选题 / 审稿 / 内容 / 投放 / 分析）——归各 work-skill；本 skill 只回答「能不能跑」，不干业务的活。
- **共享数据底座等项目外设施的建设**——本 skill 只验通可用，不建、不修其内部。

## 两层状态模型（速览）

- **项目级＝飞书「项目档案」**：一项目一份，落在项目云盘**顶层**的一份 lark-doc，标题固定为「tingle-项目档案」，正文为约定结构的 JSON 代码块（档案 schema 版本当前为 **2**）。记项目身份（id / name）、标签（品类三级＋品牌）、阶段、**项目云盘地址（顶层 `folder_token`，"项目云盘在哪"的唯一真相源）**、各 skill 的输入与输出地址（`skills.<skill_name>` 下分 `inputs` / `outputs` 两段）、项目级初始化完成日。项目内全体成员共读共用同一份。
- **个人级＝本地薄锚 `.tingle/state.json`**：每名成员一份，落在自己机器上该项目工作文件夹根下的 `.tingle/` 内。仅三字段：`tingle_state_version`（当前为 **2**）、`profile_link`（项目档案链接）、`initialized_at`（个人级初始化完成日）——没有第四个字段，不存项目云盘地址、不存任何输入 / 输出地址。
- 一个项目 N 名成员＝ **N 份锚＋1 份档案**；项目云盘地址与一切输入、输出地址都只记在档案一处，地址变更只改档案，各成员下次运行自动获得新地址。两份模板的字段全文见参考件。

## 三种入径与返回契约

| 入径 | 触发 | 行为 |
|---|---|---|
| ① 用户直呼 | 使用者说「把这个项目弄就绪」等 | **初始化判定**：第一步环境＋第二步 1–5 查（不含第 6 查、不含第三步，不读任何技能的声明）→ 不就绪则进补齐编排 → 复验 → **收尾逐条过 DoD**，才下结论 |
| ② 被入口路由 | using-tingle 扫锚发现缺失 / 不可解析，路由过来 | 同直呼径。判定会自行揭示是「项目未初始化」还是「项目已初始化、仅这名成员个人未就绪」（后者走加入路径，见下） |
| ③ 被 work-skill 运行前一行调用（step0） | 该 skill 每次运行前 | 只判**无条件前置**（第二步 1 锚在、3 档案打得开、4 档案版本匹配、5 项目字段齐）＋**只针对该 skill 自己**的第 6 查与第三步；该 skill 声明 requirements 为空（既无声明输入、也无声明落点）时，第 6 查与第三步空过（记「本次无输入、无落点可判」，放行）。按下述返回契约返回——**返回放行前先过「收尾」那一步** |

**一行调用的返回契约**：
- **就绪** → 返回「放行」＋该 skill 全部声明输入的**已解析地址**（从档案 `skills.<skill_name>.inputs` 段取出）＋该 skill 全部声明落点的**已解析地址**（从 `skills.<skill_name>.outputs` 段取出）。两者同一取法：逐项给 `type` 与对应值字段（`lark-doc`→`link`；`lark-base`→`base_token`＋`table_id`；`lark-drive`→`folder_token`）。调用方直接照地址取用，不再自行读档案。**对声明了落点的 skill，返回「放行」时落点一栏不可能为空**——声明了落点却没在档案里登记的，第二步第 6 查就已判不就绪、根本走不到这一行（为什么这样定，见该查）；**落点一栏仅在该 skill 未声明任何落点时为空**。所以这类调用方永远不会拿着"放行 + 没有落点"这副牌，也就没有"自己挑个地方写"的机会。**返回「放行」之前先过「收尾」那一步**（编排 procedure 末「收尾 · 下结论前逐条过一遍 DoD」）——**"各查全过"不是返回放行的充分条件**；step0 的这一遍很短（适用的恒是第 1、2、3、8、9 条，其余各条的不适用已写死在条文里），但这五条每次都要指得出，指不出即不返回放行。
- **不就绪** → 返回「不就绪」＋卡点清单（卡在哪一条）＋补齐去向；**该 skill 本次不运行**。**返回前同样先过「收尾」那一步**（第 1、3 条正是为这一支写的）。

**work-skill 侧的标准一行写法**（各 work-skill 的运行前检查一节照此照抄，此外不得自带任何判定步骤）：

```markdown
**Step 0 · 运行前检查（仅此一行，不自带判定）**：REQUIRED SUB-SKILL: `tingle:project-readiness`
——传入本 skill 名；返回「放行」才继续运行，并以其返回的已解析地址为各输入与各落点的取用地址；
返回「不就绪」则本次不运行，待其补齐并复验通过后重来。
```

## 引擎 procedure：三步就绪判定（唯一实现）

**判定范围按入径定**：初始化入径（直呼 / 被路由）执行第一步环境＋第二步 1–5 查——问的每一件都是项目或人的地基，不读任何技能的声明；step0 入径执行无条件前置（第二步 1、3、4、5 查）＋第 6 查与第三步——只问发起调用的那个 skill 这一次要的东西，不查环境、不查别的技能。顺序不可颠倒——环境是最基础依赖，前置不成立，输入也读不了。**本次入径所含各查全过＝本次就绪；任一查不过＝不就绪，转入补齐 / 修复，不运行这一次。** 判定全程只读（读文件、读飞书、跑只读命令），不写任何东西。

**"各查全过"是判定的结论，不是"本次运行到此合格"的结论**——不论本次有没有补齐，**下结论之前（宣告就绪 / 返回放行 / 返回不就绪＋卡点，三种都算；第四种"停机交人"另有规定，见「收尾」）都要照编排 procedure 末「收尾」逐条过一遍 DoD**，各条按本次运行实际做过什么判"在哪一步满足"或"本次为何不适用"（纯判定那一次哪五条不适用，收尾那一步已写死）。

**目标 skill 的取法**：step0 入径＝发起调用的那个 skill（只此一个）；直呼 / 被路由入径＝**不取目标 skill 集**——初始化判定只问项目和人的地基，与插件里装了哪些技能无关。

### 第一步 · 环境（仅初始化入径执行；现场查，永不落盘）

按**官方装备清单**（当前 v1；清单按需可扩展——新 skill 入驻带新依赖时，随其 requirements 声明进清单）逐项核查，全部成立才过：

1. **lark-cli 二进制已装**：`command -v lark-cli` 有输出；
2. **lark-* skill 目录全套在场**：`~/.claude/skills/lark-*` 或 `~/.agents/skills/lark-*` 路径下存在完整一套 lark 相关 skill 目录；
3. **`lark-cli` 授权有效，且有效的是使用者本人的 `user` 身份**：跑 `lark-cli auth status`，按下方「授权判据」三态判——**只认 `user`，不认 `bot`**；
4. **tingle 插件自身已装**：核对插件处于已安装、已启用状态。

任一项不成立→环境未就绪，**不必再看第二步**，先转补齐编排的装备 / 权限道次。环境状态永远现场查、永不写进锚或档案。技能运行前（step0 入径）不查环境；运行中环境失效＝出了问题检查配置修掉，执行 AI 按报错性质自行判断处置。

**授权判据（第 3 项的判法）：只认 `user` 身份，三态判定**

`lark-cli auth status` 返回的是**两套并列的身份状态**——应用身份（`bot`）一套、使用者本人身份（`user`）一套，**没有一个代表整体的总状态字段**。本判据**只看 `user` 那一套**：`bot` 是不是 ready 不作数，"有一个身份 ready"也不作数。**返回顶层那个标着默认身份的字段（写作本文时是 `identity`）是"默认用哪个身份发请求"的设置、不是状态**——它写着 `user` 不等于 `user` 的授权还活着，不得据此判过。

**为什么锁 `user`**：本体系记「谁产出的」不靠字段，靠**写入飞书时的创建人元数据即为本人**。`user` 已失效而 `bot` 尚在时若判了通过，此后所有飞书写入都会以**应用身份**落地——表照建、行照写、**不报任何错**，但每条记录的创建人都成了这个应用，多人协同的经手人追溯**无声整体失效**；要等到有人来查"这几行是谁写的"才发现，那时已经分不清，也无法回溯补救。

`user` 这一套按三态处置（**"需刷新"是常态，不是故障**）：

| 态 | 语义 | 动作 |
|---|---|---|
| ① 可直接用 | `user` 身份在场，授权仍在有效期内 | **过** |
| ② 已过期、可自动续 | access token 已过期，refresh 的有效期**尚未到** | **先刷新，成功即过**（常态路径） |
| ③ 连 refresh 也过期 | refresh 的有效期已过，续不回来 | **不过**→转道2，由使用者本人重新授权 |

- **② 是日常路径，不是异常分支**：实测 access token **数小时**即过期、refresh 撑**约一周**——隔几个小时再开工的会话，遇到的几乎都是 ②。不要当事故处理，也不要为它惊动使用者。
- **② 怎么刷**：靠 `lark-cli` **在下一次 API 调用时自动续期**——跑一条**只读**的用户身份命令即可触发（例如再查一次状态），续上即过、继续往下走。**不得改跑 `lark-cli auth login`**——那会平白打断使用者做一次本不必做的完整授权；`auth login` 只属于 ③（道2）。
- **字段路径与取值都只作示例，语义才是判据**：写作本文时，三态对应的位置是 `identities.user.available`、`identities.user.tokenStatus`、`identities.user.expiresAt` 与 `identities.user.refreshExpiresAt`。**随 `lark-cli` 版本可能变——实际返回对不上时按上面的语义重判（哪一套是使用者本人的、授权还在不在有效期内、refresh 到期没有），不要照着这里的路径猜一个相近的字段**，也不得因为对不上就把这一项跳过去。**取值同样只作示例**：真机上见过 `valid`（＝①）与 `needs_refresh`（＝②），但**这套取值没有公开的枚举承诺、随版本走，见过的两个不是全集**。所以**判据不写成"等于某个字面值才算过"**，一律按有效期语义判；**遇到不认识的取值也不得当作"没见过＝没问题"放过**，按判不准处理、转 ③。

### 第二步 · 锚与档案（六查，按顺序）

1. **锚在**：当前项目工作文件夹下 `.tingle/state.json` 存在，且 `tingle_state_version`、`profile_link`、`initialized_at` 三字段齐全非空；
2. **锚版本匹配**：`tingle_state_version` 值等于 **2**（当前锚 schema 版本）；
3. **档案打得开**：以 lark-doc 打开 `profile_link` 指向的文档，能读取正文中的 JSON 代码块并成功解析；
4. **档案版本匹配**：档案 `tingle_profile_version` 值等于 **2**（当前档案 schema 版本）；
5. **档案项目字段齐**：`project.id`、`project.name` 存在且非空；`project.tags.品类` 下三级（`业务线` / `合规类目` / `产品品类`）均存在且非空；`project.tags.品牌` 存在且非空；`project.阶段` 存在且非空；**顶层 `folder_token` 存在且非空**；项目级 `initialized_at` 字段存在；
6. **目标 skill 输入与落点齐**：目标 skill（按其名字）在档案 `skills` 段下有对应键，且**两段都齐**——① 该键 `inputs` 下，它 requirements 里**声明的每一个输入**都在且字段齐全；② 该键 `outputs` 下，它 requirements 里**声明的每一个落点**都在且字段齐全。两段的"齐"同一标准：`type` 有值，且按 `type` 对应的值字段有值（`lark-doc`→`link`；`lark-base`→`base_token`＋`table_id`；`lark-drive`→`folder_token`）。**声明里没有的不查**——`requirements.outputs` 为空的 skill，本查只看 `inputs`。

**为什么落点没登记也算不就绪**：一个必须往外写的 skill，**落点和输入一样是它的运行前提**——输入缺了它读不着，落点缺了它没地方放。放它先跑、指望写的时候再说，等于把决定推到**活已经干完、正找地方放**的那一刻，而那一刻正是"就写这儿吧"发生的地方。所以落点未登记＝**不就绪，本次不跑**；补法是道10 登记（写档案、先放行，地址由使用者在放行清单里给出），登记完复验第 6 查，过了才跑这一次。**"过了"含收尾那一步**：复验第 6 查过、**且照编排 procedure 末「收尾」逐条过完 DoD**，才放这一次跑。**这一路是 step0 唯一会写飞书的路径**（道10 登记、走了放行闸），所以它**不是"纯判定的那一次"**——**十条全数适用、复核包按整包交出**，不适用那五条一条都不能套（见「收尾」与「接口与边界」）。

**入径范围**：初始化入径（直呼 / 被路由）执行 1–5 查，不执行第 6 查；step0 入径执行 1、3、4、5 查（无条件前置）＋第 6 查（只针对发起调用的那个 skill）。声明 requirements 为空（**既无声明输入、也无声明落点**）的技能，第 6 查与第三步空过（记「本次无输入、无落点可判」，放行）——不得因为它在档案 `skills` 段下没有键就判它永不就绪。**这一路同样在返回放行前过「收尾」那一步。**

任一查不成立→不就绪：第 2 查（锚版本不匹配）→按当前模板**重建锚**（本地动作，道11）；第 4 查（档案版本不匹配）→走**迁移入径**——**就地覆盖那一份档案，不新建**（只跑道10，写飞书，先放行；见「档案版本不匹配：迁移入径」）；其余各查→路由补齐（对应道次见编排节的卡点映射表）。

### 第三步 · 验（仅 step0 入径执行；地址可达＋就绪判据）

对发起调用的那个 skill 在档案 `skills.<skill_name>.inputs` 下记录的**每一个输入**（只此一个 skill，不及其他；`outputs` 是产出落点，**登记齐不齐已由第二步第 6 查管住**，其地址可达性不在本步范围——真写不进去时按报错性质当场处置），逐个执行两项：

1. **地址当场打得开**：按 `type` 对该地址轻量访问一次——`lark-doc` 读取文档标题、`lark-base` 读取表的基本信息、`lark-drive` 列出文件夹内容——访问成功即通过。链接失效、资源被删、**当前成员权限不足**都在此项暴露；
2. **就绪判据逐条过**：该输入在其 skill 的 requirements 里声明的每一条「就绪判据」，当场验证成立；未声明判据的输入，只做第 1 项。

任一输入任一项不过→不就绪，转入修复：地址失效→更新档案中对应配置（写飞书，先放行）；判据不过且该输入标有 `produced_by`→调该生产者 skill 重产此输入（如蒸馏产物→回调 context-distill 重蒸，此时项目云盘 `folder_token` 由本 skill 从档案顶层解析后传入）；无 `produced_by` 的输入→交人修复——该输入是这个 skill 自己的运行前提，**其来源**随该功能自己的接口定。

**同一个输入，调过生产者之后仍不过 → 停，不再重试。** 生产者跑完后复验该输入，**仍缺或判据仍不过**时立刻停下，**不做第二次回调**——同样的调用第二遍不会有不同结果，只会一圈圈转，而且转得无声无息。停时报出四样：①**这个输入的名字**；②**调了哪个生产者**；③**该生产者报的完成状态**；④**一句诊断**——「生产者跑完了但这件仍缺，很可能它不在该生产者的产出清单里：名字不符 / 尚未接入 / 模板未就位」。**这不是本 skill 能修的**：真正的修法是把那件东西接进生产者的产出清单与物料 IO 表，或改正声明里的输入名——交人处理，本 skill 只负责把卡点报清楚，不替人猜、不反复重试。

## 编排 procedure：完备集补齐（十一道）

判定不就绪后进入本节：把卡点映射到道次，逐道补齐，补完**复验**（按本次入径重跑判定）＋**逐条过一遍 DoD**（收尾那一步，见本节末），两者都过才宣告就绪。十一道补的都是项目和人的地基，**不由任何技能的声明驱动**——初始化不读 requirements；新 skill 入驻，本节零改。

**两级划分**：**项目级七道，一个项目只做一次**（开云盘落点、打标、定阶段、收料、转可读、蒸馏、项目档案 + 总索引）；**个人级四道，每名成员各做一次**（锚项目 / 建工作文件夹、装备预装、权限、本地锚）。新成员加入已初始化的项目只走个人级四道（见下节）。

**写飞书道次的放行闸（永久行为）**：道4、道7–9（合并调用整体）、道10 含对外写入。执行到任一道前：先产出**待建内容清单**（要建什么 / 写什么 / 落在哪），**停**，摆出待使用者放行状态；放行后才执行，未经放行绝不写飞书。**道4 的触发条件比其余各道更宽，须单独记住**：它**不以"本次是否真的往飞书写了东西"为条件**——复用一个现成文件夹、本次一个字节都不写，同样要摆清单、停、等放行。理由与做法见紧随本表之后的「道4 落点闸」。

**道4 落点闸：定落点就停，不是"要建文件夹"才停**

道4 要定死的是**本项目全部产物往哪儿写**，不是"要不要新建一个文件夹"。所以**本道没有绕过闸的分支**：最后是新建一个文件夹、还是复用使用者已有的某个文件夹，闸都一样；本次是否真的往飞书写了字节，闸也一样。"复用现成的、这次不写飞书、所以不必放行"**不成立**。（这条不是假想：一次实跑正是判「不必新建」，整道闸随之不触发，差点把全项目产物写进客户存原始资料的那个文件夹。）

三步按序，一步不可省：

1. **先问一句落点性质**：使用者给的这个文件夹，是**产物落点**（tingle 要往里写东西）还是**来料来源**（只供读取的资料夹）？**两者在飞书上长得一模一样，不问就无从区分。** 答"来料来源"→ 它不能当落点，继续问产物落点在哪；使用者说不清 → 停，等他定，**不替他挑一个**。
2. **摆待建内容清单**（新建要摆，复用一样要摆），四样都写上：
   - ① 这个文件夹的**名称与链接 / `folder_token`**，以及它是**新建的还是复用已有的**——复用的注明它原本装着什么、第 1 步问出来的性质是什么；
   - ② **本项目后续全部产物都将写入此处**，逐项列出：`raw/`（含 `raw/索引.md` 与 `raw/_台账/`）、九件认知件（各占一个同名子文件夹）、`tingle-认知件索引`、云盘顶层的「tingle-项目档案」与「tingle-项目索引」、日后迁移档案时的 `_tingle/` 存档件；
   - ③ 复用时另加：使用者对该文件夹**已有内容**的处置意见（照原样留着 / 先归置 / 换一个文件夹）；
   - ④ 一句话点明：**放行即等于同意 tingle 此后在此文件夹内建子文件夹、建文档并就地更新**。
   
   只摆"我要建一个文件夹"**不算摆**——使用者照样点头，坑原样保留。清单要让他看见的是"我的这个文件夹从此变成 tingle 的产物落点"。
3. **停，等放行**。放行后才取 / 建 `folder_token`。

**补齐台账里道4 不得记「已满足跳过」**——落点已经现成也是「已补齐」，且必须附上本次的待建内容清单与放行记录。台账里道4 一栏记着「已满足跳过」，即本次运行不合格（见 DoD 第 4 条）。

**合并调用入参契约（道7–9 调 context-distill 时必守）**：
- **必传一＝项目云盘 `folder_token`**，恒成立；
  - **初蒸**（初始化中的合并调用）：`folder_token` 由**道4 的产出直传**——此时档案尚无 context-distill 条目，**不得假设档案已有、不得去档案解析**；
  - **重蒸 / 修复路由**（第三步判据不过、按 `produced_by` 回调）：由本 skill **从档案顶层 `folder_token` 解析**后传入——项目云盘地址只记在档案顶层这一处，不从 `skills` 段下任何输入 / 落点的 `folder_token` 反推；
- **必传二＝蒸馏清单**：该产哪几件、每件什么形态、缺格怎么标、落哪儿、索引怎么写，全由清单定死。**清单是本 skill 传给被调方的入参，不是被调方现场问人产出的东西**——没有「无清单则现场询问」这条路，两次调用产出的件数与件名不因谁执行、现场怎么问而变。清单原文见下块，**连起止标记一起整块字节照传，不改写、不重排、不摘录**；
- **可选**＝已知来料线索（有则传；无则由被调方在引导收料时现场获取）。

- **第 0 步 · 先取项目云盘坐标**：版本 1 的档案**顶层没有 `folder_token`**，这个值记在 `skills.context-distill.项目云盘.folder_token`——**从旧档案的这个路径读出来**。这是**读旧档案的内容**（档案就是这个项目的状态记录），**不是读某个技能 SKILL.md 里的 `requirements` 声明**——「初始化不读技能的声明」禁的是后者，本步不违反；也不与「不得从 `skills` 段反推项目云盘根」冲突——那条管的是有顶层字段的版本 2 档案，而 `项目云盘` 这一项名下记的本来就是云盘根本身，是版本 1 档案里唯一记着它的地方，**仅限读旧档案的一次性例外**。**该路径在旧档案里也不存在→停，问使用者本项目云盘顶层文件夹是哪一个（要到 `folder_token` 或可定位的链接），拿到答复再往下**：不猜文件夹、不拿别的文件夹顶替、也不因为取不到就把顶层 `folder_token` 略过不写。
- **第 1 步 · 读旧档案**：以 lark-doc 打开这份档案——**初始化入径下**＝锚里 `profile_link` 指向的那一份；**新成员加入路径下**＝使用者刚粘贴或按标题搜到的那条链接（此时他还没有锚）。读出正文 JSON 全文并逐字留底。
- **第 2 步 · 复制一份存档**：把旧 JSON 原样另存为**另一份文档**，放进项目云盘 `_tingle/` 子文件夹（没有则建），标题带旧版本号与迁移日期，形如 `项目档案-v1-20260803`。两条硬约束：① **必须移出云盘顶层、且必须改标题**——档案靠"云盘顶层 ＋ 固定标题「tingle-项目档案」"寻址，顶层一旦出现第二份同标题文档就是多命中、即停，新成员从此加不进这个项目；② **不许把旧 JSON 附在新档案正文底部当"历史版本"**——档案判定动作是「读取正文中的 JSON 代码块并解析」，一份正文里两个 JSON 代码块会取错一个且**不报错**。存档只能是另一份文档。
- **第 3 步 · 原档案就地覆盖成新结构**：**链接、位置、标题全不变**，只把正文 JSON 换成版本 2 的形状——版本值改 **2**；**顶层补 `folder_token`**（值＝第 0 步所取）；`skills.<skill_name>` 下原本直挂的各输入项**整体包进 `inputs`**（键名与值一字不改，只改层级）；`outputs` 段**不发明落点**——只有使用者在本次放行的待建内容清单里明确给出了落点才照实登记，否则本次不写（**本次不写≠日后不必登记**：某个声明了落点的 skill 真要运行时，第二步第 6 查会判它不就绪，再走道10 补登记，那时地址同样由使用者给）；`project`（id / name / tags / 阶段）与 `initialized_at` **原值照搬**，不重新问人、不重新认定。
- **第 4 步 · 项目总索引按现状建出或核齐**：迁移一旦完成，这就是一个**版本 2 的项目**，而版本 2 的状态模型要求云盘顶层有一份「tingle-项目索引」。**顶层没有 → 按道10 的规矩建出来**（固定标题、落顶层、五段行式、三行：认知件 / 原料 / 内务件；某一类没东西可指，那一行照留、入口链接写「—」）；**顶层已有一份 → 不重复建**，改为按现状核那三行齐不齐，缺行补齐、已有行不动。**为什么迁移也非建不可**：不建就留下一个**没有总索引的版本 2 项目**——`raw/_可读件/`、`raw/_台账/` 这些内务件靠总索引「内务件」那一行覆盖，没有它就**无人覆盖，直接违反无孤儿文件不变量**，下游也无处查"这个项目有哪几类东西"。**为什么这不算"重跑道4–9"**：建总索引**不重新收料、不重新蒸馏**，只是把一份缺失的索引按现状建出来，三行的入口指向的是**已经存在的**认知件索引与 `raw/索引.md`；跳过道4–9 的理由是"重跑是白干、还可能覆盖正在用的产物"，这条理由对建一份缺失的索引不成立。
- **第 5 步 · 前置各道不重跑**：覆盖完按初始化入径复验（第二步 1–5 查，第 5 查现含顶层 `folder_token`），全过、**且照编排 procedure 末「收尾」逐条过一遍 DoD 之后**（本入径跑了道10，DoD 第 10 条同样适用），才算恢复就绪。**锚分两种**：初始化入径下**锚不必动**（链接没变，`profile_link` 仍然有效）；新成员加入路径下他本就没有锚，迁移完成后**必须**按加入路径写锚指向这份档案。

**放行闸照道10 的规矩摆**（本道含写飞书）：先产出**待建内容清单**、停、等使用者放行。迁移的清单须**同时列出三样**——① **存档哪一份、存到哪**（哪份文档、存进 `_tingle/`、新标题叫什么）；② **哪些字段改成什么**（版本值、顶层 `folder_token` 取到的具体值、`inputs` 怎么包、`outputs` 写不写）；③ **建不建总索引、建出来是哪三行**（顶层已有一份则写明"不重复建、只核三行齐不齐、缺哪行补哪行"）。一次放行覆盖本次迁移的建 `_tingle/`、写存档件、覆盖原档案、建 / 补总索引四个动作。

**为什么是"原处覆盖"而不是"新建一份落到顶层"**：每名成员的锚里存的是**档案链接**，锚不会自己更新。新建一份就是新链接——全员的锚仍指向被移走的旧档案，谁打开都还是旧版本、还是判不就绪、还是被路由来做一次迁移，一圈圈转，每转一圈还多一份存档。就地覆盖则一次到位：链接没变，全员下次运行读到的就是新结构，谁都不必动自己的锚。这正是开头那条通则——**要换掉一个有人指向的东西时，新建的必须是没人指向的那一个**——的第一个实例。

## 多人共用一个项目

- **N 锚 1 档案**：档案是项目共享真相，锚是个人的；地址变更只改档案一处，各成员下次运行自动获得新地址。
- **就绪按人各自判**：每名成员在自己的机器与自己的飞书账号下各自判，互不代表、互不复用结论。

## 材料纪律（项目全程）

过程中使用者直接交给 AI 的材料（对话里粘贴的、本地文件），**必须先上传该项目的飞书项目云盘并转成相应格式，然后才处理**——飞书＝材料真相源，材料不滞留对话、不滞留本地。此纪律覆盖项目全程，不限于初始化；收料环节由 context-distill 执行时同样遵守，两处一致。

## 接口与边界（声明）

- **适用环节**：「项目就绪的判定与补齐」——每个项目、每名成员、每次 work-skill 运行前都会发生的可复用环节，非一次性事务。
- **input schema**：`entry`（入径，枚举：`direct` 直呼 / `routed` 入口路由 / `step0` 运行前一行调用）；`project_folder`（项目工作文件夹路径，字符串）；`target_skill`（目标 skill 名，字符串；仅 `step0` 入径使用且必带——`direct` / `routed` 入径做初始化判定，**不取目标 skill 集**，此参数不适用）。
- **output schema**：`verdict`（枚举：`ready` / `not-ready`）；`blockers`（卡点清单，逐条指向本次入径所执行各查的具体条目）；`resolved_inputs`（已解析输入地址集，仅 `ready` 且 `step0` 入径返回：逐输入 `type`＋对应值字段）；`resolved_outputs`（已解析落点地址集，同上取自档案 `outputs` 段；**仅在该 skill 未声明任何落点时为空**——声明了却未登记的不会走到这里，那已在第二步第 6 查判为不就绪）；`remediation_log`（补齐台账：每道＝已满足跳过 / 已补齐 / 待放行 三态之一；**道4 不得取「已满足跳过」**——落点现成也须走完那三步，记「已补齐」并附本次清单与放行记录）。可沉淀候选：无——判定结论即用即弃、永不落盘，状态与地址不是内容资产。
- **写回位置**：本地锚 `.tingle/state.json`（个人级）；飞书「项目档案」（项目级，写经放行）。
- **规则层与项目事实**：不挂载品类 / 品牌 / 类型任何规则层（本 skill 不产内容、不碰红线）；项目事实（标签 / 阶段）是本 skill 的**登记对象**而非注入输入，取值只来自使用者确认或项目材料。
- **工具**：文件系统读写（锚、工作文件夹）；`lark-cli`（环境核查与授权状态）；`lark-doc`（读写项目档案——写经放行）；`lark-drive`（云盘落点、按标题搜档案、列文件夹验地址——建经放行）；`lark-base`（读表基本信息验地址）；Skill 工具（调 context-distill）。
- **决策档**：判定＝自动（按本次入径所含各查机械执行）；补齐中的对外写入＝复核（待建内容清单经使用者放行后执行）。
- **复核包（交人复核 / 放行时随附；宣告就绪时整包交出）**：判定逐条记录（按本次入径范围）；卡点清单；补齐台账；待建内容清单（写飞书前）；复验结果；**DoD 自核结果**（十条逐条：在本次运行的哪一步满足，或本次为何不适用——见编排 procedure 末「收尾」）。**step0 的界（否则每次运行前检查都被逼交一份十条自核，这不是本 skill 的本意）**：一次运行**只判定、没转入补齐**时，**不另起整包**——它的复核包就是那份返回件本身（判定逐条记录 ＋ 放行或不就绪的结论 ＋ 已解析的输入与落点地址），DoD 自核只涉恒适用的五条（第 1、2、3、8、9），随返回件带出即可，不必逐条写成文档；**这一次一旦转入补齐**（写飞书 / 写锚 / 走道5 道6 / 做了复验），按上面的整包规矩交。**停机交人时（命中下方升级条件、或「停，不再重试」）**：把**手上已有的那部分**随停机报告一并交出（判定逐条记录 ＋ 停在哪一条 ＋ 已做到哪一步 ＋ 相关卡点 ＋ **本次已经写出去的东西**：建了哪个文件夹、写了哪份档案 / 表、动了哪些字段，各附对应的放行记录）——**已经落地的字节不因后来停机就无须交代**：停机常发生在道4 / 道10 写完之后，那时云盘与档案已经变了，接手的人必须知道现场是什么样；**不必补齐 DoD 十条**——这一次没走完，谈不上合格，但**必须说清停在哪、手上有什么**，不得只丢一句"停了"。
- **升级条件（命中任一即停、交人裁决，不自行推进）**：①**输出需对外发送 / 写飞书**（建文件夹、建表、建 / 改档案）——先放行再执行；②**缺关键项目事实**——标签 / 阶段无法从使用者或项目材料获得；③**档案定位不唯一**——按标题搜档案零命中且使用者不能确认项目状态，或多命中不能确认哪份为准；④**合规红线不确定**；⑤**四层规则冲突**。（④⑤在本 skill 极少出现——本 skill 不产内容；出现即停、不自行推进。）

## 产出验收判据（DoD）

一次运行合格，当且仅当以下全部成立：

1. **判定结论明确且有据**：本次入径所含各查逐条有过 / 不过记录（初始化入径＝第一步环境＋第二步 1–5 查；`step0` 入径＝无条件前置＋第 6 查＋第三步）；结论为「就绪」或「不就绪＋卡点清单」，卡点逐条对应到具体条目；
2. **一行调用返回件齐全**：`step0` 入径就绪时，返回件含放行结论＋该 skill **全部声明输入**的已解析地址＋其**全部声明落点**的已解析地址（逐项 `type`＋对应值字段，取自档案 `inputs` / `outputs` 两段）。**声明了落点的 skill，落点一栏为空却仍返回了放行，本条即不合格**——那说明第 6 查漏查了 `outputs`；未声明任何落点的 skill，落点一栏本就为空，不在此列；
3. **不就绪不跑这一次**：判不就绪时，未放行任何 work-skill 的本次运行；
4. **写飞书零未经放行执行**：每次飞书写入前都有「待建内容清单＋使用者放行」记录。**道4 另加一条，且不以本次是否真写了飞书为条件**：无论落点是新建的还是复用现成的，都有清单＋放行记录，清单里写明了"本项目后续全部产物都落此处"，并记着"产物落点还是来料来源"那一问的答复；补齐台账里道4 记着「已满足跳过」即本条不合格。**（本条对"只判定、全程一个字节没写飞书"的那一次不适用——但这不是"没写就不必摆清单"的出口：只要这一次真的动了飞书，不论哪条入径，清单＋放行一样不能少；道4 更是连"本次不写"都要摆。判"本次不适用"之前先答一句：这一次到底写没写飞书？）**；
5. **缺料不发明**：打标 / 定阶段的取值均来自使用者确认或项目材料；取不到的标待补，不凭常识填；
6. **补齐后复验通过**：宣告「已就绪」前按本次入径重跑判定且全过；复验不过则继续补**尚未补过的卡点**，**同一卡点补过一次仍不过→停交人，不再补第二遍**（按卡点各自计次：这一轮该补几道就补几道，禁的只是回头重补同一个卡点）；
7. **落盘合模板**：写出的锚恰三字段且版本＝2；写出 / 更新的档案版本＝2 且字段齐（照参考件模板：顶层含 `folder_token`，`skills` 段分 `inputs` / `outputs`）。**迁移入径下另加**：旧档案已另存为 `_tingle/` 下的一份独立文档（已改标题、不在云盘顶层、未附在新档案正文里），且原档案的链接、位置、标题未变；
8. **判定零外泄**：本次工作未在任何其他 skill 文件中添加判定逻辑——引擎只此一份；
9. **零自行降级**：本次运行中凡出现"这一道 / 这一件 / 这一格不用走、走不了"的判断，都有摆出来、停下、等人拍的记录，没有一处是自己判完就往下走的。**按既定判法走完得出的「无」不算降级**，但须指得出走的是哪条判法、在哪一步走完的；指不出，即按自行降级论，本条不合格。
10. **总索引已建出**——**适用范围＝本次运行跑了道10 的，一律适用**：既含完备集补齐路径（道4–10），**也含只跑道10 的迁移入径**（迁移完成后那就是一个版本 2 的项目，同样要有总索引）；只走个人级四道（新成员加入、且档案版本已是 2 无须迁移）或 `step0` 运行前检查的，本条不适用。**判法**：云盘顶层的「tingle-项目索引」在、打得开，三行（认知件 / 原料 / 内务件）都在——迁移入径下顶层原已有一份的，判法相同（核过三行、缺行补齐后再判）。**空的也算建出**——某一类没东西可指，那一行照留、入口链接写「—」即满足本条；**文件根本不在，本条不合格**。第 9 条挡的是"自己判了不必建"，本条挡的是**忘了建**——两条各挡一路，不可互相顶替；而本条要真被过一遍，靠的是编排 procedure 末「收尾 · 下结论前逐条过一遍 DoD」那一步。

| 云盘文件夹客户已有、判定"不必新建" | **道4 照样走三步**：问性质→摆清单→等放行。本道挡的是"定落点"，不是"建文件夹"；本次不写飞书也照挡 |
| 使用者递来一个文件夹当落点 | 先问一句：这是**产物落点**还是**来料来源**？两者在飞书上长得一样，不问分不出 |
| 判出"这一道 / 这一件 / 这一格不用走、走不了" | 摆出来、停、等人拍——**降级是人的决定**；只有按判法走完得出的「无」才不算降级 |
| 声明了落点、档案里却没登记（step0 入径） | **不就绪，本次不跑**（返回前先过「收尾」）；走道10 登记（先放行、地址由使用者给），复验第 6 查过了**再过「收尾」**才跑——**本路写了飞书＝十条全适用、整包交出** |
| 验收道9（蒸馏） | 两条都要：产物按清单齐＋`raw/_台账/评审判定-<YYYYMMDD>.md` 在。缺后者即不通过，口头说"评审做过了"不顶用 |
| 走到道10 | 建**两件**：项目档案 ＋ 云盘顶层「tingle-项目索引」（三行：认知件 / 原料 / 内务件）。**空的也要建出来**，那一行照留、入口链接写「—」。**迁移入径只跑道10，同样是这两件** |
| 补齐做完、要宣告「已就绪」 | 复验（按本次入径重跑判定）＋**逐条过一遍 DoD 十条**：每条指得出在本次运行哪一步满足、或本次为何不适用；指不出即回去补，不得带过 |
| 一个地址该记在哪一层 | 指针→本地锚（`profile_link`）；配置、慢变量→项目档案；清单、快变量（有哪几条）→索引。**总索引管有哪几类，每一类自己管有哪几条** |
| 新成员加入已初始化项目 | 只走个人级四道；档案靠链接直粘或按「tingle-项目档案」搜云盘顶层 |
| 使用者递来材料 | 先上传项目云盘转格式，再处理 |

## Common Mistakes

- **替入口做锚定 / 建工作文件夹**——道1 归入口引导，本 skill 不重复；未锚定回入口。
- **把判定逻辑抄进别的 skill**——引擎只此一份；其他 skill 的运行前检查只允许一行调用。
- **代替 context-distill 收料 / 蒸馏**——它是黑盒，本 skill 只发起合并调用、只按道7–9 各自判据验收结果。
- **判"不必新建文件夹"就跳过道4 的闸**——道4 定的是本项目全部产物的落点；新建与复用同样摆清单、同样等放行，本次不写飞书也一样。本道没有"不必放行"的分支。
- **把客户的来料文件夹当成产物落点**——来料夹与落点夹在飞书上长得一模一样，道4 第 1 步那一问不是礼节，是唯一能分开它们的动作。
- **待建内容清单只写"我要建一个文件夹"**——使用者照样点头，坑原样保留。清单必须让他看见本项目后续全部产物（`raw/`、九件认知件、认知件索引、项目档案、项目总索引、日后的 `_tingle/` 存档）都落进这个文件夹。
- **道10 建了档案就收工**——本道建**两件**：项目档案 ＋ 云盘顶层的「tingle-项目索引」。总索引这次没东西可指也要**把文件建出来、那一行照留**（入口链接写「—」）：「文件在但那一行是空的」与「文件根本不在」是两回事。
- **把认知件、原料的地址抄进项目档案**——那些是**快变量**（每次重蒸都可能变），归各自的索引管；档案是慢变量，抄进去的那份没有任何工序负责维护，存进去就等着变成旧链接。档案记配置，索引记清单，本地锚记指针，三层不混。
- **把总索引的行并进认知件索引、或反过来拿总索引代管认知件条目**——两者不是一套列：认知件索引的行记状态与缺口、每次重蒸都变；总索引的行记这一类从哪儿进、很少动。**总索引管有哪几类，每一类自己管有哪几条。**
- **自己判"这一道 / 这一件 / 这一格不必做"然后接着跑**——降级要人拍；判法走完得出的「无」才是判定结论。
- **验收道9 只数产物、不查评审判定记录**——两条判据缺一不过；被调方口头说"评审做过了"不是记录。
- **声明了落点却让它先跑起来、回头再找地方写**——落点未登记即不就绪；"活干完了总得放个地方"正是往没人批准的地方写的那一刻。
- **初蒸时去档案解析 `folder_token`**——初蒸时档案尚无该条目，由道4 产出直传。
- **把就绪结论写进锚或档案**——两层只存事实（地址、日期），就绪每次现算。
- **环境状态落盘或沿用上次结果**——环境永远现场查。
- **复用他人 / 上次的判定结论**——就绪按人、按次各自判。
- **补完不复验就宣告就绪**——补齐后必须按本次入径重跑判定且全过。**复验过了也还不能宣告**：还要逐条过一遍 DoD 十条——复验只重跑判定，照不到放行记录、降级记录、总索引这些判定之外的条目。
- **迁移时重跑前置各道**——档案版本旧只说明档案这一份文件的结构该换；云盘落点 / 打标 / 定阶段 / 收料 / 转可读 / 蒸馏在这个项目上早已完成，一律不重跑，原值照搬。**总索引不在此列**：建它不是重跑某一道，是把一份缺失的索引按现状建出来（不收料、不蒸馏，三行指向的都是已经存在的东西），拿"迁移跳过道4–9"驳不掉它。
- **迁移时只换档案就收工**——道10 建的是**两件**，迁移只跑道10 也是这两件：档案就地覆盖 ＋ 总索引按现状建出或核齐。只换档案，留下的是一个**没有总索引的版本 2 项目**，内务件无人覆盖、下游查不到这个项目有哪几类东西。
- **迁移时拿某个输入的 `folder_token` 顶替项目云盘根**——`skills` 段下 `lark-drive` 输入记的是那个输入自己的文件夹。迁移取项目云盘坐标只有一条路：旧档案的 `skills.context-distill.项目云盘.folder_token`——**这一项名下记的就是云盘根本身，是版本 1 档案里唯一记着它的地方，仅此一处例外**；取不到就停下问人，不猜，别的 `folder_token` 一概不作数。

## Red Flags（出现即停，回到该守的闸）

- 「环境上次查过了，跳过第一步吧」→ 环境现场查，永不沿用。
- 「就差一点点，先放行这一次」→ **不就绪不跑这一次**。
- 「标签 / 阶段看着像这个，先填上吧」→ **缺料不发明**——问人或从材料认，取不到标待补。
- 「文件夹 / 表 / 档案顺手就建了吧」→ **对外动作先放行**——先摆待建内容清单，等放行。
- 「云盘文件夹现成的，不用新建，直接拿来用」→ 道4 挡的是**定落点**、不是建文件夹——**复用同样摆清单、停、等放行**，本次一个字节不写也一样。
- 「这个文件夹他给我了，那就是让我往里写」→ 先问一句：**产物落点还是来料来源**。没问过就不算定过落点。
- 「这一道对这个项目不适用，跳过吧」/「这件先简化一下跑完，回头补」→ **降级是人的决定，不是执行者的决定**——摆出来、停、等人拍。
- 「产物看着挺全，评审判定记录没有也算了」/「他说评审做过了」→ 道9 两条判据缺一不过，口头回报不是记录。
- 「落点回头再说，先把活干完再找地方写」→ 干完再找地方，就是往没人批准的地方写；落点没登记就是不就绪。
- 「我这边就绪，他那边肯定也行」→ 就绪按人各自判。
- 「把三步抄一份进那个 skill，省得调用」→ 判定引擎只此一份，抄即坏架构。
- 「材料先在对话里用起来，回头再传云盘」→ 先上飞书项目云盘转格式，再处理。
- 「锚里顺便多存几个地址，省得每次读档案」→ 锚仅三字段，地址只在档案。
- 「总索引现在没什么可写的，等有东西了再建吧」→ **空的也要建出来**，三行照留、拿不到链接的写「—」；不建＝下游分不清"还没做"与"做了但没有"。
- 「这次是迁移，跳过道4–9，总索引也跟着跳过吧」→ **跳的是道4–9，不是道10 的第二件**：迁移完成后这就是版本 2 项目，总索引照建（顶层已有则只核三行、缺行补齐）——建它不收料、不蒸馏，"重跑是白干"这条理由对它不成立。
- 「顺手把认知件的链接也写进档案吧，省得查索引」→ 快变量归索引、慢变量归档案；写进档案的那份没人维护，下次重蒸就成了旧链接。
- 「档案结构旧了，新建一份新的、把旧的挪走就行」→ **原件就地改、副本另存**——新建即换了链接，全员的锚还指着被挪走的那一份。
- 「旧 JSON 就附在新档案正文底下留个底吧」→ 一份正文两个 JSON 代码块会取错一个且**不报错**；存档另存一份文档，放 `_tingle/`、改标题、不留在顶层。
