# check-claim-citations

## 概述与核心原则

一句话职责：**给一份已成稿的内容稿做文献引用校对并交出标注好的稿件**——逐句判哪些声明需要证据、把需要的声明配到证据上、按稿内首次出现重编号，再把定下来的角标与文末条目落进稿件的副本，交出一份可直接送审的成品稿，并附上据以复核的校对结论。

**这算一个职责，不算两个。** 标注在这里没有独立的消费者——它读的是本环节自己刚产出的判断（这一句配哪条证据、角标落在哪一处、这一条排第几号），脱离这份判断它无事可做。**一个动作是另一个动作的最后一步，不构成两个能力。** 反过来，把判断交出去让另一个环节再执行，必然失真：做判断的知道"为什么"，做落地的只知道"做什么"，位置一有歧义就只能猜；而两边各自都不是使用者能直接用的东西——前一半交出的是中间件，后一半要靠别人喂。至于"标成什么样"那套会随项目变的规则，本环节**不自带**，由输入「标记体例说明」外置提供，与读同一份体例的其它环节天然一致，不会各自漂开。

**适用环节**：换一个客户项目也会再次发生的固定环节——凡产出要受监管或受内部审核的内容，成稿之后、送审之前都要过这一道，不是一次性事务。

**属于哪组能力**：项目自动化（供上位方案对账用——本环节是项目执行链上的一道，不属诊断、洞察、盯盘、策略建议或复盘沉淀）。

**三条核心原则（越一条即错）**：

- **只给"会被人追问出处"的那一句挂引用。** 判别问句：读到这一句，一个审稿的人会不会问"这话有什么依据"？会 → 需要证据，角标落在**那一句的末尾**，不落在段末、不落在离它两句远的地方。叙事钩子、过渡句、场景铺陈、纯修辞不因为身处一段医学内容里就一并需要引用。
- **"证据里有这句话"不等于"这条证据可以引"。** 一条证据能被写成正式角标，须同时具备两样：**来源可指认**，且**该来源里被引的那一处有获批凭证**（凭证形态由项目的既定标记体例定，可能是标注、可能是审批编号、可能是索引表里的一个状态格）。只满足前一样的，一律标「待确认·缺获批凭证」并指出是哪条来源的哪一处，**不得据以生成正式角标**。**项目本身没有独立获批机制的，凭证退化为"证据入库本身即为凭"——但这一退化须由该项目的「标记体例说明」明写，不由本环节自行认定**；说明里没写的，一律按"须有独立凭证"处理。
- **不编造，不补全。** 著录条目缺作者、缺年份、缺卷期、缺页码范围的，标「待确认」交人，不按常识补一个看起来对的值。

## 何时用 / 何时不用

**何时用**
- 一份成稿要送内部审核或对外发布，需要先过一轮"哪句缺引、哪句引错、编号对不对"的校对，**并要拿回一份角标与文末条目都已标好、可以直接送审的稿子**。
- 稿子改过之后引用顺序变了，要重新按稿内首次出现排一遍号并同步文末条目。
- 想知道某几句话在现有证据里有没有可引的支撑，以及缺的是"没有证据"还是"证据有但没获批"。

**何时不用（When NOT）**
- **完整的合规、医学或法务终审**——本环节只判"引用对不对"，不判"这话该不该这么说"。稿件上那些属于别的审核环节的意见（表达是否均衡、面向什么人群、用法用量表述是否妥当一类），本环节不据以判不合格。
- **改写稿件文案**——本环节只插入或调整引用，不重写声明本身。要改措辞是另一件事，交回作者。
- **维护证据库**——本环节只读证据索引表与证据原文库，不往里写、不新增条目、不改获批状态。
- **稿件读不全时硬跑**——只读版式文件的文本层残缺、表格里的正文取不到，一律停并报，索要可编辑原件。
- **拿不到可编辑原件却硬出成品**——只读版式文件不作为成品载体，先索要可编辑原件，不产出一份改不动的东西。

## 方法

### 一 · 判哪一句需要证据

逐句扫，对每一句问：**读到这一句，审稿的人会不会问"这话有什么依据"？** 会问的，就是需要证据的那一句。

哪几类声明属于"会被追问"，由输入**「标记体例说明」**给出（那份文件是本项目引用规矩的唯一落点，见下方「依赖的规则层与项目事实」），本页不列举——换一个合规类目，那张清单整张换。

**它没写到怎么办**：仍照上面那个问句逐句判，**并把"这一类算不算须有出处，本项目没写"当成待确认标出来交人**，不自己定一类进去。判得松与判得紧在产出里都看不出来，只有把没写到的那几类显式列出来，人才核得动。

**逐句都要留痕，包括判"不需要引用"的那些。** 只列有问题的句子，等于让"漏判"与"这句没问题"在产物里长得一模一样，而漏判的代价是一句该有出处的话就这么发出去了。

### 二 · 配证据

**禁止**：

- **禁止在只有"原文里有这句话"的情况下生成正式角标。** 证据原文支持该声明、但被引的那一处没有获批凭证的，标「待确认·缺获批凭证」，写明是哪条来源的哪一处，交人补批或改引别处。**已观测的原样**：原文里读到一句意思对得上的话，就照常写出一个形式完整的角标——它和一条合规角标在稿面上完全一样，而复核的人不回证据原文逐条核就看不出来。
- **禁止按字面关键词配对。** 按声明的**实质含义**配：一句里裹着修辞的，先把"事实声明"与"修辞表达"拆开，只给事实声明配证据。
- **禁止拿"现象层的证据"支撑"机制层的声明"。** 一份材料说"会同时出现某某表现"，不等于它说明了"为什么会同时出现"；稿件若把机制当作事实陈述写出来，那是另一条声明，要另一条证据。判不准两者是不是同一层的，停，交人（升级条件⑥）。
- **禁止把一长句里几个各有出处的声明合挂一个角标。** 支撑它们的是不同证据的不同处时，逐段分别挂。
- **禁止为缺失的著录元素补一个看起来对的值。** 缺作者、缺年份、缺卷期、缺页码范围的，标「待确认」。

**合理化对照表**

| 心里的那句话 | 实际是什么 | 怎么裁 |
|---|---|---|
| 「原文里明明就有这句，标一个角标怎么了」 | 有支撑与可引用是两回事；获批凭证是这条证据被允许对外引用的唯一凭据 | 标「待确认·缺获批凭证」，指出来源与位置 |
| 「关键词对上了，就是它」 | 同一个词在两条证据里可以指两件事 | 按实质含义配，对不上就标不匹配 |
| 「这句是文案写手编的比喻，跳过」 | 比喻里常裹着一条真的事实声明 | 拆成事实声明与修辞表达，只给前者配 |
| 「一整句挂一个角标，看着干净」 | 几个声明各有出处时，一个角标只能证明其中一个 | 逐段分别挂 |
| 「页码差一点，先填上，回头再核」 | 填上去的与核过的在稿面上分不开 | 缺什么标什么，交人 |
| 「这句只有我这个项目才有人较真」 | 判的不是谁较真，是这句会不会被追问出处 | 照样跑那个问句 |

**Red Flags（出现即停）**

- 「证据里有，直接标」
- 「差个凭证，先按有算，回头补」
- 「这一句我记得以前引过那一篇」（记得不是核过）
- 「没找到证据，那就当它不需要引用」（找不到与不需要是两回事）
- 「时间紧，只列明显有问题的几句」

### 三 · 编号与文末条目

- **编号是稿内的，不是证据库里的行号。** 按每条来源在**本稿**中首次出现的顺序赋号；同一来源在稿内重复出现时复用同一个号。
- **插入一条更早的引用，会改动它之后已赋的全部号**——正文角标与文末条目须一并改。这也是判需引、配证据、重编号三步必须在同一遍扫描里做完的原因：三步共用一份只在环节内部存在的中间态（现有引用的清单与已赋的号），拆开做就得让它在环节之间来回传。
- **角标由哪几个成分组成、文末条目怎么写，一律以「标记体例说明」为准**；本页只声明角标必须携带的三样：本稿内的序号、到来源的指认、到该来源被引处的定位（含其获批凭证）。
- **著录条目以证据索引表提供的条目为准**，不以证据原文件里印着的引用格式为准——后者常被排版截断。**著录按什么规范写、各类来源各自什么样式，一律以「标记体例说明」为准**，本页不列样式；它没写到某一类来源的样式时，保持索引表给的原样并标出来问，不自造一种。

### 四 · 把标注落进成品

判定表交人过目、拿到确认之后（必停，见下），把定下来的角标与文末条目落进稿件的**副本**，交出成品。这一步不再产生新的判断——它只是把上面三节已经定死的东西落到纸面上；凡到这里还得重新判一次的，说明前三节没做完，回去补。

- **成品的载体跟随稿件的载体，本环节不预设也不选择。** 进来的是可编辑文稿，就交同一形态的文稿；是云文档，就在云文档的副本上标注；是纯文本，就交纯文本。**只读版式文件不作为成品载体**——遇到这类稿件，停并索要可编辑原件之后再出成品，不产出一份改不动的东西。
- **具体标成什么样，由项目的「标记体例说明」提供。** 角标由哪几个成分组成、各成分呈现成什么样、文末条目栏与正文角标怎么区分开——一律以它为准。**本 skill 只带"怎么标而不破坏原件"的手艺，不带"标成什么样"的规定。** 体例说明里没写到的情形，保持原稿原样并标出来问（升级条件⑩），不自己发明一种——现造一种写法，等于在这份稿子上开了一个只有你知道的先例。
- **在原稿的副本上只增不改。** 要加的只有两样：正文里的角标、文末条目栏里的编号与条目。除此之外的一切（措辞、段落、表格、字体、行距、间距、换行）都是作者的成果，保持你没来过的样子；原件必须能随时拿出来与成品逐段对照。**不顺手规范化**——原稿里那些不统一的地方不是本环节要修的东西，你也并不知道它是不是有意为之。
- **动手的手艺见随校对工具一并提供的排版手艺参考件（《把标注排进成品文件》，`references/typesetting-craft.md`）**：先是与成品载体无关的通则，再是成品为 Word 时的具体手法（角标以 run 级插入、不整格重写、不重建表格与文末条目栏、编号是打上去的字而不是文档的自动编号）。**落成品之前读它，排完照它的收尾自查逐项核一遍**，核不过就是没排完。
- **待确认项不在成品里替人做决定。** 判为「待确认」或「待确认·缺获批凭证」的那些，成品里该处保持原稿原样、**不生成正式角标**（编造出来的角标与核过的角标在稿面上分不开），另在随成品交出的待确认项里逐条写明卡在哪、缺什么、要谁补。

### 五 · 步骤

1. **抽稿件结构**——取出正文、顺序信息、现有角标、文末条目栏；稿件上属于别的审核流程的系统编码不参与本环节判定。**交出覆盖清单**（抽到几段、几处现有角标、文末几条），请人确认没有漏抽（必停，见下）。
2. **建当前引用图**——按首次出现列出现有角标，核角标内的序号与其成分自洽、文末条目里有同号。
3. **逐句判需不需要证据**（方法一），逐句留痕。
4. **给需要的那些配证据**（方法二）。
5. **按稿内首次出现重编号**（方法三），同步正文与文末。
6. **核文末条目的著录**是否合规范、是否与索引表提供的条目一致。
7. **出校对结论**——逐句判定表、建议引用顺序、建议文末条目、待确认项、覆盖清单。**这是给人复核的中间结论，不是最终交付物。**
8. **把结论交人过目、取得确认**（必停，见下）。**没有这份确认就没有可落的成品**——第 9 步的输入就是"经确认的判定表"这一件东西本身。**人在这一步提的改动，回到相应步骤改、出新一版判定表再确认**，不在成品上直接补。
9. **落成品**（方法四）——在稿件副本上按「标记体例说明」标注角标与文末条目，只标第 8 步确认过的那些，表外不新增。
10. **收尾自查并交付**——照随件的收尾自查逐项核（成品是新副本、原件未动、与原稿逐段可对照、正文除新增角标外无第二处差异、文末条目栏对得上体例说明），核过之后交出成品稿，并附上校对结论与复核包。

## 依赖的规则层与项目事实

- **挂两层**：**品类层**——哪几类声明会被追问出处、文末条目按什么规范著录、某些类别的证据是否须随附来源披露，这几样按合规类目取值，换一类整套换；**品牌层**——本项目已约定"这类简单表述默认不必引用"的豁免条款、以及随附披露的具体文案与呈现要求。

- **这两层当下的承载，就是输入「标记体例说明」那一份项目件——组织级的规则库还不存在。** 跨项目的品类规则库是显式预留、尚未建出的，所以本环节运行时**不去任何组织级的地方取规则**：上述两层要用的内容，全部写在本项目那一份「标记体例说明」里（它的就绪判据已把这几样逐条列出）。**这不是权宜**——规则库建出来之前，项目件就是唯一真相源；建出来之后，改的是那份文件从哪儿继承内容，本 skill 的读法一个字不变。
- **它没写到的，一律标出来问，不自己补一条。** 取不到规则与"这一类不必引用"是两回事：前者要停下来问人（升级条件⑪），后者要有人写明才算。**自己补进去的那一条，跟项目约定的那一条在产出里长得一模一样**，而复核的人不会知道有一条是 AI 当场定的。
- **不挂通用层**：本环节的判法都是本 skill 自己的方法，没有一条是别处维护、别的 skill 也在读的清单。
- **不挂类型层**：现有材料里没有出现"换一种产出类型，这一句该不该引就变了"的情形。**这一条是按现有材料判的，不是验过的**——若日后出现产出类型改变引用门槛的项目，此处须重判。
- **所需项目事实字段**：`合规类目`、`品牌`（决定装载哪一套上述规则），由运行前检查从项目档案取得。

## 依赖的工具与接口

- 结构化表读取接口（读证据索引表）。
- 文档与云盘读取接口（取稿件、取证据原文件）。
- 版式文件与只读文件的取文能力（把成稿与证据原文件转成可逐句读的文本）。
- **文稿写入能力**（在稿件副本上落角标与文末条目）——须支持**最小改动**：只动涉及处，不重排未涉及的段落与表格。能力随成品载体走，可编辑文稿、云文档、纯文本各用各的写入方式。
- 同族 skill：REQUIRED SUB-SKILL: `tingle:project-readiness`（Step 0 运行前检查）。
- **随件**：排版手艺参考件《把标注排进成品文件》——随校对工具一并提供，落成品之前读。它管"怎么标而不破坏原件"，不管"标成什么样"（后者一律看「标记体例说明」）。

**写入只发生在两处：稿件的新副本、本 skill 自己的产出落点。** 原稿不动、证据侧只读——不往证据索引表与证据原文库里写、不新增条目、不改获批状态。

## 输入 / 输出 schema

**input schema**
- `待校对稿件`（本次要校对的那一份成稿，含其现有角标与文末条目。**由调用时当场给出**，三种来源一律接：本地文件 / 云文档链接 / 云盘文件。它不登记在项目档案里，故不出现在上方 requirements 里——这一处与家族其余 skill 的输入声明方式不同，后续会有统一规定）
- `稿件形态`（枚举：可编辑文稿 / 只读版式文件 / 纯文本。只读版式文件的文本层残缺时停并报，索要可编辑原件；**只读版式文件也不作为成品载体**——要出成品须先拿到可编辑原件，否则本次只能交出校对结论并停在那里）
- `证据索引表`（结构化表；提供每条证据的著录条目、可引原文段、分类与检索关键词、获批凭证定位、到原文件的指认）
- `证据原文库`（各条证据原文件所在的文件夹）
- `标记体例说明`（本项目角标与文末条目的既定写法）
- 上述后三样的实际地址以 Step 0 运行前检查返回的已解析地址为准。

**output schema**

**最终交付物（一件）**

- `标注好的稿件`（在稿件副本上落好角标与文末条目、可直接送审的成品；原稿不被改动，两份逐段可对照）。**载体跟随稿件的载体**——可编辑文稿进则可编辑文稿出、云文档进则云文档出、纯文本进则纯文本出；本 skill 不预设某一种文件格式，也不把成品固定成某个后缀。**标成什么样以「标记体例说明」为准**，本 skill 只保证标注动作不破坏原件。

**给人复核的中间结论（六项，随成品一并交出）**——它们不是最终交付物，是成品的依据：没有它们，复核的人只能看成品的样子，核不到每一处角标凭什么。

- `逐句判定表`（每行：句子位置与摘录 / 判定 / 建议或卡在哪。判定取值：引用正确 · 需补引用 · 引用位置需调整 · 引用不匹配 · 编号需调整 · 待确认 · 待确认·缺获批凭证 · 无需引用）
- `经确认的判定表`（记录第 8 步那次过目确认本身：谁确认的、确认的是哪一版判定表。没有这一项，一次运行有没有经过第 8 步的确认，在交出的东西里看不出来）
- `建议引用顺序`（按稿内首次出现排序的来源清单）
- `建议文末条目`（按稿内序号列出的著录条目）
- `待确认项`（每条：卡在哪一样、缺什么、要谁补。**这几处在成品里保持原稿原样、未生成正式角标**）
- `覆盖清单`（抽到的段落数、现有角标数、文末条目数）

**可沉淀候选（reusable_candidates）**

- `本次新确认的声明与证据的对应关系`（下一稿再遇到同类声明可直接复用，宜回写证据索引表）、`待补获批凭证的证据条目`（供证据库补批，补齐后全项目受益）

## 决策档 · 必停名单 · 复核包 · 升级条件

**决策档**：**复核**。产出是一份将被送去审核的成品稿，且它下游连着对外发布，不标自动。**能自动出成品不改变这一档**——越是交出去就能直接用的东西，越要有人在中间点过头。

**哪几步必停（不是统一档位，是这一份名单）**：

| 步 | 判 | 这一步做错了，谁会在什么时候发现 |
|---|---|---|
| 1 抽稿件结构 | **必停**——交出覆盖清单请人确认 | **没有人。** 漏抽一段与"这一段没问题"在产物里长得一模一样：判定表只呈现它看见的东西，漏掉的部分不留任何痕迹；而那一段照样会原样出现在成品里，成品看上去是完整的，没人会想到有一段从头到尾没被判过 |
| 2 建当前引用图 | 可自动 | 下游必然看到：读漏一处现有角标，会导致同一来源在建议顺序里占两个号，这在结论里是直接可见的 |
| 3 逐句判需不需要证据 | 可自动（**条件是逐句留痕**） | 若只列有问题的句子，漏判无痕、无人发现；改为逐句都出现在判定表里之后，漏掉的句子变成看得见的缺口，人核得动 |
| 4 配证据 | 可自动，命中下列升级条件⑤⑥⑦即停 | 配错在"实质含义不同层"这一类上最难发现——形式完整、有凭证，只有懂那门专业的人回读证据原文才看得出来，故那一类判不准即停 |
| 5 重编号 | 可自动 | 机械可核：正文角标与文末条目一一对照即暴露 |
| 6 核著录 | 可自动 | 人对照著录规范当场可见 |
| 7 出校对结论 | 可自动 | 它本身就是交给人看的东西，错处在下一步的过目中暴露 |
| 8 出成品之前 | **必停**——把逐句判定表连同建议引用顺序、建议文末条目、待确认项交人过目，**得到确认才落成品** | **没有人。** 成品在稿面上就是一份可以直接送审的样子：配错的角标与配对的角标长得一模一样，而拿到成品的人默认它已经核过——校对结论那一层没人再回头看 |
| 9 落成品 | 可自动（**前提是第 8 步已确认**） | 机械可核：成品与那份确认过的判定表逐条对照，多标、漏标、标错位置当场暴露 |
| 10 收尾自查 | 可自动 | 与原稿并排翻一遍即见：段落数、表格结构、正文里除角标外的第二处差异都在对照中暴露 |

**这一停是结构上跑不过去的，不是一句劝告。** 落成品这一步的输入不是"稿件 + 判定表"，而是**"经人确认的判定表"这一件东西本身**：判定表未经确认时，第 9 步没有可用的输入，本次运行到此为止——产出只有校对结论，没有成品件。**没有确认就没有可写的成品**，绕不过去也不必绕：人点过头，这一步才存在。

**复核包**（随产出附上，使复核的人不必回头翻上下文）。**它与第 8 步那次过目是两回事**：第 8 步定的是"该怎么标"，发生在成品之前；复核包供的是"标得对不对、有没有弄坏原稿"，随成品一并交出。内含：待校对稿件本身**与标注好的成品稿**（两份并排，供逐段对照——正文除新增角标外不应有第二处差异）、逐句判定表、**经确认的判定表**（谁确认的、确认的是哪一版）、建议引用顺序与文末条目、待确认项清单、**本次每条被引证据的定位与其获批凭证**（复核要核的正是这一处，没有它复核的人只能信、不能核）、覆盖清单。

**升级条件（命中即停交人）**：①合规红线不确定；②四层规则冲突（两层各有一套说法）；③缺关键项目事实（合规类目或品牌未取到，不知道该装哪套规则）；④产出需对外发送；⑤证据原文支持该声明、但被引处无获批凭证；⑥一条声明与候选证据是不是同一层（现象与机制）判不准；⑦证据索引表取不到某条证据的必需信息（著录条目、可引原文段、获批凭证定位、到原文件的指认，缺其一即停）；⑧稿件读不全（只读版式文件文本层残缺、表格内正文取不到）；⑨稿件只有只读版式文件、拿不到可编辑原件——读得全也出不了成品，停并索要；⑩要标的这一处「标记体例说明」没写到——保持原稿原样并标出来问，不自造一种写法；⑪**判需不需要引用时撞上「标记体例说明」没写到的那一类声明**——照核心问句判出结论，但把"这一类本项目没写"随判定表标出来交人，不把自己的判断当成项目约定（与⑩是两处：⑩发生在落标注、⑪发生在判需引）。

## 写回位置 · 可沉淀候选

- **写回位置**：requirements 落点「校对产出落点」，地址由项目档案填、运行前检查解析。成品稿与校对结论**各自成件**落在这里，每次校对各自一套、不覆盖上一次——上一稿的结论是这一稿改动的对照物。**原稿不覆盖**：成品是新副本，原件原样留着，两份要能并排对照。落点只管归档在哪，**不决定成品是什么形态**——形态跟随稿件。
- **可沉淀候选**：见 output schema 中标出的两项。

## 产出验收判据（DoD）

一次运行合格，当且仅当：

1. 稿件中每一句都在逐句判定表里有一行，含判为"无需引用"的；覆盖清单已交出且经人确认。
2. 每一条判为"需补引用"或"引用不匹配"的，都给出了配到哪条证据、该证据的被引处及其获批凭证；配不出的，落在「待确认」或「待确认·缺获批凭证」，并写明缺的是哪一样。
3. 建议引用顺序按稿内首次出现排列，同一来源全稿复用同号；文末条目与正文角标逐条对得上，无孤号、无空号。
4. 全部文末条目按「标记体例说明」给的著录规范写成，缺元素的标「待确认」而非补值；该说明没写到的来源类别，条目保持索引表原样并已标出来问。
5. **交出了标注好的成品稿**，且它是在判定表经人确认之后落的——成品里每一处角标都出自那份确认过的判定表，无表外新增；判为待确认的那些在成品里保持原稿原样、未生成正式角标。**凡本环节判得了的，都已落进成品**，没有"只写在表里、等人回原文件敲进去"的遗留。
6. **成品的载体与稿件一致**（不是某个固定文件格式），每一处角标的成分与每一条文末条目的写法都对得上「标记体例说明」；体例说明没写到的情形已标出来问，未自造写法。
7. **成品与原稿逐段可对照**：原件未被改动，段落数、段落顺序、表格结构与原稿一致，正文里除新增的角标外没有第二处差异，文末条目栏与正文角标逐条对得上。
8. 复核包齐全（含成品稿与原稿两份），复核的人据它可以逐条核到证据的被引处，不必回头问作者。

## Quick Reference

| 问题 | 一句判法 |
|---|---|
| 这一句要不要引用？ | 审稿的人会不会问"这话有什么依据"？会 → 要，角标落在这一句末尾。哪几类算"会被追问"看「标记体例说明」；它没写到的那一类，判归判、另标出来问 |
| 这条证据能引吗？ | 来源可指认 **且** 被引处有获批凭证。少一样 → 待确认·缺获批凭证（项目无独立获批机制、且体例说明已写明的，入库即为凭） |
| 配得对不对？ | 按实质含义配；现象层证据不支撑机制层声明 |
| 编号怎么排？ | 按本稿首次出现，同源复用同号；插入更早的引用要改它之后的全部号 |
| 角标长什么样？ | 以本项目「标记体例说明」为准；本页只要求它携带稿内序号、来源指认、被引处定位 |
| 什么时候能落成品？ | 判定表经人确认之后；没有确认就没有可落的成品 |
| 成品交什么形态？ | 跟稿件同一形态（文稿进文稿出、云文档进云文档出、纯文本进纯文本出）；只读版式文件先索要可编辑原件 |
| 怎么标才不弄坏原稿？ | 在副本上只增不改、最小改动、不顺手规范化；手法见随件《把标注排进成品文件》 |
| 待确认的那几处成品里怎么办？ | 保持原稿原样，不生成正式角标，另在待确认项里写明缺什么 |
| 哪一步不许自动？ | 抽稿件结构后的覆盖确认、出成品前的判定表确认；另有十条升级条件命中即停 |

## 常见错误（Common Mistakes）

- **只列有问题的句子**——漏判与"没问题"在产物里分不开，逐句留痕才把漏判变成看得见的缺口。
- **拿"原文里有"当"可以引"**——两者在稿面上产出的角标一模一样，而只有一个是合规的。
- **按关键词配证据**——同一个词在两条证据里可以指两件事。
- **沿用证据库里的行号当稿内编号**——两套号一旦混用，文末条目与正文再也对不上。
- **只交一张判定表就收工**——判得了却没落进成品的，等于把最后一次搬运转嫁给了同事；而他照表敲角标时手上没有判断依据，位置一有歧义就只能猜。
- **在原稿上直接改，或整段整格重写**——原件与成品再也无法并排对照，作者改下一版时无从合并；重写还会丢掉那段继承来的格式，而丢没丢在屏幕上常常看不出来。
- **把某个客户的角标样式写进本页**——样式随项目变，写进正文的那一份不会跟着体例说明改，而落成品的人读的是正文这一份。
- **把证据库里的映射抄一份进本 skill**——抄来的那份不会跟着证据库改，而用的人读的是抄来的那份。
- **把某台机器上的路径写进文件、让装的人自己改**——改源码不是配置，每装一次分叉一次。

## Red Flags

- 「这份表跨项目都一样，不用声明」
- 「路径先写死，用的人自己改」
- 「凭证放参考件里最方便」
- 「差个凭证，先按有算」
- 「这次先交，覆盖清单回头补」
- 「判定表先交了，成品回头补」
- 「还没人确认，我先把角标标进去，反正大概率是对的」
- 「体例说明没写到，我照着看起来对的做」
- 「格式最后统一调一遍」
