# 把标注排进成品文件

本件管「怎么动手」，不管「引得对不对」。判断在 SKILL.md 正文；到了这里，判定已经定了，剩下的只有一件事：**把角标与文末条目落进成品文件，而不弄坏别人的原稿。**

**样式的具体取值本件一个都不给。** 角标由哪几个成分组成、各成分呈现成什么样、文末条目栏与正文角标如何区分开——一律以项目的「标记体例说明」为准。本件只管动作：哪些能动、哪些碰都不要碰、动坏了会丢什么。

## 一 · 通则（与成品载体无关）

全部要领是一句话：**在原稿的副本上只增不改。** 你要加的只有两样——正文里的角标、文末条目栏里的编号与条目。除此之外的一切（措辞、段落、表格、字体、行距、间距、换行）都是别人的成果，保持你没来过的样子。

- **保留原件，改动写到新副本上。** 原件必须能随时拿出来与成品逐段对照。
- **不触碰未涉及的部分。** 没有引用变化的段落、单元格、表格，一个字节都不动——动过的地方越多，作者核对成品时要重新读的地方就越多，你也就越难说清哪些改动是他要的。
- **不顺手规范化。** 原稿里字体不统一、行距不一致、某段样式很怪——那不是你要修的东西。顺手"理顺"会让成品与原稿对不上，作者改下一版时无从合并；而且你并不知道那处不一致是不是有意为之。
- **成品与原稿逐段可对照**：段落数、段落顺序、表格结构与原稿一致。核对方法就是把两份并排翻一遍。
- **已经有可接受格式的地方，就地最小改动，不要推倒重来。** 尤其是文末条目栏：要给某一条加上稿内序号，就在既有的那段文字上把前缀补进去；**不要为了加一个序号就把整段删掉重打——重打出来的段落丢掉了它继承来的格式**。而丢的是什么、到底丢没丢，在屏幕上常常看不出来，要等打印或换台机器打开才暴露。
- **编号是你打上去的字，不是交给文档的自动编号功能生成的列表。** 稿内序号由每条来源在本稿中首次出现的顺序定；自动编号只按它自己的规则从头排，一旦在前面插入一条更早的引用，它会自行重排，而正文角标不会跟着变，两边当场对不上。
- **一处声明需要两个来源时，两个角标并排放在同一个声明边界上**，按各自的稿内序号顺序相连，中间不插入其它文字，也不拆到两个位置去。
- **体例说明里没写的，保持原稿原样并标出来问，不要自己发明一种。** 现造一种写法，等于在这份稿子上开了一个只有你知道的先例。

## 二 · 若成品载体是 Word（.docx）

上面的通则在这一层落成具体手法。稿件若是云文档或纯文本，本节整节不适用，通则仍然照用——届时问的是同一个问题：**在这个载体上，怎样做到只增不改。**

Word 的关键在于：一段文字在文件里由若干个 **run**（连续同格式的文字片段）拼成，格式挂在 run 上。整段、整格地重写，等于把这些 run 全部作废重建，继承来的格式随之丢失。

**要做的**

- **角标以 run 级插入在声明边界**——在那一处声明末尾新建 run，不动同段其它 run。
- **复制周围 run 的字体、字号、粗斜、颜色与样式**，能复制的都复制。
- **只设体例说明要求的那几样格式，其余全部继承。** 不要因为"顺便"就给角标指定一整套格式。
- **不要另指定字号**，除非是为了与相邻既有 run 对齐才必须指定。
- **角标里格式不同的成分各自成一个 run。** 体例说明若要求角标的某一段与另一段在呈现上不同（位置、字号、底色等任一样），只有分开成 run 才能各带各的格式，而不污染前后的正文。
- **保留段间距、换行、表格列宽、行高与单元格格式。**
- **文末条目栏若已经是可接受的格式**：只在既有 run 上增改编号前缀。**不要删掉重建那些段落**（理由见通则）。
- **文末条目栏若在插完引用后仍停在默认、无样式的状态**，那是没做完——按体例说明补齐，但**保留单元格本身的几何尺寸**（列宽、行高、边距不动）。

**不要做的**

- **不要用 `cell.text = ...` 一类写法整格赋值，也不要用纯文本替换整格或整段。**（唯一例外：使用者明确要的就是一份重排过的稿子——那是另一件事，须先说清楚再动手。）
- **不要重建表格**——重建会把列宽、行高、合并单元格与单元格格式一次性作废，而这些正是稿件版式赖以成立的东西。
- **不要重建文末条目栏**——只要在既有 run 上改前缀就能达成，就不许重建。
- **不要规范化字体、行距或段落样式。**
- **不要给文末条目栏另造一套观感**，也不要另造一套编号样式——另造的那套只有你知道，下一个人接手时它与体例说明各说各话。

## 三 · 交稿前的收尾自查

排完之后回头核这几样，核不过就是没排完：

- 成品是新副本，原件未被改动。
- 成品与原稿的段落数、段落顺序、表格结构一致。
- 正文里除了新增的角标，没有第二处差异。
- 文末条目栏：条目之间没有多出来的空段；没有出现由文档自动编号功能生成的列表；字体、字号、行距与原件一致。
- 文末条目栏的呈现与正文角标区分得开——**不要把正文角标的那套样式带到文末条目栏来**；至于区分成什么样，看体例说明。
- 每一处角标的成分、每一条文末条目的写法，都对得上体例说明。

## 四 · 常见错误

- **"格式我最后统一调一遍"**——统一调过的成品与原稿再也对不上，作者改下一版时无从合并。
- **"删掉重打一段比改前缀快"**——快的是这一步；丢掉的是那段继承来的格式，而且丢没丢在屏幕上常常看不出来。
- **"整格重写最省事"**——整格重写把这一处原有的格式一次性作废，包括你没注意到的那些。
- **"用文档自带的编号功能自动排"**——自动编号按它自己的规则重排，正文角标不会跟着变。
- **"体例说明没写，我照着看起来对的做"**——现造一种写法，等于开一个只有你知道的先例；该做的是标出来问。
- **"顺手把原稿那处明显不统一的地方也修了"**——那不是本环节的活，而且你不知道它是不是有意为之。
