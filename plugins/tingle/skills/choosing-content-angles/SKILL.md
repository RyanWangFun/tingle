# choosing-content-angles

## 概述

一句话职责：**把每条需求落成一个具体的内容方向，并为它选定一种内容形态。**

- **选形态不是挑款式，是先判断用户处在哪个认知阶段，再用对应形态去触达他。**
- **放不出量的根因永远是内容，不是预算也不是定向**。放量与一条链路强相关：素材点击率 → 互动率 → 组件点击率 → 转化。**点击率这一关不过，后面无从谈起。**
- **方向必须具体到能直接开工**。"做个测评""做个科普"不是方向，那是体裁；方向是一句能让人立刻知道要讲什么的话。

## 何时用 / 何时不用

**何时用**：需求表已定，要把需求变成能开工的方向与形态；内容发了很多但放不出量、要回头查方向；有爆文却没转化、要查形态与人群是否错配。

**何时不用**：
- 要挖需求本身——那是上游环节，本环节吃它的产出。
- 要写标题、封面、正文、评论——那是下游"造内容"的活，**本环节不写一个字的成片**。
- 要配投放工具、做搜索承接、做卖货、做复盘——各归各的环节。

## 运行前

**第一步跑 `tingle check choosing-content-angles`**，拿到开工单再开工；拿到卡点单本次不跑，按卡点单载入 REQUIRED SUB-SKILL: `tingle:project-readiness` 修完复验。开工单上附着的就绪判据由本 skill 开跑时逐条对照判，判不准停下问人。

## 业务方法

四道工序按序走。**每道工序的细节在它自己的深读件里，走到那一道再读那一份。**

| 工序 | 产出内容方向表的哪几列 | 读哪份 |
|---|---|---|
| 一 · 给人群定认知阶段 | 认知阶段 | `references/cognition-stages.md` |
| 二 · 定决策链路段与种草割草配比 | 决策链路段、种草或割草、可模板化度 | `references/decision-path-and-templates.md` |
| 三 · 选内容形态（四关筛） | 内容形态、形态门槛与风险 | `references/content-formats.md` |
| 四 · 具象成选题并找对标 | 内容方向、对标取法、为哪段意图作证 | `references/finding-the-angle.md` |

### 工序一 · 给人群定认知阶段

**把这条需求里的人放进认知坐标轴**：泛用户 → 认知空白 → 有认知无购买欲 → 决策阶段 → 已购买过的品类用户。**阶段不同，形态完全不同。**

**禁止**：

- **禁止把用户当成一个单一画像、或当成"一个流量"来运营。** 这是人群渠道不是流量渠道；每一条内容本质都是写给一个具体的人看的。
- **禁止对已购买过的品类用户讲泛泛卖点。** 他已经有了基于使用经验的新判断标准，内容必须命中那个标准。

### 工序二 · 定决策链路段与种草割草配比

**用户的决策链路是**：知道我 → 需要我 → 想买 → 是否值得买。**据此内容分两类**：种草（对应前两段）、割草（对应后两段）。

**禁止**：

- **禁止只种草不割草**——用户想找你时没看到相应内容，流量被竞品截走。
- **禁止只割草不种草**——能割的割完了，没有新草长出来，销售会撞天花板。
- **禁止让内容脱离产品特性。** 判据是那句终检：**把产品从这条内容里去掉，还影不影响用户看下去**——不影响，就是无效曝光。

**这一道还要标可模板化度**：品牌词类内容与结构固定的正文高度可复制（高）；靠内容内功撬曝光的方向不可复制（低）。**可模板化的方向，要把给合作方的要求做成一道填空题**——围绕产品特性、能突出卖点，让他只需把自己的生活场景填进去。**不许让合作方自由发挥**，一旦自由发挥就不可控。

### 工序三 · 选内容形态（四关筛）

四种形态构成一个倒三角，越往下能拿到的整体流量越大：**横测**（人群渗透，天花板低）／**产品直推软广**（高效引流转化，中）／**产品直推硬广**（建立品牌心智与信任，较高）／**高曝光软广**（撬动最大曝光，最高）。

**四关逐个过，任一关不过就换形态**：

| 关 | 问什么 | 不过怎么办 |
|---|---|---|
| ① 人群匹配 | 这个形态抓的人群 = 我这条需求的人群吗？ | 换形态，不是硬做 |
| ② 天花板 | 它的流量天花板撑得起这条需求要的量吗？ | 换或叠加另一形态 |
| ③ 该用判据 | 这个形态自己的前置条件满足了吗？（如做横测须满足"用户会主动搜这类词"且"这些词的搜索量占比够高"） | 不满足就不做 |
| ④ 平台当下 | 这个形态当下还让不让这么做？低真实性、批量号一类做法会被限流 | 按当下要求调整做法 |

**禁止**：

- **禁止看到别人做什么就跟做**，不判断"这个形态抓的人群是不是我的人群"。
- **禁止在品类主动搜索量很低时硬做横测**——拿不到多少流量。
- **禁止在团队没有内容内功时强上高曝光软广**——它的门槛不在预算，在内容挖掘、表达与用户洞察能力。
- **禁止只追爆文大小**。要看效率：**爆文没带来搜索、没带来转化，就没达成结果。**

### 工序四 · 把方向具象成选题，并找对标

**所有优质内容的出发点是需求洞察的两个面：用户在想什么、品牌该讲什么。二者的交集才是方向。**

**禁止**：

- **禁止把体裁当方向。** "做个测评""做个科普"是体裁；方向要具体到一句话能让人知道要讲什么。
- **禁止没有数据支撑就拆对标。** 没数据就拆，可能拆的是一条无效爆文——它自己都没带来结果。
- **禁止无脑抄爆文。** 同品类不代表同人群：一个面向入门用户的低价品，它的封面标题内容全是为入门用户设计的；照抄过来吸来的也是入门用户，而你的价位他买不起——**结果是有爆文、没转化**。
- **禁止让方向答不出"为哪段意图作证"。** 每个方向都必须能挂回一段定性意图（渗透／信任／曝光／转化），**答不出的方向直接砍。**

## 接口与边界（声明）

- **适用环节**：「把需求落成具体内容方向并选定形态」——换一个客户项目也会再次发生的固定环节，非一次性事务。
- **input schema**：`需求表`（数组，每行含人群、需求／痛点、用户语言表述、离痛点近度、搜索池／曝光池、市场需求量）；`定性意图集`（数组，本项目已记录在案的意图，方向要挂回它）；`团队能力`（内容产能与内容内功自评，对象）；`平台数据读数`（可选，对象；品类人群画像、热词、痛点趋势、对标榜单）。
- **output schema**：`内容方向表`（数组，每行含：内容方向、对应需求与人群、认知阶段、决策链路段、内容形态、为哪段意图作证、种草或割草、对标取法、可模板化度、形态门槛与风险、备注）；`种草割草配比`（对象）；`已砍方向及原因`（数组）；`对标拆解`（数组，每条含封面／标题／正文结构／评论四个模块的可复制点与其数据来源）。**可沉淀候选（reusable_candidates）**：`对标拆解`（同品类下一单直接调用）、验证过的方向→形态映射、可模板化度为高的那些方向的填空式要求模板。——**它们只是候选；够不够格真的留下、沉进哪一格、标什么成色，按 REQUIRED BACKGROUND: `tingle:banking-proven-assets` 判。**
- **写回位置**：`内容方向表落点`（见 requirements 的 outputs 段），地址由项目档案登记，不自行选址。
- **规则层与项目事实**：运行时挂 **合规类目层**（判某个方向、某种形态在本类目下允不允许，如涉及功效对比、前后对比的形态）、**品牌层**（品牌惯用切入角度与调性）与 **类型层**（不同内容形态各自的成文规范）。所需项目事实字段：`合规类目`、`产品品类`、`品牌`、`阶段`。
- **工具**：读飞书文档与多维表格（经开工单地址取得）、写飞书多维表格（登记的落点）。平台侧的人群画像、热词与榜单数据由人提供读数，本 skill 不直接调用平台接口。
- **决策档**：**复核**——方向与形态决定下游全部内容产能投向哪里，选错了整批内容作废，产出须有人过目才算数。
- **复核包**：内容方向表本体 ＋ 每个方向"为哪段意图作证"的挂回记录 ＋ 每个形态四关筛的逐关判定 ＋ 对标拆解的数据来源（榜单出处与采集时间）＋ 已砍方向及原因 ＋ 待确认项清单。
- **升级条件（命中即停交人）**：①某个方向或形态触及合规红线而判据不确定（尤其涉及功效表述、前后对比、专业身份背书）；②四层规则冲突；③缺关键项目事实（合规类目、产品品类、阶段任一取不到）；④输出需对外发送；⑤要上高曝光软广这一档（门槛是团队内容内功，须人判断）；⑥要砍掉某个方向；⑦拿不到任何对标榜单数据、方向只能凭经验定；⑧一个全新方向的切入点定稿。

## 产出验收判据（DoD）

一次运行合格，当且仅当：

1. 每个方向都写成一句**具体到能直接开工**的话，不是体裁名（"做个测评""做个科普"一律不合格）；
2. 每个方向都标了认知阶段与决策链路段，且形态与该阶段的匹配关系能说出理由；
3. 每个形态都留下了**四关筛的逐关判定**，任一关不过的形态不在表内；
4. 每个方向都**挂回了一段先于本次内容就已记录在案的定性意图**，并能逐字指认是哪一条；挂不回去的方向已砍并记录原因；
5. 种草与割草的配比写成了具体比例，并写明依据；
6. 对标拆解的每一条都标了数据来源与采集时间；**没有数据支撑的对标不在表内**；
7. 可模板化度为高的方向，随附一份填空式的要求模板；
8. 内容方向表里出现的每一个量化字段都挂得回一个定性意图——按 REQUIRED BACKGROUND: `tingle:keeping-metrics-anchored` 判，有孤儿指标或裸承诺即不合格。

## Quick Reference

| 情形 | 动作 |
|---|---|
| 需求表里一条需求要落形态 | 先给它的人群定认知阶段，再取对应形态 |
| 用户已在比较该买哪个 | 决策阶段——直推、横测、前后对比、专业身份推荐 |
| 用户还不知道有这类东西 | 认知空白——痛点切入、场景带入、教育科普 |
| 用户已经用过同类产品 | 命中他基于经验形成的新判断标准，不讲泛泛卖点 |
| 品类主动搜索量很低 | 不做横测 |
| 团队没有内容内功 | 不上高曝光软广，停下交人判断 |
| 内容点赞很高却没搜索 | 查内容是否围绕产品特性；产品是不是可有可无的道具 |
| 有爆文没转化 | 查人群是否错配（价位与人群不匹配是最常见的一种） |
| 方向答不出为哪段意图作证 | 砍掉，记录原因 |
| 拿不到对标榜单 | 停，交人——没有数据的对标可能是无效爆文 |
| 方向要交给外部合作方执行 | 做成填空式要求，不让对方自由发挥 |

## Common Mistakes

- **把体裁当方向**——"做个测评"不是方向，下游没法开工。
- **看别人做什么就跟做**——不判断这个形态抓的人群是不是自己的人群。
- **搜索量很低还硬做横测**——天花板本来就低，前置条件不满足就是零。
- **没内容内功强上高曝光**——它的门槛在能力不在预算。
- **无脑抄爆文**——同品类不同人群，抄来的是别人的用户。
- **没有数据就拆对标**——可能拆的是一条自己都没带来结果的爆文。
- **只种草不割草或只割草不种草**——前者流量被截，后者撞天花板。
- **让合作方自由发挥**——不可控，且磨合周期长。
- **只追爆文大小不看流转**——爆文没带来搜索和转化，就没达成结果。
- **方向挂不回意图还留在表里**——那是孤儿方向，它做出来也没人能验收。

## Red Flags（出现即停，回到对应工序）

- 「这个人群应该处在决策阶段吧」→ 回工序一，用坐标轴定位，别猜。
- 「先做种草，割草以后再说」→ 回工序二，定配比。
- 「这个形态大家都在做」→ 回工序三，过四关。
- 「高曝光那套我们试试」→ 回工序三，停下交人判内容内功。
- 「这条爆文点赞很高，拆它」→ 回工序四，先看它带没带来转化。
- 「这个方向挺好的，先做着」→ 回工序四，挂不回意图就砍。
