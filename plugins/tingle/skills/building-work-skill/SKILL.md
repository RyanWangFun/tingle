# building-work-skill

## 概述

一句话职责：**把一段真实做法造成一个能装进插件的通用工作 skill。**

- **闸守的是下笔之前的那段时间，不是下笔之后的检查。** 造完之后照哪些条目自检，见本 skill 参考件 `skill-standard.md`（构建标准的运行态全量投影）；下笔之前怎么想，是本页管的事。
- **本页不提供 SKILL.md 模板。** 有模板可填，四道闸就会被跳过——填出来的是空。

## 下笔之前（硬闸）

**禁止在闸一至闸四各有落成文字的答案之前，动 SKILL.md 的任何一行。**

这不是"建议先想一想"：**四道闸的答案，就是 SKILL.md 里那几节声明的内容本身**——没答就没有东西可写，先动笔只能填进去一个空壳，而空壳与真答案在文本上分不出来。

| 没答的闸 | 于是写不出来的那一节 |
|---|---|
| 一 · 这是不是一个环节 | `name`、`description`、一句话职责、适用环节——name 按"做什么"命名，那个"做什么"就是闸一要交的动词短语。**这一格与另外三格不同**：名字凭直觉编得出来，而编出来的与跑过三问才起的，在文本上分不开——所以闸一另设一条禁止（见下），要求三问的答案与名字一起落成文字 |
| 二 · 哪些是程序、哪些运行时装 | 正文留下的方法；「运行时装哪几层规则」的声明 |
| 三 · 每一样东西从哪来 | requirements 与工具／接口依赖两份清单 |
| 四 · 哪一步不许自动 | 决策档、复核包、必停交人的条件 |

**第五道闸不在下笔之前，在交出去之前**：拿什么证明它能用。

## 何时用 / 何时不用

**何时用**：为一个具体工作环节造一个可复用的 skill；把一份已成文的自用件改造成能跨项目用的 skill。

**何时不用**：

- **平台运转类的 skill 不走本页**——会话入口、项目就绪判定、以及"造 skill"这件事本身，管的是平台怎么转而不是某一个业务环节，数量稀少、各自单独设计。
- **但"不走本页"不等于"不受判"**：任何一个 skill（含本页自己）合不合格，一律由参考件里那 23 条判——本页决定谁走这条路径，参考件决定任何一个 skill 合不合格，两件事不同。
- **对一个已有 skill 的等价小改不走本页**——判定见参考件的琐碎豁免一节。
- **判一份已写好的 skill 合不合格、出判词，不在本页**——造与判是两件能力，本页只造；判由人拿参考件逐条判。

## 闸一 · 这是不是一个环节

**禁止**：

- **禁止用一个凭直觉起的名字代替闸一的答案。** `name` 写得出来不等于闸一跑过了——越是天天在干的活，名字越是一开口就有，而"随口起的"与"跑过三问才起的"在文本上分不开。三问的答案（换个客户项目还会不会再次发生、一个动词短语说不说得清、拆分三问怎么答）须与名字一起落成文字；有一问落不下来，那一问就是还没答，不许接着写下去。
- **禁止拿一个说不清的东西当环节。** 一句话职责若不是一个动词短语能说清的，里面就不止一件事——先拆，不许把它当成"一个复杂的环节"接着写下去。
- **输入件自带一套现成的切分时，禁止沿用它划好的边界。**「自带切分」指原件已经把活分好了段——一份已成文的 skill、一份分步骤的自用 SOP、一次按工序记下来的工作流走查纪要，都算；只有纯口述与不分工序的知识材料不算。边界一律无视原文件重划一次。**重划结果与原划法一致的，禁止不写理由**——"我重划了、结果相同"与"我根本没重划"在文本上分不开，理由是唯一能把两者分开的东西。这条不是形式主义：已观测到的失败里，一份审核类自用件把隔壁环节才该做的判断混进了本环节，而另一件与它各自带了一套同样的规则——原作者划的边界既跨了界又重了叠，照它的结构走，闸一会在无人察觉的情况下被整道架空。
- **禁止把一件"整个为这一个项目服务"的大活原样当成一个环节。** 大不是拆不动的理由：先拿拆分三问把它逐段跑一遍，跑不出第二个能独立命名的能力，才轮到问它是不是一次性事务。

**判法**（用来裁本页未列举的情况）：

1. **换一个客户项目，这件事还会再次发生吗？** 不会（只在这一个项目、这一次成立）→ 它是一次性事务，不是环节，不为它造 skill。
2. **一个动词短语说得清吗？** 说不清 → 里面不止一件事，接着往下拆。
3. **拆分三问**：两段能否**各自被独立命名**？是否**各有第二个消费者、或可被单独调用**？拆开之后，两段之间**还要不要来回传一份只在过程中存在的中间结果**？前两问答"是"且第三问答"不要" → 拆；第三问答"要" → 不拆，并写明那份中间结果是什么（那才是不拆的承重理由）。

**合理化对照表**

| 心里的那句话 | 实际是什么 | 闸怎么裁 |
|---|---|---|
| 「这活我天天干，什么活我还不清楚吗」 | 最熟的活最容易被当成一件——熟悉给的是操作细节，不是边界；名字张口就来，恰恰说明它没被裁过 | 照样跑三问，把答案和名字一起写下来 |
| 「原作者天天干这活，他划的边界肯定比我清楚」 | 未加工的做法不自带边界，成品自带；照抄结构＝闸一从未执行 | 无视原划法重划一次，一致也写理由 |
| 「这是一整套流程，客户就是这么要的，拆开没人会用」 | 交付场景不是环节边界。按产物与消费者划——一份能提前交出、被别人直接消费的产物，绑在流水线末尾就把它的交付时点锁死在最晚 | 按产物与消费者重划 |
| 「先合成一件大的，以后不好用再拆」 | 已观测：一件里打包四条各有下游的能力，只想用其中一条的人被迫吃下另外三条的规则 | 造之前拆，不留到以后 |
| 「这一小段太碎了，不值得单开一件」 | 判的不是体量，是有没有第二个消费者、能不能被单独调用 | 跑拆分三问，按答案定 |
| 「换个客户就不成立了，但这个客户特别重要」 | 换客户不再发生的是一次性事务，重要与否不改变它不是环节 | 不为它造 skill |

**Red Flags（出现即停，回闸一）**

- 「名字都想好了，闸一就不用跑了」
- 「照着它原来的目录结构改一改就行」
- 「一句话说不清，那我用三句说」
- 「先按他的划法走，回头再看要不要拆」
- 「重划完跟他划的一样，那就不用写理由了」
- 「划界理由我写了，做法材料就不用给复核的人了」（理由不回源就只能信，不能核）
- 「顺手把上下游也一起做了，反正都是我做」

## 闸二 · 哪些是程序、哪些运行时装

判的是**内容取值随不随项目变**。

**禁止**：

- **禁止把一条内容规则的取值写进正文。** 取值随项目变的，按层归位（品类／品牌／类型）、声明运行时加载，正文只留声明。已观测的原样是：什么话都往里面填，最后也能跑出来，但换个项目全废。
- **禁止把"两遍反问都成立"直接读成"进程序"。** 两遍都成立只排除了一件事——它不随项目变；没排除另一件——它可能是**别处维护的一条规则条款**，只是恰好这一层对谁都适用。一份谁都适用的创作原则、一份平台通行的禁用词清单、一套通用的审稿判据，换哪个客户都一字不改，可它们不是本 skill 的方法：它们有自己的维护者和自己的改版节奏，**归通用层，与品类／品牌／类型一样声明运行时加载，正文只留声明**——写进正文即撞参考件 A10（不内嵌知识层可变规则）。两个判别问句：**这一条在说"这件活怎么做"，还是在说"产出的内容本身必须是什么、不许是什么"？** 后者是条款不是方法。**要改它的时候，改的是这个 skill，还是改另一份别的 skill 也在读的清单？** 改的是那份清单 → 它不属于这里；抄进正文就有了第二份，那份改了这份不会跟着改。
- **禁止只拿一个客户反问。** 反问必须取两个客户项目：一个**要遵的硬规矩与本次同一套**、一个**红线完全另一套**——**不是换个产品、换个人群，是换一套要遵的硬规矩**（同一套规矩下的两个项目，产品可以毫不相干，那套不许碰的条文却一字不差）。只拿规矩同一套的客户问，一整批只在这套规矩内共用的规则会表现为"换客户一字不变"，被误判成通用方法进程序——同一套规矩内不变是对的，同层复用正是分层的目的，它不是"通用"的证据。
- **禁止以"手上只有一个客户"为由跳过第二遍。** 第二个客户是反问用的参照物，不是一个要你去服务的项目——同事手上的、公司做过的、你只知道它红线另成一套的任何一个，都算数。**一个都举不出来的，这几句一律判"未验"：不许按"两遍都成立"处理、不许写进正文**，连同这个理由交人（升级条件⑦）。未验与验过在文本上分不开，而按验过处理的代价是把一整批同层规则当成通用方法写死在程序里。
- **禁止拿"归通用层"当拿不准时的安全去处。** 判不准就往通用层扔，与一律标复核是同一种错——**方法一旦被判成条款，正文就空了**，交出去的是一个只会声明加载、不会干活的壳；而随项目变的取值被塞进通用层，换个客户照样全废，只是错法从"写死在正文"换成"装错了层"。通用层收的是"内容必须是什么、不许是什么"的条款，不收"这件活怎么做"的判法与步骤，也不收换个客户就要改的取值——一条一条过那两个判别问句，不许整批归。
- **禁止一条规则只许进一个桶。** 一条规则常常要拆句归两处。
- **禁止把"我无权做什么、无权宣称什么"的条款当内容规则来分层**——那是权限，是闸四的料；分层之前先把它摘出去，否则闸四开工时会发现料已经被用掉了。
- **禁止把不是规则的东西硬塞进三桶**（数据、二进制资产、脚本、样例、凭据）。它们闸二不判，直接点名转闸三；**"闸二无桶"不等于"可以不提"**。
- **留在客户层的那一类，禁止只写一句"留在客户层"。** 须再分两种：**(a) 客户方维护的既定约定**——写清由客户方维护、不进插件；**(b) 凭据、身份、某台机器上的绝对路径**——不留在任何文件，转闸三声明为运行前取得的输入。只有一个桶会把 (b) 合法化，而它的成品就是"请装的人自己打开文件把路径改成他自己机器上的"。

**判法**：

- **每一句问两遍"换客户还成立吗"**——规矩同一套的那个客户问一遍、红线完全另一套的那个再问一遍。两遍都成立 → **还要再过一道**：它说的是"这件活怎么做"（方法）→ 进程序；它说的是"产出的内容必须是什么、不许是什么"（条款）→ 归通用层，声明运行时加载。换一套规矩那遍不成立 → 按品类／品牌／类型归位，声明运行时加载；两遍都不成立 → 留在客户层，再按 (a)(b) 分。**去处四个、桶仍是三个**——通用层与品类／品牌／类型同属"运行时按层加载"那一桶。两遍都成立只排除了品类／品牌／类型与客户层这两个去处，剩下的还有两个，**不等于它进正文**。
- **一条规则要拆时**：先剥"这条在说一个什么样的要求"（形状，多半进程序或归高层），再剥"要求的具体值是什么"（取值，归低层）。

**合理化对照表**

| 心里的那句话 | 实际是什么 | 闸怎么裁 |
|---|---|---|
| 「什么话都往里面填，最后也能跑出来」 | 跑得动与泛化得了是两件事；已观测：这样填出来的 skill 出不了这一个项目 | 逐句问两遍，分三桶 |
| 「换了另一个客户也一字不改，那就是通用方法」 | 那个客户若与本次遵同一套硬规矩，不变是分层本该有的样子，不是通用的证据；换了产品、换了人群都不算换 | 再拿一个红线完全另一套的客户问第二遍 |
| 「这条原则放之四海而皆准，两遍都成立，那就写进正文」 | 通用不等于是本 skill 的方法——它是别处维护的一条条款，只是这一层恰好谁都适用；抄进正文就有了第二份，那份改了这份不会跟着改 | 归通用层，声明运行时加载，正文只留声明 |
| 「判不准是方法还是条款，那就都归通用层，最安全」 | 与一律标复核同一种错：方法被判成条款，正文就空了，交出去的是个只会声明加载的壳 | 一条一条过那两个判别问句，不许整批归 |
| 「我手上就一个客户，第二遍没法问，先按通用算」 | 没问过与问过都成立在文本上分不开；按问过处理，一整批同层规则会被写死进程序 | 举不出第二个客户的判"未验"，不进正文，交人 |
| 「这条既像通用方法又像客户规范，只能挑一个桶」 | 一条规则可以拆句归多处 | 拆形状与取值，各归各位 |
| 「这一步不许自动，也是一条规则，一并放进分层」 | 那是权限不是内容 | 先摘进闸四的篮子，再对剩下的分层 |
| 「名册、模板、脚本不是规则，三桶里没它的位置，先不管」 | 闸二无桶不等于可以不提 | 点名转闸三 |
| 「这条是客户那边定的，写一句"留在客户层"就完了」 | 留在客户层的有两种命运：客户方维护的既定约定不进插件，凭据与某台机器上的绝对路径连文件都不该落——混成一句，第二种就被默认成"写进某个文件里" | 再分 (a)(b)，(b) 转闸三 |

**Red Flags（出现即停，回闸二）**

- 「这一条挺通用的，直接进程序」（没问第二遍）
- 「这条原则从来不变，写死在正文里最省事」（不变的是它现在的取值，不是它的归属）
- 「拿不准的都归通用层，反正运行时会装上」（通用层不是待定区）
- 「先写死，跑通了再抽出来」
- 「这几行是客户给的原文，原样留着最保险」
- 「这个不是规则，跳过」
- 「案例攒在这儿当规则用挺好」（历次纠错的留痕是项目记忆，不是规范，装进规则层会污染规则层）

## 闸三 · 运行时要用到的每一样东西从哪来

**禁止**：

- **禁止在点名清单落进 SKILL.md 本体之前收工。** 清单只留在设计稿里、不挂进 SKILL.md 的，等于没声明——装进插件跑的是 SKILL.md，设计稿不随包。已观测：声明写在契约文档里、未挂进本体。
- **禁止只声明想得起来的那几样。** 逐样点名，**下面四类一类不落，每类下有几样写几样**：
  - **要读的项目材料**（**共享上下文的投影面**——这个项目的散装材料被蒸成的那套全体 skill 共读的认知件，本 skill 只取其中相关的一面；产它的是 REQUIRED BACKGROUND: `tingle:context-distill`。此外还有要引的表与标签、别的环节产的既有产物）
  - **要写的落点**
  - **要用的工具与授权**
  - **要调用的同族 skill**

  已观测：某 skill 要三样输入只声明了一样，其余孤儿化，到首个真实项目跑时取不到。
- **禁止把上一件的清单改几个名字接着用。** 上一件的四类里各有几样，是上一件的答案；照抄来的清单与逐样点名出来的清单在文本上分不开，而漏掉的那一样只有到别人机器上第一次跑时才现形。**一样一样地问"这一件要读什么、要写到哪、要用什么与要谁授权、要调谁"**，不许拿上一件的清单当起点——越是一件接一件地交，这条越吃劲。
- **禁止把随项目变的东西随包发布。** 已观测两例：把随项目变的名册当 skill 自带参考件；把资料库位置写成某台机器上的绝对路径，于是分发时只能靠每个人各改一份，每装一次分叉一次。
- **禁止另写一套 requirements 声明格式。** REQUIRED BACKGROUND: `tingle:project-readiness`——其参考件 `readiness-contract.md` 的「requirements 声明格式」一节是唯一真相源，照它写；本页不复述，两处各写一套必然漂移。
- **禁止把落点留到产出的时候再找地方放。** 落点与输入一样是运行前提。

**判法**：**每一样先问"它什么时候变"**，三条出路各有各的归处（2026-08-17 定，此前只有前两条，装不下第三类——后果是同一个月造出的两个 skill 对同一类东西给了两种互不相容的答案，两个都通过了独立评审，因为没有一条规矩说该往哪走）：

| 它什么时候变 | 走哪条 | 程序管不管 |
|---|---|---|
| **随项目变**（换个项目换一份） | 进 `requirements.inputs`，地址登记在项目档案 | 管：查登记齐不齐、地址打不打得开 |
| **跨项目同一份**（谁用都是它） | 算工具与接口依赖，装机时验通 | 不管（归 `tingle doctor` 那份写死的装备清单；真缺了提给维护者加进去） |
| **每次跑都不一样**（同一个项目里每次都是另一份，如这次要处理的那份稿子／材料） | 进 `requirements.inputs` 并标 `"每次输入不一样": true`，**不写 `type`**、不登记进档案 | 不管地址；只在开工单上记一行提醒 |

**三条出路都算有着落，悬空才是错**。**别在这一格上现场发明**——判不出它属哪一类，停下问人。

**合理化对照表**

| 心里的那句话 | 实际是什么 | 闸怎么裁 |
|---|---|---|
| 「这几样运行时自然就有」 | 没被声明的东西在别人机器上不存在 | 逐样点名 |
| 「清单我写在设计稿里了」 | 跑的是 SKILL.md | 落进 SKILL.md 本体 |
| 「这份表跨项目都一样，不用声明」 | 跨项目同一份不等于不用声明——它是工具与接口依赖，初始化时要验通 | 归工具依赖，照样点名 |
| 「路径先写死，用的人自己改」 | 改源码不是配置 | 声明为运行前取得的输入 |
| 「凭据放参考件里最方便」 | 凭据不属于任何文件 | 运行前取得，不落盘 |
| 「声明格式我照着印象写一份」 | 两处各写一套必然漂移 | 照唯一真相源写 |
| 「上一件的清单拿过来改改就行，两件差不多」 | 抄来的清单与点名出来的清单在文本上分不开；差的那一样到别人机器上才现形 | 四类重新逐样点一遍，不拿上一件当起点 |

**Red Flags（出现即停，回闸三）**

- 「装的人自己配一下就好」
- 「先跑通我这台机器」
- 「这个应该不算输入吧」
- 「落点等有产出了再说」
- 「上一件的清单复制一份改改」（抄来的与点名出来的分不开）

## 闸四 · 哪一步不许自动

判的是**权限**，与闸二判内容分工不重叠；同一句话可能两处都要进，归档位置不同。

**禁止**：

- **禁止在没有逐步回答"这一步做错了，谁会在什么时候发现"之前收工——无论你打算把它标成自动还是复核。** 发现不了的，必停；而**一律标复核不是答案，是把这道闸整个跳过**——闸四要交的是"哪几步必停"这份名单，不是一个统一档位。
- **禁止只写结论。** 每一条必停背后的那个答案（谁、在什么时候发现）须随件交出——SKILL.md 里只写结论（哪一步必停），而复核要看的恰是这个推理。
- **禁止用裸形容词充当验收判据。** 已观测：验收判据写成"写得好、够吸引人"，判不动任何一次产出。
- **禁止在正文里写谁复核、怎么路由、留什么日志、谁终裁。** 那是运行环境的事，写进正文即越层。正文只声明该声明的三样：决策档、复核包、必停条件。

**判法**：**这一步做错了，谁会在什么时候发现？** 下游有人必然看到、且看得出来 → 可自动；错了没人会发现，或发现时已经对外 → 必停。

**合理化对照表**

| 心里的那句话 | 实际是什么 | 闸怎么裁 |
|---|---|---|
| 「拿不准的一律标复核，总不会错」 | 方向上确实不会错，但闸四要交的是"哪几步必停"这份名单——一个统一档位等于一步都没判，下一个人照样不知道哪一步真的不能放手 | 逐步跑那个问句，答案落成名单 |
| 「这一步 AI 做得挺准的」 | 判的不是准不准，是错了有没有人发现 | 跑那个问句 |
| 「复核太慢，先自动跑，出问题再说」 | 出问题的时候它已经在下游了 | 发现不了的必停 |
| 「必停条件写了，理由记在脑子里」 | 复核要看的正是理由 | 随件交出 |
| 「把复核人和路由写清楚，别人才知道找谁」 | 那是运行环境的事，写进正文即越层 | 正文只声明决策档、复核包、必停条件 |
| 「验收判据写'质量过关'就够了」 | 裸形容词判不动一次具体产出 | 写成可判句 |

**Red Flags（出现即停，回闸四）**

- 「全标复核，最稳妥」（一步都没判，只是把档位统一调到最紧）
- 「这步大概没人会看，那就自动吧」（正好反了——没人会看才是必停的理由）
- 「先标自动，跑一阵再收紧」
- 「必停条件照抄上一件」
- 「这一步我盯着呢」（盯着的是这一次，不是这个 skill）

## 闸五 · 拿什么证明它能用

这道闸在交出去之前，不在下笔之前。

**禁止**：

- **禁止在没有一份故意造坏的样例、且写明它被哪条判 FAIL 之前，把这个 skill 交出去。**
- **禁止拿一次顺利的实跑代替判废样例。** 跑顺了证明的是这一次没走岔，不是它拦得住什么。
- **坏样例没被任何条目抓住的，禁止读成"这件 skill 没毛病"**——那说明那几条在这件 skill 上没有牙，回去补条目，不是放行。
- **守"人明知规则却在压力下会违反"这一类的 skill，禁止走轻量测法**——须按完整测法做，测法与分级判据见参考件 B11，本页不复述。

**判法**：**这件 skill 要拦的失败，是"不知道该怎么做"，还是"知道该怎么做但在压力下不做"？** 后者 → 按纪律类测，走完整测法。

**合理化对照表**

| 心里的那句话 | 实际是什么 | 闸怎么裁 |
|---|---|---|
| 「跑通了一次，能用」 | 顺路不是判别力 | 造一份坏的撞一次 |
| 「我知道哪里会错，不用真造一份」 | 没被条目抓过的 skill 未验 | 留下记录，写明被哪条判 FAIL |
| 「坏样例造了，一条都没抓住，说明它没毛病」 | 说明条目在这件上没牙 | 回去补，不是放行 |
| 「时间紧，压力测试下一轮补」 | 下一轮就是它第一次真跑的时候 | 交出去之前做完 |

**Red Flags（出现即停，回闸五）**

- 「这次先发，样例回头补」
- 「拿真实项目当第一个测试」
- 「上一件的测试记录复制一份改改」

## 随件交出的三样

五道闸的答案各有各的落点，只有三样在那些落点里无处安放；**它们缺一件，复核的人就只能把五道闸重跑一遍**。

1. **闸一的划界理由**——**一律要写，不分输入是什么**：写下你为什么把边界划在这里，即那句一句话职责，以及为何这不是两件事。不写，"跑过闸一"与"凭直觉起了个名字"在文本上分不开。输入件自带切分时（见闸一），另须写明为何与原划法一致或不一致——"重划了、结果相同"与"根本没重划"同样只有理由能分开。
2. **闸二判为"留在客户层"的那一类**——SKILL.md 里没有它的位置（进程序的和运行时装的都有位置），不写下来就等于凭空消失。
3. **闸四每一条必停背后的那个答案**——SKILL.md 只写结论，而复核要看的是推理。

**形式不设模板、不设文件名**，只有一条硬要求：**与 skill 一起送达，且复核的人读得到**。写在提交说明里、附件里、消息里都算。

## 入驻收尾（写完之后到发布之前）

1. **SKILL.md 按官方规范写成**——文件体例与 description 的写法见参考件 B 层条目，本页不复述。
2. **requirements 声明写进 SKILL.md 本体**，不是写在设计稿里（格式见闸三所指的唯一真相源）。
3. **声明要读的是共享蒸馏产物的哪一面**——那套认知件（`tingle:context-distill` 蒸出的）是全体 skill 共读的一份，本 skill 只声明读它的哪一面；不为本 skill 另蒸一份，不私藏材料副本。
4. **声明产物往哪类落点写**——初始化按此声明建落点。
5. **入仓**——skill 目录进插件仓的 skills 下，提交即发布。**自建件在入仓之前，须由人拿参考件逐条判过。**
   - 同时：**随目录一起走的、为这一个 skill 单独声明展示名／默认提示词／是否允许被隐式触发的清单件，不进插件**——判法与理由见参考件 A11 下的「同级文件的处置（指引，不参与 PASS／FAIL）」②。

## 接口与边界（声明）

- **适用环节**：「为一个工作环节造一个可复用的 skill」——换一个客户项目也会再次发生的固定环节，非一次性事务。
- **input schema**：`做法来源`（枚举：口述做法／工作流走查纪要／已成文的自用件）；`做法材料`（该做法的全部可读材料：文字记录、文件或目录）；`两个反问客户`（两个客户项目——一个要遵的硬规矩与本次同一套、一个红线完全另一套，供闸二反问用；换的是要遵的规矩，不是产品或人群）。
- **output schema**：`环节定义`（一句话职责＋适用环节＋划界理由；输入件自带切分时，划界理由内含与原划法一致或不一致的缘由）；`分层结果`（三桶：进程序／运行时按层加载（通用／品类／品牌／类型）／留在客户层，第三桶再分约定与凭据两种）；`来源清单`（每一样 → requirements 输入 或 工具与接口依赖）；`不许自动清单`（决策档＋复核包＋必停条件，每条附"谁会在什么时候发现"）；`SKILL.md 草稿`（可被逐条判的文件本体）；`判废样例记录`（写明被哪条判 FAIL）。**可沉淀候选（reusable_candidates）**：`分层结果` 里判进程序的那部分（通用方法，同族别的 skill 还用得上）与 `来源清单` 里判为工具与接口依赖的项（跨项目同一份）。
- **写回位置**：新 skill 自己的目录（插件仓 skills 下以其 name 命名的一个目录）——SKILL.md 落目录根，参考件落其 `references/`；随件三样交给复核的人，不落固定文件。
- **规则层与项目事实**：通用／品类／品牌／类型四层中一层不挂（本 skill 不产内容、不碰红线）；所需项目事实字段：无。
- **工具**：文件系统读写（读做法材料、建新 skill 目录与文件）。无外部接口调用。
- **决策档**：复核——产出是一份 SKILL.md 草稿，须由人拿参考件逐条判过才算数。
- **复核包**：随产出附上「随件交出的三样」＋ SKILL.md 草稿 ＋ 判废样例记录 ＋ **做法材料本身**（划界理由属不属实，只有回它才查得出——一份产物自洽不等于边界划对了；复核的人据它核这一处，不必重跑五道闸）。
- **升级条件（命中即停交人）**：①做法材料里涉及合规红线而其判据不确定；②同一条规则在四层规则里冲突（两层各有一套说法）；③缺关键项目事实——某一样东西连"从哪来"都问不出来；④产出需对外发送（入仓、或交给团队之外的人）；⑤闸一的划界理由写不出来（含：输入件自带切分、重划后与原划法一致却说不出为何一致）；⑥闸四某一步"做错了谁会发现"答不上来；⑦举不出第二个反问客户（红线另成一套的那一个），闸二只问得了一遍。

## 产出验收判据（DoD）

一次运行合格，当且仅当：

1. 闸一至闸四各有落成文字的答案，且每个答案都落进了它该去的那一节（对照「下笔之前」那张表逐行核）；**闸一那一格不认"有个 `name` 和一句职责"**——三问各自的答案与划界理由须都在，缺哪一问即判闸一未跑；
2. 闸三的点名清单上**每一样**在 requirements 或工具与接口依赖两处之一有着落、归类理由可复述，无一样悬空；
3. SKILL.md 草稿可被另一个人拿参考件逐条判，判的过程中不需要回头问作者补充信息；
4. 「随件交出的三样」随件送达，复核的人读得到；做法材料本身一并在复核包内，划界理由回得了源；
5. 留有一份判废样例记录，写明被哪条判 FAIL。

## Quick Reference

| 闸 | 一句判法 | 答不出就写不出的那一节 |
|---|---|---|
| 一 · 是不是一个环节 | 换个客户项目还会再次发生吗？一个动词短语说得清吗？拆分三问 | 一句话职责、适用环节 |
| 二 · 程序还是运行时装 | 逐句问两遍"换客户还成立吗"——规矩同一套的客户一遍、红线完全另一套的客户一遍；两遍都成立的再判一次它是方法还是条款 | 正文留下的方法；运行时装哪几层的声明 |
| 三 · 每样东西从哪来 | 每一样问"随项目变吗"——变的进 requirements，不变的算工具依赖 | requirements 与工具／接口依赖两份清单 |
| 四 · 哪一步不许自动 | 这一步做错了，谁会在什么时候发现？发现不了的必停 | 决策档、复核包、必停条件 |
| 五 · 拿什么证明能用 | 造一份坏的撞一次，写明被哪条判 FAIL（交付前，不是下笔前） | 判废样例记录 |

## Common Mistakes

- **照着一份自带切分的原件顺手改**（一份已成文的 skill、一份分步骤的 SOP、一次按工序记的走查纪要）——最常见的一种：整道闸一被跳过而无人察觉，原作者的边界连同它的错一起被继承。
- **四道闸在对话里答过就算数**——三样随件的东西没落成文字，复核的人只能把五道闸重跑一遍。
- **把本页当填空表用**——本页管的是判之前怎么想；判完之后照哪些条目自检，在参考件里。
- **先写文件再补声明**——补出来的清单只覆盖当时想得起来的那几样，其余悄悄孤儿化。
- **一次造两件**——造与判是两件能力，判 PASS/FAIL 与出判词不在本页。
- **平台运转类的 skill 也照本页走**——本页覆盖的是业务环节的 skill；平台类另行设计，但它同样受 23 条判。
