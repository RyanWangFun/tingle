# teaching-from-company-knowledge

## 概述与核心原则

一句话职责：**就一个问题或一个主题，回公司自己的知识库取原文，讲到提问的人能用**——先弄清他要拿它干什么，再去库里定位到具体页面取原话，按他的水位讲，每条结论标出处，最后指出下一步该读哪一篇。

**答一句和带人学一个主题，是同一件事的两个深度，不是两件事。** 两者的承重步骤完全同一套：定位 → 取原文 → 按水位组织 → 标出处 → 指路。教学只是把同一条骨架跑得更深、末尾多一道回检；而带人学的过程里会不断冒出"这个词到底指什么"的小问题，每冒一个都要走一遍同样的定位取原文——这份**已定位到具体页面、带出处的原文摘录**只在过程中存在、对外没有独立价值，拆成两件就得在两件之间来回传它。

**分类：平台技能。** 它**不挂在任何客户项目上**——不读项目事实、不写项目落点、不加载任何一层内容规则，因此也不跑运行前的项目就绪检查（与会话入口、项目就绪、造技能三件同属这一类）。公司里任何人、任何时候都能用它，包括手上还没有任何项目时。

**适用场景**：一个人要弄懂一个概念、一套打法、一个框架怎么用，或要把一个主题从不会学到会——公司里反复发生，与在做哪个客户项目无关。

**三条核心原则（越一条即错）**：

- **没打开过任何一页之前，不许开口回答。** 营销方法论这类题目，模型"本来就懂"——正因为懂，它会直接从通用常识里答出一段听起来完全正确的话，而那段话不是公司买来并提炼过的这一套。**公司知识库与公开常识的差别，恰恰是这家公司的差异化所在**；跳过取原文，这个环节就等于没发生。
- **每一条实质结论都要能指回"哪个库·哪一篇·哪一节"。** 库里没有的，明说库里没有；确实要用通用常识补位的，**逐句标明这句不是公司知识库里的**，不许混在有出处的句子中间。
- **两个库对同一件事说法不同时，分别讲、各标出处，不替它们调和。** 同一个词在不同的一套方法论里常常不是一回事，揉成一个折中版讲出去，提问者拿到的是一个世上不存在的说法。

## 何时用 / 何时不用

**何时用**：要弄懂一个概念、一套打法、一个框架怎么用；要把一个主题从不会学到会；接手不熟的品类前补方法论；新人补公司内部工具与做法的底子。

**何时不用**：

- **替某一个具体客户项目做判断**（这条稿子该怎么改、这个品牌该走什么策略）——那归该环节自己的 skill。本环节只讲方法论本身，讲完把人指过去。
- **维护知识库**（新增、修改、整理页面）——本环节只读，一个字都不往库里写。
- **公司知识库里根本没有的题目**——如实说没有。要不要用通用常识补位由提问者定，补了就逐句标明。

## 工序

### Step 0 · 输入与开工前自检

**输入就是下面这三个知识源——本 skill 的全部范围，表上有几个就是几个，不多不少。** 不在表上的库，即便知道它存在、即便它就在旁边，本次也不查。

| 知识源 | 打这个链接进 | 里面是什么、适合问什么 | 入口形态 |
|---|---|---|---|
| 内容科学要素课 | https://vcn9ngc4ok4o.feishu.cn/wiki/Uad5wfhwmi5Q53kEKHhcx1iEnof | 把"做内容"解构成要素的一整套方法：2 个思维、3 个模型、14 个要素、20 个工具。适合问：一条内容由什么构成、某个要素怎么专项攻、跑赢的内容怎么拆成还能再用的东西、只会抄不会创怎么办 | 有入口页（知识地图 → 六本手册 → 8 篇逐篇精读原文） |
| 小红书品牌营销全链路 | https://vcn9ngc4ok4o.feishu.cn/wiki/M3gcwM32GiCMwqkDc5tcrsPPnOh | 小红书"产品 → 人 → 需求 → 内容 → 数据"的全链路打法，87 篇课程提炼成 7 大模块、13 个核心框架。适合问：投放策略与节奏、大促怎么排期、某个类目怎么打、某个框架怎么用、爆文没转化怎么办 | 有入口页（知识地图 7 模块 → 核心框架手册 → 87 篇课程文章） |
| AI 内部学习文档 | https://vcn9ngc4ok4o.feishu.cn/wiki/ALBYwEdSziZxQGkqpQYcrHsmnAe | 公司内部 AI 工具的入门教程：选什么 AI 工具、Agent 怎么装、Skill 是什么怎么装怎么做、飞书命令行怎么用、Context 是什么为什么要紧，另有现成的飞书模版与通用 prompt | 无入口页（根页写了一条推荐学习路径，从它读起） |

**加一个知识源＝往上表加一行**，四样填齐：名称（人一眼认得出，别用内部代号）／链接（**优先填入口页**——知识地图、目录、学习路径那一篇；没有入口页就填根页）／一句"里面是什么、适合问什么"（这一句是给定位用的，它决定一个问题该不该往这个库里找，写空了这一行等于白加）／入口形态。**改完要跟着发一次版**，同事机器上才拿得到。

**开工前逐行确认链接打得开。两种情形停，本次不运行**：

- **表里一行都没有** → 报要先加行。
- **某一行的链接打不开** → 报是哪一行，并指出两个可能：飞书授权失效（重跑 `lark-cli auth login`），或本人对该知识源没有访问权（找管资源的人开）。**不静默跳过那一行**——跳过的表现是「答案缺一块」，没人看得出来。

> **本件不跑项目就绪检查**：判据不是「它属于哪一类技能」，而是**它读不读项目事实、写不写项目落点、有没有地址要解析**——三样都没有，就没有什么可查的。三个知识源就在上表里。跑那道检查只会平白要求先有一个已就绪的客户项目，把还没建过项目的人挡在门外——而那正是最需要本环节的人。

### Step 1 · 先弄清要什么（问一句再动手）

两件事定下来才开口：

1. **要解决的是什么**：一个具体问题（要一个能用的答案），还是一个主题（要学到会用）。
2. **要拿它干什么**：马上要写进一份方案？要跟客户讲？还是先打底子？

**这一步不许跳过。** 讲深了浪费他的时间，讲浅了不够他用——而这两种错，提问者都不会开口告诉你。说不清就问，不许猜着讲。

### Step 2 · 定位（逐库进，从入口页往下钻）

对每个候选库：

1. **先读它自己的入口页**——第一层节点里那篇知识地图 / 目录 / 索引 / 学习路径。它是这个库的作者留下的导航，比任何猜测都准。
2. **入口页给出什么层级就照它走**（例如"地图 → 手册 → 原文"这样的分层，就一层层钻到最底下那篇原文）。
3. **没有入口页的库**，从它的顶层节点树读起，按标题判哪一支相关，再进去。
4. 入口页与节点树都看不出来的，用关键词在该知识源内搜。

**取到原文才算定位完成**——只看到标题不算，标题会骗人。

### Step 3 · 判归属（跨库时先分清）

- 只有一个库覆盖这个问题 → 说清是哪个库的说法。
- 两个及以上库都覆盖 → **分别讲，各标各的出处**，并说清它们分工上的差别（一套讲的是什么、另一套讲的是什么）。**不许合成一个折中说法。**
- 同一个词在两个库里指的不是一回事 → 明确点出这一点，这本身往往就是提问者最需要知道的。

### Step 4 · 按水位讲（四层，教学模式跑全，问答模式按需截断）

1. **一句内核** —— 这套东西到底在解决什么，一句话说完。
2. **结构** —— 它由哪几块组成、彼此什么关系。
3. **动作** —— 落到手上具体怎么做，给到能照着干的颗粒度。
4. **指路** —— 想再深一层，去读哪一篇（给出具体页面标题）。

问答模式常常只需要第 1 层加第 3 层，答到够用为止；**但第 4 层的指路一律要给**——提问者今天要的是一个答案，明天要的是自己能找回去。

### Step 5 · 标出处（每一条实质结论）

格式：**（库名 · 页面标题 · 章节）**。

- 库里没有这一条 → 明说「这几个库里没有」。
- 用通用常识补位 → **逐句标明这句不是公司知识库里的**。
- 两个库说法不一致 → 分别标，不调和。

### Step 6 · 回检（教学模式必做）

讲完让对方做一件事：**用自己的话把内核复述一遍**，或**把它套到他手上正在做的一件具体事上**。

- 说得出来 / 套得上 → 这一段过了。
- 卡住 → 回 Step 4 的**上一层**重讲。**不许把原话再说一遍**——他不是没听清，是上一层没接住。

### Step 7 · 收口

交出五样（即下方复核包）：讲解正文、本次查过哪几个库、每条结论的出处、没有出处的那几句、库里查不到的那几条。

## 接口与边界（声明）

- **适用场景**：「就一个问题或一个主题，回公司知识库取原文并讲到提问的人能用」——与客户项目无关、公司内反复发生，非一次性事务。
- **input schema**：`要解决的是什么`（枚举：一个具体问题／一个主题）；`问题或主题原文`（字符串，提问者的原话）；`要拿它干什么`（字符串，用途与场合，决定讲到哪一层）；`可用知识源`（列表，即 Step 0 那张表，每项含名称、链接、一句「里面是什么、适合问什么」、入口形态）。
- **output schema**：`讲解正文`（按四层水位组织的文本）；`出处清单`（列表，每项＝结论 + 库名 · 页面标题 · 章节）；`本次查过的知识源`（列表，清单上的名称）；`无出处标注`（列表，哪几句不是库里的）；`库里查不到的条目`（列表）；`下一步该读什么`（列表，具体页面标题）。**可沉淀候选（reusable_candidates）**：`库里查不到的条目`——反复查不到的题目，正是知识库该补的缺口。
- **写回位置**：**无飞书落点**，产出交给提问者本人（这次对话）。本环节只读，不往任何知识库写。
  > `库里查不到的条目` 当下没有承载物——组织级的"知识库缺口登记"尚未建出，所以它随产出交给提问者本人，由他决定要不要提给知识库维护者。**这是已知缺口，不是疏漏**；缺口登记建出来之后，改的是这一条往哪里落，本页其余读法一个字不变。
- **规则层与项目事实**：通用／品类／品牌／类型四层**一层都不挂**——本环节不产对外内容、不碰内容红线，只讲方法论本身。**所需项目事实字段：无**（本环节不读项目档案、不读任何项目认知件）。
- **工具**：`lark-cli`（`docs +fetch` 读页面、`wiki +node-list` 列知识源的节点树、`drive +search` 在指定知识源内按关键词搜）＋ 本人飞书授权有效。无其它外部接口。**不调用任何同族 skill。**
- **决策档**：**复核**——产出是给人拿去用的讲解，讲错了他学到手上还会拿去跟客户讲，须有人对着出处核过才算数；不标自动。
- **复核包**：随产出附上——讲解正文、本次查过哪几个库、每条结论的出处（库·篇·节）、没有出处的那几句、库里查不到的那几条。
- **升级条件（命中即停交人）**：①合规红线不确定；②规则冲突——本环节不挂任何一层规则，其实际形态是：两个库对同一件事的说法互相冲突，且分不出该照哪一套；③缺关键项目事实——问题必须知道某个具体项目的事实才答得了；④产出需对外发送（转给客户、发到群里、写进对外材料）；⑤知识源表为空，或其中某一行的链接打不开；⑥问题落在某个客户项目的判断上（转对应环节的 skill，本环节不接）。

## 产出验收判据（DoD）

一次运行合格，当且仅当：

1. Step 0 实际跑过，产出里列得出**本次查过哪几个库**；
2. 讲解正文里**每一条实质结论**要么带出处（库·篇·节），要么被明确标为"不是公司知识库里的"——两者之外没有第三种句子；
3. 库里查不到的题目，产出里有一句明说"这几个库里没有"，而不是被一段通用常识悄悄填上；
4. 两个及以上库都覆盖该问题时，产出里两套说法**分列**且各有出处，正文中不存在把它们合成一句的表述；
5. 无论问答还是教学，产出里都有"下一步该读什么"，且指到**具体页面标题**，不是"去某某库里找找"；
6. 教学模式另加一条：**回检发生过**——提问者复述或套用过，且卡住时回到了上一层重讲，而不是把原话重说。

| 表里某个链接打不开 | 停，报是哪一行，指向授权失效或没有访问权；**不静默跳过** |

| 库有入口页（知识地图／目录／学习路径） | 从入口页往下钻，照它给的层级走 |
| 库没有入口页 | 从顶层节点树读起，按标题判哪一支相关 |
| 两个库说法不一样 | 分别讲、各标出处，不调和 |
| 库里查不到 | 明说没有；补通用常识须逐句标明 |
| 只要一个快答案 | 讲第 1 层加第 3 层，但指路照给 |
| 要学会一个主题 | 四层跑全，末尾必做回检 |
| 回检时对方卡住 | 回上一层重讲，不重复原话 |
| 问题其实是某个客户项目的判断 | 说明超出本环节，指向对应环节的 skill |

## Common Mistakes

- **凭已有的理解直接答**——最常见的一种。答出来的东西听着完全正确，却不是公司这一套；提问者正在学，他分辨不出来，还会拿着它去跟客户讲。
- **只看标题就当定位完成**——标题相似的页面在同一个库里可能讲的是两件事。取到原文才算。
- **把出处标到库一级**（"这是公司知识库里说的"）——标到库一级等于没标，提问者回不去那一页。要标到篇与节。
- **把两个库揉成一套讲**——听起来更整齐，代价是造出一个不存在的融合版。
- **只答不指路**——他今天得到一个答案，明天还得再来问一遍。
- **教学模式跳过回检**——讲完就散，"听懂了"和"会用了"之间那道坎从没被验过。
- **顺手替他把项目里的活也判了**——问题从"这个框架怎么用"滑到"那我这条稿子该怎么改"，滑过去就越界了。

## Red Flags（出现即停，回到工序）

- 「这个概念我很熟，不用查库了」→ 熟正是本环节要拦的那个失败，去库里取原文。
- 「先给他个大概，细节他自己去翻」→ 指路要指到具体页面，不是把翻找推回给他。
- 「库里没查到，但这个业内通行做法是……」→ 先说"库里没有"，再标明这句不是库里的。
- 「两个库讲的差不多，合起来说更清楚」→ 分别讲，差异往往才是他要的。
- 「他没说要拿这个干什么，我按最全的讲」→ 讲深浅是这一步定的，回 Step 1 问。
- 「顺便把他项目里那个问题也答了」→ 那是另一个环节，指过去。
- 「我知道还有个库也讲这个，一起查了吧」→ **表上有几个就是几个**；要它进来，去 Step 0 那张表加一行，不在本次现加。
- 「这一行链接打不开，先跳过它把其余的查了吧」→ 停下报出来。跳过的表现是「答案缺一块」，提问者看不出本该有。
