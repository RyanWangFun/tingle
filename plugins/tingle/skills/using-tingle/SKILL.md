# using-tingle

## 概述

tingle 的会话入口，一句话职责：**回答「现在在哪个客户项目里工作、能不能直接开工」，不能直接开工就路由给就绪 skill——只引路，不干活。**

- **dispatcher，不是 digest**：本页是调度器。就绪判定与补齐的全部内容都在就绪 skill 里，只有路由过去才加载；读完本页不等于会判就绪。
- **先于响应调度**：会话开启后，回应用户第一条消息之前，先走完下面的入口三步。
- **本闸每轮重查**：工作文件夹一旦切换（会话中途换客户项目），重新走入口三步；不是会话开头跑一次就完。

## 何时用 / 何时不用

**何时用**：每个会话开启时（hook 已自动注入，直接执行）；会话中途切换工作文件夹时；不确定当前在哪个项目里工作时。

**何时不用**：
- 要判项目就绪、要补齐缺项——那是就绪 skill 的活，路由过去，入口不代做其中任何一步。
- 要干具体业务活（选题、蒸馏等）——那归各 work-skill；它们每次运行前自带检查，入口不替它们把关。

## 入口三步（硬结构，逐步走，不跳步）

**Step 1 · 锚定项目**：当前工作文件夹（cwd）对应哪个客户项目？
- 对应得上 → 记下文件夹路径，进 Step 2。
- 对应不上（不在任何客户项目文件夹里，或分不清）→ 问使用者在哪个客户项目工作，走 Step 1a。

**Step 1a · 引导/帮建项目文件夹**。规则双侧同构（成员与管理者同一套）：**一客户一文件夹一本地指针**——每个客户项目在自己机器上是一个专属工作文件夹，本地指针落在文件夹根；把多个客户集中放在同一个上级目录下管理的，也按客户各开一个子文件夹，本地指针各落各子文件夹根。
- 命名规则只此一条：**客户名英文小写 kebab，无通行英文名则用拼音**（示例：`acme-beauty`、`xinghe`）。
- 与使用者确认名称后帮建文件夹，以它为工作文件夹，进 Step 2。

**Step 2 · 跑 `tingle resolve`**（入口自己不判任何事，把判定交给程序）。它回**五种结论之一**，照下表引路：

| 程序说 | 什么意思 | 入口怎么办 |
|---|---|---|
| **正常** | 这个项目在这台机器上可以直接开工 | 宣布可开工，进「刷一次缓存」 |
| **本机未配置** | 这台机器上还没配过这个项目 | 路由 `tingle:project-readiness` 走初始化 |
| **配置不完整** | 东西在、但某一栏是空的（点名是哪一份） | 路由 `tingle:project-readiness`；若点名的是本地指针，它跑 `tingle migrate` 照模板重建即可，不必重走整套初始化 |
| **结构旧** | 某一份的结构版本过时了（点名是哪一份） | 路由 `tingle:project-readiness` 走升级 |
| **打不开** | 项目档案访问不了（附错误码） | 按错误码转对应修法：链接失效或没权限找项目资源管理者；网络问题重试 |

- **怎么调它**：`tingle-core` **不在 PATH 上**，它的绝对路径由会话开头那段注入给出（「tingle 程序在这台机器上的绝对路径」那一行）；本页写 `tingle resolve`，实际敲的是那个路径加上命令，另可加 `--cwd <项目文件夹>` 指定工作文件夹。
- 边界：**入口不自己读 `.tingle/state.json`、不自己判任何字段**——判定只有程序一份实现。入口只负责把结论翻成一句人话，并按上表引路。

**Step 3 · 路由**：按上表把项目交给 REQUIRED SUB-SKILL: `tingle:project-readiness`（就绪 skill）补齐，入口的活到此为止（随后仍顺手刷一次缓存）。

## 三步之后 · 刷一次缓存（非阻断，不是第四步）

**每次走完三步**（含中途换文件夹后重走），跑一次 **`tingle refresh`**。它拉「tingle-项目档案」与「tingle-项目索引」，整体覆盖写进 `.tingle/cache/` 那两个文件；拉不到就把已有的清空、各留一行失效说明；本地指针不在时整段跳过、不建空壳。

- **这层是纯加速，不许让入口失败**：`tingle refresh` 永远返回 0，不挡开工、不改三步结论。
- **缓存只加速浏览，不参与任何判定**：凡判定、加载红线、取落点地址一律读云盘。

## 接口与边界（声明）

- **适用环节**：「会话开始的项目锚定与就绪路由」——每个会话、每个客户项目都发生的可复用环节，非一次性事务。
- **input schema**：`cwd`（当前工作文件夹路径，字符串）；`tingle resolve` 的输出（五种结论之一）。**入口不直接读任何状态文件**。
- **output schema**：`project_folder`（锚定的客户项目文件夹路径，字符串）；`结论`（枚举：`正常` / `本机未配置` / `配置不完整` / `结构旧` / `打不开`，照抄程序，不自拟）；`route`（枚举：`proceed` / `project-readiness` / `按错误码转修法`）。可沉淀候选：无——路由结论会话内即用即弃。
- **写回位置**：无。缓存由 `tingle refresh` 写；Step 1a 帮建的项目文件夹是唯一一处持久副作用。
- **规则层与项目事实**：不挂载品类/品牌/类型任何规则层（本 skill 不产内容、不碰红线）；所需项目事实字段：无。
- **工具**：跑 `tingle resolve` 与 `tingle refresh` 两条命令 + 看文件夹 + 调用同族 skill（路由到 `tingle:project-readiness`）。不写飞书、不自行解析任何状态文件。
- **决策档**：自动——锚定/跑命令/路由机械执行；Step 1a 改动使用者机器（建文件夹）须经其确认名称后执行。
- **复核包**：交人复核时随附——锚定的项目文件夹路径、程序给的结论原文、路由去向。
- **升级条件（命中即停交人）**：①无法唯一锚定项目且使用者不给出答案；②建文件夹未获使用者确认；③合规红线不确定；④四层规则冲突；⑤缺关键项目事实；⑥输出需对外发送。（③–⑥在本 skill 极少出现，出现即停、不自行推进。）

## 产出验收判据（DoD）

一次入口运行合格，当且仅当：
1. 有明确锚定结论——具体项目文件夹路径，或已走 Step 1a 引导；
2. **跑过 `tingle resolve`**，且路由与它给的结论一一对应（见 Step 2 那张表）；
3. 全程未自行判定、未自行补齐、未直接读任何状态文件；
4. 完成于回应用户第一条消息之前（或文件夹切换后的第一个动作之前）。

**`tingle refresh` 拉到与否不进本判据。**

## Quick Reference

| 情形 | 动作 |
|---|---|
| cwd 是某客户项目文件夹 | 锚定它 → 跑 `tingle resolve` |
| 分不清在哪个项目 | 问使用者 → 必要时帮建文件夹（英文小写 kebab / 拼音） |
| 程序说「正常」 | 直接开工，不重走初始化 |
| 程序说「本机未配置」「配置不完整」「结构旧」 | 路由 `tingle:project-readiness`，把程序原话一并带过去 |
| 程序说「打不开」 | 按它给的错误码转对应修法，别当成"没配过" |
| 会话中途换文件夹 | 重新走入口三步 |
| `tingle refresh` 拉不到 | 照常开工；读档案／总索引走云盘 |

## Common Mistakes

- **自己动手判**——发现状态文件不对就自己解析、自己下结论：判定只有程序一份，入口跑命令、读结论、按表引路。
- **替就绪 skill 干活**——发现缺东西就自己补：只路由，入口不代做。
- **程序说「正常」还重走初始化**——正常＝可开工，直接干。
- **把「打不开」当成「没配过」**——前者是访问不了（找权限或重试），后者是没配过（走初始化），修法完全不同。
- **先干活后锚定**——入口先于响应，第一条消息前走完三步。
- **文件夹名随手起**（中文名 / 大写 / 空格）——只此一条命名规则：英文小写 kebab，无通行英文名用拼音。
- **拿入口结论当运行前检查**——过了入口 ≠ 每次运行都就绪；各 work-skill 每次跑 `tingle check <自己名>`，入口不替代。

## Red Flags（出现即停，回到入口三步）

- 「先把用户的问题答了，锚定回头再说」→ 先于响应，先锚定。
- 「我打开 `.tingle/state.json` 看一眼就知道了」→ 入口不读状态文件，跑 `tingle resolve`，听它的。
- 「程序这个结论我觉得不对，按我判的来」→ 判定以程序为准；有不一致，报上来，别自行改判。
- 「就缺个配置而已，我直接建一个」→ 建与重建归就绪 skill 与 `tingle migrate`，路由过去。
- 「换了文件夹，大概还是刚才那个项目」→ 重新走入口三步。
- 「上次那份缓存留着先用吧」→ 缓存不参与判定，走云盘。
