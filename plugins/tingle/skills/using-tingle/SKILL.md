# using-tingle

## 概述

tingle 的会话入口，一句话职责：**回答「现在在哪个客户项目里工作、能不能直接开工」，不能直接开工就路由给就绪 skill——只引路，不干活。**

- **dispatcher，不是 digest**：本页是调度器。就绪判定与补齐的全部内容都在就绪 skill 里，只有路由过去才加载；读完本页不等于会判就绪。
- **先于响应调度**：会话开启后，回应用户第一条消息之前，先走完下面的入口三步。
- **本闸每轮重查**：工作文件夹一旦切换（会话中途换客户项目），重新走入口三步；不是会话开头跑一次就完。

## 何时用 / 何时不用

**何时用**：每个会话开启时（hook 已自动注入，直接执行）；会话中途切换工作文件夹时；不确定当前在哪个项目里工作时。

**何时不用**：
- 要判项目就绪、要补齐缺项——那是就绪 skill 的活，路由过去，入口不代做其中任何一步。
- 要干具体业务活（选题、蒸馏等）——那归各 work-skill；它们每次运行前自带检查，入口不替它们把关。

## 入口三步（硬结构，逐步走，不跳步）

**Step 1 · 锚定项目**：当前工作文件夹（cwd）对应哪个客户项目？
- 对应得上 → 记下文件夹路径，进 Step 2。
- 对应不上（不在任何客户项目文件夹里，或分不清）→ 问使用者在哪个客户项目工作，走 Step 1a。

**Step 1a · 引导/帮建项目文件夹**。规则双侧同构（成员与管理者同一套）：**一客户一文件夹一锚**——每个客户项目在自己机器上是一个专属工作文件夹，锚落在文件夹根；把多个客户集中放在同一个上级目录下管理的，也按客户各开一个子文件夹，锚各落各子文件夹根。
- 命名规则只此一条：**客户名英文小写 kebab，无通行英文名则用拼音**（示例：`acme-beauty`、`xinghe`）。
- 与使用者确认名称后帮建文件夹，以它为工作文件夹，进 Step 2。

**Step 2 · 扫锚**：工作文件夹根下的 `.tingle/state.json`——只判一件事：**文件存在，且能解析出 `profile_link`**。
- 在且解析得出 → 项目已初始化。对齐这一已有进度直接开工，不重走初始化、不重建锚。
- 缺失或不可解析（文件不存在 / JSON 非法 / 解析不出 `profile_link`）→ 进 Step 3。
- 边界：锚里的版本号与其余内容合不合格、新不新，入口一概不判——判定归就绪 skill 单一实现（全家族只此一份）；陈旧锚由各 work-skill 每次运行前的检查兜住。

**Step 3 · 路由**：REQUIRED SUB-SKILL: `tingle:project-readiness`（就绪 skill）——把项目交给它判定与补齐，入口的**判定**到此为止（随后仍顺手刷一次缓存）。

## 三步之后 · 刷一次缓存（非阻断，不是第四步）

**每次走完三步**（含中途换文件夹后重走），**尝试**拉一次「tingle-项目档案」与「tingle-项目索引」。缓存恰两个文件、**不进锚**；**两件怎么寻址、什么时候才算数、锚不在时为何整段跳过，见就绪 skill 参考件 `readiness-contract.md` 「本地缓存」**：

- **拉到** → **整体覆盖写入** `.tingle/cache/项目档案.json`、`.tingle/cache/项目索引.md`。
- **拉不到**（离线／无权限）→ **那两个文件若在，清空、各只留一行**：`本缓存已失效：本次会话未能从云盘拉取。请直接读云盘，不要使用任何旧副本。` 然后**照常开工**：不重试、不报错、不改三步结论。这层是纯加速，不许让入口失败。
- **只搬运、不判读**：**不据档案内容做任何判定**（取一个地址字段 `folder_token` 以定位第二件除外，那是搬运本身）；凡判定、加载红线、取落点地址一律读云盘。

## 接口与边界（声明）

- **适用环节**：「会话开始的项目锚定与就绪路由」——每个会话、每个客户项目都发生的可复用环节，非一次性事务。
- **input schema**：`cwd`（当前工作文件夹路径，字符串）；`state_file`（`.tingle/state.json`，JSON，仅取 `profile_link` 一个字段）。
- **output schema**：`project_folder`（锚定的客户项目文件夹路径，字符串）；`anchor_status`（枚举：`present` / `missing` / `unparsable`）；`route`（枚举：`proceed` / `project-readiness`）。可沉淀候选：无——路由结论会话内即用即弃。
- **写回位置**：仅 `.tingle/cache/` 那两个缓存文件（整体覆盖或清空留说明），不写锚；Step 1a 帮建的项目文件夹是另一处持久副作用。
- **规则层与项目事实**：不挂载品类/品牌/类型任何规则层（本 skill 不产内容、不碰红线）；所需项目事实字段：无。
- **工具**：文件系统读写（看文件夹、读 JSON、写缓存）+ 调用同族 skill（路由到 `tingle:project-readiness`）+ 刷缓存读一次飞书（读不到即跳过），不写飞书。
- **决策档**：自动——锚定/扫锚/路由/刷缓存机械执行；Step 1a 改动使用者机器（建文件夹）须经其确认名称后执行。
- **复核包**：交人复核时随附——锚定的项目文件夹路径、`anchor_status`、路由去向。
- **升级条件（命中即停交人）**：①无法唯一锚定项目且使用者不给出答案；②建文件夹未获使用者确认；③合规红线不确定；④四层规则冲突；⑤缺关键项目事实；⑥输出需对外发送。（③–⑥在本 skill 极少出现，出现即停、不自行推进。）

## 产出验收判据（DoD）

一次入口运行合格，当且仅当：
1. 有明确锚定结论——具体项目文件夹路径，或已走 Step 1a 引导；
2. `anchor_status` 为三值之一，且 `route` 与之一一对应（`present`→`proceed`；`missing`/`unparsable`→`project-readiness`）；
3. 全程未执行任何就绪判定或补齐动作；
4. 完成于回应用户第一条消息之前（或文件夹切换后的第一个动作之前）。

**刷缓存拉到与否不进本判据。**

## Quick Reference

| 情形 | 动作 |
|---|---|
| cwd 是某客户项目文件夹 | 锚定它 → 扫锚 |
| 分不清在哪个项目 | 问使用者 → 必要时帮建文件夹（英文小写 kebab / 拼音） |
| 锚在且解析出 `profile_link` | 直接开工，不重走初始化 |
| 锚缺失 / 不可解析 | 路由 `tingle:project-readiness` |
| 会话中途换文件夹 | 重新走入口三步 |
| 刷缓存拉不到 | 清空已有缓存（没有就不必建）、留失效说明，照常开工；读档案／总索引走云盘 |

## Common Mistakes

- **替就绪 skill 干活**——发现锚缺失就自己动手判、动手补：只路由，入口不代做。
- **锚在场还重走初始化**——锚在＝已初始化，直接开工。
- **先干活后锚定**——入口先于响应，第一条消息前走完三步。
- **文件夹名随手起**（中文名 / 大写 / 空格）——只此一条命名规则：英文小写 kebab，无通行英文名用拼音。
- **拿入口结论当运行前检查**——过了入口 ≠ 每次运行都就绪；各 work-skill 运行前检查每次都跑，入口不替代。

## Red Flags（出现即停，回到入口三步）

- 「先把用户的问题答了，锚定回头再说」→ 先于响应，先锚定。
- 「顺手看下锚里各字段对不对」→ 入口只判存在 + 解析出 `profile_link`，其余一概不判。
- 「就缺个锚而已，我直接建一个」→ 建锚归就绪 skill，路由过去。
- 「换了文件夹，大概还是刚才那个项目」→ 重新走入口三步。
- 「上次那份留着先用吧」→ 清空，不留旧副本，走云盘。
