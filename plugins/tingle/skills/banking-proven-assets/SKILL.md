# banking-proven-assets

## 概述

一句话职责：**判一批跑出来的东西够不够格沉成下一单能直接调用的资产，定它沉进哪一格、标成什么成色。**

**这是一份方法技能**：它不对应任何一个工作环节，不读项目材料，不产出独立交付物。它被各环节以 `REQUIRED BACKGROUND:` 引为共同前提，**用来在那个环节收尾、要把这一单的东西留下来时过一遍。**

- **沉下来的不是"内容"，是被验证过的、能被单独取出来用的最小单元。** 整条片子、整份方案、整套打法不是资产——**能被拆出来装到下一条上的那一颗才是。**
- **经验不一定可复制，数据可复制。** 一个人说"我觉得这样对"，换个人未必成立；一个带着数和来源的结论，谁拿去都成立。**没有证据的一律不沉。**
- **宁可薄，不许掺。** 一条没验过的东西沉进去，下一单会照着它调料、拿不到结果、然后把原因归到执行头上——**掺进来的假资产比空着更贵，因为它不会自己暴露。**

## 何时用 / 何时不用

**何时用**：一个环节跑完、要判这一批产出里哪些值得留给下一单；某件事这次是靠某个人的手感做对的、要把它变成别人也能照做的规则；要判一条已经沉着的东西成色标对了没有。

**何时不用**：

- **要做出这一批产出**——怎么定人群、怎么挖需求、怎么写成片、怎么配投放，各归各的环节，本件只判"跑完之后哪些留下"。
- **要判一个东西算不算一个最小单元**——那是 REQUIRED BACKGROUND: `tingle:elementizing-content` 的三属性闸（重要／重复／独立）。**本件不重判它，本件判的是另一件事：它验过没有、够不够格留下。**
- **要判它挂没挂回一段定性意图**——那是 REQUIRED BACKGROUND: `tingle:keeping-metrics-anchored`。本件只要求这一格必须填、且填的是真意图，具体怎么判归它。
- **要用沉下来的东西**——从哪一格取、怎么组合、怎么放大，归取它的那个环节。

**本件不独立运行**，没有运行前检查，由引它的技能在自己的收尾工序里加载。

## 方法

三道工序。**工序一、二对每一条候选都要走；工序三只在"这次是靠某个人做对的"时才走。**

| 工序 | 交出资格判定单的哪几列 | 读哪份 |
|---|---|---|
| 一 · 过资格闸 | 判定（沉／不沉）、被哪一条拦下 | 本页 |
| 二 · 定格与定成色 | 沉进哪一格、成色、公共字段 | `references/eight-shelves.md` |
| 三 · 把手感转成规则 | 规则原文、验证记录、仍需人的部分 | `references/turning-judgment-into-rules.md` |

### 工序一 · 过资格闸

每一条候选逐条过下面四条。**四条缺一，本次不沉**——不是"先放进去以后再补"。

| 闸 | 判据 | 不过的样子 |
|---|---|---|
| **有证据** | 带得出数和来源：跑出了什么、数据在哪能查到 | "我觉得这个挺好的""这条感觉能爆" |
| **过得了它那类的线** | 达到本项目为这一类东西确立的判断基点 | 基数太小就下结论；或干脆没有可对照的基点 |
| **是本项目的数** | 验证它的数据来自本项目自己跑出来的结果 | 拿别人模板上的数、行业传说的数当证据 |
| **意图那一格填得出** | 说得清它在为哪一段意图作证（怎么判归 REQUIRED BACKGROUND: `tingle:keeping-metrics-anchored`） | 数据很漂亮，但说不出它在证明什么 |

**关于判断基点**：每一类东西的线是多少，**由本项目自己确立**，本件不给数。**基点必须从自己的历史结果或竞品结果归因得来——从已经拿到结果的往前推，找出它凭什么拿到，得出参考线，再套用验证。不许拍一个数当基点。** 取不到基点的，本次不沉，把这件事记下来交人。

**禁止**：

- **禁止把没有证据的东西沉进去。** 没有数就是没验过，没验过就不是资产，是待办。
- **禁止拿别人的数当自己的证据。** 别人模板上那个转化率、那个比值，不是通用真理。**套用之前必须用自己的数据再验一遍**，验之前它只能算一条待验的规则。
- **禁止为了让格子看起来厚而放宽标准。** 格子的价值不在条数，在打开任何一条都还成立。
- **禁止把整条产出当成一条资产沉进去。** 粒度到"能被单独取出来装到下一条上"为止——整条沉进去，下一单取不出能用的东西。
- **禁止把这次没过闸的东西改个说法再送一遍。** 没过就是没过，记下它被哪一条拦下，等它真验过了再来。

**合理化对照表**

| 心里的那句话 | 实际是什么 | 怎么裁 |
|---|---|---|
| 「这一单交账在即，格子还这么空」 | 交账压力不改变一条东西验没验过 | 空着交账，附上没过闸的清单和原因 |
| 「这个专项花了两周，总得留下点什么」 | 已经花掉的时间不是证据。**花得越多越想留下点什么，恰恰是最容易掺进假资产的时刻** | 留下的是"没过闸的清单和它缺什么"——那也是产出，而且是真的 |
| 「剩下这几条都差不多，一起标了」 | 成色是逐条判的，"差不多"是省事不是判定 | 一条一条判；判不动的进未过闸清单 |
| 「这条我有八成把握，先放进去，回头补数据」 | 放进去之后没有人会回头补——下一单会直接拿它调料 | 不沉，记成待验项 |
| 「行业里都这么说，还要验？」 | 通行说法是别人的结论，不是本项目的证据 | 用自己的数据验过再说 |
| 「数据是漂亮的，虽然说不清在证明什么」 | 说不清在证明什么的漂亮数据，下一单不知道该怎么用它 | 意图那一格填不出就不沉 |
| 「这一整套打法都挺好的，整个存下来」 | 整套存下来等于没存——下一单取不出可用的一颗 | 拆到能被单独取用为止 |
| 「上次那条虽然没验过，但用着还行」 | "用着还行"不是数据，且它已经在污染后面每一次归因 | 回头把它降级为待验 |

### 工序二 · 定格与定成色（详见 `references/eight-shelves.md`）

过了闸的每一条，做三件事：**沉进八格里的哪一格 → 标成色 → 填齐公共字段。**

**成色只有四档，是一把单调的尺**——它量的是"验到什么程度"，不是"谁能做"：

| 档 | 意思 | 能拿它干什么 |
|---|---|---|
| **未成文** | 只在某个人脑子里，还没写出来 | **不入格**。它是原料，先走工序三 |
| **待验** | 已经写成了别人能照做的规则，但本项目还没验过 | 可入格。**只能拿来当测试的依据，不能当结论用** |
| **已验** | 本项目跑出过一次达标结果 | 可复用、可放大 |
| **可放量** | 本项目多次跑出达标结果 | 可放量，可以被自动调用 |

**禁止**：

- **禁止把"待验"标成"已验"。** 差一档，下一单就会拿它当结论而不是当假设，错了还查不出来。
- **禁止跳档。** 没验过就不能是"已验"，验过一次就不能算"可放量"。
- **禁止一条东西同时躺在两格里。** 它属于哪一格由它的最小单元形态决定，两可的记下来交人，不自己挑一个。
- **禁止公共字段留空。** 缺一格不沉——**尤其是证据来源与合规要点这两格**，缺了的话下一个取用它的人无从核实、也不知道它有没有踩线的风险。

### 工序三 · 把手感转成规则（详见 `references/turning-judgment-into-rules.md`）

**触发条件**：这一单里某个做对的决定，是靠某个人的手感或临场判断做出来的，换个人做不出来。

五步：**抓出来 → 追出他凭什么 → 写成新人能照做的 → 用数据验它可复制 → 入格标成色。**

判据只有一条：**团队里任何一个新来的人读了能听懂、能照着做。** 达不到这条的，是笔记不是规则。

**禁止**：

- **禁止接受"凭经验"作为判据。** 追到可描述为止：他看了哪个数、比了什么、卡了哪条线。追不出来的，如实标"仍需人"。
- **禁止把还没验过的手感写成规则推广。** 它看起来像规则、实际不可复制；下游照做拿不到结果，还会把原因归到自己执行不好。**写出来了但没验的，成色只能是"待验"。**
- **禁止假装某个判断已经不需要人了。** 有些判断短期就是抽不成规则（典型是"从一堆标签里跳到一个还没被人发现的细分人群"那一击）。**如实标出来"这一步仍需人"，不假装它已经自动化了**——诚实比数量重要。

## 接口与边界（声明）

- **适用范围**：「判一批跑出来的东西够不够格沉成可复用资产、定格与定成色」——**它不对应链上任何一站**，是横切多个环节的方法与判准，被别的技能引为共同前提。这件事**换一个客户项目、每一个环节每跑完一次都会再次发生**，非一次性事务；且它同时被每一个会产出东西的环节共用（这两条正是它立为方法而非某一个环节正文的理由）。全文不含任何客户事实、不含任何具体阈值。
- **input schema**：`候选资产`（数组，每条含：本体、它是怎么跑出来的、手上有的数据与来源、它所属的最小单元形态；由调用方在会话里递入）；`本项目判断基点`（对象，本项目已确立的各类判断基点及其归因来源，由调用方持有并提供）；`本项目已有的成色定义`（可选，对象；已经在用的分档如与本件四档不一致，停下交人）。**每次输入不一样，不登记进项目档案。**
- **output schema**：`资格判定单`（数组，每行含：本体、判定（沉／不沉）、被哪一条闸拦下、沉进哪一格、成色、公共字段是否填齐、证据与来源、挂回的意图、合规要点）；`未过闸清单`（数组，每条含它被哪一条拦下、要补什么才能再送）；`转成规则的记录`（数组，每条含规则原文、追出来的判据、验证记录、仍需人的部分）；`基点缺口`（数组，取不到判断基点因而本次无法判的那些类）。**可沉淀候选（reusable_candidates）**：`转成规则的记录` 里已经验过的那些条（它们本身就是能给下一单直接用的规则）、`基点缺口`（它指出本项目还缺哪几条判断基点，是下一次要补的活）。
- **写回位置**：**无**。本件不写任何落点——判定单交回调用方，由调用方写它自己声明的落点（八格实际落在哪张表，由调用方的项目档案登记）。
- **规则层与项目事实**：**四层规则一层不挂**（本件不产对外内容、不判任何一条内容能不能发）。本件只要求"凡有合规风险的条目，合规要点这一格必填"——**要求这一格非空是判准，格子里填什么由引本件的环节按它自己挂的层判。** 所需项目事实字段：`本项目判断基点`（由调用方提供，本件不自取）。
- **工具**：**无**。不读写任何文档与表格、不调任何平台接口、不读文件系统——本件只吃调用方递进来的候选与基点。
- **决策档**：**复核**。本件的判定单须有人过目才算数——**因为它有一步做错了没有人会发现**：把一条没验过的东西判成"已验"沉下去，下一单照着它调料、拿不到结果时，归因几乎不会回溯到"当初那一条不该沉"。
- **复核包**：交人复核时随附——资格判定单本体 ＋ 每一条的证据与来源 ＋ 未过闸清单及各自被哪一条拦下 ＋ 成色判定的理由（尤其是判成"已验"与"可放量"的那几条，须写清验过几次、数据在哪）＋ 转成规则的记录及其验证情况 ＋ 仍需人的部分 ＋ 基点缺口。
- **升级条件（命中即停交人）**：①合规红线不确定；②四层规则冲突；③缺关键项目事实——**取不到本项目的判断基点，因而无法判某一类够不够格**；④输出需对外发送；⑤要把某一条判成"已验"或"可放量"，而验证数据不是本项目自己跑出来的；⑥要新开一格、改公共字段、或改成色档位的定义；⑦某一条两可地属于两格；⑧某个判断追不出可描述的判据，要标成"仍需人"；⑨本项目已经在用的分档与本件四档不一致。

## 产出验收判据（DoD）

一次运行合格，当且仅当：

1. **每一条候选都有判定**（沉或不沉），没有一条悬在那里；
2. 判"不沉"的每一条都写明**被四条闸里的哪一条拦下**、以及要补什么才能再送；
3. 判"沉"的每一条都**带得出数和来源**，且那个数是本项目自己跑出来的；
4. 判"沉"的每一条都**填齐了公共字段**，**证据来源与合规要点两格无一空缺**；
5. 每一条的成色**在四档之内**，且判成"已验"或"可放量"的那几条写清了**验过几次、数据在哪**；
6. **没有一条被标为"未成文"却仍进了格**；
7. 走过工序三的每一条，其规则原文**由一个没参与这一单的人读了能照着做**——写成只有原作者看得懂的笔记的，判不合格；
8. 追不出判据的那些判断**如实标了"仍需人"**，没有被写成看起来像规则的东西；
9. 取不到判断基点的那几类**列进了基点缺口**，没有被随手拍一个数糊过去。

## Common Mistakes

- **没数就先放进去，想着回头补**——没有人会回头补，下一单已经拿它调料了。
- **拿别人模板上的数当证据**——那是别人的结论，不是本项目的验证。
- **为了让格子显厚而放宽标准**——掺进来的假资产不会自己暴露，只会让后面每一次归因失真。
- **把整条产出原样存下来**——粒度不对，下一单取不出能用的一颗。
- **"待验"当"已验"用**——差一档，假设被当成了结论。
- **验过一次就标可放量**——一次是运气还是规律，一次分不出来。
- **公共字段留空，尤其是来源和合规要点**——下一个取用它的人无从核实，也不知道有没有踩线风险。
- **接受"凭经验"当判据**——那等于什么都没抽出来。
- **把没验过的手感写成 SOP 推广**——看起来像规则，实际不可复制。
- **假装某个判断已经不需要人了**——短期抽不成规则的就如实标出来，诚实比数量重要。
- **改个说法把没过闸的再送一遍**——闸没变，它也没变。

## Red Flags（出现即停，回到对应工序）

- 「这条我有八成把握」→ 回工序一，把握不是证据。
- 「行业里都这么说」→ 回工序一，用自己的数据验。
- 「数据这么好看，先存着」→ 回工序一，说不出在证明什么就不沉。
- 「基点先随便定一个，回头再调」→ 回工序一，基点要归因得来，取不到就列缺口。
- 「上个项目的线拿过来用一下」→ 回工序一，基点要从本项目自己的结果归因得来。
- 「这个专项花了两周，总得留下点什么」→ 回工序一，花掉的时间不是证据。
- 「剩下这几条都差不多，一起标了」→ 回工序二，成色逐条判。
- 「这一整套都挺好的，整个存」→ 回工序一，拆到能单独取用。
- 「先标已验，反正快验了」→ 回工序二，没验就是待验。
- 「跑成了一次，那就是能放量」→ 回工序二，一次分不出运气和规律。
