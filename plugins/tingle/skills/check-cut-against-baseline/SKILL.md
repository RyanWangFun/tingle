# check-cut-against-baseline

## 概述与核心原则

一句话职责：**逐时点核一条已制作的成片对不对得上本次基准与本项目既定制作规范，交出带时间定位的返工清单、通过项与一个交付判断**——先锁死本次唯一的基准并抽全它的结构，再按分层取证把成片变成可指认的时点证据，然后两维核对（对不对得上基准 / 守没守住既定制作规范），每一条不符都带定位与可直接执行的改法，最后汇总成一个「能不能交出去」的判断。

**这算一个职责，不算两个。** 取证在这里没有独立的消费者——抽出来的帧只服务本环节的核对，核完即弃；而核对没有取证就无从指认（"产品出现得有点晚"与"约第几秒才出现"是两种东西，只有后者能被执行）。**一个动作是另一个动作的前一步，不构成两个能力。**

**基准是外面给的，不是本环节判出来的。** 基准可能是定下来的那一版稿，也可能是上一轮的修改意见清单；**本环节只核成片对不对得上它，不判它本身对不对**。基准里的话本身有没有表述风险，是稿件送出去之前那一环的事——本环节遇到时按升级条件停并报，不在这里顺手判。

**适用环节**：换一个客户项目也会再次发生的固定环节——凡成片要交给客户或对外发布，交出去之前都要过这一道，不是一次性事务。

**属于哪组能力**：项目自动化（供上位方案对账用——本环节是项目执行链上的一道，不属诊断、洞察、盯盘、策略建议或复盘沉淀）。

**三条核心原则（越一条即错）**：

- **判定必须落在可指认的时点上。** 每一条不符都要带定位（约第几秒、或第几秒到第几秒），不带定位的判定制作方无从下手，也无从反驳。
- **通过项与不符项一起交。** 只列问题，制作方就不知道哪些不必返工，于是要么重做多余的、要么把已经对的也一起改坏了；而漏核的项与"核过了没问题"的项在只列问题的清单里长得一模一样。
- **看不清就回去重取，不靠猜下结论。** 低清帧上的小字、拿不准是不是标准色值的颜色、听不清的口播——回原始清晰度重取、或改用可指认的表述（"可见字幕显示…"、"视觉上不是…，需按色值复核"），**不许挑一个解释直接判**。

## 何时用 / 何时不用

**何时用**

- 一条成片做完了，交客户或对外发布之前，要核它对不对得上定下来的那一版、本项目的硬性制作规矩守住了没有。
- 上一轮提过修改意见，新版来了，要逐条核哪些改了、哪些只改了一半、哪些没动。
- 只有成片、没有基准稿——**照样能跑**，只核制作规范那一维，并在产出里显式声明"本次无基准，一致性未核"。

**何时不用（When NOT）**

- **判基准本身的表述有没有风险**——"这句话本身能不能说"是稿件送出去之前那一环的事。成片逐字还原了一句有风险的话，那是基准的问题不是制作的问题；本环节遇到时停并报，**不在返工清单里把它写成制作错误，也不自己给它下合规结论**。
- **在两个剪辑版本之间推荐一版**——那是一个选择，不是一次核对。要比两版：各跑一遍本环节，把两份清单交给人比，推荐哪一版由人定。
- **剪辑、压缩或重制成片**——本环节给出该砍哪一段、该补什么，**不动手改片**。
- **图文类成品的核对**——本环节的方法建在"按时点取证"上，图文成品没有时间轴；现有材料不足以支撑，须另判。
- **基准不唯一时硬跑**——手上有两份稿、或调用方没指定以哪一份为准，一律停并问，**不混用、不取并集**。
- **成片取不到帧或取不到元数据时硬跑**——停并报，索要可读取的原片。

## 方法

### 一 · 锁定唯一基准并抽全它的结构

- **一次运行只认一个基准。** 调用方中途说"以这一份为准"，立刻整体切换，**不与之前那一份混用、不取并集**；切换后此前已出的判定全部作废重跑，并在产出里记明换过基准。
- **取文时连表格一起取。** 脚本类基准的正文常整段躺在表格里，只读普通段落会漏掉整块口播而不留任何痕迹。
- **基准为稿时，抽出四样并分辨清楚**：要念出来的口播、屏幕上的文字、画面与镜头说明、元信息（标题、编码、发布文案一类）。分不出来就没法核一致性——分不出来即停并报。
- **基准为修改意见清单时，抽出每一条的原始要求**，逐条编号，后面按这个编号闭环。
- **交出基准覆盖清单**（抽到几段口播、几处屏幕文字、几条画面说明；或几条修改意见），请人确认没有漏抽（**必停**，见下）。
- **顺手记下基准的体量**（稿的字数、意见的条数）——超时归因那一步要用。

### 二 · 取证

1. **先取元数据**：时长、画幅、分辨率。**时长是后面所有时点判定的坐标系**，也是取证覆盖清单的分母。
2. **分层抽帧**：先按固定间隔通抽一遍建立总览，**间隔要取到让任何一次画面切换都落不进两帧之间的空档**；再对下列关键段加密到逐秒——
   - 每一个必须露出的元素，其首次出现的前后；
   - 每一项必须常驻的标识与免责表述，其起点、终点与**最后一处画面**；
   - 出现精准数字、排名说法与比较性说法的段落；
   - 需要遮挡或替换的画面对象出现的段落；
   - 片尾各页（汇总页、引导关注页一类），逐页各取。
3. **交出取证覆盖清单**——抽了哪些时点、哪几段做了加密、总时长多少。**没有这份清单，漏抽就不留痕**：返工清单只呈现它看见的东西，而拿到清单的人默认全片都被核过。

**取证的具体手艺——分层间隔怎么定、动态元素怎么查首帧、看不清怎么回取、颜色怎么描述——见随件参考件《取证手艺》（`references/frame-evidence-craft.md`），取证之前读它。**

### 三 · 两维核对

**维一 · 对不对得上基准**（基准为稿时逐段核；基准为修改意见清单时逐条核；无基准时整维标"未核"并写明原因）

逐段核下列各项，**每一项判定都带时点定位**：

- 口播的**顺序**与**内容**：漏段、并段、改词、加词；
- **限定语与适用条件**有没有被删——"可能""部分情况下""在专业人士指导下""某某条件下"这一类被删掉，是最常见也最难看出的一种偏离，因为删完之后句子更顺；
- **数字、年龄、比较对象、行动指令**有没有被改；
- **屏幕文字**有没有把一整句压缩成一个更绝对的结论；
- **字幕**与口播是否同步，有没有漏字、错字、同音错字、把词组或产品全名拆断的错误断句。

基准为修改意见清单时，逐条给出四值之一：`已改` · `部分修改` · `未改` · `无法核实`，每条附当前状态与仍需动作。

**维二 · 守没守住既定制作规范**

逐项使用输入「成片规范说明」，**每一项不符都带时点定位与可直接执行的改法**：

- 必须露出的元素——出现了吗、够不够早、形式算不算数（近似说法不能替代）；
- 视觉要求——从出现的第一帧起就生效了吗（先是别的样子、下一秒才变对的，不算数）；
- 必须常驻的项——起点对不对、中途丢没丢、**最后一处画面还在不在**、片尾各页是否同样保留；
- 外部素材与合成素材的标识——标了吗、和素材同时出现吗、看得清吗；
- 需要遮挡的对象——遮住了吗、多个对象并列时口径一致吗；
- 时长与字数——超没超，超了要**同时指出成片超出多少与基准体量的根因**，并点名最该压缩的具体段落；
- 片尾各页与字幕呈现——行数、可读性、停留时长、有没有被别的元素压住。

**禁止**：

- **禁止拿一处代表全体。** 同一个元素每次出现都要各查一次——首次出现处、并列出现处、片尾出现处各自成立与否互不代表。**已观测的原样**：中段几处都合规，首次露出那一处却是另一个样子，只查中段就会整条放过。
- **禁止只看静止的那一帧就判动态元素。** 屏幕文字可能先是一种样子、下一秒才变成对的，也可能先缺字后补齐——**出现的第一帧与完整停留帧都要看**。
- **禁止在看不清时下结论。** 低清帧上的小字回原始清晰度重取再判；颜色拿不准写"视觉上不是…，需按色值复核"；口播听不清写"可见字幕显示…"，不断言音频内容。
- **禁止把"我建议这样更好"写成不符项。** 硬性不符与可选优化分两栏列，混在一起会让制作方把建议当成必须返工的，也会让真正的硬伤被淹掉。
- **禁止把硬性不符降格成可选优化。** 一条归哪一栏，由「成片规范说明」里那一项是不是硬性要求决定，**不由制作方返了几轮工、片子重剪有多贵、交期还剩多久决定**。要让步是人的决定，摆出来交人，不在清单里悄悄换栏。
- **禁止只列不符项、不列通过项。** 通过项是制作方判断"哪些不必动"的唯一依据。
- **禁止把基准本身的表述问题写成制作错误。** 成片逐字还原了基准，那就是"对得上基准"；基准本身有没有风险，停并报，交给稿件那一环。
- **禁止在被指出误判之后换个说法继续坚持。** 画面上清清楚楚的字被判成错字、经人指出后应当撤回该条并在产出里记明撤回，不改口成"虽然是对的但建议调整"。

**合理化对照表**

| 心里的那句话 | 实际是什么 | 怎么裁 |
|---|---|---|
| 「中间几处都对，首尾应该也一样」 | 已观测：首次露出与片尾恰恰是最常出错的两处 | 每次出现各查一次 |
| 「抽了几张关键帧，看着没问题」 | 抽了几张与按覆盖清单抽过是两回事，而漏抽不留痕 | 分层抽帧 ＋ 交覆盖清单 |
| 「这张帧太糊看不清，估计是对的」 | 猜出来的判定与核过的判定在清单里分不开 | 回原始清晰度重取，仍不清就标"需人工复核" |
| 「颜色看着差不多，算它对」 | 屏幕呈现的色与标准色值是两件事 | 写"视觉上不是…，需按色值复核" |
| 「片子超时了，建议整体倍速」 | 那不是可执行的改法，也没说清根因 | 指出超出多少 ＋ 基准体量根因 ＋ 点名该压缩的具体段落 |
| 「这句话本身有风险，写进返工清单」 | 成片忠实还原了基准，返工也解决不了 | 停并报，交给稿件那一环 |
| 「他们已经返两轮了，这条降成建议吧」 | 归哪一栏由规范的硬性程度定，不由返了几轮定 | 照列硬性栏，让步摆出来交人 |
| 「这周第八条了，前七条都没问题，参照上次的清单」 | 上次没问题可能是上次漏核了；每一条片子各是各的 | 照样走完整取证与两维核对 |
| 「顺手把我觉得更好的剪法也写上」 | 建议混进硬伤里会淹掉硬伤 | 硬性不符与可选优化分两栏 |
| 「只列问题，通过的就不写了」 | 制作方不知道哪些不必动，漏核项也无从暴露 | 通过项照列 |
| 「他说我判错了，但我换个角度还是有点问题」 | 换说法坚持＝不承认误判 | 撤回该条并记明 |

**Red Flags（出现即停，回方法三）**

- 「先粗看一遍，有明显问题再细查」
- 「这条片子和上一条差不多，参照上次的清单」
- 「时间紧，关键几项核一下就交」
- 「他们已经返两轮了，这条降成建议吧」
- 「这周第八条了，前七条都没问题」
- 「这处看不清，先按合格算」
- 「基准里就是这么写的，所以没问题」（对得上基准 ≠ 这话没风险；两者都要各归各处）

### 四 · 写结论

- **时点用"约第几秒"或区间**，不假装精确到帧。
- **每一条不符都带可直接执行的改法**——写"在第几秒到第几秒之间补上…"，不写"产品出现得有点晚"。
- **描述事实，不写评价。** 好：「约第 43 秒才首次出现完整名称，超出本项目规定的最迟时点」。差：「产品露出偏晚」。
- **不把内部过程堆给读者**——抽帧的临时文件路径、基准文件在哪台机器上、用了什么命令，一律不进产出。

### 五 · 下交付判断

汇总成三档之一，**不用第四种说法、不用模糊结论收尾**：

| 档 | 什么时候用 |
|---|---|
| **可提交** | 无硬性不符，仅有可选优化 |
| **修改后提交** | 存在硬性不符，但都可在现有素材上改完，不需重剪主体或补拍 |
| **不建议提交** | 出现下列任一：必须露出的元素缺失或严重超时、必须常驻的项大段缺失、与基准的偏离大到需要重剪主体或补拍、基准本身的问题导致改也没用 |

**下「可提交」这一档必停交人**（见下方必停名单）。另两档是"要改"，人本来就要动手，不必停。

**本环节无权宣称任何外部审核已通过。** 交出的判断只说"已按本次基准与本项目现有制作规范核过哪些项"，**不得写成"已通过医学审核／法务审核／平台审核"**。

### 六 · 步骤

1. **锁定唯一基准并抽全结构**（方法一）。**交出基准覆盖清单请人确认**（必停，见下）。
2. **取元数据、分层抽帧**（方法二），**交出取证覆盖清单**。
3. **维一核一致性**（方法三），逐段或逐条留痕。
4. **维二核规范符合**（方法三），逐项留痕，通过项照列。
5. **写结论**（方法四）——硬性不符与可选优化分两栏，各带定位与改法。
6. **下交付判断**（方法五）。
7. **判断为「可提交」时，交人点头**（必停，见下）；另两档直接交出。
8. **收尾自查并交付**——照 DoD 逐条核，核过之后交出产出与复核包。

## 依赖的规则层与项目事实

- **挂三层**：**通用层**——不分行业都适用的呈现要求（外部素材与合成素材的标识义务、绝对化用语）；**品类层**——按合规类目取值的常驻标识与免责表述要求（哪几项必须常驻、位置与起止、片尾各页是否适用），换一个合规类目整套换；**品牌层**——本项目的露出时点、视觉色值、遮挡口径、术语正名。

- **这三层当下的承载，是输入「成片规范说明」与输入「品牌项目红线」两份项目件——组织级的规则库还不存在。** 所以本环节运行时**不去任何组织级的地方取规则**。规则库建出来之后，改的是这两份文件从哪儿继承内容，本 skill 的读法一个字不变。

- **不挂类型层**：现有材料里没有出现"换一种成片类型，同一项该不该核就变了"的情形。**这一条是按现有材料判的，不是验过的**——若日后出现成片类型改变核对门槛的项目，此处须重判。

- **它没写到的，一律标出来问，不自己补一条。** 规范说明里没写到的要求，判 `待确认·规范未写到` 交人，不按"看起来应该这样"自己定一条。

- **所需项目事实字段**：`合规类目`、`品牌`（决定装载哪一套上述规则），由运行前检查从项目档案取得。

## 依赖的工具与接口

- 视频元数据读取（时长、画幅、分辨率）。
- 按时点抽帧能力——须支持按指定时点重抽，且能按原始清晰度取帧。
- 图像查看能力（看帧、放大核小字与颜色）。
- 版式文件取文能力（把基准稿转成可逐段读的文本）——**须连表格一起取**。
- 文档与云盘读取接口（取两份项目件、取基准）。
- 同族 skill：REQUIRED SUB-SKILL: `tingle:project-readiness`（Step 0 运行前检查报卡点时载入）。
- **随件**：取证手艺参考件《取证手艺》（`references/frame-evidence-craft.md`）——取证之前读。它管"怎么取到站得住的证据"，不管"要核哪几项"（后者一律看输入「成片规范说明」）。

**写入只发生在一处：本 skill 自己的产出落点。** 成片不动、基准不动、两份项目件只读。

## 输入 / 输出 schema

**input schema**

- `待核成片`（本次要核的那一条成片。**由调用时当场给出**，本地文件 / 云盘文件一律接）
- `本次基准`（**一次运行只认一个**。枚举其形态：定下来的那一版稿 / 上一轮的修改意见清单 / 无基准。取"无基准"时，维一整维标"未核"并写明原因）
- `基准形态`（枚举：可编辑文稿 / 只读版式文件 / 纯文本 / 意见清单。只读版式文件的文本层残缺、或四样分不出来时停并报）
- `成片规范说明`（本项目对一条成片的既定制作要求）
- `品牌项目红线`（术语正名、必须随附的限定语与免责表述原文）
- 上述后两样的实际地址以 Step 0 运行前检查返回的已解析地址为准。

**output schema**

**最终交付物（一件）**

- `核对产出`（一份文件，含下列六项）：
  - `返工清单`（每行：时点定位 / 事实描述 / 撞的是哪一项 / 可直接执行的改法。**硬性不符与可选优化分两栏**）
  - `通过项`（每行：核了哪一项 / 结果 / 依据的时点。**不得省略**）
  - `取证覆盖清单`（总时长、通抽间隔、加密到逐秒的是哪几段、基准抽到几段或几条）
  - `交付判断`（三档之一：可提交 · 修改后提交 · 不建议提交，附一句理由）
  - `待确认项`（每条：卡在哪一样、缺什么、要谁补。含判为「需人工复核」的色值与看不清处、以及 `待确认·规范未写到` 的那几项）
  - `本次基准与规则来源`（这一次核的是哪一份基准、依据的是哪一份规范说明的哪一版；中途换过基准的，记明换过）

  **基准为修改意见清单时，`返工清单` 换成闭环表**：每行 `意见编号 / 原始要求 / 当前结果 / 结论（已改·部分修改·未改·无法核实）/ 仍需动作`。

**可沉淀候选（reusable_candidates）**

- `本次判为「待确认·规范未写到」的那几项`（它们是规范的缺口，补进「成片规范说明」之后全项目受益）
- `本次高频复现的制作偏差类型与其最低成本改法`（同一个制作方下一条片可直接沿用，宜回写「成片规范说明」的常见偏差一节）

## 决策档 · 必停名单 · 复核包 · 升级条件

**决策档**：**复核**。产出连着对外——成片改完要交客户或直接发布，不标自动。

**哪几步必停（不是统一档位，是这一份名单）**：

| 步 | 判 | 这一步做错了，谁会在什么时候发现 |
|---|---|---|
| 1 抽基准结构 | **必停**——交出基准覆盖清单请人确认 | **没有人。** 脚本类基准的正文常整段在表格里，只读段落会漏掉整块口播；漏掉的那块在返工清单里不留任何痕迹，成片看上去是被完整核过的 |
| 2 取证抽帧 | 可自动（**条件是交出取证覆盖清单**） | 成片总时长由元数据给出，覆盖清单能显示"全长多少、通抽间隔多少、哪几段加密"，缺口对人是可见的。**没有覆盖清单则漏抽无痕**——故覆盖清单是产物必备项，不是可选项 |
| 3 核一致性 | 可自动 | 下游必然看到：制作方拿清单对成片，判错当场被顶回来 |
| 4 核规范符合 | 可自动，**判不准即停**（见升级条件⑤⑥） | 色值是不是标准色、低清小字是不是错字，这两类肉眼判不准；判不准仍下结论，制作方按错误结论返工，返完工才发现白改 |
| 6 下「修改后提交」「不建议提交」 | 可自动 | 这两档都是"要改"，人本来就要动手，动手时判断错没错当场暴露 |
| 6 下「**可提交**」 | **必停**——交人点头 | **发现时已经对外。** 拿到"可提交"的人就把片子交客户或发出去了，那边看出问题时已经对外，而清单上"可提交"与真的没问题长得一模一样 |
| — 把返工清单发给制作方之外的人 | **必停** | 清单一旦发给客户即不可撤回 |

**复核包**（随产出附上，使复核的人不必回头翻上下文）：本次基准本身、返工清单与通过项、取证覆盖清单、**每一条判定所依据的那一帧或那一段时点**（复核要核的正是这一处，没有它复核的人只能信、不能核）、交付判断及其理由、待确认项清单、本次装载的规则来源。

**升级条件（命中即停交人）**：①合规红线不确定；②四层规则冲突（两层各有一套说法）；③缺关键项目事实（合规类目或品牌未取到，不知道该装哪套规则）；④产出需对外发送；⑤某一处看不清、回原始清晰度重取后仍判不准；⑥色值、字号一类须按标准值比对而当前只能凭视觉判的；⑦基准不唯一——手上有两份、或调用方没指定以哪一份为准；⑧基准读不全（只读版式文件文本层残缺、表格里正文取不到、四样分不出来）；⑨成片取不到帧或取不到元数据；⑩**基准本身的表述疑似有风险**——不在本环节判，停并报，指向稿件送出去之前那一环；⑪「成片规范说明」对某一项完全没写到——判 `待确认·规范未写到` 交人，不自己补一条；⑫判断为「可提交」。

## 写回位置 · 可沉淀候选

- **写回位置**：requirements 落点「核对产出落点」，地址由项目档案填、运行前检查解析。每次核对各自成一件落在这里、不覆盖上一次——上一轮的清单是这一轮闭环的对照物。**成片与基准都不动**。
- **可沉淀候选**：见 output schema 中标出的两项。

## 产出验收判据（DoD）

一次运行合格，当且仅当：

1. 本次只用了一个基准；中途换过的已记明，且换基准之前的判定已作废重跑。
2. 基准覆盖清单已交出且经人确认；取证覆盖清单已交出，含总时长、通抽间隔与加密段。
3. 每一条不符都带时点定位（约第几秒或区间）与可直接执行的改法，无"偏晚""不太好"一类无法执行的表述。
4. 硬性不符与可选优化分两栏列出，未混编；**每一条归哪一栏都指得出「成片规范说明」里对应那一项的硬性程度**，未因返工轮次或交期让步而换栏。
5. **通过项已列出**，每项附核了什么、结果、依据的时点。
6. 判不准的处（看不清、色值、字号）落在待确认项并写明"需人工复核"，未凭猜下结论。
7. 「成片规范说明」没写到的那几项，已逐条标为 `待确认·规范未写到` 交人，未自己补规范。
8. 基准本身疑似有风险的表述，未被写成制作错误、也未被下合规结论，而是单列交给稿件那一环。
9. 交付判断落在三档之一并附理由；判为「可提交」的，已取得人的点头。
10. 产出里没有内部过程信息（临时抽帧路径、命令、本机路径）。
11. 复核包齐全，复核的人据它可以逐条回到那一帧核对，不必回头问作者。

## Quick Reference

| 问题 | 一句判法 |
|---|---|
| 基准是哪一份？ | 一次运行只认一个；调用方换了就整体切换、此前判定作废重跑；不唯一即停 |
| 抽帧抽多密？ | 先按固定间隔通抽到"任何一次画面切换都落不进空档"，再对关键段加密到逐秒；手艺见随件《取证手艺》 |
| 哪些是关键段？ | 必须露出的元素首次出现前后、常驻项的起止与最后一处、精准数字与比较说法处、遮挡对象处、片尾各页 |
| 同一个元素查几次？ | 每次出现各查一次——首次、并列、片尾互不代表 |
| 动态元素怎么查？ | 出现的第一帧与完整停留帧都要看，不拿静止代表帧代替 |
| 看不清怎么办？ | 回原始清晰度重取；仍不准则写"需人工复核"，不猜 |
| 颜色怎么写？ | 判不准时写"视觉上不是…，需按色值复核"，不断言 |
| 超时怎么写？ | 超出多少 ＋ 基准体量根因 ＋ 点名该压缩的具体段落，不写"整体倍速" |
| 基准里那句话本身有风险？ | 不在这里判——停并报，交给稿件送出去之前那一环 |
| 通过项要不要写？ | 要——制作方靠它判断哪些不必动，也是漏核唯一能暴露的地方 |
| 两个版本选哪个？ | 不选——各跑一遍，两份清单交人比 |
| 哪一步不许自动？ | 抽基准结构后的覆盖确认、下「可提交」这一档、把清单发给制作方之外的人；另有十二条升级条件命中即停 |

## 常见错误（Common Mistakes）

- **拿一处代表全体**——中段几处合规不代表首次露出与片尾也合规，那两处恰恰最常出错。
- **只看一张静止帧就判动态元素**——屏幕文字可能先是一种样子、下一秒才变对，也可能先缺字后补齐。
- **看不清就估一个结论**——猜出来的判定与核过的判定在清单里长得一模一样。
- **只列问题、不列通过项**——制作方不知道哪些不必动，漏核项也无从暴露。
- **把硬性不符悄悄降成可选优化**——让步是人的决定，不该在清单里发生。
- **把可选优化混进硬性不符**——真正的硬伤被淹掉，制作方还返了多余的工。
- **把基准本身的表述问题写成制作错误**——成片忠实还原了基准，返工也解决不了。
- **超时只说"建议压缩"**——没有可执行的改法，也没说清根因。
- **只读基准的普通段落、漏掉表格里的正文**——整块口播漏核且不留痕。
- **被指出误判后换个说法继续坚持**——该撤回的条目要撤回并记明。
- **把某个客户的色值、时点、编码抄进本页**——它们随项目变，抄进正文的那一份不会跟着项目件改，而核片的人读的是正文这一份。
- **把抽帧路径、命令、本机路径写进产出**——那是内部过程，不是给读者的东西。

## Red Flags

- 「先粗看一遍，有明显问题再细查」
- 「这条和上一条差不多，参照上次的清单」
- 「时间紧，关键几项核一下就交」
- 「他们已经返两轮了，这条降成建议吧」
- 「这周第八条了，前七条都没问题」
- 「这处看不清，先按合格算」
- 「基准里就是这么写的，所以这句没问题」
- 「顺手把我觉得更好的剪法也写上」
- 「两份稿差不多，一起当基准用」
- 「通过项就不写了，省得清单太长」
- 「取证覆盖清单回头补，先把问题交了」
