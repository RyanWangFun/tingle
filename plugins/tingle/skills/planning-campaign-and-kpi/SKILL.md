# planning-campaign-and-kpi

## 概述

一句话职责：**把一个已定的目标做成一份能对外承诺的投放策划——包含它撑得起的那组指标，以及这组数凭什么成立。**

- **指标不是拍出来的，是倒推出来的**。照搬客户拍脑袋的数，等于把一个做不到的承诺签下来；本环节的价值就在于把"拍脑袋"换成"算过的账"。
- **策划与指标是同一件交付物的两面**：策划说要做什么，指标说做到什么算数，谈判依据说这组数凭什么。三样分开交，客户会各挑一样来压你。
- **拿不到参照物就不给数**。没有历史数据、没有竞品回收、没有行业口径时，正确动作是写"需先建监控，当前无法给确定值"，不是给一个看起来合理的数。

## 何时用 / 何时不用

**何时用**：目标、真问题、链路终点已经确定，要产出策划；客户问"这个数合不合理"；要准备一次关于指标的谈判；阶段变化（进入放大期、进入大促周期）要重排节奏与指标。

**何时不用**：
- 还没读懂客户要什么、真问题还没验——先走上游那个环节，本环节吃的是它的产出。
- 要定人群、挖需求、做内容、配投放工具、做搜索承接、做卖货、做复盘——各归各的环节。

## 运行前

**第一步跑 `tingle check planning-campaign-and-kpi`**，拿到开工单再开工；拿到卡点单本次不跑，按卡点单载入 REQUIRED SUB-SKILL: `tingle:project-readiness` 修完复验。开工单上附着的就绪判据由本 skill 开跑时逐条对照判，判不准停下问人。

## 业务方法

五道工序按序走。**每道工序的细节在它自己的深读件里，走到那一道再读那一份**——主手册只装每次都要遵的东西。

| 工序 | 产出什么 | 走到这一步读哪份 |
|---|---|---|
| 一 · 从生命周期定打法 | 阶段定位、核心打法、人群发散顺序 | `references/lifecycle-playbooks.md` |
| 二 · 定链路与人群预算 | 链路组合、多产品线取舍、各人群层预算占比 | `references/channel-and-budget-tradeoffs.md` |
| 三 · 排预算节奏 | 测试期／放大期／节点期的钱怎么分时间花 | `references/budget-pacing.md` |
| 四 · 给出合理指标 | 主指标 + 过程指标链（每段带折损基点）+ 数值来源 | `references/deriving-kpi.md` |
| 五 · 备好谈判依据 | 客户原始指标的脱锚点、反驳数据、重定后的数 | `references/negotiating-kpi.md` |

### 第 0 步 · 凌驾性前提：先锁目标

**所有动作都挂在上游钉死的真问题与链路终点上。禁止在本环节重新定义目标**——目标含混就退回上游，不在这里补。**不要"既要又要还要"**：目标不同，对标竞品不同、打法不同、预算结构不同。先锁一个具体要完成的结果。

### 工序一 · 从生命周期定打法

**禁止**：

- **禁止给一个还在起盘的品配成熟期打法。** 阶段错配是这个环节的头号大病，它会在后面变成"指标根本放不出去"。
- **禁止照搬另一个平台的人群顺序。** 这个平台有强搜索心智，是**先找到最核心人群、再向外发散**；按"先大曝光囊括泛人群再层层洗"的顺序做，前面的钱基本浪费。

**本工序必须产出**：阶段定位（上市／成长／成熟／换新，对应快／拓／占／新）、核心打法动作组合、人群发散顺序与各层的内容形态。

### 工序二 · 定链路与人群预算的组合取舍

**禁止**：

- **禁止在没判决策成本档之前定链路。** 低决策成本的重心是把"互动 → 搜索 → 转化"快速建起来；高决策成本的重心在搜索卡位与信任型身份，追爆文没用。
- **禁止按产品逻辑绑定多产品线。** 能不能绑、跟谁绑，唯一判据是"它们想触达的核心人群是不是落在同一场景"——这是人群逻辑。异场景硬绑只会摊薄精力。
- **禁止把预算平摊到各人群层。** 铁律只有一条：**宁愿把核心人群洗两三遍，也不把泛人群投一遍。**

**本工序必须产出**：链路组合（各链路的角色与占比）、产品线取舍（核心大单品 + 关联辅助）、人群预算分配百分比。

### 工序三 · 排预算节奏

**禁止**：

- **禁止一上线把预算全花完。** 先切一小块做数据回收、建数据基点，验证对标打法在本方是否有效，再放大。
- **禁止在没算总账之前设放量上限。** 单日消耗好看、单次投入产出比达标，算总账却是亏的——投得越多亏得越多。放到哪一步就不能再放，由客单价、点击成本、复购特性共同决定。
- **禁止把难度一上来拉满。** 做不适合团队基因的事，会有很长试错期，最后被误判成"这个打法不可行"。

**本工序必须产出**：测试期切多少、要买回哪些数据基点；放大期的复制与放弃规则；节点期的提前量与阶段拆分；放量上限与止损条件。

### 工序四 · 给出合理指标

**这是本环节的灵魂之一。**

**禁止**：

- **禁止照搬客户拍来的数。** 本工序的产出是"我方倒推出来的、撑得起的那组数"，客户的原始数是待判对象、不是输入前提。
- **禁止把执行动作影响不到的东西设成它的指标。** 只考核它能影响的核心要素；影响不到的，再怎么要求也没用。
- **禁止上来就卡结果指标。** 考核从链路最前端卡起——连前端阅读量都没完成，考核后面的投入产出比没有意义。
- **禁止给抽象指标。** "有效内容模板""投入产出比"对执行动作没有感觉，要拆成"哪几个方向、对标是什么、这周做多少条"。
- **禁止在没有参照物时给一个数。** 三条倒推路（可控要素／历史与竞品结果／销售额公式降维）全都走不通时，写"需先建监控，当前无法给确定值"。
- **禁止用一个统一指标考核全链路。** 不同内容形态的流转效率差很多，用唯一标准要求所有动作，等于没考核。

**本工序必须产出**：主指标（挂回链路终点的那个结果指标）、过程指标链（每段带折损基点）、每个数值的来源、复购特性下的卡法（无复购卡单次投入产出；高复购单次不亏即可、算总账）。

### 工序五 · 备好谈判依据

**这是本环节的灵魂之二。守一条心法：不抛观点，先摆数据。**

**禁止**：

- **禁止用"我觉得"参与谈判。** "我觉得转化率不高""我觉得人群不精准"既找不到真问题，也说服不了人。要把"差"界定成"比谁低多少"的具体差距，参照物来自往期、预期、行业、竞品。
- **禁止一竿子打死客户之前的动作。** 花过的钱或多或少都有结论，只是相对当前阶段高效与否、匹配与否。重定的是口径与预算投向，不是全盘否定。
- **禁止为了好谈又造一个孤儿指标。** 重定后的每个数仍要挂回一段定性意图。

**本工序必须产出**：客户原始指标的脱锚点属于哪一类、每个脱锚点配的反驳数据、重定后双方能对齐的数、以及这次对话的骨架（先界定 → 再拆解 → 摆参照物算账 → 给重定的数与达成路径）。

## 接口与边界（声明）

- **适用环节**：「把已定目标做成一份能对外承诺的投放策划与指标」——换一个客户项目也会再次发生的固定环节，非一次性事务。
- **input schema**：`目标与真问题`（预期类型、品牌阶段、真问题一句话、链路终点，对象）；`产品事实`（品类、客单价、决策成本、是否有复购、毛利、产品线数量，对象）；`约束`（预算规模、时间窗口、有无节点、内容产能、团队基因、历史数据是否存在，对象）；`客户原始指标`（客户拍来的原始数，字符串）；`可对标竞品`（数组）。
- **output schema**：`策划`（生命周期定位、核心打法、链路组合、人群预算分配、预算节奏、阶段拆解）；`指标建议`（主指标、过程指标链含折损基点、每个数值的来源、复购特性处理）；`谈判依据`（脱锚点分类、反驳数据、重定后的数、对话骨架）；`放量与止损`（上限条件、止损触发条件）；`待确认项`（数组）；`未披露项`（数组）。**可沉淀候选（reusable_candidates）**：`指标建议`里回收到的折损基点与单位成本（同品类下一单直接复用）、`策划`里被验证过的打法组合、`谈判依据`里成立过的反驳路径。——**它们只是候选；够不够格真的留下、沉进哪一格、标什么成色，按 REQUIRED BACKGROUND: `tingle:banking-proven-assets` 判。**
- **写回位置**：`策划案落点`（见 requirements 的 outputs 段），地址由项目档案登记，不自行选址。
- **规则层与项目事实**：运行时挂 **合规类目层**（判承诺的指标口径能不能给——某些品类不允许把疗效相关结果写成承诺）与 **品牌层**（品牌既有心智与阶段）；不挂类型层。所需项目事实字段：`合规类目`、`产品品类`、`品牌`、`阶段`。
- **工具**：读飞书文档与多维表格（经开工单地址取得）、写飞书文档（登记的落点）。无其它外部接口调用。
- **决策档**：**决策**——本环节对项目走向本身做判断（该走什么策略、承诺什么指标、花多少预算），这件事本身要由人来定，本 skill 只负责把料备齐、把账算清。**不得标自动。**
- **复核包**：策划本体 ＋ 指标建议本体 ＋ 每个数值的来源与倒推过程（哪条路推的、参照物是什么）＋ 客户原始指标与本建议的逐项差距对照 ＋ 谈判依据 ＋ 未披露项清单 ＋ 待确认项清单。
- **升级条件（命中即停交人）**：①指标口径触及合规红线而判据不确定；②四层规则冲突；③缺关键项目事实（合规类目、产品品类、阶段任一取不到）；④产出需对外发送（交给客户、进提案、进合同）；⑤给出的任一指标数值将被对外承诺；⑥判定客户原始指标不合理、需要重定；⑦三条倒推路全走不通、拿不到任何参照物；⑧要决定放量上限或止损点。

## 产出验收判据（DoD）

一次运行合格，当且仅当：

1. 策划六格（生命周期定位、核心打法、链路组合、人群预算分配、预算节奏、阶段拆解）全部填了，人群预算分配写成百分比且各层加总为一；
2. **每一个指标数值都写明它由哪条路推出来、参照物是什么**（可控要素／历史数据／竞品回收／行业口径）；推不出来的写"需先建监控，当前无法给确定值"，**没有一个数是拍出来的**；
3. 过程指标链每一段都带折损基点，且基点标了来源；引用了任何示例量级的，明确标注"示例、非本项目基准"；
4. 复购特性已判定，并据此写明卡单次投入产出还是算总账；毛利与复购两个数取到或标未披露；
5. 客户原始指标与本建议逐项对照，差距处已归到脱锚五类之一，并各配了一条可摆出来的数据；
6. 放量上限与止损触发条件各写成一条可当场判定的句子（不是"看情况""效果不好就停"）；
7. 策划与指标里每个数字都挂得回一段定性意图——按 REQUIRED BACKGROUND: `tingle:keeping-metrics-anchored` 判，有孤儿指标或裸承诺即不合格；
8. 待确认项与未披露项两份清单随产出交出，**不许因为清单空着好看就把不确定的项填掉**。

## Quick Reference

| 情形 | 动作 |
|---|---|
| 还在起盘的品，客户要成熟期指标 | 阶段错配，回工序一；把错配摆成谈判依据 |
| 高决策成本品类 | 链路重心放搜索卡位与信任型身份，不追爆文 |
| 产品线超过三个 | 先收敛到核心大单品 + 同场景关联辅助 |
| 预算怎么分到人群层 | 核心层吃大头，洗两三遍；泛人群最后 |
| 客户要一上来全投 | 先切测试期建数据基点，回收后再放大 |
| 没有历史数据也没有竞品数据 | 写"需先建监控，当前无法给确定值" |
| 高复购高毛利品 | 单次不亏即可、算总账，不卡死单次投入产出 |
| 客户并列要多个指标 | 摆出三者各自需要的打法与预算，逼他锁一个 |
| 客户说"同行能做到" | 摆客单价、毛利、复购三项差异，以及对方看不见的投入 |
| 客户说"某某说该这么做" | 摆对方的预算量级与打法对应关系 |
| 要不要硬刚 | 停，交人——含客户关系判断 |

## Common Mistakes

- **把客户拍来的数当输入前提**——它是待判对象；照搬等于把做不到的承诺签下来。
- **只给一个总销售额指标，没有拆解**——没有过程指标链就没有数据基点，做不到时也说不清断在哪。
- **给了执行动作影响不到的指标**——影响不到的东西，再怎么要求也没用。
- **上来就卡结果指标**——连前端阅读量都没完成，后面的数没有意义。
- **用一个统一指标考核全链路**——不同内容形态的流转效率差很多。
- **拿别的品类的折损率、转化率、点击率当本项目基准**——必须用本方历史或本次回收重建。
- **放量没算总账**——单次达标、总账亏损，投得越多亏得越多。
- **谈判时先抛观点**——先摆数据、把对方拉到同一认知水平线，再给结论。
- **一竿子打死客户之前的动作**——重定的是口径与投向，不是全盘否定。

## Red Flags（出现即停，回到对应工序）

- 「目标还有点模糊，边做边清晰」→ 退回上游环节，不在这里补目标。
- 「先按行业平均值填一个」→ 回工序四，标"需先建监控"。
- 「这个数客户已经定了，照着排就行」→ 回工序四，倒推一遍再谈。
- 「预算先全花出去，跑起来再说」→ 回工序三，切测试期。
- 「日耗很高、单次投入产出也达标，继续加」→ 回工序三，算总账。
- 「我觉得是人群不精准」→ 回工序五，找参照物、说出具体差距。
- 「这个数不合理，直接跟客户说不行」→ 停，交人。
